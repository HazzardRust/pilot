1. **See the current state** of the merge/rebase. Check git history, and the conflicting files.

2. **Find the primary sources** for each conflict. Understand deeply why each change was made, and what the original intent was. Read the commit messages, check the PRs, and read the slice file that each side was implementing — that is where the intent was written down before the code was.

3. **Resolve each hunk.** Preserve both intents where possible. Where incompatible, pick the one matching the merge's stated goal and note the trade-off. Do **not** invent new behaviour. Always resolve; never `--abort`. A generated file is regenerated by its generator, never merged by hand: this package's `docs/adr/README.md` by `node scripts/adr-index.mjs`.

4. Run the **phase gate** on the result, not a subset of it: `node --test`, the slice's own verification command, and the build. Fix anything the merge broke. A conflict resolved by hand is exactly the change least covered by the tests that were already green on each side.

5. **Finish the merge/rebase.** Stage the files you resolved, by name, and commit. If rebasing, continue until all commits are rebased.
