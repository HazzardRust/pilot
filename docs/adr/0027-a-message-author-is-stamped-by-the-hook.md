# A deck message's author is stamped by a PreToolUse hook, never claimed by the agent

The user asked that every crew message on a thread say which kind of agent wrote it — the pilot, the architect, an implementer, the fundamentalist, QA, the teacher, an explorer, or something else — and that the label never come from what an agent writes about itself (spec 1 and 2 of `docs/design/run-record/architecture.md`). The stdio client (`deck/client.mjs`) serves every agent of a session through one process, so it cannot tell a QA agent's `deck_reply` from the pilot's; the only point where a call and its caller are both known is the harness's hook payload, which carries `agent_type` for a subagent. We decided that `hooks/deck-author.js`, a `PreToolUse` hook matched on `mcp__plugin_pilot_deck__deck_(post|reply|resolve)`, returns `updatedInput` as the tool input plus `author` set to the raw `agent_type`, or `""` when there is none, **always**, so a value the agent put there itself never survives; that `author` is a declared optional property of those three tools' schemas, because Claude Code validates `updatedInput` against the tool's `inputSchema`; and that the daemon maps the raw type to a kind in one function, `authorKind` in `deck/items.mjs` (strip `pilot:`, then `pilot-`; `""` and `pilot` are the pilot; a crew name is itself; anything else, the harness's own `Explore` included, is `other`), storing the kind as `author` on the item, on each crew message and as `resolvedBy` on a resolution. A live probe on 2026-09-23 against Claude Code 2.1.280 settled that `updatedInput` reaches an MCP tool with no `permissionDecision` in the hook's answer: a main-session `deck_post` stored `""`, a subagent's `deck_reply` stored its `agent_type`, and a main-session `deck_reply` that named `author: "qa"` itself stored `""`. So the hook answers no permission question on the user's behalf. Rejected: a `PostToolUse` lane keyed by item id (two writes per message, and a window where the message reads unattributed — the fallback only had the probe failed); the agent declaring itself (the user's last resort, and exactly what spec 2 forbids); mapping the kind in the hook, which would put a second copy of the kind set on the CommonJS side of the L35 line; and parsing the body for identity.

**Amends ADR 0024** on the pilot's payload. The header of `hooks/agent-roster.js`, written under ADR 0024, read "a main session's payload carries no `agent_id` and no `agent_type`". That is true of a session started with `/pilot:pilot` and not of one started with `claude --agent pilot:pilot`, which carries `agent_type` `pilot:pilot` and no `agent_id` (code.claude.com/docs/en/hooks: `agent_type` is "present when the session uses `--agent` or the hook fires inside a subagent"; `agent_id` is "present only when the hook fires inside a subagent call"). So "no `agent_id`" is what identifies the pilot, and `authorKind` maps both `""` and `pilot:pilot` to `pilot`. The roster's behaviour was already right, because it requires `agent_id`; only its header was corrected.

**Consequences**: a message stored before this change has no `author` and renders as `pilot`, which is what it rendered as before, so nothing is migrated and nothing already on a deck changes its reading; a message written over HTTP by a hook rather than through the three tools is not stamped and also reads `pilot`, which is why a crew agent's own notice is told apart by its kind rather than its author (L17); a session running a plugin copy without this hook can still pass an `author` of its own, and a hook payload the script cannot parse goes out unstamped rather than failing the call; the user's own messages keep `from: 'user'` and read "you"; and each kind's colour is one custom property in `deck/ui/deck.css`, mixed with the text colour so it holds in light and dark (A4).
