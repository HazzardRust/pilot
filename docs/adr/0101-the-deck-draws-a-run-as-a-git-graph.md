# The deck draws a run as a git graph computed at render time, from a list of blockers

ADR 0014 drew a run as an indented tree: one `after` per row, so a slice that needed two others could not say so, and two slices that could run side by side looked like parent and child. The user's own fixture (S1 to S2 and S3, converging on S4, then S5 and S6 to S7 to S8) is a graph, and they asked for it drawn as `git log --graph` draws it. We decided (`docs/design/slice-graph/architecture.md`, L1 to L5, L9, A2) that `graphOf(slices)` in `deck/status.mjs` replaces `treeOf` and is still computed at render time from the flat rows, nothing stored, so every deck already written renders (0014's D1 holds). The lane rule is git's: rows go in stable topological order, a dot takes the leftmost lane whose open edge targets it or the first free lane, its first child keeps the lane and each other child takes the first free lane, and a sink's lane stays open to the end point, so no line crosses a foreign dot. A blocker reachable through another blocker is not drawn (transitive reduction), so the user's S4 "requires S1, S2, S3" draws two converging lanes, not three. `after` becomes a list: an entry matches a row by full name or by `S<n>` identifier, two rows with one identifier are refused on write, and a blank entry, an empty list or a duplicate entry is refused. One `blockersOf(row)` reads a legacy string as a one-entry list and the next merge upgrades it, so no migration runs. 0014's D2 validation, that a name matching no row and a cycle are refused in the deck's own voice, carries over to lists unchanged. `delivers` is dropped from the schema and from the pilot's mirroring (A2): a stored value is accepted and discarded, and the spec lines stay in the artefact. The crew's wording follows the picture: the pilot starts the next slice on N's lane and runs in parallel the slices no line joins, the architect lists blockers and puts parallel slices on side-by-side lanes, and each change is net zero bytes or fewer in its definition, the pilot's pin lowered with a history line (L9). Rejected: a new `deck/graph.mjs` (needs `sliceKey` exported and a second vocabulary home), lane packing by longest path (reorders rows away from the plan), drawing every listed edge (a phantom lane from S1), and a one-off migration of `deck.json` (irreversible for no gain).

**Consequences**: a run whose rows name several blockers draws as the graph it is, and the pilot's definition stops teaching "DAG edge"; the edge tab strip and the `<details>` bookmark of ADR 0014 stand, so that ADR is superseded only for its tree and its single `after`; and spec lines no longer appear on the deck, only in the artefact.
