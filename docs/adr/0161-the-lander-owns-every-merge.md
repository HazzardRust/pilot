# The lander owns every merge

We decided that one new agent, the lander, owns every merge onto `pilot` and the clean tail after it, and that the user's one Sign off press is the only press a feature needs.

## Context

A landing that conflicted went to a `pilot-implementer` the pilot briefed per conflict (ADR 0154 L6), QA resolved the step-9 conflict in the kept worktree (ADR 0116 L5), and a refused landing offered Sign off again (ADR 0111), which is the user's second press. Three commands (`land`, `sync`, `integrate`) each worded a conflict their own way, and nothing checked `pilot` before the press. The slice branches were left on origin after a landing.

## Decision

- **L2 The pilot spawns the lander, and the lander is a new agent type.** The deck cannot spawn an agent, so the press line asks once and the brief is the gate2 id.
- **L3 The lander never moves `pilot` itself.** `pilot` moves only through the deck's spawned `pilot land` on the lander's `Land again`; `feat/<slug>` moves through `pilot integrate --default`; a standalone sync conflict is the one push it makes itself, `pilot sync`.
- **L4 No destructive edit mid-merge.** A hunk is resolved with the Edit tool only; a generated file is regenerated by its generator; the lander stages by name and runs `git commit --no-edit`, and never runs `sed -i`, `git checkout --ours/--theirs`, `reset`, `--abort`, `rm` or `clean` mid-merge.
- **L5 One lander per repository, and nothing yields a gate slot.** A second due lander waits on the first's hand-back, and the lander runs `npm test` once, on its final resolution, never while the deck's `pilot land` runs; it waits on `pilot landing <gate2>` instead. Nothing yields a gate slot: slots stay first come, first served for QA, the lander and the pilot alike.
- **L6 The gate2 check is merge-tree plus a prepared merge.** No worktree is made at post time, and a conflict that only generated files have counts as clean.
- **L7 Every refused landing goes to the lander, and the deck refuses a second press.** `Land again` from the lander runs land on any `refused` gate2: in the kept worktree when there is a conflict, otherwise fresh.
- **L8 The exempt paths move to `scripts/vocabulary-exempt.txt`**, one path per line, `merge=union`.
- **L9 The lander claims by `Resolving`.** It is accepted from the lander on any signed gate2 and stops the 15-minute clock; a due lander is derived from items, so nothing is migrated.
- **L10 The run record is committed on `feat/<slug>` before the landing merge**, by `commitRecords`, so the one merge carries it.

## Rejected

- *A `pilot-implementer` on a fix brief* (L2): the pilot writes a brief per conflict, which is today's shape.
- *The lander running `git push`/`git merge` onto `pilot`, or `pilot land`* (L3): the first is refused as a merge without review, the second from the crew (ADR 0154 L5). *A deck route that runs sync*: a second spawn shape.
- *Whole-file side picks* (L4): the shape the classifier refused.
- *Lander priority* (L5): it needs a preemptive slot and would stall QA's gate mid-suite.
- *Merging `pilot` into `feat/<slug>`* (L6): ADR 0116 L6 forbids it.
- *Keeping Sign off again for non-conflict refusals* (L7): the user's second press.
- *A line-level resolver for `vocabulary.mjs:27`* (L8): code that parses code.
- *A second commit on `pilot` after the merge* (L10): a second push.

## Consequences

- The user presses Sign off once; a refusal reaches the lander, not the user.
- ADR 0154, 0116 and 0111 are amended to say so, and their other lines stand.
- Landing-keeps-worktrees' prune step is the lander's; its ADR is amended when it lands on `pilot`.
- The agent budget and the closing report are recorded in the lander's architecture (L11, L12), not here.
