# The panel stack is written by a layout pass, and CSS stops positioning a panel

The walkthrough of 2026-09-22 asked for the deck's open panels to stop floating: each widget's top edge touching the bottom edge of the one above it, and a panel opening at the height of its content instead of a share of the viewport (spec 22 and 23 of `docs/design/deck-workspace/architecture.md`). L3 of that feature had taken the panels out of the flow inside the already-fixed strip and positioned each one from two custom properties — `--open`, how many tabs are open, and `--above`, how many open tabs precede this one — so a panel's top was `calc(var(--above) * (100vh - 5rem) / var(--open))`, a viewport fraction that no sibling's real height ever entered. Both new behaviours need exactly that: a panel's offset is the sum of the **used** heights of the open panels above it, and those heights are either the content's or the height the user dragged, neither of which CSS can read off another element. We decided that `deck/ui/deck.js` gains a layout pass which walks the open panels in document order and writes each one's `top` as the running sum and its `max-height` as what is left to the bottom of the screen, and that the `--open`/`--above` counters and the `:has()` rules that set them are deleted; the pass writes `top` and `max-height` and never `height`, because the `ResizeObserver` beside it persists `panel.style.height` and a written height would store a size nobody dragged, breaking the per-deck remembered size one slice after it was built. Rejected: **CSS anchor positioning** — `top: anchor(--tree-panel bottom, 0px)` chained through the panels' fixed source order, with `anchor-size()` for the cap — which really would express it in pure CSS, but ships in Chromium and Safari and not Firefox, on a package whose whole point is installing on someone else's machine, and is unreadable and unverifiable outside a browser that has it; **re-parenting the three panels out of their `<details>` into one flex column**, which buys the column at the price of the native disclosure that L3 and ADR 0014 both exist to keep, and of the selectors that hide a shut panel; and `display: contents`, already rejected in L3. The disclosure itself is untouched: what becomes scripted is *where* a panel is, never *whether* it is open.

**Consequences**: the deck's panels no longer lay out with JavaScript off — they sit at the tab group's top and overlap — which is a real loss and a small one, since the remembered size, the live region swap, Esc and the tab restore are all already scripted and only the disclosure was ever load-bearing without them; `deck/test/tabs.test.mjs`'s pin on `top: calc(` is rewritten by the slice that lands this, so a stylesheet that quietly goes back to positioning a panel fails a test rather than passing one written for the old mechanism; the three-panel ceiling baked into the old counters goes with them, so a fourth bookmark costs the group nothing, which is what `deck/ui/strips.html`'s own comment always claimed; and L3 of the architecture artefact is amended in place and dated rather than reversed, because its first sentence — the panels out of the flow inside the fixed strip, which is what keeps a bookmark from moving when another opens — is still the mechanism.
