# S2 The gate2 and the closing report list the pilot's closes

Feature `blocking-close` · delivers spec 3 · source: `../architecture.md` §2, A1, L6 · after: S1 (`isPilotClose`)

## Files owned

- `deck/pilot-closes.mjs` (new): the query and the section text.
- `deck/closing-report.mjs`: `postFilled` appends the section to a gate2 body with a ticket (only when it has a close); `closingReportOf` takes `closes` and adds the section, `- none` when empty. At most 10 changed lines here (overlap with lander-tail #959).
- `deck/README.md`: one row for `pilot-closes.mjs`.
- `deck/test/pilot-closes.test.mjs` (new).

## Tests

1. `a pilot close is listed`: `pilotClosesOf` → the `Assumed:` close of a design question, not a user-answered one, not another ticket's.
2. `the report names it under its heading`: `closingReportOf` → body has `Closed by the pilot:` and the id and reason; with none, `- none`.
3. `the gate2 lists it before Sign off`: `postFilled` → a gate2 on a ticket with 1 pilot close has the section in its body; with 0, the body is as posted.
4. `the report still asks nothing`: `closedByPilotLines` → a reason ending `?` passes `reportAskGaps` (code-spanned as `said` does).

Rewrite check: computing the closes inside `postFilled` keeps all four results.
