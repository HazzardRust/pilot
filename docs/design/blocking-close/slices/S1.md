## Interface

```
deck/blocked-shape.mjs
  PILOT_CLOSES = ['Moot:', 'Assumed:']
  isPilotClose(item, resolution: string, author: string): boolean
    // a question with blocking === true, not proposal; author kind pilot;
    // resolution = a PILOT_CLOSES prefix + a non-empty reason;
    // no message reads `Closed with: Moot:` or `Closed with: Assumed:` (the user's reopen, spec 6)
deck/store-items.mjs  resolveItem(id, resolution, author)   // refusal: "... or the pilot's `Moot: <why>` / `Assumed: <what>`"
deck/store-items.mjs  resumeIn(deck, question)              // unchanged signature
```

## Tests

1. `the pilot closes a blocking design question as Moot`: `resolveItem` → closed, `notice === true`, gate2 post accepted.
2. `the pilot closes a blocking design question as Assumed`: `resolveItem` → closed; gate2 refused before, accepted after.
3. `a bare or empty close is refused naming both prefixes`: `resolveItem` → refusals on `Done` and `Moot:` alone name `Moot:`, `Assumed:` and Assume the default.
4. `only the pilot`: `isPilotClose` → false for a QA writer and an unstamped one.
5. `never a gate, walkthrough or proposal`: `resolveItem` → a `Moot:` close refused on a gate1, gate2, signoff, blocking walkthrough and blocking proposal (5 kinds).
6. `a pilot close resumes the ticket a design question paused`: `resumeIn` → the ticket is yellow, `paused` gone, in the close's write.
7. `the user's reopen restores the hold for good`: `isPilotClose` → false after a reopen; the gate2 is refused again and a second `Moot:` close is refused.

Rewrite check: inlining `isPilotClose` into `resolveItem` keeps all seven results.
