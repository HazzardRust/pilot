# S2 Ids in a refusal or a notice read as titles

Feature `deck-title-prose` · delivers spec 2, 3 · source: `../architecture.md` §2, L5, L6, A2 · after: S1

## Files owned

- `deck/ui/render.mjs`: `withTitles`; `renderRefusal` (2264) and `renderClosedNotice` (1661) call it; their callers pass `items`.
- `deck/test/title-ref-ids.test.mjs` (new): the pins below.

## Interface

```
render.mjs  withTitles(text: string, items): string
              // escapes text; each /\bitm_[0-9a-f]{12}\b/ naming an item in items becomes
              // <a class="ref" href="/thread/<id>">escaped title</a>; an unknown id stays as escaped text
            renderRefusal(reason: string | null, items): string     // capRefusal first (L6), then withTitles
            renderClosedNotice(item, back, items): string           // the resolution's first line through withTitles
S1's .ref: the class and rule reused, never restated
```

## Tests

1. `a gate2 refusal shows its ticket and question titles, not ids`: `renderRefusal` → for the `store.mjs:919` reason, both titles appear in `class="ref"` links and no `itm_` id is bare.
2. `an id the deck does not hold stays as written`: `withTitles` → `itm_000000000000` is kept, with no link.
3. `a title with markup is escaped`: `withTitles` → `<b>` shows as `&lt;b&gt;`.
4. `the cap applies before the swap`: `renderRefusal` → a 400-character reason is cut at 300 code points, then swapped.
5. `a closed notice's resolution line names its item by title`: `renderClosedNotice` → "merged none: <title chip>".
6. `the store's refusal text is unchanged`: `withTitles` → `press-refused.test.mjs` and `red-grilling.test.mjs` still pass unedited.

Rewrite check: whatever matched the ids, a page reason or a notice line holding a known item's id would still draw that item's title in one `class="ref"` link, and an unknown id would be left alone.
