## Interface

```
releaseNotes({ git, pilotRef, mainRef, prs }) -> { title: string, body: string, rows: Array<{ slug, pr: number|null, sha }> }
  // rows: first-parent two-parent commits `Merge feat/<slug> into pilot` in mainRef..pilotRef, oldest first
  // prs: Array<{ number, headRefName }> from one `gh pr list --base pilot --state merged`
  // title: `Release: a, b, c +N more`, at most 120 characters; body: a markdown table, one row each
releasePr({ git, gh, already }) -> { number: number|null, opened: boolean, why?, byHand?, none? }
  // as mainGetsPilot answered (land.mjs:294); every gh call is argv, never a shell string
  // ensures label: gh label create release --force; then create or gh pr edit <n> --title --body --add-label release
```

## Tests

1. `two landings name both slugs`: `releaseNotes` → after landing `feat/a` then `feat/b`, title `Release: a, b`, 2 rows.
2. `a sync merge is no row`: `releaseNotes` → `Merge main into pilot` on pilot's first parent adds 0 rows.
3. `the title is bounded`: `releaseNotes` → 30 slugs give a title of at most 120 characters ending `+N more`.
4. `every landing rewrites and labels`: `releasePr` → an open release PR: 1 `pr edit` carrying `--add-label release`, 0 creates.
5. `the first landing opens it labelled`: `releasePr` → none open: 1 `label create release --force`, 1 `pr create` with the release title.
6. `a fork run remote opens none`: `releasePr` → `pilot.remote` a fork: number null, 0 gh calls.

Rewrite check: replacing git log parsing with any other walk keeps the titles, rows and gh calls above.
