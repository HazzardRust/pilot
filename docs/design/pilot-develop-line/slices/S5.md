# S5 `pilot base` names the concluding feature

Feature `pilot-develop-line` · delivers spec 4 · source: `../architecture.md` §2, L5, A5 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: opus — assumed A5 and a read across the deck's HTTP seam.

## Files owned

- `deck/tickets.mjs`: `queueView` answers `concluding`: the open green ticket of the repo and its record's slug and branch, or null.
- `scripts/base.mjs`: reads `concluding` (injected; default the deck's `/api/tickets`), fetches `origin/feat/<N>` and prints the chained line.
- `scripts/test/base-chain.test.mjs` (new): the pins below.

## Interface

```
queueView(items, repo, records, opts) -> { live, red, decision, records, concluding: { ticket, slug, branch } | null, … }
base({ cwd, say, warn, concluding }) -> Promise<number>
  // concluding: () => Promise<{ ticket, slug, branch } | null>
  // prints `base feat/<N> <sha> (concluding <ticket>)` when concluding names a branch origin holds; else today's `base pilot <sha>…`
  // deck not reached: `base pilot <sha> (deck not reached)`
```

## Tests

1. `a green ticket is the concluding feature`: `queueView` → one open green ticket with a record: `concluding.branch` `feat/n`.
2. `no green ticket, no chain`: `queueView` → `concluding` null.
3. `base prints the chained line`: `base` → stub concluding `feat/n` pushed to origin: `base feat/n <sha> (concluding itm_1)`.
4. `a concluding branch origin lacks falls back`: `base` → `base pilot <sha>`.
5. `an unreachable deck falls back and says so`: `base` → concluding throws: `base pilot <sha> (deck not reached)`, exit 0.

Rewrite check: any deck read keeps the three printed lines above.
