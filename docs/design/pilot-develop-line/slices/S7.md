# S7 land guards the chain and retargets

Feature `pilot-develop-line` · delivers spec 4b, 4c · source: `../architecture.md` §2, A2, A6 · after: S2 (`land.mjs`), S6 (`baseOf`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a refusal on the landing path and a `gh` process start (security trigger).

## Files owned

- `scripts/land.mjs`: `chainGuard` before any push; `retarget` after pilot is pushed.
- `scripts/test/land-chain.test.mjs` (new): the pins below.

## Interface

```
chainGuard({ cwd }) -> void
  // S6's baseOf: chained 'feat/<N>' throws `NOT landed: built on feat/<N>, which has not landed; land it first, or revert it (fix round); nothing pushed`, exit 1
retarget({ gh, head }) -> string[]
  // each open PR with base `head`: `gh pr edit <n> --base pilot`; answers `retargeted #<n> to pilot` lines; never throws
```

## Tests

1. `N+1 before N is refused`: `chainGuard` → land in N+1 with N unlanded: exit 1, the line names `feat/n`, origin pilot unmoved.
2. `N+1 after N lands clean`: `chainGuard` → land N, then N+1: exit 0, no conflict, one merge each.
3. `N's landing retargets N+1's PR`: `retarget` → fake gh lists #12 with base `feat/n`: 1 `pr edit 12 --base pilot`.
4. `a failed retarget is a line`: `retarget` → gh throws: landing exit 0, `retarget failed` line.

Rewrite check: any guard keeps N+1 off pilot until N is, and N+1's PR on pilot after N lands.

## Done

- **Expected**: a chained feature cannot land its base unsigned, and its PR shows only its own diff once N lands.
- **Verification**: `node --test scripts/test/land-chain.test.mjs scripts/test/land*.test.mjs`; `npm test`.
- **Evidence**: test output; test 2's `git log --first-parent pilot` pasted in the report.
- **Prohibited**: no revert inside `land`; no forced push; no shell-string gh call.
- **Done when**: the four tests pass and `npm test` is green.
