## Interface

```
skills/audit/areas/navigability.md   frontmatter { area: navigability, owner: explorer, model: sonnet, spec: [7] }
  ## Measure            // read-only commands only, so pilot-explorer's standing rules hold unchanged
    oversized files: tracked source files over 800 lines (`git ls-files` + `wc -l`), largest first, top ten
    dead code: exports with no importer (`git grep` on the export name), stated as candidates with the grep
    duplicates: modules of the same name or near-identical bodies in two places, with both paths
    entry points: package.json bin/main/scripts, a README "start here", or their absence
    map and glossary: an architecture doc, CONTEXT.md or glossary, or their absence
  ## Rows
    one row per finding in S1's Row shape; command = the exact grep or wc; output = the counts
  ## Return
    the rows as JSON the auditor merges, plus the explorer's friction line
```

## Tests

1. `the navigability area is owned by an explorer and delivers spec 7`: frontmatter parses.
2. `every measurement in it is a read-only command`: no install, build, test or server verb appears under Measure.
3. `oversized files are counted with the command that counted them`: the 800-line threshold and `wc -l` are named.
4. `dead code is reported as candidates with the grep that found no importer`.
5. `the explorer returns rows in S1's Row shape`: the Return section names the fields.
