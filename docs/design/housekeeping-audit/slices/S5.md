## Interface

```
// deck/audit.mjs, beside S1's validateReport, rankRows, renderReport, saveReport
export const OFFER_EVERY_RUNS = 10
type AuditRecord = { offers: { answer: 'yes' | 'no', at: string }[], counted: string[] }   // record.json, per repoKey
export function countRun(repo: string, runKey: string): number   // adds runKey once; a key already counted is a no-op
export function auditDue(repo: string): 'first' | 'every' | null  // reads only; every: counted.length >= OFFER_EVERY_RUNS
export function recordOffer(repo: string, runKey: string): AuditRecord   // fix round: no yes/no; empties counted and remembers runKey, so a resume does not count it again
bin/pilot.mjs
  pilot audit count <run key>    → prints the count; exit 2 on an empty key
  pilot audit due                → exit 0, prints "due first" or "due every <n>"; exit 1, prints "not due <n>"
  pilot audit offered <run key>  → records that the offer was made; exit 2 on an empty key
skills/pilot/SKILL.md step 1, after the depth-question paragraph:
  run `pilot audit count <slug>` (`<slug>#<n>` for run n ≥ 2 of a split feature), then when `pilot audit due`
  exits 0 and full auto is off (L13), post beside the depth question a `question` offering the audit
  (yes / no), record the offer with `pilot audit offered <slug>`, and on yes spawn `pilot:pilot-auditor` in the
  background with "a run is live", as `${CLAUDE_PLUGIN_ROOT}/skills/audit/SKILL.md` says
skills/pilot/SKILL.md Models:   | pilot-auditor | Opus |
```

## Tests

1. `a repository with no offer and no report is due`: temp `PILOT_DECK_DIR`.
2. `recording an answer makes it not due until ten more runs are counted`: nine → null, ten → 'every'.
3. `counting one run key twice counts it once`: the double step-1 check (L15).
4. `a saved report resets the count`: S1's `saveReport` then `auditDue` is null.
5. `pilot audit due exits 0 then 1 across an offer, and 0 again on the tenth count`.
6. `pilot audit offered and count reject an empty key; the answered run is not counted again`.
7. `step 1 counts the run, then offers the audit beside the depth question when pilot audit due says so`: a sentence regex on step 1.
8. `the pilot can spawn the auditor, and the Models table budgets it Opus`: `CREW` checks, `:682`'s pin included.
9. `step 1 offers nothing under full auto, and still counts`: the same regex. The 9800 pin stays green (L10).
