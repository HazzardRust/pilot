# S2 The report shows setup cost and whether the preview comes up

Feature `housekeeping-audit` · delivers spec 5, 10 · source: `../architecture.md` §2, L2, L5 · after: S1

## Files owned

- `skills/audit/areas/setup.md` (new): the setup-and-preview area, owner `auditor`, in S1's area-file format.
- `scripts/test/audit-setup.test.mjs` (new): the pins below.

## Interface

```
skills/audit/areas/setup.md   frontmatter { area: setup, owner: auditor, spec: [5, 10] }   // rows use S1's Area 'setup' | 'preview'
  ## Measure
    install: the repo's own install command (lockfile → npm ci | pnpm i --frozen-lockfile | pip install -r | …), timed, in S1's scratch
    steps-to-green: every command from a fresh scratch until one test file passes, counted and timed
    env vars: names the code reads (process.env.X, os.environ["X"], …) minus those in .env.example or docs → one row
    services: detected from docker-compose*, supabase/config.toml, README; never started
    preview: the dev/start script started in the scratch under a timeout (default 120 s), then stopped;
             row = the URL it answered on, or the timeout and the last output lines
    seeds: the one-command seed or reset path found, with file:line, or its absence; only --help or a dry-run form is run
  ## Rows
    what one row from this area looks like, with one worked example per kind above
```

## Tests

1. `the setup area names its owner and spec lines`: frontmatter parses; owner `auditor`; spec 5 and 10.
2. `the setup area times the install and the steps to a first green test in the scratch worktree`.
3. `env vars are reported by name, never value`: the file says so in a sentence, not only the word.
4. `services are detected and never started`.
5. `the preview runs under a timeout and is stopped, and the row names the URL or the timeout`.
6. `the audit never seeds or migrates any database`: only `--help` or dry-run forms are run.

## Done

- **Expected**: an audit of this repository shows an install row with seconds, a steps-to-green row, an env-var row
  or none, and a preview row with its URL or its timeout; no database was touched.
- **Verification**: `node --test scripts/test/audit-setup.test.mjs`, then `npm test`; then `/pilot:audit` live on a
  repository with a dev server (this one: `pilot deck --foreground` counts as its preview).
- **Evidence**: tests red before the file exists, green after; the deck item's setup and preview rows.
- **Prohibited**: editing `agents/pilot-auditor.md` or `skills/audit/SKILL.md` (S1's; the area file is the seam);
  starting a database or any service other than the preview; printing an env var's value.
- **Done when**: the pins and `npm test` are green and a live audit shows the setup and preview rows.
