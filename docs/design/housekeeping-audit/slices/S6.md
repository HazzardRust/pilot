# S6 A picked row becomes a ticket the next run takes

Feature `housekeeping-audit` · delivers spec 14 · source: `../architecture.md` §2, L11, L16, A6 · after: S5, S7

## Files owned

- `deck/audit.mjs`: reads a saved report's row spec and parses a typed pick.
- `bin/pilot.mjs`: `audit spec` beside S1's and S5's subcommands.
- `deck/test/audit-pick.test.mjs` (new): the pins below, the chain round-trip included.
- `skills/audit/SKILL.md`: adds `## Picking` after S1's `## Post`.
- `fixtures/audit-repo/**` (new): one planted item per area, listed in `PLANTED.md`; no `test/` directory or
  `*.test.*` name, so `node --test` never collects it. `fixtures/audit-repo-broken/**` (new): an install that fails.
- `README.md`: the layout row for `fixtures/`.

## Interface

```
// deck/audit.mjs, beside S1's and S5's exports
export function parsePicks(reply: string, ids: string[]): { picked: string[], unknown: string[] }
//   "F1, f3 and F9" with ids F1..F5 → picked ["F1","F3"], unknown ["F9"]; "none", or any word that is neither id nor separator → both empty
bin/pilot.mjs   pilot audit pick <report.json> <reply-file>   → picked ids, one per line; stderr "unknown: F9"; exit 0; the reply is never an argument
export function specFor(reportJson: string, id: string): string   // the row's spec text, verbatim; throws on an unknown id
bin/pilot.mjs   pilot audit spec <report.json> <id>   → prints the spec text; exit 1 naming the unknown id
skills/audit/SKILL.md  ## Picking
  wait on S1's `audit` item; `none` or no ids → reply "no tickets posted" and resolve
  each picked id, in pick order → deck_post({ kind: "ticket", title: `Audit <id>: <finding, ≤ 60 chars>`,
    body: `pilot audit spec` output, unedited })   // repo: the audited repository
  then one deck_reply listing each ticket id, any unknown ids named back; resolve the audit item
  the pick is the user's words the ticket rule needs; no ticket without one; `deck/chain.mjs` starts each later

fixtures/audit-repo/PLANTED.md   one line per planted item: area · file · what the audit should report
  loops: no lint or typecheck script; a flaky clock check · setup: an env var absent from .env.example; a dev script
  navigability: a 1,200-line module; a duplicate helper · open: a README naming a script that does not exist
  context: a 30 KB CLAUDE.md; .claude/rules/react/ with paths on **/hooks/**/*.js and no React
```

## Tests

1. `picks are parsed case-insensitively and unknown ids are named`.
2. `none picks nothing`.
3. `specFor returns the row's spec text byte for byte`.
4. `pilot audit spec exits 1 naming an unknown id`.
5. `a pick posts one ticket per id with the row's spec as its body, and none posts nothing`: a regex on `## Picking`.
6. `a picked row's ticket reaches the next run verbatim`: `postItem` a ticket with `specFor`'s text in a temp
   `PILOT_DECK_DIR`, then `chainNext(repo, { atStart: true })`; the hand-off body equals the row's spec byte for byte.
7. `the audit skill and the auditor never name deck_launch or headless` (ADR 0039).
8. `the fixture plants at least one item for every area file in skills/audit/areas`: PLANTED.md against the
   frontmatter of each area file.
9. `no fixture file is collected by node --test`: the default patterns match nothing under `fixtures/`.

## Done

- **Expected**: replying `F1, F3` to an audit report posts two tickets, bodies those rows' spec text, and starts
  nothing; `pilot run` there starts F1's ticket. The fixture copy, `git init`-ed, audits to every planted item.
- **Verification**: `node --test deck/test/audit-pick.test.mjs`, then `npm test`; live: audit the fixture copy, reply
  with two ids, read both tickets' bodies, then `pilot run` in the copy and read the hand-off body.
- **Evidence**: tests red before, green after; the two tickets and the hand-off; the fixture report beside PLANTED.md.
- **Prohibited**: a ticket on anything but a typed pick; starting any session; paraphrasing the spec text; writing
  to `deck/chain.mjs` or the run record; a fixture file under a `test/` directory or named `*.test.*`.
- **Done when**: the pins and `npm test` are green and the live pick posted one ticket per id with verbatim bodies.
