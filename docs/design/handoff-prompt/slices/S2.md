# S2 The run's main session stamps its tool calls

Feature `handoff-prompt` · delivers spec 4 · source: `../architecture.md` §2, §3 Seams, §5 L3 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it edits `hooks/` (agent configuration, the security trigger); otherwise precise, ~80 lines on `markTurnEnded`'s idiom.

## Files owned

- `hooks/lib/deck.js`: `stampRun` folds `markTurnEnded`'s body; `markToolRan` added.
- `hooks/post-tool.js`: calls `markToolRan` for a main-session call before its modules run.
- `deck/run-claim.mjs`: `stampAt` folds `lastTurnEnded`'s body; `lastToolRan` added and exported.
- `hooks/test/tool-ran.test.js` (new): the pins.

## Interface

```
// hooks/lib/deck.js
stampRun(env, cwd, name: 'turn-ended' | 'tool-ran'): void   // claims/<name>-<PILOT_RUN_PID>.stamp = Date.now(), only in PILOT_RUN_REPO
markTurnEnded(env, cwd): void                               // stampRun(env, cwd, 'turn-ended'), unchanged behaviour
markToolRan(env, cwd): void                                 // stampRun(env, cwd, 'tool-ran')
post-tool.js: input without agent_id -> markToolRan(process.env, input.cwd); never throws, never delays output
// deck/run-claim.mjs
stampAt(name): number            // ms, or 0 for none
lastTurnEnded(): number          // stampAt('turn-ended'), unchanged
lastToolRan(): number            // stampAt('tool-ran')
```

## Tests

1. `a main-session tool call stamps tool-ran`: `markToolRan` → `lastToolRan()` is at or after the call's start.
2. `a subagent's tool call stamps nothing`: `post-tool.js` → `lastToolRan()` stays 0 for a payload carrying `agent_id`.
3. `outside the run's directory nothing is stamped`: `markToolRan` → `lastToolRan()` stays 0 for a foreign cwd.
4. `the turn-ended stamp is unchanged`: `markTurnEnded` → `lastTurnEnded()` reads it as before; `hooks/test/inbox.test.js:877` stays green.

Rewrite check: storing the stamps anywhere else keeps the four results, read through `lastToolRan` and `lastTurnEnded`.

## Done

- **Expected**: under `pilot run`, every tool call the pilot itself makes leaves a fresh `tool-ran` stamp the wrapper
  can read; subagents and other directories leave none.
- **Verification**: `node --test hooks/test/tool-ran.test.js hooks/test/inbox.test.js deck/test/run.test.mjs`; the gate.
- **Evidence**: tests 1-3 red before, green after; `node hooks/post-tool.js < payload.json` with a planted env shows the stamp file.
- **Prohibited**: no new `hooks.json` entry; no stamp without the env's run pid and repo; no throw out of the hook.
- **Done when**: the tests and the gate are green and the stamp is seen written by the real hook process.
