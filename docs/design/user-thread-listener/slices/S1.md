## Interface

```
pilot wait [--as <kind>] [--item <id>] [--timeout <minutes>]
  stdout line 1: listening on <repo>
  then, per reply: REPLY <id> "<title>"\n<text>\n[<fallback note>\n]\n
  or:              NO REPLY after <n> minutes
listeningRepo(cwd: string, git?: (args: string[], cwd: string) => string): string  // main checkout, else cwd
wait({ cwd, kind, item, timeoutMinutes, pollMs, say, warn, repo? }): Promise<0|1>   // repo defaults to listeningRepo(cwd)
```

## Tests

1. `the first line names the repository it listens on`: `say`'s first call is `listening on <repo>\n`.
2. `a reply prints REPLY <id> "<title>" above its text`: one reply gives `REPLY itm_… "t"` and then the text.
3. `a timeout prints NO REPLY after <n> minutes`: replaces the existing `/no reply after 0\.001 minutes/`.
4. `a wait started in a git worktree takes a reply posted on the main checkout`: a real `git init` with `git worktree add` in tmp; the reply's item `repo` is the main checkout; the wait run with `cwd` = the worktree prints it.
5. `outside git the wait listens on its cwd`: a tmp dir with no `.git` → `listening on <tmp>`.
6. pilot-rules: `the pilot reads the wait's output before any exit label the harness gives`, plus the 110-minute pin on the new string.
