## Interface

```
memoryLogFile(): string                        // <storeDir()>/memory.jsonl, beside usage.jsonl (A5)
type Reading = { at: string, process: 'wait'|'daemon'|'client', pid: number,
                 event: 'start'|'tick'|'exit', rss: number, free: number }   // bytes
readingOf(name, event, { now?, memoryUsage?, freemem? }): Reading
startMemoryLog(name, { now?, schedule?, append?, on?, enabled? }?): { stop(): void }  // start, 10-min unref'd tick, exit once
                                               // enabled defaults to () => readUsageSwitch().enabled, read before each reading (L12)
readMemory(file, span: { from: number, to: number }): Map<string, Reading>   // peak rss per process inside span
readRun(...) -> { ..., span: { from: number, to: number } | null }            // S4 adds span
pilot analytics <slug>   // adds "Memory" table: process | peak rss | free at peak | readings
```

## Tests

1. `a reading names its process and carries rss and free`: `readingOf('wait', 'start', stubs)` has every field, from the stubs.
2. `start writes a start line, then a tick every 10 minutes`: a stubbed `schedule` fired twice gives `start, tick, tick`.
3. `exit writes one exit line however many ways it is reached`: `stop()`, the `exit` hook and SIGTERM through a stubbed `on` give one `exit` line.
4. `the tick never holds the process open`: the scheduled timer is `unref`'d.
5. `wait() and startDaemon() write no reading`: the existing wait and daemon tests leave no `memory.jsonl` in their `PILOT_DECK_DIR`.
6. `a real pilot wait that times out leaves start and exit`: spawn `bin/pilot.mjs wait --timeout 0.001` against a scratch store; the file has both lines for its pid.
7. `readRun returns the run's span`: the fixture run's span is its earliest `first` to its latest `first + spanMs`.
8. `analytics prints the peak per process inside the span`: readings in and out of the span; the row shows the in-span peak and its `free`.
9. `analytics with no memory log says so in one line`: no file → `No memory readings in <file>.`, exit 0.
10. `logging off writes no reading, and on resumes at the next one`: after `setUsageSwitch(false)`, a start and a fired tick write nothing; after `setUsageSwitch(true)`, the next tick writes. With no switch file it writes (spec 11).

## Done

- **Expected**: after a run, `pilot analytics <slug>` shows how much memory the listener, the daemon and the tool client peaked at, and how much the machine had free then. `memory.jsonl` holds every reading.
- **Verification**: `node --test deck/test/memory.test.mjs deck/test/analytics.test.mjs deck/test/wait.test.mjs deck/test/daemon.test.mjs`, then `npm test`.
- **Evidence**: tests 3, 6, 8 and 10 fail before and pass after. A live scratch-store run (`PILOT_DECK_DIR=<tmp>`, `PILOT_DECK_PORT=4399`): the daemon started, one wait to timeout and one stopped with Ctrl-C, with `memory.jsonl` pasted and the `pilot analytics` memory row pasted. Then `pilot logging off` and one more wait, with the file shown not to have grown.
- **Prohibited**: no write into `~/.claude/pilot/` from any test; no readings in `usage.jsonl` (A5); no `startMemoryLog` in `wait()` or `startDaemon()`; no ref'd timer; no reading the memory of another process; no second switch, and no edit to `deck/usage-switch.mjs` (S5's).
- **Done when**: all ten tests and `npm test` are green, and the live run's file holds `start` and `exit` for both waits and `start` for the daemon, and nothing after `pilot logging off`.
