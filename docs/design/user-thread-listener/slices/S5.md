## Interface

```
pilot logging on|off|status
  stdout: logging on|off, <storeDir()>          exit 0
  bad word: stderr "usage: pilot logging on|off|status"   exit 2
pilot usage [anything]
  stderr: pilot usage is now pilot logging on|off|status   exit 2, no state change
[deck] logging on, <storeDir()>   |   [deck] logging off (pilot logging on)   // daemon start-up line
deck/usage-switch.mjs readUsageSwitch / setUsageSwitch / usage-log.json: unchanged (L15)
```

## Tests

1. `pilot logging status prints the state and the store dir`: on by default, then `off`, `status`, `on`.
2. `pilot logging with a bad word exits 2 with its usage`: `maybe`, and no word at all.
3. `pilot usage points to pilot logging and changes nothing`: `usage off`, `usage status` and bare `usage` all exit 2 with the pointer, and `usage-log.json` is untouched.
4. `an off set before the rename is still off`: a hand-written `usage-log.json` `{enabled:false}` makes `logging status` print `logging off`, and a stubbed tick writes no usage line.
5. `the daemon names logging on its first lines`: the `:164` pin, on and off.
6. `the install guide names pilot logging off`: the INSTALL.md row pin, which no longer matches `pilot usage off`.
