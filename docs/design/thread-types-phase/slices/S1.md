# S1 Handoff threads offer Handoff failed and Reply

Feature `thread-types-phase` · delivers spec 3, 2 (the handoffs) · source: `../architecture.md` §2, F2-F4, L2-L4, A7 ·
after: – · walking skeleton: it adds the type table, deck buttons stored at post, and a type note, end to end, for one type.

## Files owned

- `deck/items.mjs`: `KIND_CREW_HANDOFF`, `HANDOFF_FAILED`, and a `buttons` and `note` entry per type. `handoff` and `crew-handoff` join `SPECS` (now known), and not `KINDS` (L4).
- `deck/store.mjs`: `postItem` writes the type's `buttons` into `options` for a type that has them (the chain's handoff included).
- `deck/ui/render.mjs`: a `KIND_RENDERERS` entry for both handoffs: their options, no Teach me, no confirm step. The type note sits beside `renderChainNote`. There is no Dismiss for them, which follows from their being known.
- `deck/test/handoff-buttons.test.mjs` (new): the pins.
- `agents/pilot.md`: the crew-handoff rule: resolve it when the agent's handoff arrives, and on `Handoff failed` brief a fresh agent from its branch.

The four `'handoff'` literals (`items.mjs:60`, `deck/run.mjs:113`, `hooks/session-handoff.js:49`, `scripts/handoff.mjs:105`)
and `'crew-handoff'` in `hooks/context-size-guard.js:556` stay as they are. The kind strings do not change, and
`hooks/test/join.test.js` is the place to pin any that a test must.

## Interface

```
// deck/items.mjs
export const KIND_CREW_HANDOFF = 'crew-handoff';
export const HANDOFF_FAILED = 'Handoff failed';
export function buttonsFor(kind: string): string[] | null   // the deck's options for a type, or null: the agent's own
export function noteFor(item): string | null                // the type note drawn on card and page
```

## Tests

1. `a crew-handoff posted with no options is stored with options ["Handoff failed"]`
2. `the chain's handoff gets the same button` (via `postItem` directly, as `chain.mjs` posts it)
3. `a handoff's card and page draw Handoff failed and Reply, and no Dismiss`
4. `a handoff is not closed by full auto`: it is posted to a repo with auto on and is still open.
5. `pressing Handoff failed stores that reply`: `/reply` with `choice=Handoff failed`, and the thread's last user message is `Handoff failed`.
6. `a stored item of an unknown kind still draws Dismiss` (L3 regression)
