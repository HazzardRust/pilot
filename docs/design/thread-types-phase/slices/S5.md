# S5 In yellow the user is away

Feature `thread-types-phase` · delivers spec 6 · source: `../architecture.md` §2, F6, F7, L7, L12 · after: S4

## Files owned

- `deck/store.mjs`: in `postItem`, a `question` whose directory is `implementing` (S4's `runPhaseOf`, read before the push) must carry `recommended` and is stored with `away: true`. Gate items are never away.
- `deck/server.mjs`: `deck_post`'s answer for an away item names the default, in the pattern of the full-auto answer (`server.mjs:654-659`).
- `hooks/stop-gate.js`: `awaitsUser` returns false for an item with `away: true`.
- `hooks/test/away.test.js` (new): the Stop hook pin.
- `deck/test/away.test.mjs` (new): the deck pins.
- `agents/pilot.md`: in step 6 and the Legend, the day and night cycle. The user is expected at the gates, in green and red. In yellow they are away: take the default the deck names, record it assumed, relay it at once, and revise if they answer.

## Interface

```
// stored item field
away?: true                     // set by postItem only; refused if an agent sends it
// deck_post answer for an away question
"the user is away (implementing): go with \"<recommended>\", record it as assumed, and revise if they answer on <url>"
// refusal in yellow without recommended
"a question in implementing needs recommended: the user is away and your default is what the run goes on"
```

## Tests

1. `a question posted while implementing without recommended is refused`
2. `with recommended it is stored away and the answer names the default`
3. `a question in planning or closing is not away`
4. `a gate-2 walkthrough or signoff posted while implementing is not away`
5. `away is refused as a posted field`
6. `the Stop hook does not hold a turn on an away item, and still holds on a planning question` (hooks/test)
7. `a later user reply on an away question still wakes pilot wait`
