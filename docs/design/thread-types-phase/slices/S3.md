# S3 Spec, sign-off and audit buttons come from the deck, and gates are tagged

Feature `thread-types-phase` · delivers spec 2 · source: `../architecture.md` §2, F4, F5, L2, L5, A6, A9 · after: S2

## Files owned

- `deck/items.mjs`: `buttons` for spec (`agree`, `agree with edits`), signoff (`SIGN_OFF`, `Not yet`) and audit (`none`). A `GATE_FIELD` (`only: ["1","2"]`) on signoff, and (`only: ["2"]`) on walkthrough. Type notes for spec, gate 1 and gate 2.
- `deck/store.mjs`: `postItem` refuses `options` (and `recommended` outside the buttons) for a type with deck buttons.
- `deck/tools.mjs`: the `gate` property, and the `options` description names only the types that take the agent's own options.
- `deck/test/type-buttons.test.mjs` (new): the pins.
- `agents/pilot.md`: step 1's spec post without options; Gate 1 posted with `gate: "1"` and Gate 2 with `gate: "2"`; a gate item is resolved only on a pass, and Not yet keeps it open (A9).
- `agents/pilot-qa.md`: the feature walkthrough carries `gate: "2"` (a small ticket's carries `ticket`, never both).
- `skills/audit/SKILL.md`: the audit item is posted without options.

## Interface

```
// deck/items.mjs (S1's buttonsFor / noteFor, extended)
deck_post { kind: 'signoff', gate?: '1' | '2', ... }       // no options
deck_post { kind: 'walkthrough', gate?: '2', ... }
// refusal: `a <kind>'s buttons are the deck's: <buttons>; post it without options`
```

## Tests

1. `a spec with no options is stored with agree / agree with edits and renders Teach me after them`
2. `a signoff is stored with Sign off / Not yet, and its row still asks before it sends`
3. `an audit is stored with none and no Teach me`
4. `options on a spec, signoff or audit are refused, and a question's own options are kept`
5. `gate takes "1" or "2" on a signoff and only "2" on a walkthrough, and anything else is refused`
6. `a gate-1 sign-off's page carries the gate-1 note, and a wizard's sign-off without gate carries none`
7. `a stored spec with its own old options still renders them` (no migration)
