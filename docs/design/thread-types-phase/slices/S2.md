# S2 deck_post accepts only the thread types

Feature `thread-types-phase` · delivers spec 1 · source: `../architecture.md` §2, F1, L1, L3, L9 · after: S1

## Files owned

- `deck/items.mjs`: `POSTABLE_KINDS`, which is `KINDS` plus both handoffs. It is the one list of thread types.
- `deck/store.mjs`: `postItem` refuses a kind outside `POSTABLE_KINDS` and names them. It keeps its `chat` / `user` refusals, which fall inside this one.
- `deck/tools.mjs`: `deck_post`'s `kind` becomes `enum: POSTABLE_KINDS`, and its description is shortened to match.
- `deck/test/types.test.mjs` (new): the pins.
- `deck/test/run.test.mjs`, `deck/test/spec-gate.test.mjs`: they post kinds outside the list. Seed those items through the store's write path for stored items, as other tests seed old data, rather than through `postItem`.
- `docs/adr/0051-thread-types-are-a-closed-list-with-deck-buttons.md` (new): L1-L5, in the `domain-modeling` ADR format. It supersedes the open-kind half of the earlier A11.

## Interface

```
// deck/items.mjs
export const POSTABLE_KINDS: string[]   // question, walkthrough, signoff, spec, report, ticket, audit, handoff, crew-handoff
// deck_post refusal (DeckRefusal): `kind must be one of <andList(POSTABLE_KINDS)>, not "<kind>"`
// deck/tools.mjs deck_post.inputSchema.properties.kind: { enum: POSTABLE_KINDS }
```

## Tests

1. `every postable kind is accepted`
2. `an unknown kind is refused, naming all nine types`
3. `chat and user are still refused with their own reasons`
4. `a stored item of an unknown kind still reads, renders and dismisses` (L3)
5. `deck_post's schema lists exactly POSTABLE_KINDS`
