# S1 A stored ticket starts itself when the run before it finishes cleanly

Feature `run-chaining` · delivers spec 3, 4, 5 (clean finish only), 9 · source: `../architecture.md` §2, L3–L5 · after: – · walking skeleton

## Files owned

- `deck/chain.mjs` (new): decides and posts the chain hand-off; says whether a finish is superseded.
- `deck/items.mjs`: `KIND_TICKET`, `KIND_HANDOFF`, and a `SPECS` entry giving a hand-off its `next` field.
- `deck/runs.mjs`: `FINISHED_CLEAN`, the one spelling of a clean finish.
- `deck/server.mjs`: `deck_status` calls `chainNext` on a clean finish; `stopReason` ignores a superseded finish.
- `hooks/session-handoff.js`: a next-run frame for a hand-off carrying `next`, and resolves it on delivery.
- `deck/test/chain.test.mjs` (new), `hooks/test/session-handoff.test.js`: the pins.

## Interface

```
export const FINISHED_CLEAN = 'closing report posted'               // deck/runs.mjs
// deck/items.mjs
export const KIND_TICKET = 'ticket'; export const KIND_HANDOFF = 'handoff'  // ticket: title its name, body its spec
// SPECS[KIND_HANDOFF] = { options: false, fields: [REPO_FIELD, NEXT_FIELD] }; handoff stays out of KINDS
// deck/chain.mjs  (sync store calls only: one daemon process, one tick)
export function chainNext(repo: string):
  { handoff: Item } | { handoff: null, reason: 'no ticket' | 'not finished cleanly' | 'hand-off open' }
  //   head = oldest open KIND_TICKET with sameRepo; record = recordFor(repo); no open handoff on repo
  //   resolves head ("taken by <handoff id>"), then posts
  //   { kind: 'handoff', repo, title: `Next run: ${head.title}`, body: head.body, next: head.id }
export function isSuperseded(record: Record, items: Item[]): boolean
  //   a resolved handoff with `next`, sameRepo, postedAt > record.updatedAt
deck_status (deck/server.mjs): after setSlices, args.finished === FINISHED_CLEAN → chainNext(repoOfRun(args.run))
stopReason: finished stops only if record.updatedAt >= run.startedAt && !isSuperseded(record, listItems())
// hooks/session-handoff.js
notice(item, record): item.next ? nextRunNotice(item) : today's frame, unchanged
nextRunNotice(item): "the previous run finished; this ticket was stored with the user's agreement;
  start a new run with it: if it names an approved artefact and its slices, begin at step 4 with
  those slices, otherwise step 1 with it as the spec"; no record, no "pick the run up"
on delivering a `next` hand-off: deck.tool('deck_resolve', { id, resolution: 'picked up' })
```

## Tests

1. `a clean finish with an open ticket posts one hand-off carrying the ticket's spec and takes the ticket`
2. `an abandoned finish, no ticket, or an open hand-off posts nothing`: each returns its `reason`.
3. `two tickets chain oldest first`: after the second clean finish, the second ticket.
4. `deck_status with the clean finish posts the hand-off through /api/tool`
5. `a chained session is not told to stop listening; the finishing session still is`: `stopReason` both ways.
6. `the lane gives a next hand-off the next-run frame without the record, and resolves it`
7. `the lane's frame for an ordinary hand-off is unchanged`
