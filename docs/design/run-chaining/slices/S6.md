# S6 Parallel decks each chain their own runs

Feature `run-chaining` · delivers spec 5 (A5), 7, 10 · source: `../architecture.md` §2, L3, L7, A5 · after: S5

## Files owned

- `deck/tools.mjs`: `deck_post` gains `dir`, for a `ticket` only.
- `deck/items.mjs`: `DIR_FIELD` on `SPECS[KIND_TICKET]`.
- `deck/store.mjs`: `postItem` files a ticket under `dir` when given.
- `deck/server.mjs`: `dir` checked as a worktree of the caller's repository; `POST /api/chain`.
- `deck/chain.mjs`: S1's `chainNext` gains the start condition.
- `deck/run.mjs`: one `POST /api/chain` once the session is registered.
- `skills/pilot/SKILL.md`: step 3's "In parallel" branch.
- `deck/test/parallel.test.mjs` (new), `deck/test/run.test.mjs`: the pins.

## Interface

```
deck_post { …, dir?: string }  // ticket only: absolute path of a worktree of this repository; the ticket's repo
                               // becomes dir; refused otherwise, as deck_status refuses a bad worktree
S1's chainNext(repo, { atStart = false } = {})
  atStart: chains when recordFor(repo) is null or has any `finished` (A5); otherwise S1's clean-finish rule
POST /api/chain { repo } → { handoff: id | null, reason? }     // loopback, fromOwnPage-equivalent origin check
deck/run.mjs watch(): after the first registered(cwd), POST /api/chain once; the existing watcher types /clear
skills/pilot/SKILL.md, step 3, on "In parallel on separate decks":
  create one worktree per extra deck; deck_post each deck's runs as tickets with `dir`;
  one walkthrough step per deck: `cd <path> && pilot run`
```

## Tests

1. `a ticket posted with dir belongs to that worktree's deck`: listed on its tab, not on the posting one.
2. `a dir that is not a worktree of this repository is refused`.
3. `chainNext at start chains with no record, or a finished one, and not over an unfinished run`.
4. `pilot run asks the deck to chain once at start`: `run.test.mjs` with a stub deck.
5. `SKILL.md's parallel branch names the worktree, the dir, and the walkthrough command`.
6. `the pilot share stays at or under 9800`.

## Done

- **Expected**: two worktrees with one ticket each. `pilot run` in each starts its own ticket, and each tab lists
  only its own.
- **Verification**: `npm test`; `node scripts/measure-prompt.mjs`; the live run below.
- **Evidence**: tests red before, green after; two live `pilot run` terminals each clearing into their own ticket.
- **Prohibited**: the daemon starting a session; typing into a pty from the daemon; `dir` on any kind but `ticket`.
- **Diff limit**: about 200 added lines and +50 tokens on the pilot share; past either, stop and ask `main`.
- **Done when**: tests 1–6 are green and both decks have been seen chaining.
