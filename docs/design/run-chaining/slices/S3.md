# S3 Tickets and closing reports have their own sections and never hold a turn

Feature `run-chaining` · delivers spec 2, 6 · source: `../architecture.md` §2, §4, L6 · after: S2

## Files owned

- `deck/items.mjs`: `KIND_REPORT`, `STANDING_KINDS`, `isStanding`; `isQueued` false for a standing kind; both kinds in `KINDS`.
- `deck/ui/render.mjs`: a **Tickets** and a **Closing reports** section on the repository tab, read-only, in the left-side section group and its schema (L13), never the right strip.
- `deck/ui/deck.css`: the two sections, in the existing `.run-section` idiom.
- `hooks/lib/deck.js`: `isStanding`, the hooks' spelling of the same list.
- `hooks/stop-gate.js`: `awaitsUser` false for a standing item.
- `deck/test/standing.test.mjs` (new), `hooks/test/standing.test.js` (new): the pins.
- `hooks/test/join.test.js`: the daemon's and the hooks' lists agree.

## Interface

```
// deck/items.mjs
export const KIND_REPORT = 'report'                          // SPECS: walkthrough's shape (url, login, screens)
export const KINDS = [question, walkthrough, signoff, spec, report, ticket]
export const STANDING_KINDS = [KIND_TICKET, KIND_REPORT]        // S1's KIND_TICKET
export function isStanding(item): boolean
isQueued(item): false when isStanding(item)                   // so not waiting, not in Yours, no dead-record keep
// deck/ui/render.mjs, called from renderHomePage beside renderQueue
renderStanding(items: Item[], repo: string): string
  // <details class="run-section tickets"> open tickets of repo, oldest first, head badged "next", body collapsed
  // <details class="run-section reports"> report items of repo, newest first, open ones marked, each a thread link
// hooks/lib/deck.js
isStanding(item): boolean                                     // same two kinds
// hooks/stop-gate.js
awaitsUser(item, posted): false when deck.isStanding(item)
```

## Tests

1. `a ticket is open but not waiting`: `isQueued` false, `appearsInYours` false.
2. `a report renders as a walkthrough and is not waiting`.
3. `the tab lists tickets oldest first with the head marked next, and reports newest first`: render pin.
4. `the sections carry no form`: no `<form>` or button inside either section.
5. `tickets survive a daemon restart`: write, re-read the store, same list.
6. `full auto leaves a report open`: posting a `report` under full auto returns it undecided.
7. `the Stop gate lets a turn end with its own report and tickets open`: `awaitsUser` false.
8. `the daemon and the hooks agree on the standing kinds`: `join.test.js`.
