# S1 Land keeps its concluding worktrees and names them

Feature `landing-keeps-worktrees` · delivers spec 1 · source: `../architecture.md` §2, §3, L1 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — the option, the state and the three tests are fixed here; about 80 lines; no security trigger.

## Files owned

- `scripts/worktrees.mjs`: `prune` takes `keep`, branches reported `kept concluding` and never removed.
- `scripts/land.mjs`: `clear()` passes `keep: ['feat/<slug>', 'qa/<slug>']`; the header comment says so.
- `scripts/test/land-clear.test.mjs`: the feature worktree is kept now, plus a merged-clean qa worktree.
- `deck/test/closing-report.test.mjs`: a `kept concluding` landing line reaches "Worktrees kept".

## Interface

```
prune(repo, base, { dryRun?, run?, merged?, keep?: string[] }) -> { removed: string[], kept: { path, state }[], failed }
  // a tree whose branch is in keep is kept with state 'concluding', checked before 'merged-clean'
clear({ cwd, git, head }) -> string[]   // 'kept concluding <path>' lines for feat/<slug> and qa/<slug>
closingReportOf(record, gate)           // unchanged; reads the kept lines
```

## Tests

1. `a landing keeps its qa and feat worktrees`: `clear` → after `main([])` lands, both directories exist and stdout holds `kept concluding <path>` for each; a merged-clean `slice/<slug>-s1` worktree is still removed.
2. `keep wins over merged-clean`: `prune` → a merged-clean tree on a kept branch is in `kept` with state `concluding`, its branch not deleted.
3. `the report lists a concluding worktree`: `closingReportOf` → "Worktrees kept:" is followed by `- kept concluding <path>`.

Rewrite check: computing the concluding set some other way keeps all three results, as long as land answers the same lines.

## Done
