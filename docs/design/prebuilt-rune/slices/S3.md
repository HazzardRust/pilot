## Interface

```
runeRow({ state: RuneState, version: string }): { name: 'rune deck', verdict: 'pass'|'warn', detail: string, steps?: string[] }
  // built:   pass  rune deck: built here, <path>
  // fetched: pass  rune deck: fetched <version>, verified
  // missing: warn  rune deck: missing: <reason>   steps: what to run (`pilot deck`), or none when nothing helps
checkAll({ ..., findRune = (root, host) => S2's findRune(root, host) })
```

## Behaviours

1. `a built deck is named` (test): `runeRow` → `pass` and `built here, <path>` for a built state.
2. `a fetched deck says verified` (test): `runeRow` → `pass` and `fetched 0.9.11, verified`.
3. `each missing reason names its step` (test): `runeRow` → `warn` for not fetched yet (step `pilot deck`), no pin for this version, no asset for this platform, hash mismatch, Smart App Control enforced.
4. `doctor never downloads` (test): `checkAll` → completes with a `findRune` stub and no `get` reachable from it.

Rewrite check: any row wording keeps one row whose verdict is `pass` only for built or fetched.
Misses: how the row reads beside the others in a real terminal; QA's walkthrough reads it.
