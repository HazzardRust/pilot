# S1 A late join fits the wait, and a failure says why (walking skeleton)

## Files owned

- `deck/client.mjs`: `export` on `START_TIMEOUT_MS` and `REGISTER_TIMEOUT_MS`; values unchanged.
- `deck/test/daemon.test.mjs`: `until`, `tracked`/`heard`, `SESSION_JOIN_MS`, the two-sessions test's probes, three harness tests.

## Interface

```
// deck/client.mjs
export const START_TIMEOUT_MS = 10_000
export const REGISTER_TIMEOUT_MS = 5_000
// deck/test/daemon.test.mjs
SESSION_JOIN_MS: number   // START_TIMEOUT_MS + REGISTER_TIMEOUT_MS + a fixed Node-start margin
until(probe: () => Promise<T | null>, opts?: { timeoutMs?: number, what?: string }): Promise<T>   // default SESSION_JOIN_MS; timeout message names the last answer
tracked(t, child: ChildProcess): ChildProcess   // stderr kept, not dropped
heard(child: ChildProcess): string              // what a tracked child wrote to stderr so far
```

## Tests

1. `until names the probe's last answer, not a stale error`: `until` → a probe that throws once and then returns null rejects with a message naming the null answer, not the earlier error (the one `until` call allowed its own short `timeoutMs`).
2. `the wait budget covers the client's join contract`: `SESSION_JOIN_MS` → strictly greater than `START_TIMEOUT_MS + REGISTER_TIMEOUT_MS` read from `deck/client.mjs`.
3. `a tracked child's stderr is kept for the failure message`: `heard` → returns the text a spawned `node -e "console.error('x')"` wrote.

Rewrite check: replacing `until`'s polling loop with an event-driven wait keeps a budget above the join contract and a timeout message naming the last answer.
