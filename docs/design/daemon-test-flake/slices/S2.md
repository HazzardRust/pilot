## Tests

1. `a wait that finds nothing says so once per poll, so the harness knows it is alive`: `waitPolls` → after `waitForReply({ timeout: 1500 }, 300, onEmptyPoll)`, the reports equal `1..(requests − 1)`, with `requests ≥ 2`. Red step: a stub `waitForReply` that reports one poll fewer than it made fails it.
2. `a progress token of 0 is a token`: `waitPolls` → the notifications sent equal `requests − 1 ≥ 1`, and every one carries `progressToken: 0`.
3. `waitPolls counts only deck_wait`: `waitPolls` → a `deck_post` and a `deck_wait` through the client count 1.

Rewrite check: if `waitForReply` polled over a different transport, "one report per empty poll made" still holds as long as the counter sits at that transport.

## Done

- **Expected**: the two tests assert the contract (one report per empty poll, numbered in order) at any machine speed. A loaded machine that fits only 2 polls in the window still passes, and a client that skips a report still fails.
- **Verification**: `node --test deck/test/daemon.test.mjs`; `npm test`; `node --test deck/test/daemon.test.mjs` run while the full suite runs beside it, 3 times.
- **Evidence**: test 1's red step failing; all three green; the two tests green in each loaded run; a PR paragraph saying that a wall-clock window held too few 300 ms polls under load.
- **Prohibited**: no change to `timeout: 1500` or `pollMs: 300` as the fix; no lowering of the assertion to `>= 1` without the equality to the requests counted; no change to `deck/client.mjs`.
- **Done when**: the two tests assert equality against the counted requests and stay green under load.
