# S15 The record carries `qa` refs; a red walkthrough reply reaches the live pilot

Feature `ticket-states` · run 2 · delivers spec 19 (deck half) · source: `../architecture.md` §2, L5, L6 · after: S14

## Files owned

- `deck/runs.mjs`: `qa` joins the record (`{branch, worktree, url}`).
- `deck/items.mjs`: `walkthrough` gains an optional `ticket` field.
- `deck/server.mjs`: a reply on a walkthrough that names a parked ticket is handed to the live pilot in that repository, carrying `ticket`, through `deck_wait`.
- `deck/test/qa-resume.test.mjs` (new).

## Interface

```
record.qa: { branch, worktree, url }     // set by deck_status
walkthrough fields: ..., ticket?
deck_wait reply frame: { item, reply, ticket? }   // ticket present when the item names a parked ticket
S8's GET /api/record?ticket=  -> includes qa
```

## Tests

1. `deck_status stores qa refs on the record`.
2. `a reply on a parked red ticket's walkthrough reaches the live pilot with its ticket id`.
3. `the ticket route returns the qa refs`.
