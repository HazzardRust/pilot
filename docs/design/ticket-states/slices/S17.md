# S17 A hand-off never leaves the fresh session idle

Feature `ticket-states` · run 2 · delivers spec 16 (e) and 18 (the chain's hand-off reaches a session that works) · source: `../architecture.md` §2, A8 · after: none in this run (disjoint files; branch from the current `feat/ticket-states` tip) · added on the user's word, 2026-10-02: "just do it in this run"

## The defect

On the clean finish of run 1 (2026-10-01T23:19Z) the daemon chained a `handoff` (itm_3b422012fde0) and `pilot run`'s
wrapper typed `/clear` 64 ms later (`~/.claude/pilot-inbox/claims/clear-typed-itm_3b422012fde0.claim`). The
SessionStart lane (`hooks/session-handoff.js`) never wrote `handoff-itm_3b422012fde0.claim`, so `deck/run.mjs`
(`LANE_WAIT_MS`, 2 min) typed no prompt and the fresh session sat idle on `/clear` until the user typed. The hand-off
before it (itm_389a5eb517c0) has both claims 4 s apart. Neither the wrapper nor the lane logs a line, so why the lane
did not mark is not in the record. One candidate: the user pressed "Handoff failed" on the item 8 s after the
`/clear`, and the lane may skip an item that carries that reply; verify, do not assume.

## Cause found (PR #273)

The claim's mtime is when the claim was *taken*, before the wait for the turn to end; `/clear` was typed at 23:20:14Z. By then the old pilot had resolved the hand-off itself (23:20:06Z, after the user's "Handoff failed" at 23:19:21Z, because the chain had re-offered run 1's finished ticket), so the lane rightly found no open hand-off. Fix: `clearOnce` reads the deck again after the turn ends and types no `/clear` into a closed or superseded hand-off; plus the log lines and fallback B.

## Interface

```
~/.claude/pilot/wrapper.log   // appended by run.mjs and session-handoff.js, one ISO-stamped line per decision:
  "<ts> run: typed /clear for <id>" | "<ts> run: no marker for <id> after <ms>" | "<ts> lane: handed <id>" |
  "<ts> lane: no item" | "<ts> lane: skipped <id> (<reason>)" | "<ts> lane: deck read failed (<err>)"
```
  "<ts> run: no /clear for <id> (closed before the turn ended | superseded by <id>)" | "<ts> run: marker for <id>, typed the prompt" |
  "<ts> run: could not post the missing marker for <id> on the thread|chat (<err>)"   // added in PR #273 (F11)

Fallback on no marker within `LANE_WAIT_MS` (A8, option B): the wrapper posts one reply on the handoff thread and one
chat line naming the failure ("no fresh session marked for <id> within 2 min; type /clear yourself"), through the
daemon's existing post route, and keeps its claim. It never types the prompt into a session it cannot identify.
