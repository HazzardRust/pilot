# S3 Gate2 posted turns red, the closing report closes; three queues

Feature `ticket-states` · run 1 · delivers spec 1 (red, closed), 2 (gate2's `ticket`), 3 · source: `../architecture.md` §2, L3, L6, L11 · after: S2

## Files owned

- `deck/items.mjs`: the required `ticket` field on `gate2` and on `report`; `ticketQueueOf(items, repo, state)`.
- `deck/store.mjs`: posting a `gate2` turns its yellow ticket red in the same write; posting a `report` naming a red ticket closes and resolves it in the same write; signing the `gate2` leaves it red.
- `deck/ui/render.mjs`: the Tickets panel as three queues, green, yellow, red, each in deck order; closed tickets are not drawn.
- `deck/ui/deck.css`: the queue headings.
- `deck/test/ticket-state.test.mjs`: extended.

## Interface

```
gate2 fields: pr, sha, walkthrough?, ticket (required)
report fields: ..., ticket (required for a closing report)
ticketQueueOf(items, repo, state = 'green'): Item[]    // open tickets of that state, deck order
closed ticket: { state: 'closed', resolvedAt, resolution: 'closed by <report id>' }
S1's stateOf
```

## Tests

1. `posting a gate2 turns its yellow ticket red`: at post, not at sign-off.
2. `a gate2 naming a green or closed ticket is refused by name`.
3. `posting a closing report closes and resolves its red ticket; a report naming a ticket that is not red is refused by name`.
4. `a gate2 resolved, signed or not, leaves the ticket red`.
5. `the panel draws three queues in deck order and no closed ticket`.
6. `up and down move a ticket within its own queue only`.
