# S5 The chain makes the next ticket live instead of resolving it

Feature `ticket-states` · run 1 · delivers spec 13 · source: `../architecture.md` §2, L16, L19 · after: S4

## Files owned

- `deck/items.mjs`: `nextTicketOf(items, repo, mode = 'attended')` replaces `queueHeadOf`, returning the first green ticket that is not live.
- `deck/chain.mjs`: `chainNext` posts the hand-off and calls S4's `takeTicket` for the head; it no longer resolves it.
- `hooks/session-handoff.js`: whatever it reads of a taken ticket (resolution text) moves to `live`.
- `deck/test/chain.test.mjs`: rewritten.

## Interface

```
nextTicketOf(items, repo, mode = 'attended'): Item | undefined   // run 1: first green, not live
chainNext(repo, opts) -> { handoff } | { handoff: null, reason }  // the head becomes live, stays open
S4's takeTicket
```

## Tests

1. `after a chain hand-off the head ticket is open and live`.
2. `the chain refuses while a ticket is live`, with reason `ticket live`.
3. `the tab's next marker and the chain name the same ticket` (both read `nextTicketOf`).
4. `a yellow or red ticket is never the chain's head in run 1`.
