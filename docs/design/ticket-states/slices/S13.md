# S13 Next ticket by mode; autonomous chains at gate 2 posted

Feature `ticket-states` · run 2 · delivers spec 16, 18 (deck halves) · source: `../architecture.md` §2, L19, B2, B4 · after: S12

## Files owned

- `deck/items.mjs`: S5's `nextTicketOf` gains the mode branches.
- `deck/chain.mjs`: in autonomous mode, `chainNext` chains on `FINISHED_GATE2` and `FINISHED_BLOCKED`, as well as on a clean finish. The ticket in hand must be parked first.
- `deck/runs.mjs`: `FINISHED_GATE2 = 'gate 2 posted'` and `FINISHED_BLOCKED = 'blocked'`.
- `deck/server.mjs`: the `deck_status` finish path passes the mode to `chainNext`.
- `deck/test/chain.test.mjs`, `deck/test/next-ticket.test.mjs` (new).

## Interface

```
nextTicketOf(items, repo, mode): Item | undefined
  // 'autonomous': first yellow ticket without an open question naming it
  // 'attended':   first ticket (any state) with an open question naming it, else first red, else first green
  // 'full':       as attended
chainNext(repo, opts): unchanged signature; reads S12's modeFor
chain hand-off body for a yellow ticket: its plan + `GET /api/record?ticket=` path (S8)
```

## Tests

1. `autonomous: the next ticket is the first yellow, skipping a yellow ticket with a queued question`.
2. `attended: red before green, and a ticket with a queued question first`.
3. `autonomous: a 'gate 2 posted' finish with the ticket parked chains to the next yellow ticket`.
4. `attended: a 'gate 2 posted' finish does not chain`.
5. `the tab's next marker matches nextTicketOf for each mode`.
6. `a yellow hand-off body names the plan and record route`.
