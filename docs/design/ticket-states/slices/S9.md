# S9 Merge a green ticket into the live one

Feature `ticket-states` · run 2 · delivers spec 11 (deck half) · source: `../architecture.md` §2, L15, A2 · after: S8

## Files owned

- `deck/store.mjs`: `mergeTicket(id)`.
- `deck/tools.mjs`: `deck_ticket` gains `merge`.
- `deck/server.mjs`: the handler.
- `deck/test/merge.test.mjs` (new).

## Interface

```
mergeTicket(id): { host: Item, merged: Item }
  // id: an open green ticket, not live; host: the repo's live ticket, green
  // merged: resolved 'merged into <host id>', mergedInto = host id, state 'closed'
  // host: a reply carrying the merged title, body and comments; estimate += merged.estimate
deck_ticket { action: 'merge', id }
```

## Tests

1. `merging closes the absorbed ticket as merged into the live one`.
2. `the host gains one reply carrying the absorbed body, and its estimate is the sum`.
3. `merge is refused with no live ticket, a non-green host, a yellow source, or the live ticket itself`.
4. `the merge is one store write`.

## Done

- **Expected**: two green tickets on a scratch deck become one live ticket whose thread holds both specs.
- **Verification**: `node --test deck/test/merge.test.mjs`; `npm test`.
- **Evidence**: tests; the merge seen on a scratch deck.
- **Prohibited**: no host body edit; no merge of a signed (yellow) ticket.
- **Done when**: tests green and the merge seen live.
