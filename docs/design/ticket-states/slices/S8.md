# S8 A record names its ticket and is read by it

Feature `ticket-states` · run 1 · delivers spec 14 · source: `../architecture.md` §2, L5 · after: S7

## Files owned

- `deck/runs.mjs`: `ticket` joins `RECORD_ORDER` and `recordFields`.
- `deck/store.mjs`: `recordForTicket(repo, ticketId)`.
- `deck/server.mjs`: `GET /api/record?repo=&ticket=`.
- `deck/tools.mjs`: `deck_status` accepts `ticket`.
- `deck/test/record.test.mjs`: extended.

## Interface

```
record: { slug, feature, ticket, branch, worktree, artefact, slices, ... }
recordForTicket(repo, ticketId): Record | null
GET /api/record?repo=<path>&ticket=<itm_id> -> { record, ticket }   // ticket = the item, its plan included
GET /api/record?repo=<path>              -> unchanged (newest)
```

## Tests

1. `deck_status with ticket stores it on the record and the run.json mirror`.
2. `the ticket route returns that ticket's record, not the newest`.
3. `an unknown ticket id is refused by name`.

## Done

- **Expected**: after two tickets are planned in one session, each ticket's record can be read by its id.
- **Verification**: `node --test deck/test/record.test.mjs`; `curl "http://127.0.0.1:<port>/api/record?repo=...&ticket=..."` on the scratch deck.
- **Evidence**: tests; the curl output showing the plan and the record.
- **Prohibited**: no copy of the record onto the ticket (L5).
- **Done when**: tests green and the curl read back.
