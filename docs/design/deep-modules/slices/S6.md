# S6 Named commands and deck tools are checked, not pinned

Feature `deep-modules` · delivers spec 4 (b) · source: `../architecture.md` §2, §3 Seams, L5, A3 · after: S3, S4, S5

## Files owned

- `scripts/check-references.mjs`: three more failure kinds inside `checkReferences`.
- `scripts/test/references-hold.test.mjs` (new): tests through `checkReferences` on scratch trees.
- `scripts/test/*.test.mjs` except `merge-first`, `slice-interface`, `pilot-rules`: deletes the pins
  whose only assertion is that a prompt names a `pilot <subcommand>` or a deck tool.

## Interface

```
checkReferences(root, paths?) -> { ok, failures, checked, references }   // signature unchanged
  new failures, one string each, "<file>:<line>: …":
  - `pilot <word>` where <word> is not a subcommand bin/pilot.mjs dispatches
  - `mcp__plugin_pilot_deck__<tool>` where <tool> is not a name in deck/tools.mjs TOOLS
  - an agents/*.md body naming a deck tool its frontmatter `tools:` does not grant
```

## Tests

1. `an unknown pilot subcommand fails`: `checkReferences` → a failure naming the file, line and word.
2. `an unknown deck tool fails`: `checkReferences` → a failure naming the tool.
3. `an agent naming an ungranted deck tool fails`: `checkReferences` → a failure naming the agent and tool.
4. `the shipped surface holds`: `checkReferences` → `ok` on this repository.

Rewrite check: replacing how the subcommands and tool names are discovered (parsing
`bin/pilot.mjs` or importing it; reading `TOOLS` or the MCP list) keeps every result above.
