# S9 The subagent status line follows the reach

Feature `plain-session` · added slice (found by S4's live check on the L10 HOME) · delivers spec 3, 4 · source: `../architecture.md` §5 L4 (its statusLine treatment, extended to the twin key) · after: S4 (`applyReach`), S8 (`reach.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: sonnet — the same treatment `statusLine` already has, applied to `subagentStatusLine` at three named sites.

## The issue

At `nothing` and `rules`, user settings keep the pilot's `subagentStatusLine` (`node "<root>/hooks/context-size-guard.js" --subagent-status-line`), so a plain session's subagents still run pilot code. `installSettings` writes it at every level (`scripts/install-settings.mjs`, the `commandSettingStep(... COMMAND_SETTINGS.subagentStatusLine ...)` step) and the repair re-points it at every level (the `repairCommandStep(... subagentStatusLine ...)` step). The plugin's own `settings.json` copy does not take effect (comment above `SUBAGENT_STATUSLINE_SCRIPT`), so `pilot run` must carry it itself.

Co-pilot's call (a seam inside the rails, no spec line moved): `subagentStatusLine` gets exactly the treatment L4 gives `statusLine`.

## Files owned

- `scripts/install-settings.mjs`: `installSettings({ statusLine: false })` removes the pilot's own `subagentStatusLine` too (the fix round folded the separate flag in); the repair re-points it only at `everything`, as it does `statusLine`.
- `scripts/apply-reach.mjs`: below `everything`, `statusLine: false` removes the pilot's own `subagentStatusLine` the way S4 removes its `statusLine` (a user's own line is left).
- `deck/run.mjs`: `runSettings` (moved here from `scripts/reach.mjs` by the fix round) adds `subagentStatusLine` below `everything`, beside `statusLine`.
- Tests: `scripts/test/apply-reach.test.mjs`, `scripts/test/install-settings-reach.test.mjs`, `deck/test/run.test.mjs`.

## Interface

```
applyReach(level, { home?, pluginRoot, now? }) -> report   // S4's; below everything no pilot subagentStatusLine
repairSettings({ home?, settingsPath?, pluginRoot? }) -> report   // re-points subagentStatusLine only at everything
claudeArgs(reach, pluginRoot?) -> argv                     // --settings carries subagentStatusLine below everything
```

## Tests

1. `nothing leaves no subagent status line`: `applyReach` → at `nothing` user settings hold no pilot `subagentStatusLine`; a user's own one is kept.
2. `everything restores the subagent status line`: `applyReach` → set at `everything`.
3. `repair below everything leaves the subagent status line alone`: `repairSettings` → no `subagentStatusLine` written at `nothing`.
4. `the prompt stays last after a variadic --add-dir`: `claudeArgs` → `--settings` includes `subagentStatusLine` at `nothing`; at `everything` it does not.

Rewrite check: replacing the settings merge with any other writer keeps the pilot's subagent status line in user settings only at `everything`.
