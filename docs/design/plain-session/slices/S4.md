# S4 `pilot reach <level>` applies and stores the choice

Feature `plain-session` · delivers spec 1, 2, 4 · source: `../architecture.md` §5 L1 L4 L5 · after: S2 (`installRules({only})`), S3 (`installSettings({enablePlugin, statusLine})`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument and the marketplace manifest (security trigger).

## Files owned

- `scripts/apply-reach.mjs` (new): writes `reach.json` and applies the plan to both rules targets and the settings.
- `scripts/test/apply-reach.test.mjs` (new): one apply per level over a fake HOME.
- `bin/pilot.mjs`: the `reach` subcommand and its usage line.
- `.claude-plugin/marketplace.json`: `defaultEnabled: false` on the entry.

## Interface

```
applyReach(level, { home?, pluginRoot, now? }) -> { level, rules: report, settings: report }
  // S2's installRules per S1's rulesPlan on both targets, then S3's installSettings({ enablePlugin, statusLine })
  // both rulesPlan(level).user, removing the pilot's own status lines below everything; then, last, writes
  // <home>/.claude/pilot/reach.json { level, at } (tmp + rename), so an apply that throws leaves the old level
pilot reach                 -> prints the level, whether chosen, and the three choices
pilot reach <level>         -> applyReach; prints what changed; an unknown level -> exit 2
```

## Tests

1. `nothing leaves no pilot in a plain session`: `applyReach` → 0 shipped rules home, `enabledPlugins` false, no `statusLine`, `reach.json` level `nothing`.
2. `everything restores today's install`: `applyReach` → 113 home, `true`, `statusLine` set.
3. `rules is the middle`: `applyReach` → 111 home, 2 in the root, `false`.
4. `an unknown level changes nothing`: `pilot reach` → exit 2, the fake HOME's bytes unchanged.

Rewrite check: replacing the apply order keeps the end state of each level.
