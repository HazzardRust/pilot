## The issues

1. `scripts/reach.mjs:37` checks `Object.hasOwn(PLANS, level)`, which coerces its key: a `reach.json` of `{"level":["nothing"]}` passes and returns an array as the level. Guard with `typeof level === 'string'`; a non-string reads as A2's not chosen. `rulesPlan` gets the same guard (it throws).
2. `pilot uninstall` (`removeShippedRules`) clears `~/.claude/rules` but not the rules root (`rulesRoot({home})/.claude/rules`), which S2 now fills below `everything`. Remove the ledger-identical copies there too, with the same edited-copy rule; empty directories it leaves go, up to and including `rules-root` itself when empty.

## Interface

```
readReach({ home? }) -> { level, chosen }            // a non-string level reads as not chosen
rulesPlan(level) -> { home, root, user }             // throws on a non-string or unknown level
removeShippedRules({ target, home?, stateDir?, dryRun? }) -> { removed, kept }
planUninstall(home, deps) -> step[]                  // a remove and a leave step per rules place; the root's
                                                     // remove also takes the emptied dirs up to rules-root
```

## Tests

1. `a non-string level reads as not chosen`: `readReach` → `{ level: 'everything', chosen: false }` over `{"level":["nothing"]}`; `rulesPlan(['nothing'])` throws.
2. `uninstall clears the rules root`: `removeShippedRules` → an edited root copy kept and named; applying the root step removes rules-root.
3. `the uninstall plan names the rules root when it holds shipped copies`: `planUninstall` → a remove and a leave step at the root.
