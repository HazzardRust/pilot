# S5 A closed steps thread offers no Reopen

Feature `human-steps` · added slice (found in the S1 look) · delivers spec 3 (marked added: no dead press on the closed thread) · source: `../architecture.md` A2, L4 · after: S1 (`reopenItem`'s steps refusal)
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — one guard on a known line and one test; every change is named here.

## Why

A steps thread's Done closes it and its ticket; `reopenItem` refuses a steps thread (`deck/store-items.mjs:683`), yet the thread page draws the Reopen form for every closed thread (`deck/ui/render-pages.mjs:464`), so the button is a press the deck always refuses. Moves no locked decision.

## Files owned

- `deck/ui/render-pages.mjs`: the `REPLY` slot draws no Reopen form for a closed `KIND_STEPS` item (empty, as an archived thread's is).
- `deck/test/human-steps-reopen.test.mjs` (new): the pins.

## Interface

```
renderThreadPage(item, items): string  // a closed KIND_STEPS item: its steps, no /reopen form; any other closed item: the /reopen form
```

## Behaviours

1. `a closed steps thread draws no Reopen` (test): `renderThreadPage` → a steps thread closed by Done has no `action="/reopen"` form.
2. `any other closed thread still draws Reopen` (test): `renderThreadPage` → a closed question's page still has it.

Rewrite check: any markup of the closed page keeps 1 and 2 while steps carry no `/reopen` form and a question carries one.
Misses: how the page looks; the browser look reads that.

## Done

- **Expected**: a closed steps thread shows its steps and resolution, and no button.
- **Verification**: `node --test deck/test/human-steps-reopen.test.mjs deck/test/reopen.test.mjs deck/test/human-steps.test.mjs`; `npm test`.
- **Evidence**: behaviour 1 red before, green after; a `look` at a closed steps thread's page in a browser (headless screenshot read) showing no Reopen.
