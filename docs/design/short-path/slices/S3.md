## Interface

```
postItem({ kind: 'gate1', …, sliceCount, surface?: boolean })   // behind deck_post
  // sliceCount <= SHORT_PATH_MAX and surface absent: refused `a gate1 of <n> slices names surface: true or false`
  // checked on the raw argument: a flag is stored only when true (store-core.mjs:536)

  // fewer lines starting `Verdict:` than plan.sliceCount: refused naming the count
  // no line starting `Gate:`: refused

```

## Tests

1. `a small gate1 names its surface`: `postItem` → refused for `sliceCount: 2` without `surface`; posted with `surface: false`; a 3-slice gate1 without it posts.
2. `a short gate2 carries a Verdict per slice and a Gate line`: `postItem` → refused with 1 `Verdict:` on a 2-slice plan, refused with no `Gate:`, posted with both and no walkthrough.
3. `a surface needs its walkthrough`: `postItem` → refused on a plan with `surface: true` and no `walkthrough`; posted with one.
4. `a short gate2 lands as any other`: `postItem` → the ticket turns green, its lane claim is released, and its Sign off reads `landing started`.

Rewrite check: moving the checks to another module keeps all four results so long as the deck refuses at post, before anything is written.
