# S2 A word looks up its entry, never the whole file

Feature `project-glossary` · delivers spec 9 · source: `../architecture.md` §2, §5 L11 · after: S1 (`scripts/glossary.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument is the security trigger, though every result is fixed below.

## Files owned

- `scripts/glossary.mjs`: `matchGlossary`, `termOf`, and the `match` and `term` commands beside S1's `check`.
- `scripts/test/glossary-match.test.mjs` (new): the pins, over `GLOSSARY.md` and S1's fixture.

## Interface

```
matchGlossary(text: string, glossary: string): { term: string, via: 'term' | 'avoid', word: string, entry: string }[]
  // whole-word, case-insensitive; an entry once even if several words hit; order as in the file
termOf(name: string, glossary: string): string | null   // the one entry's text, term or an _Avoid_ word as name
node scripts/glossary.mjs match <text…> [--file GLOSSARY.md]   // the matched entries, each led by `<term> (via <word>)`; exit 0
node scripts/glossary.mjs term <name> [--file GLOSSARY.md]     // one entry; exit 1 `no entry for <name>`
S1's parseGlossary
```

## Behaviours

1. `an Avoid word names its canonical entry` (test): `matchGlossary` → "the subagents finished" gives exactly 1 result, term `Crew`, via `avoid`.
2. `a term hits by its own name` (test): `matchGlossary` → "take the base now" gives `Take the base` via `term`, and not `Base` twice.
3. `a word with no entry gives nothing` (test): `matchGlossary` → "hello world" gives 0 results.
4. `the lookup is small` (test): `matchGlossary` → on "the subagents", the printed `match` output is under 6 lines of the file's 300.
5. `term by an Avoid word` (test): `termOf` → "Orchestrator" returns the `Pilot` entry; "nothing" returns null.

Rewrite check: any lookup giving these results on `GLOSSARY.md` keeps 1-5.
Misses: an overloaded word with no `_Avoid_` listing; grilling's judgement (S3's prose) reads it.

## Done

- **Expected**: an agent asks the glossary about the words in front of it and reads 1-3 entries, not 300 lines.
- **Verification**: `node --test scripts/test/glossary-match.test.mjs`; `node scripts/glossary.mjs match "the subagents"`; `npm test`.
- **Evidence**: behaviours 1-5 red before, green after; the `match` output pasted in the report.
- **Prohibited**: no substring match ("base" in "database"); no regex built from glossary text; no edit to `parseGlossary`'s shape.
- **Done when**: the 5 behaviours hold and `npm test` is green.
