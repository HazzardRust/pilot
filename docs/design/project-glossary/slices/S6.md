# S6 The glossary log shows a term's history

Feature `project-glossary` · delivers spec 10, 11 · source: `../architecture.md` §2, §6 A4 · after: S1 (`parseGlossary`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — A4 is assumed, and a term argument reaches a `git log` process (security trigger).

## Files owned

- `scripts/glossary-log.mjs` (new): `glossaryLog` and its CLI.
- `scripts/test/glossary-log.test.mjs` (new): the pins, over a scratch git repository the test builds.

## Interface

```
glossaryLog(repoDir: string, opts?: { term?: string, limit?: number }): LogRow[]
type LogRow = { term: string, change: 'added' | 'changed' | 'removed', run: string | null, sha: string, date: string }
  // from `git log --follow -p -- GLOSSARY.md`, newest first; each commit's before and after parsed by S1's parseGlossary
  // run = <slug> from a `feat|fix(<slug>):` or `Merge feat/<slug>` subject, else null; limit defaults to 20
node scripts/glossary-log.mjs <repo> [--term <t>] [--limit <n>]   // one `<date> <run> <change> <term>` per row
```

## Behaviours

1. `three changes are three rows with their run` (test): `glossaryLog` → a history of add, change, remove of one term gives 3 rows, change kinds in order, each `run` the commit's slug.
2. `the log is bounded by default` (test): `glossaryLog` → 30 term changes give 20 rows; `limit: 5` gives 5.
3. `the log follows the rename` (test): `glossaryLog` → a term added in `CONTEXT.md` before a `git mv` to `GLOSSARY.md` keeps its `added` row.
4. `one term's history only` (test): `glossaryLog` → `term: 'Crew'` returns rows naming Crew and no other term.

Rewrite check: any reader of the history giving these rows keeps 1-4; a stored log would have to equal them.
Misses: a squash merge whose subject names no slug (run null); the report names that count.

## Done

- **Expected**: an agent asks for one term's history, or the newest 20 changes, and reads that, never the whole history.
- **Verification**: `node --test scripts/test/glossary-log.test.mjs`; `node scripts/glossary-log.mjs . --term Glossary`; `npm test`.
- **Evidence**: behaviours 1-4 red before, green after; the `--term Glossary` output pasted in the report.
- **Prohibited**: no stored log file (A4); no `shell: true`; the term passed to git only after `--`; no edit to `scripts/glossary.mjs`.
- **Done when**: the 4 behaviours hold and `npm test` is green.
