## Interface

```
Check = { name: string, outcome: 'pass'|'fail'|'pending', url: string }
Host.checks(sha: string) -> Check[]      // sha full hex or throws before run; GitHub: GET repos/{owner}/{repo}/commits/<sha>/check-runs?filter=latest&per_page=100
Verdict = { state: 'green'|'red'|'pending'|'none'|'unread', sha: string, failed: string[], pending: string[], why?: string }
checksAt({ host: Host|null, sha: string }) -> Verdict      // host null: none, why 'no host'; a throw: unread
ciConfigured(git: (args) => string, sha: string) -> boolean   // .github/workflows/*.yml|yaml or .gitlab-ci.yml in the tree
checksGate({ host, git, sha, at: 'land'|'gate2' }) -> { ok: boolean, line: string, verdict: Verdict }
checkLine(verdict) -> string             // `checks <state> at <sha7>[: <names>]`
parseCheckLine(line: string) -> { state, sha7, names } | null
```

## Behaviours

1. `a failed run is red, named` (test): `checksAt` → #121's three `failure` runs give red, `failed` the 3 names in order.
2. `pending, none, unread are told apart` (test): `checksAt` → an `in_progress` run pending; `[]` none; a throwing run unread with its first line.
3. `red wins over pending; neutral and skipped pass` (test): `checksAt` → fail+pending red; neutral+skipped+success green.
4. `the gate fails closed` (test): `checksGate` → ok only on green, or on none where `ciConfigured` is false.
5. `the line round-trips` (test): `parseCheckLine` → `checkLine`'s output parses back to state, sha7 and names.
6. `only the one GET reaches gh` (test): `Host.checks` → argv is the fixed check-runs path; a short sha, `-X POST` or another path throws `not a host verb`, no run.
7. `#121 reads red live` (run): `node -e` over `checksAt({ host: hostFor('.'), sha: '5fef2ab…' })` prints the red line.

Rewrite check: replacing `gh api` with GraphQL `statusCheckRollup` keeps 1-5 unchanged.
Misses: check runs from apps other than Actions on a real repo; QA's live read covers this repo's only.
