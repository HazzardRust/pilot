# S2 `pilot checks` prints it and waits

Feature `ci-gate` · delivers spec 7 · source: `../architecture.md` §2, §5 L1, L10 · after: S1 (`checksAt`, `checkLine`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a new CLI argument and an install allow rule, both on the security trigger.

## Files owned

- `scripts/checks-cli.mjs` (new): `pilot checks [<ref>] [--wait <min>]`.
- `bin/pilot.mjs`: import, usage line and dispatch for `checks`.
- `scripts/install-permissions.mjs`: `Bash(pilot checks *)` beside `Bash(pilot landing *)`.
- `scripts/install-settings.mjs`: the prose list mirrors the rule.
- `scripts/test/checks-cli.test.mjs` (new): one test per exit code, fake host and fake clock, 0 spawns.
- `scripts/test/install-allow-checks.test.mjs` (new): the rule is written, no `Bash(pilot *)`.

## Interface

```
pilot checks [<ref>] [--wait <min>]    // ref default HEAD, resolved by `git rev-parse --verify <ref>^{commit}`, never passed to gh
  stdout: S1's checkLine; exit 0 green, 1 red, 4 pending, 5 none, 6 unread, 2 usage
  --wait <min>: poll every 30 s while pending, up to min (default 20, 1..60); then the last line
main(argv, { cwd, host, git, sleep, now }) -> exit code
Bash(pilot checks *)   // the install's allow rule, scripts/install-permissions.mjs
```

## Behaviours

1. `each state has its exit code` (test): `main` → green 0, red 1, pending 4, none 5, unread 6, each printing one check line.
2. `wait ends when it stops pending` (test): `main` → with `--wait 5`, pending, pending, red gives exit 1 after 2 sleeps.
3. `wait is bounded` (test): `main` → with `--wait 1`, always pending exits 4 after at most 2 polls on the fake clock.
4. `a ref is a commit or usage` (test): `main` → `--wait 0`, `--wait 61`, a ref starting `-`, or one git cannot verify exit 2, no host call.
5. `the install allows it` (test): `Bash(pilot checks *)` → written once by the install, beside no `Bash(pilot *)`.
6. `#121 from the shell` (run): `pilot checks 5fef2ab` prints S1's red line, exit 1.

Rewrite check: replacing the polling loop with `gh run watch` keeps 1-4 only if exit codes stay.
Misses: a real 20 min wait against GitHub; QA's live pending read sees one.

## Done

- **Expected**: anyone in a worktree types `pilot checks` and sees the tip's CI in one line, or waits for it.
- **Verification**: `node --test scripts/test/checks-cli.test.mjs scripts/test/install-allow-checks.test.mjs scripts/test/cli-wiring.test.mjs`; `npm test`.
- **Evidence**: 1-5 red before, green after; behaviour 6's output and exit code.
- **Prohibited**: no ref reaching `gh` argv; no unbounded wait; no `Bash(pilot *)` wildcard.
- **Done when**: six behaviours hold and `npm test` is green. Estimate about 130 lines.
