# S3 `pilot sync` pulls the default branch into the pilot branch

Feature `pilot-branch` · delivers spec 5, 4 · source: `../architecture.md` §2, L20 · after: S2

## Files owned

- `scripts/sync.mjs` (new): merges `origin/<default>` into `pilot` in a temporary detached worktree, tests, pushes.
- `scripts/test/sync.test.mjs` (new): scratch clone with a bare origin.
- `bin/pilot.mjs`: the `sync` subcommand and its usage line.

## Interface

```
sync({ cwd, git, test = 'npm test' }): { sha: string, merged: boolean }
pilot sync [--test "<cmd>"] -> "synced pilot <sha> (<default>@<sha>): N pass" | "pilot already has <default>@<sha>"
exit 1: red or push failed, nothing pushed; exit 3: conflict, nothing pushed, the conflicting paths named
S1's assertPushable on the push; S2's git helper for the commands
```

## Tests

1. `sync merges a new main commit into pilot`: pilot contains it, by a merge commit whose second parent is main.
2. `sync with nothing new pushes nothing`.
3. `a conflicting main exits 3 and leaves pilot unchanged`: the remote SHA is unchanged and the paths are named.
4. `red tests push nothing`.
5. `sync leaves the caller's checkout untouched`: the temporary worktree is removed.

## Done

- **Expected**: one command brings main's work onto the pilot branch, or says why it could not.
- **Verification**: `node --test scripts/test/sync.test.mjs`; `npm test`; `pilot sync` in a scratch clone after a commit to its origin's main.
- **Evidence**: test 3 failing before and passing after; the scratch clone's `git log --oneline -3 origin/pilot`.
- **Prohibited**: no rebase; no forced push; no merge in the caller's own worktree.
- **Done when**: tests are green and the scratch-clone run shows main's commit on `pilot`.
