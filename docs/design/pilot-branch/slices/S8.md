# S8 The main deck concludes from the sub-deck's record

Feature `pilot-branch` · delivers spec 10 · source: `../architecture.md` §2, L6, ADR 0059 · after: S7

## Files owned

- `deck/store.mjs`: a record posted by a sub-deck run is filed under its parent's key, so `recordFor` and `recordForTicket` on the main directory return it.
- `deck/server.mjs`: the record mirror still writes `run.json` into the record's `worktree`, which is validated against the parent's repository.
- `deck/test/subdeck-record.test.mjs` (new): the pins.

## Interface

```
recordForTicket(mainDir, ticketId) -> { record, ticket }   // includes records a sub-deck of mainDir posted
S6's run.parent; S7's role
```

## Tests

1. `a record the sub-deck posts is read back by the main directory by ticket`.
2. `the record's worktree is still validated against the parent's repository`: a foreign path is refused.
3. `a fresh main-deck session's SessionStart recovery hands it the sub-deck's record` (ADR 0059 lane).

## Done

- **Expected**: after the sub-deck hands a ticket back, a main-deck session started cold finds the run's record and resumes the red phase from it.
- **Verification**: `node --test deck/test/subdeck-record.test.mjs`; `npm test`; `curl "http://127.0.0.1:<scratch port>/api/record?repo=<main>&ticket=<id>"` on a scratch deck.
- **Evidence**: test 1 failing before and passing after; the curl output.
- **Prohibited**: no copy of the record onto the ticket; no second record lookup path.
- **Done when**: tests are green and the curl returns the sub-deck's record.
