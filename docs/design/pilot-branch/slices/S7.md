# S7 The sub-deck takes the yellow head and holds it

Feature `pilot-branch` · delivers spec 7, 10, 16 · source: `../architecture.md` §2, L6, L7, L8 · after: S6

## Files owned

- `deck/items.mjs`:
  - `liveTicketOf` matches `holder ?? repo`.
  - `nextTicketOf` takes a role.
  - `liveTicketsOf` (new) returns every live ticket of a repository, held or not.
- `deck/tabs.mjs` (`tabsOf`): a tab with a `parent` selects its tickets by the parent's directory; its phase colour is the ticket it holds, the main tab's is its own in-hand ticket.
- `deck/ui/render.mjs` (`renderStrips`, `renderTicketQueue`, `renderTicketRow`, `renderMakeTickets`): the tickets panel is drawn from `tab.parent ?? tab.repo` (`:1700-1717` today), every live ticket's row is marked, and the add-ticket form's hidden `repo` is the same directory. The `li` keeps its shape: `in-hand.test.mjs`, `ticket-folds.test.mjs`, `ticket-state.test.mjs` and `next-ticket.test.mjs` match it literally.
- `deck/store.mjs`:
  - `takeTicket(id, from)` sets `holder` when `from` is a sub-deck of the ticket's directory.
  - `needTicket` clears `live` and `holder`.
- `deck/server.mjs`:
  - `/api/record` returns `role`.
  - The `deck_ticket` handler passes the caller's directory.
- `deck/client.mjs`: under `PILOT_SUB_OF`, posts, ticket actions and record reads name the parent directory.
- `deck/test/subdeck-take.test.mjs` (new), `deck/test/subdeck-panel.test.mjs` (new): the pins.

## Interface

```
type Role = 'main' | 'sub'
liveTicketOf(items, dir): Ticket | undefined           // live && (holder ?? repo) is dir
nextTicketOf(items, repo, role: Role): Ticket | undefined   // sub: first yellow not live; main: today's attended order
takeTicket(id, from?: string): Ticket                   // a sub-deck may take only a yellow ticket of its parent
liveTicketsOf(items, repo): Ticket[]                    // at most two: one a sub-deck holds, one the main deck's
GET /api/record?repo=&ticket= -> { record, role }
S6's run.parent: what makes a caller a sub-deck
```

## Tests

1. `a sub-deck takes its parent's yellow head while the main deck holds a green ticket live`: both are live, each in its own slot.
2. `a sub-deck taking a green or red ticket is refused by name`.
3. `the main deck never takes a ticket a sub-deck holds`.
4. `need on a held ticket turns it red and clears holder and live`: the main tab's in-hand ticket is then that red ticket.
5. `/api/record returns role sub for a sub-deck caller and main otherwise`.
6. `a child tab renders its parent's ticket list`: the same rows, in the same order, as the main tab.
7. `with a held yellow ticket and a live green one, both rows are marked on both tabs`, and no third.
8. `the add-ticket form on a child tab names the parent's directory`.
