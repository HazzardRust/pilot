# S5 The pilot cuts and lands by the pilot branch, and names the merge order

Feature `pilot-branch` · delivers spec 2, 3, 4, 5 · source: `../architecture.md` §2, §4, L5, L14, L15, L20, A6 · after: S4

## Files owned

- `agents/pilot.md`, in six places:
  - "The shape of a run" names the pilot branch. Every run is cut from it. The feature PR is `feat/<slug>` against the default branch, one per feature, and only the user merges it.
  - Taking a ticket runs `pilot sync`, then `pilot base`.
  - Gate 1 opens the feature PR as a draft against the default branch, with no `Stands on` line.
  - Step 5 drops the stack wording.
  - Step 9, after the sign-off: run `pilot land`, then `gh pr ready`.
  - "Ending a run": the closing report names the landing SHA and the human step "merge #a, #b, then this PR, oldest first, with a merge commit, never squash", taken from `land`'s `merge first` line. Teardown keeps `feat/<slug>` while its PR is open.
- `agents/pilot-architect.md`: "Where you work" cuts from `origin/pilot`.
- `CONTEXT.md`: entries for Pilot branch, Land, Sync and Promote; Base rewritten; Stands on removed.
- `docs/adr/0083-the-pilot-owns-a-branch.md` (new): supersedes 0067 and 0069, and amends 0068 and step 9.
- `scripts/test/pilot-branch-rules.test.mjs` (new): the sentence pins.

## Interface

```
agents/pilot.md headings unchanged
step 9: "run `pilot land` in the feature worktree, then `gh pr ready`; land is the only merge you make"
closing-report human step: "Merge <merge first>, then #<this>, oldest first, each with a merge commit, never squash"
```

## Tests

1. `pilot.md lands at step 9 and never merges the default branch`.
2. `pilot.md opens the feature PR against the default branch and writes no Stands on line`.
3. `the closing report names the merge order with a merge commit`.
4. `teardown keeps the feature branch while its PR is open`.
5. `the pilot prompt stays inside its measured budget`: the existing measure pin holds, paid for by the stack lines removed.
