# S10 A gate1 Sign off starts the sub-deck

Feature `pilot-branch` · delivers spec 11, 8 · source: `../architecture.md` §2, L9, A5, A7, ADR 0050 · after: S8

## Files owned

- `deck/session.mjs`: `startSession(repo, { sub: true })` runs the same fixed `cmd /c start` command with `run --sub`, using the scrubbed environment. It is refused while the parent has a live or starting sub-deck.
- `deck/server.mjs`: the gate1 Sign off path calls it for the ticket's directory after the ticket turns yellow. A refusal is logged and never fails the sign-off.
- `deck/test/subdeck-start.test.mjs` (new): the pins, with `spawn` injected.
- `docs/adr/0084-a-gate1-sign-off-starts-the-sub-deck.md` (new): amends ADR 0050 with one more press and one more argument.

## Interface

```
startSession(repo, { sub?: boolean, spawn, platform, env, ... }): same result shape as today
argv: cmd.exe /d /c start "pilot sub-deck" "<node>" "<bin/pilot.mjs>" run --sub    // cwd = repo
S6's 409 on a second live sub-deck
```

## Tests

1. `signing a gate1 with no sub-deck live spawns run --sub in the ticket's directory`.
2. `signing a gate1 while a sub-deck is live spawns nothing`.
3. `the sub start keeps ADR 0050's guards`: Windows only, `PILOT_DECK_NO_START`, no `%` or `"` in paths, and the parent markers dropped.
4. `a refused start leaves the gate signed and the ticket yellow`.

## Done

- **Expected**: the user presses Sign off on a plan, and a "pilot sub-deck" terminal window opens and starts implementing it.
- **Verification**: `node --test deck/test/subdeck-start.test.mjs deck/test/session*.test.mjs`; `npm test`; sign a gate1 on a scratch deck and see the window open.
- **Evidence**: test 1 failing before and passing after; the window seen.
- **Prohibited**: no headless or pty start from the daemon; no permission flag of its own: the command is `pilot run --sub` and S6's wrapper carries L24's mode; no start under test.
- **Done when**: tests are green and the scratch sign-off opened the window.
