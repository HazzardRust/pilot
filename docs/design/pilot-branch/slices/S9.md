# S9 The sub-deck works the queue and exits when it is empty

Feature `pilot-branch` · delivers spec 11 · source: `../architecture.md` §2, L8, L9 · after: S8

## Files owned

- `deck/chain.mjs`:
  - `chainNext` for a sub-deck hands over its parent's next yellow ticket.
  - With none left, it returns `{ exit: true }`.
  - A sub-deck's `needed` finish chains too, so the next yellow ticket is taken.
  - `CHAINING_FINISHES` is keyed by role, not mode, and `modeFor` is no longer imported, so S11 can delete it.
- `deck/run.mjs`: in `--sub`, the wrapper refreshes the worktree before typing `/clear`, and types `/exit` on `{ exit: true }`, then exits.
- `deck/server.mjs`, the wait and the finish only (seam added by the pilot, 2026-10-05, from S8's findings; it implements L6 and moves no decision). A sub-deck's wait and finish are keyed on `run.parent ?? run.repo`:
  - the `deck_wait` reply filter (`forRun(reply, repo)`, about line 991): a sub-deck's posts carry the parent's directory (`deck/client.mjs:218`) while its wait is stamped with its own (`client.mjs:229-230`), so today it never hears a reply to its own question;
  - `stopReason` (about line 947) reads `recordFor(repo)`: after S8 the record is under the parent, so a sub-deck's wait never hears "the run is finished";
  - the finish path (about lines 893-894) calls `chainNext(repoOfRun(run))`, the sub-deck's directory. Decide in one place whether `chainNext` is handed the sub-deck's directory and resolves the parent itself, or is handed the parent with the role; not both.
  - A sub-deck hears only replies to threads it owns or posted, never the main deck's other threads (L6: the main deck answers the user).
- `deck/test/chain.test.mjs`: the role rows.
- `deck/test/subdeck-chain.test.mjs` (new): the wrapper's exit.

## Tests

1. `a sub-deck finishing needed is handed the next yellow ticket`.
2. `a sub-deck with no yellow ticket left is told to exit`.
3. `the main deck's chain is unchanged`: a red ticket first, then green.
4. `the --sub wrapper types /exit once and exits on exit`.
5. `a sub-deck's wait hears the reply to a question it posted under its parent`, and not a reply on a main-deck thread it does not own.
6. `a sub-deck's wait is told to stop when its record, filed under the parent, is finished`.
