# The pilot's own branch, and the sub-deck that implements the yellow queue

Ticket itm_4f3c3e333032, with itm_2c61538cefec merged in (itm_3eb7ddc1ee23). Base: `origin/main` at `e8a0e79`.

## 1. Problem

Every ticket ends as an open feature PR against main, and the next ticket is cut from the top of
that stack. The stack is four deep (#318 to #321), two tickets worked at once would both treat
the last open PR as head, and the pilot cannot be allowed to merge to main to clear it. The
user wants one branch the pilot owns and treats as main: every ticket cut from it, every
finished ticket merged into it at Gate 2, main pulled into it now and then, promotion to main
left to the user.

Separately, "implementation mode" is a toggle that cannot take effect mid-run and gives no
feedback. The user wants a sub-deck instead: a second pilot session, in its own worktree and
its own tab beside the main deck's, that always implements whatever is in the yellow queue,
hands each ticket back to the main deck for the red phase, and closes when the queue is empty.
The two are one run because the sub-deck cuts every ticket from the pilot branch and the main
deck lands what it hands back.

## 3. Findings

- `pilot base` is `scripts/base.mjs` over `deck/stack.mjs`. It reads the deck's records and `gh pr list`, prints `base feat/<a> <sha> stands on #N` or `base <default> <sha>`, and exits 3 at a stack of three (`MAX_STACK`, `base.mjs:20`). It is pinned by `scripts/test/base.test.mjs`, `base-depth.test.mjs` and `deck/test/stack.test.mjs`.
- `pilot integrate` (`scripts/integrate.mjs`) merges `baseOf()` (the `Stands on` PR's head, or the default branch, `:102-122`) then the slice, tests, and runs `git push origin HEAD` (`:273`). **Nothing checks that HEAD is not the default branch.** The closed-base revert is `takeOut` (`:136`). Its pins are `integrate*.test.mjs`. ADRs 0067 (stack in the PR body), 0068 (integrate takes the base every call) and 0069 (take-out) record this. #311 is on main (`ece70e3`).
- The install writes no git or gh permission rule: `scripts/install-settings.mjs` merges only the status lines and opt-in `WebFetch` allows (`docs/INSTALL.md:17`). Auto mode allows a push to any branch, the default included, and Bash `ask`/`deny` rules match a command only as written (permission-modes and permissions docs).
- The feature PR is opened at Gate 1 against the default branch with `Stands on #N.` (`agents/pilot.md:344-348`). Step 9 runs `gh pr ready`, and "merge is the user's act" (`:496-504`). No script runs `gh pr merge`.
- A deck is a directory: `repoKey` is `path.resolve`, lower-cased on win32 (`deck/items.mjs:751`). A worktree is therefore already its own tab and number, and nothing links it to its repository at the tab layer. `runs.mjs:104 repoOf` resolves a worktree's `.git` file. Records, the live ticket, the mode and the queues are all per directory (`store.mjs:1660-1699`, `items.mjs:666-716`).
- Tickets store `state` and `live`. There is one live ticket per directory (`takeTicket`, `store.mjs:1085`, keyed on `item.repo`). `need` turns yellow to red, `pivot` turns red to yellow (ADR 0066). `nextTicketOf(items, repo, mode)` takes the yellow head when autonomous and never a yellow ticket when attended (`items.mjs:698`).
- The mode lives in `store.mjs:337-377`, `POST /mode` (`server.mjs:1219`), the button (`ui/render.mjs:1215-1236, 1434-1443`), `CHAINING_FINISHES` (`chain.mjs:20`), "Modes" (`agents/pilot.md:134-173`) and roughly ten test files (`deck/test/mode.test.mjs`, `chain`, `next-ticket`, `blocking`, `reply`, `wait-as`, `scripts/test/ticket-states`, `pilot-need`).
- Sessions: ADR 0039 says the daemon starts no session, and the user ruled out headless ones. ADR 0050 allows exactly one kind: a visible `pilot run` in a new window (`deck/session.mjs`, `cmd /c start`), on the Start press, with a scrubbed environment and Windows only. `pilot run` (`deck/run.mjs:91`) launches `claude --agent pilot:pilot` under node-pty with **no permission flags**, cwd = `process.cwd()`. The client registers `POST /api/runs {repo: cwd}` (`client.mjs:184`).
- The four open PRs are plans only. None changes code outside `docs/`. #319 to #321 carry `Stands on` the one below. Between them they claim ADR numbers 0070 to 0082. Their slices touch `scripts/integrate.mjs` (#319 S10), `bin/pilot.mjs` (#318 S5, #320 S6), `agents/pilot.md` (all four), `deck/server.mjs`, `store.mjs`, `items.mjs` and `ui/render.mjs` (#319).

## 4. Ubiquitous language

- **Pilot branch**: the one branch per repository the pilot owns and treats as its default: `pilot`. Every run is cut from it, and every finished run lands on it.
- **Land**: fast-forward the pilot branch to a feature's tip after taking the pilot tip into it, at Gate 2. It is the only way work reaches the pilot branch.
- **Sync**: merge the default branch into the pilot branch. It is the only way main's work reaches the pilot branch.
- **Promote**: merge one feature's PR, `feat/<slug>` against the default branch, oldest first with a merge commit. It is the user's act, never the pilot's (L15).
- **Main deck**: a repository's own deck and tab, where a ticket is planned (green) and concluded (red).
- **Sub-deck**: the one child session of a main deck, in `<repo>-subdeck`, that holds a yellow ticket while it implements it.
- **Holder**: the directory whose session holds a ticket live. It is the ticket's own repository unless a sub-deck took the ticket.
