# S5 A small ticket is marked and the chain passes it by

Feature `ticket-making` · delivers spec 11, 12 (deck side) · source: `../architecture.md` §2, L3, L7 · after: S2, S3, S4

## Files owned

- `deck/items.mjs`: `SIZE_FIELD` on `SPECS[KIND_TICKET]` (`:294`), `SIZE_SMALL = 'small'`, `isSmall(item)`.
- `deck/store.mjs`: `setTicketSize`, one write; `postItem` accepts `size` on a ticket and refuses any value but `small`.
- `deck/chain.mjs`: the head is the first regular ticket of `ticketQueueOf`, never a small one.
- `deck/tools.mjs`: `deck_post` documents `size`; `deck_ticket`'s `action` gains `small`, `regular`.
- `deck/server.mjs`: the `deck_ticket` branch dispatches the two new actions to `setTicketSize`.
- `deck/ui/render.mjs`: a `small` badge on a small ticket's row; `next` marks the chain head, not index 0.
- `deck/test/small.test.mjs` (new): the pins.

## Interface

```
// deck/items.mjs
export const SIZE_SMALL = 'small'          // a ticket with no size is regular; there is no 'regular' value stored
export function isSmall(item): boolean
// deck/store.mjs
export function setTicketSize(id: string, size: 'small' | 'regular'): Item   // 'regular' deletes item.size
  // refuses: not an open ticket; a started ticket (S6); the size it already has
deck_post { kind: 'ticket', ..., size?: 'small' }
deck_ticket { id, action: 'up' | 'down' | 'small' | 'regular' }
  -> "Marked <id> small." | "Marked <id> regular: the chain may take it."
S1's ticketQueueOf; S3's chainNext (head = ticketQueueOf(items, repo).find(t => !isSmall(t)))
```

## Tests

1. `a ticket posted with size small carries it; any other size is refused`.
2. `the chain skips a small head and takes the first regular ticket; only small tickets chain nothing` (`reason: 'no ticket'`).
3. `setTicketSize regular drops the field and the chain may then take it`; `small` refuses a ticket already small.
4. `the tab shows small on a small ticket and next on the first regular one`.
5. `deck_ticket small and regular through /api/tool announce and change the store as setTicketSize does`.

## Done

- **Expected**: on a preview deck, a ticket posted `small` at the head shows `small`; `next` sits on the ticket below;
  `deck_ticket regular` on it moves `next` onto it.
- **Verification**: `npm test`; the preview-deck flow above.
- **Evidence**: tests 1–5 red before, green after; the tab seen before and after the size change.
