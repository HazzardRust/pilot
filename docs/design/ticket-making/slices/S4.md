# S4 Make tickets opens a ticket-making thread

Feature `ticket-making` · delivers spec 1 · source: `../architecture.md` §2, A6 · after: S1

## Files owned

- `deck/ui/render.mjs`: the **Make tickets** form at the top of the tickets panel, shown with or without tickets.
- `deck/ui/deck.css`: the button, sized like the panel's other controls.
- `deck/test/make-tickets.test.mjs` (new): the pins.
- `deck/test/standing.test.mjs`: the one test `the sections carry no form` (run-chaining S3, 9dbe35a), narrowed and
  nothing else in the file. Spec 1 puts a control in the tickets panel, so the pin becomes: the reports section still
  matches no `<form` and no `<button`; the tickets section, with its one ticket, holds exactly one `<form`, the
  `class="make-tickets"` one, and exactly one `<button`. Renamed to say so. A move form on a queue of one still fails it.

## Interface

```
// deck/ui/render.mjs
export const TICKET_MAKING_TITLE = 'Make tickets'   // the name agents/pilot.md keys the skill on (S8)
renderMakeTickets(tab): string
  // <form method="post" action="/create" class="make-tickets">
  //   hidden name=TICKET_MAKING_TITLE, hidden repo=tab.repo, <button>Make tickets</button></form>
// server: the existing POST /create -> createThread({ name, repo }) -> 303 /thread/<id>; unchanged
```

One press, no name to type and no confirm step: the thread is empty until the user writes in it, and a stray one is
closed like any Create thread.

## Tests

1. `the tickets panel renders Make tickets for its repository, with tickets and with none`.
2. `posting the Make tickets form opens a user thread titled Make tickets on that repository and redirects to it`:
   through `deckOnAPort`, the form's own fields.
3. `the thread is the pilot's and a message in it wakes a pilot deck_wait with that title`: `ownerOf`, `repliesSince`.

## Done

- **Expected**: on a preview deck's Tickets tab, pressing **Make tickets** lands on a new thread titled `Make tickets`;
  typing into it wakes the pilot, whose wait shows that title.
- **Verification**: `npm test`; the preview-deck flow above in a real browser.
- **Evidence**: tests 1–3 red before, green after; the button pressed and the thread page seen.
- **Prohibited**: a new route; a `purpose` field on the item; changing `createThread` or `repliesSince`; a
  client-side-only thread.
- **Diff limit / done when**: about 70 changed lines, past 400 stop and ask `main`; done when the pins are green and
  the button has been pressed on a live deck.
