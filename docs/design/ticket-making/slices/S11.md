# S11 The pilot runs a small ticket as a side job

Feature `ticket-making` · delivers spec 13, 14 · source: `../architecture.md` §2, L10, L11, A7–A9 · after: S6, S10

## Files owned

- `agents/pilot.md`: a "Small tickets" paragraph: when to start one, the implementer's brief, the QA pass, one QA live.
- `agents/pilot-implementer.md`: a side-job brief: base `main`, a `side/<ticket id>` worktree, draft PR against `main`;
  no integration branch, no `deck_status`.
- `agents/pilot-qa.md`: for a small ticket, the same pass on the side PR; its Gate 2 walkthrough carries `ticket: <id>`.
- `scripts/test/small-ticket.test.mjs` (new): pins the three texts.

## Interface

Who posts the Gate 2 item: **QA**, as its `walkthrough` with Sign off, carrying `ticket` (S6 keys the in-flight check
and the ticket's closing on it). The pilot posts no item for a small ticket. The pilot's paragraph after the slice:

```
**Small tickets.** When none is in flight and one is queued, deck_ticket start it and hand it to one Opus
pilot-implementer as a side job (brief: the ticket's body and comments); the run carries on. On its report, spawn
pilot-qa on the side PR, the same pass a feature gets; its walkthrough carries ticket: <id>. It has no Gate 1. One QA
agent is live at a time: a small ticket's QA waits for the run's, and the reverse. QA resolves the walkthrough after
the user's Sign off, which closes the ticket.
S6's deck_ticket start and walkthrough.ticket; S2's deck_ticket
```

Budget: at most ~250 tokens added to `agents/pilot.md`; the 10400-token pin must hold. At most ~40 tokens added to
`agents/pilot-qa.md`: QA's own share is 5526 of its 5600 pin after S6 (L19) and S10 spends ~30 first. Past 40, stop
and ask `main`.

## Tests

1. `the pilot starts a small ticket only with deck_ticket start and on one Opus implementer`.
2. `the side job writes no run record and no deck_status` (implementer text).
3. `a small ticket gets a pilot-qa pass and its Gate 2 is QA's walkthrough carrying ticket; it has no Gate 1`.
4. `one QA agent is live at a time: the small ticket's QA waits for the run's, and the reverse`.
5. `the pilot's own share stays at or under 10400 tokens` (existing pin, run).

## Done

- **Expected**: in a live run on a preview deck with a small ticket queued, the pilot starts it, the run's slice table
  is unchanged, a side PR against `main` appears, QA passes it, and QA's walkthrough naming the ticket sits open while
  the run continues.
- **Verification**: `npm test`; that live run, with a session started after the plugin update.
- **Evidence**: tests 1–5 red before, green after; the deck seen with the run's status and the small ticket's walkthrough.
- **Prohibited**: a second deck or `pilot run` for the side job; a pilot `signoff` in place of QA's walkthrough; two
  QA agents live at once.
- **Diff limit / done when**: about 120 changed lines, past 400 stop and ask `main`; done when the pins are green and
  the live side job has reached QA's walkthrough once.
