# S2 The pilot moves a ticket with `deck_ticket`

Feature `ticket-making` · delivers spec 8 · source: `../architecture.md` §2, L3, A4, A5 · after: S1

## Files owned

- `deck/tools.mjs`: the `deck_ticket` entry in `TOOLS`; this slice's `action` enum is `up`, `down` (S5, S6 widen it).
- `deck/server.mjs`: the `callTool` branch calling S1's `moveTicket`; `deck_ticket` joins `WRITING_TOOLS` (`:742`).

## Interface

```
deck_ticket { id: string, action: 'up' | 'down', author?: string }
  -> text: "Moved <id> <action>: <n> of <count> in this directory's queue."
  -> refusal text from S1's moveTicket, unchanged
S1's moveTicket: the only write; S1's ticketQueueOf: the only queue
```

A pilot session's tool list is fixed when its MCP client connects: a session started before the plugin update has no
`deck_ticket`. The live check here, and QA's probes of lines 8, 12, 13 and 15, use a session started after it.
Budget: at most ~60 tokens added to `agents/pilot.md`.

## Tests

1. `deck_ticket up through /api/tool reorders the queue exactly as the arrow does`: same store state as S1's route.
2. `deck_ticket announces a change`: a `/events` listener sees `changed` once.
3. `deck_ticket refuses what moveTicket refuses, and an unknown action`: the text names the reason.
4. `the pilot's tools field grants deck_ticket` (in `pilot-agents.test.mjs`, via `DECK_TOOLS`).
