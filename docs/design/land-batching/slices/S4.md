- `scripts/sync.mjs`: `main` builds one view; `mergeIntoPilot`'s `pilotTipOf` and ancestry checks go through `tipOf` and `holdsIn`; `removeWorktree` prunes only when the removal left an entry.
- `scripts/test/sync-pin.test.mjs` (new): the sync pin and its git count.

## Interface

```
removeWorktree(cwd: string, dir: string, git?: Git): boolean   // prune runs only when `worktree remove` failed

```

## Behaviours

1. `sync prints what it printed on the base` (test): `removeWorktree` → reached through `pilot sync` on a seeded repo with main ahead of pilot, the printed `synced pilot …` line, pilot's tip parents and subject equal the pin recorded on the base.
2. `a removed worktree is not pruned again` (test): `removeWorktree` → a clean removal spawns 1 git and leaves no entry in `worktree list`; a locked one still prunes.
3. `one sync spawns at most 14 git` (test): `removeWorktree` → reached through `pilot sync` on the pin's repo, the command spawns ≤ 14 (18 on the base).

Rewrite check: any prune policy that leaves `worktree list` without the removed entry keeps 2.
Misses: a Windows handle held open in the removed dir; `sync-remote` and land-clear tests read that path.
