## Behaviours

1. `rev-list, diff and log are asked once per epoch` (test): `gitView` → each of `['rev-list','--count','HEAD']`, `['diff','--name-only','HEAD']`, `['log','-1','--format=%H']` asked twice spawns 1 git; with a `['commit', ...]` or `fetch` between, 2. Red first on the base.
2. `a working-tree diff is never stale across a write` (read): every `diff`, `log`, `rev-list` reached through a view in `land.mjs`, `integrate.mjs`, `sync.mjs`, `branches.mjs`, `worktrees.mjs`, `checks.mjs`, as file:line, with why its answer cannot move between two asks in one epoch, or the `forget()` that makes it so. A needed `forget()` in a file S8 does not own (`land.mjs`, `branches.mjs`, `worktrees.mjs` are S5's; `sync.mjs` is S4's) is not written: it goes in the report as file:line for the co-pilot to route.
3. `integrate re-measured` (test): `integrate` → `countGit` on the S3 pin's repo; the bar moves to the measured count, and to 75% of the base (18) if reached. If 18 is not reached inside S8's files, the test holds the measured number and the report names what is left.
4. `the landing re-measured` (run): S1's landing pin count before and after S8 on the same tip, in the report; `land-pin.test.mjs` is S5's and is not edited.

Rewrite check: any allowlist shape keeps 1's counts.
Misses: a diff of the working tree after a file written by the command itself, which is 2's audit.
