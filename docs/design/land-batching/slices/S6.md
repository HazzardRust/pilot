## Interface

```
buildRepos(dir: string, names: string[]): { origin, seed, clone, mover, gitIn, ...cloned }   // as today; the same origin config, refs, trees, subjects and authors, with fewer git
S1's countGit: the spawn count buildRepos is held to
S7's SPAWN_CEILING, GIT_CEILING: set to the measured run (the signed numbers are out of reach)
```

seam change, co-pilot: commitFile cannot fold; buildRepos does. A one-spawn commit of an untracked file is refused
(`git commit -i -- <new file>` exits 128), and `commit -- <file>` commits that path only, so a test that staged more
would get a different commit. commitFile stays as it is (it returns nothing, not a SHA).

## Behaviours

1. `a folded helper makes the same commit` (test): `buildRepos` → on a fresh directory each repository's refs, trees, parents, subjects, authors, HEAD, config and status equal those the base helper made, with fewer git (both counts in the test).
2. `the suite meets the signed bars` (run): `npm run test:cost` on the tip prints spawns ≤ 11,000 and git ≤ 10,000, re-recorded in `cost-after.txt`; the ceilings read 11,000 / 10,000.
3. `no test is lost` (read): the run's file count and pass count equal S7's; 0 asserts removed in the diff.

Rewrite check: a helper built on `git fast-import` or plumbing keeps 1's tree and subject.
Misses: a test that relied on a helper's intermediate state (an unstaged file between add and commit); the full suite reads it.
