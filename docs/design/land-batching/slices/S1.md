# S1 One landing runs on one view and spawns fewer git (walking skeleton)

Feature `land-batching` · delivers spec 3, 4 · source: `../architecture.md` §2, §3, §5 L2-L6 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the view's write rule (L3) is a judgement on every git argv, and `land` starts processes (security trigger).

## Files owned

- `scripts/git-view.mjs` (new): `gitView`, the per-command read memo.
- `scripts/land.mjs`: `main` and `land` build one view for the landing and pass it everywhere `git` goes today.
- `scripts/test/lib/count-git.mjs` (new): `countGit`, git spawns made inside one call.
- `scripts/test/git-view.test.mjs` (new): the view's memo and write rule.
- `scripts/test/land-pin.test.mjs` (new): the landing pin and its git count.
- `docs/adr/0222-land-batching.md` (new): a command reads git through one view (L2-L4).

## Interface

```
type Git = (args: string[]) => string        // today's runner shape, unchanged
gitView(cwd: string, { run?: Git }): Git     // run defaults to scripts/pilot-branch.mjs's git(cwd, ...args)
// reads (L4 allowlist) answered once per epoch; any other argv is a write: it runs, then every answer is forgotten
// a throw is rethrown and never remembered
Git.forget(): void                           // on a view: drop every answer, for a write made outside it
countGit<T>(fn: () => T): { value: T, git: number }   // test-only, in-process sync and async git spawns
land({ cwd, git, ... }): { head, sha, ... }   // scripts/land.mjs, unchanged; its git is now the view
```

## Behaviours

1. `a read is asked once per epoch` (test): `gitView` → two `['config','--get','pilot.remote']` calls spawn 1 git; a `['fetch','-q','origin']` between them makes it 2.
2. `a throw is not remembered` (test): `gitView` → a missing `rev-parse -q --verify` throws twice and spawns twice.
3. `the landing prints what it printed on the base` (test): `land` → on `repos(t,'x')` the printed lines (SHAs as `<sha>`), pilot's tip parents and subject equal the pin recorded on the base, written and green before the product change.
4. `one landing spawns fewer git` (test): `countGit` → one `land` on the seeded repo spawns ≤ 35 git (36 measured on the base; both numbers in the test).

Rewrite check: replacing the memo with any other store keeps 1, 2 and 4's counts and 3's lines.
Misses: concurrency between two landings on one repository; QA's walkthrough lands two features back to back.
