# S2 A suite process's write to the home store is refused and named

Feature `home-store-guard` · delivers spec 1 · source: `../architecture.md` §2, §5 L1, L4, §6 A1 · after: S1 (`scripts/gate.mjs` `runGate`, `scripts/test/gate-home-store.test.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it changes the deck store's write path, takes an env input there, and rests on assumed A1.

## Files owned

- `deck/store-dir.mjs`: `refuseGateHomeWrite`.
- `deck/store-core.mjs`: 2 changed lines, 0 added (L4). The `store-dir.mjs` import names it, and `writeDeck` calls it on `storeFile()`.
- `scripts/gate.mjs`: `gateEnv` sets the two variables when given `guard`, and `runGate` makes the log, passes it, then reads it after the census.
- `deck/test/home-write-guard.test.mjs` (new): the guard's pins.
- `scripts/test/gate-home-store.test.mjs`: the gate's log-reading pin.

## Interface

```
refuseGateHomeWrite(file: string) -> string
  // env PILOT_GATE_HOME_STORE unset, or path.resolve(file) differs (case-folded on win32): returns file
  // equal: appends "<pid> <process.argv joined> <file>\n" to PILOT_GATE_HOME_LOG, then throws
  //   Error("home store write refused under the gate: <file>")
gateEnv(env, slot, spawns, guard?: { store: string, log: string }) -> env
  // guard given: PILOT_GATE_HOME_STORE = guard.store, PILOT_GATE_HOME_LOG = guard.log
runGate(args, { homeStore, ... }) -> 0 | 1
  // each log line printed as "home store written: <file> by <pid> <argv>", exit 1
```

## Behaviours

1. `a guarded write is refused and logged` (test): `refuseGateHomeWrite` → throws and the log holds exactly one line with the pid and the file, when env names that file.
2. `any other path passes` (test): `refuseGateHomeWrite` → returns the file and writes no log, for a `tempDeck` path or an unset env.
3. `the store write goes through it` (test): `refuseGateHomeWrite` → a `postItem` with `PILOT_DECK_DIR` at the guarded dir throws, and `deck.json` is not created.
4. `the gate names the writer` (test): `runGate` → exit 1 and one `home store written: <path> by <pid>` line when the injected spawn appends to the log it was given.
5. `facade cap held` (run): `node --test deck/test/facades.test.mjs` passes; `store-core.mjs` stays at 799 lines.

Rewrite check: moving the guard anywhere on the store's write path keeps the refusal, the one log line and the gate's red.
Misses: a writer that bypasses `writeDeck` (raw `fs`, `pilot store restore`). S1's stat backstop and QA read that.

## Done

- **Expected**: a test or tool inside a gate run that writes the real home store through the deck store fails there, and the gate is red naming the file and who wrote it. The live deck is untouched.
- **Verification**: `node --test deck/test/home-write-guard.test.mjs scripts/test/gate-home-store.test.mjs deck/test/facades.test.mjs`; `npm test`.
- **Evidence**: behaviours 1, 3 and 4 failing before the change; the scratch-clone run with a planted real-HOME store write showing the line and exit 1.
- **Prohibited**: no added line in `store-core.mjs`; no guard keyed on `os.homedir()` inside the writer (the env carries the path); no swallowing the throw in `writeDeck`.
- **Done when**: behaviours 1–5 hold and `npm test` is green.
