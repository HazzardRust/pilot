# S8 No pilot process runs a git from the repository directory (added)

Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer` · PR #628, integrated at 62c48e51

## Files owned

- `scripts/pilot-branch.mjs`: adds `searchPathOnly()`; removes `gitBinary`; `holds` and `pilotLineage` spawn a bare `git` again.
- `bin/pilot.mjs`: calls `searchPathOnly()` before anything else runs.
- `deck/daemon.mjs`: calls `searchPathOnly()` first in `main()` (`deck/client.mjs` and `deck/scratch.mjs` both spawn it).
- `deck/gate2-base.mjs`: spawns a bare `git` again.
- `deck/test/gate2-base.test.mjs`: the spawned-entry pins and the `searchPathOnly` test replace S7's in-process ones.

## Interface

```
searchPathOnly(env = process.env, platform = process.platform)  // win32: NoDefaultCurrentDirectoryInExePath=1, and PATH keeps its absolute entries only
```

## Tests

1. `the pilot CLI does not run a git planted in the repository`: `bin/pilot.mjs` spawned → `pilot base` exits 0 with `base pilot <sha> (created from main)`.
2. `the deck daemon does not run a git planted in the repository`: `deck/daemon.mjs` spawned → a gate2 over `/api/tool` is posted.
3. `an entry keeps the absolute PATH entries only, on Windows alone`: `searchPathOnly` → the relative entries dropped, the flag set.

Both spawn pins run from a parent with `NoDefaultCurrentDirectoryInExePath` unset and `.` on PATH, in a repo with whoami.exe planted as `git.com` and `git.exe`; they are skipped off Windows with the reason.
