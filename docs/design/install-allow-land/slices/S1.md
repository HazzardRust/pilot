## Tests

1. `the CLI writes the three merge allow rules`: `installSettings` → with `pilotMerge: true`, all three come after the user's allow rules.
2. `a second run adds nothing`: `installSettings` → the bytes are unchanged and no backup is written.
3. `a deny covering pilot land is named`: `pilotMergeStep` → with `deny: ['Bash(pilot land*)']`, `covered` names the land rule, and only the sync and integrate rules are added.
4. `an ask covering pilot is named`: `pilotMergeStep` → with `ask: ['Bash(pilot *)']`, all three are in `covered` and none is added.
5. `the user's rules survive byte for byte`: `installSettings` → the user's allow, ask and deny keep their order and their text.
6. `the library writes no merge rule unless asked`: `installSettings` → `pilotMerge: null` when the option is absent.

Rewrite check: if `pilotMergeStep` were rewritten, the same scratch files would still end with the same `permissions` and the same named lines.
