## Tests

1. `--test is a usage error`: `pilot land | pilot sync` → `pilot land --test x`, `pilot sync --test x` and `pilot integrate --test x` each exit 1 with their usage line.
2. `package.json wins`: `repoTestCommand` → returns `'npm test'` even when `pilot.test` is set.
3. `git config pilot.test drives integrate`: `repoTestCommand` → with no package.json, `exit 0` integrates and `exit 1` stays red.
4. `neither is a named refusal`: `repoTestCommand` → it returns undefined, and `pilot integrate` exits 2 naming `git config pilot.test`.

Rewrite check: if `repoTestCommand` were rewritten, the same scratch repositories would still pick the same command and refuse with the same line.

## Done

- **Expected**: an allowed `pilot land` or `pilot integrate` command line carries no shell text of its own. The test it runs is the repository's, and only a reviewed `package.json` or a `git config` the classifier saw can set it.
- **Verification**: `node --test scripts/test/test-command.test.mjs`; `npm test`, which includes the prompt-budget and wording pins on `agents/pilot.md`; `pilot land --test x` in a scratch clone, with the output read.
- **Evidence**: tests 1, 3 and 4 fail before the change and pass after it. The usage line from a real CLI run.
- **Prohibited**: keeping `--test` as a hidden alias; reading the command from a file in the working tree; setting `shell: false` while still parsing a string; touching `assertPushable`.
- **Done when**: no CLI accepts `--test`, the four tests and `npm test` are green, and the scratch CLI run has been read.
