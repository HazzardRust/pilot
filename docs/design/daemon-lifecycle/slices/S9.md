## Tests

1. `the runbook names every heading and command`: `## When the deck misbehaves` → each subsection heading present and each command in a code span.
2. `every command it names is a pilot verb`: `## When the deck misbehaves` → each `pilot <verb>` is one `bin/pilot.mjs` dispatches.

Rewrite check: rewording the prose under each heading keeps both results above.

## Done

- **Expected**: a user whose deck misbehaves finds where it logs and the command for each failure in one place.
- **Verification**: `node --test scripts/test/operating-runbook.test.mjs deck/test/doctor.test.mjs`; `npm test`;
  run each command the section names once.
- **Evidence**: test red before, green after; each command's output read.
- **Prohibited**: no command the CLI does not have; no edit to docs/INSTALL.md (S7's).
- **Done when**: both tests pass, every named command has run and the gate is green.

Live-verification rule (co-pilot, after the S7 incident): `pilot uninstall`, `removeCommand` and the deck-stopping paths are verified only against `--prefix <scratch>`, a scratch dir and a scratch deck; never the user's install or the live port. Set the scratch env inside one script that refuses to run unless `os.homedir()`, the npm prefix and the deck dir are under a temp dir and the port is not 4321. `pilot gc` acts on the whole machine's process table: never run it in a verification.
