# S7 pilot uninstall plans, then removes the command, launcher and PATH block

Feature `daemon-lifecycle` · delivers spec 12 · source: `../architecture.md` §2, §3 Findings, §6 A4 · after: S5 (bin/pilot.mjs)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it deletes files in the user's home and stops a process (the security trigger), and A4 is assumed.

## Files owned

- `scripts/uninstall.mjs` (new): plan, apply, `main`.
- `scripts/install-command.mjs`: `removeCommand`, guarded by today's `decide()`.
- `scripts/install-path.mjs`: `removeProfileBlock`, between the `# >>> pilot >>>` markers only.
- `bin/pilot.mjs`: the `uninstall` verb and its usage line.
- `docs/INSTALL.md`: an "Uninstalling" section after "Running this again".
- `scripts/test/uninstall.test.mjs` (new): the pins.

```
export function planUninstall(home: string, deps?: { prefix?, platform?, shell?, deckPid?: () => Promise<number | null> }): Promise<Step[]>
export function applyPlan(steps: Step[], deps?: { stopDeck?, removeCommand?, removeProfileBlock? }): string[]  // one line per step
export function main(argv: string[]): Promise<number>
  // no flag: print the plan, exit 0, change nothing; --yes: apply, print each line, then the left list,
  // then "last: claude plugin uninstall pilot@pilot"; any other argument: usage, exit 1
// scripts/install-command.mjs
export function removeCommand(options?: { prefix?, home?, run? }): { removed: string[], left?: string }  // left: not ours
// scripts/install-path.mjs
export function removeProfileBlock(file: string): boolean   // true when a marked block was cut
```

## Tests

1. `the plan changes nothing`: `main` → no flag prints remove and leave lines; the scratch home is byte-identical.
2. `--yes removes the command and launcher`: `applyPlan` → `command/` and the global link gone in a scratch prefix.
3. `another package's pilot is left and named`: `removeCommand` → a foreign `pilot` stays; `left` names it.
4. `the profile block goes and nothing else`: `removeProfileBlock` → the marked block cut; lines around it identical.
5. `the store, audits, Windows PATH and excerpt are left and named`: `main` → each in the left list; the files still there.
6. `it ends naming the plugin uninstall`: `main` → last line `claude plugin uninstall pilot@pilot`.

Rewrite check: replacing the npm uninstall with direct unlinks keeps every result above.

## Done

- **Expected**: a user runs `pilot uninstall`, reads what will go and stay, runs it with `--yes`, and is told the
  one command left.
- **Verification**: `node --test scripts/test/uninstall.test.mjs scripts/test/install.test.mjs`; `npm test`; with
  `HOME`/`USERPROFILE` pointed at a scratch home, `node bin/pilot.mjs uninstall` then `--yes`.
- **Evidence**: tests red before, green after; both outputs read; the scratch home listed after.
- **Prohibited**: never the real home in a test; no recursive delete outside `~/.claude/pilot/command`; no
  Windows registry write; no removal without `--yes`.
- **Done when**: the six tests pass, the gate is green and the scratch run has been read.

Live-verification rule (co-pilot, after the S7 incident): `pilot uninstall`, `removeCommand` and the deck-stopping paths are verified only against `--prefix <scratch>`, a scratch dir and a scratch deck; never the user's install or the live port. Set the scratch env inside one script that refuses to run unless `os.homedir()`, the npm prefix and the deck dir are under a temp dir and the port is not 4321. `pilot gc` acts on the whole machine's process table: never run it in a verification.
