# S5 A scratch deck starts over a stale registry file left by a reused pid

Feature `cheaper-crew` · delivers spec 10 (added) · source: integration of S3 (2026-10-14), `deck/scratch.mjs:119` · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a process start and a file in the shared temp directory hit the security trigger (A2).

## Files owned

- `deck/scratch.mjs`: `launch` survives a stale `pilot-scratch-<pid>.json` whose pid is the daemon it just started.
- `deck/test/scratch-seed.test.mjs` or a new `deck/test/scratch-registry.test.mjs`: the pin.

## Found

`pilot integrate slice/cheaper-crew-s3` went red once on `the seeded run is listed`:
`EEXIST: file already exists, open '%TEMP%\pilot-scratch-12036.json'` at `launch (deck/scratch.mjs:119)`. The file was
dated a day earlier: a registry left behind by a dead scratch deck whose pid Windows reused. Ten such files sit in
`%TEMP%` today. The `wx` flag is deliberate (never write through a file another local user planted), so the fix must
keep it.

## Interface

```
launch(): on EEXIST for registryFile(daemon.pid), the file names a pid our own just-started daemon now holds, so it is
stale: remove that path itself (never a link's target) and write it again with `wx` and 0o600; any other error, or a
second EEXIST, keeps today's behaviour (end the daemon, throw).
```

## Tests

1. `a stale registry for the new daemon's pid does not stop the start`: `launch` → the start succeeds and the registry file holds the new port.
2. `the registry is still written with wx and 0o600`: `launch` → the existing pins stay green.

Rewrite check: if the stale file were handled another way, both results above still hold.

## Done

- **Expected**: a scratch deck starts though a stale registry file holds its pid's name.
- **Verification**: `node --test deck/test/scratch-seed.test.mjs` and the new test; `npm test`.
- **Prohibited**: no sweep or deletion of other pids' registry files; no change to `--stop`'s ownership rule (L7 of that feature).
- **Done when**: test 1 failed before the change and passes after; `npm test` green.
