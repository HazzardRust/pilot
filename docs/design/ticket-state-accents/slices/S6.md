# S6 Continue ticket requests a switch

Feature `ticket-state-accents` · delivers spec 11, 12 (the record and the reply), 15 (pending) · source: `../architecture.md` §4 (Switch), L9, L13, L20 · after: S5

Diff limit: 300 lines. Past it, stop and ask `main`.

## Files owned

- `deck/store.mjs`: `requestSwitch(repo, to)` writes the record and a user reply on `to` carrying `switch`, in one write. It refuses a `to` that is closed, yellow, already in hand, or from another repository, and refuses when a switch is already pending.
- `deck/server.mjs`: `POST /switch`, behind `fromOwnPage` as `/move` is. It announces, then 303s to `back`.
- `deck/ui/render.mjs`: `renderTicketRow` draws Continue with its confirm step on every open red or green row not in hand, as `data-switch="idle"`. The pending row's button is `data-switch="pending"` and reads "switching…".
- `deck/ui/deck.css`: the lit `pending` button.
- `deck/ui/js/confirm.mjs`: the Continue form joins the shared confirm step.
- `deck/test/switch-request.test.mjs` (new): the pins.

## Interface

```
requestSwitch(repo: string, to: string): Switch          // DeckRefusal on the cases above
POST /switch   form { repo, to, back } -> 303 back | 403 off-page | 400 refusal
Reply.switch?: { from: string | null, to: string }      // on the user reply stored on `to`
S5's Switch, deckLanes, Tab.switching
```

## Tests

1. `Continue is drawn on red and green rows not in hand, never on yellow or the in-hand row`.

5. `a yellow, closed or in-hand to is refused`.
6. `POST /switch from another origin is a 403`.
7. `the pending row's button is lit and the in-hand row is unchanged`.
