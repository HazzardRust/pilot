# S1 Add sits on the Tickets panel's title row (walking skeleton)

Feature `tickets-add-button` · delivers spec 1, 2, 3, 4 · source: `../architecture.md` §2, §3, L1–L5, A1 · after: –
Reviewers: `pilot:typescript-reviewer`

## Files owned

- `deck/ui/deck.css`: the Tickets panel's title-row grid. The dead `.panel > form.make-tickets` rule is replaced.
- `deck/test/make-tickets.test.mjs`: the layout pins.

## Interface

```
#tickets > .panel                          { display: grid; grid-template-columns: 1fr auto; align-items: baseline }
#tickets .tickets-state                      { display: contents }   // markup and deck-state L5 unchanged
.tickets-state > form.make-tickets           // row 1, column 2, beside .panel::before; carries the 0.6rem gap
.tickets-state > :not(form.make-tickets)     { grid-column: 1 / -1 } // queues or "no tickets", full width below
renderMakeTickets(repo): string            // unchanged; its form stays the first child of .tickets-state
```

## Tests

1. `the Add button shares the panel title's row`: `#tickets > .panel` → `deck.css` holds a grid rule with the two columns `1fr auto` and `align-items: baseline`, plus `#tickets .tickets-state` set to `display: contents`.
2. `what follows Add spans the row below`: `.tickets-state > :not(form.make-tickets)` → `grid-column: 1 / -1` in `deck.css`.
3. `Add is the first thing in the tickets state, so it lands beside the title`: `renderMakeTickets` → the Tickets region opens `<div class="tickets-state" …><form method="post" action="/create" class="make-tickets"`, with tickets queued and with none.
4. `no dead make-tickets rule`: `.tickets-state > form.make-tickets` → `deck.css` has no `.panel > form.make-tickets`.

Rewrite check: if flexbox or another layout replaced the grid, then on a scratch deck Add would still sit at the right of "TICKETS" on one row at 12rem and at the default width, and pressing it would still open a thread titled `Add`.

## Done
