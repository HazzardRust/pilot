## Interface

```
REPORT_HEADINGS: ['Goals', 'Your level', 'Dot points', 'Background', 'Research while planning', 'The decision to come back to']
reportProblems(markdown: string): { rule: string, message: string }[]
  // rules: 'heading', 'dot-points' (< 3), 'goal-check' (goal without "checked by"),
  //        'local-link' (link target not http/https), 'credential' (findCredential), 'size' (> 60000 bytes)
writeLessonReport(id: string, markdown: string, { store?: string }): string   // the written path
  // throws on a bad id (not /^itm_[0-9a-f]{12}$/) or any problem; writes nothing then
pilot lesson-report <lesson id>   // md on stdin; prints the path; exit 1 naming each problem
agents/pilot-teacher.md: ## Small or large, ## The report
```

## Behaviours

1. `a whole report passes and lands in the store` (test): `writeLessonReport` → `<store>/lessons/<id>.md` with the bytes given.
2. `a report without its research section is refused` (test): `reportProblems` → one 'heading' problem naming Research while planning.
3. `each shape rule refuses its case` (test): `reportProblems` → one problem per rule for dot-points, goal-check, local-link, credential, size.
4. `a bad id writes nothing` (test): `writeLessonReport` → throws for `../x` and `itm_1`, 0 files in the store.
5. `the verb pipes stdin and prints the path` (test): `pilot lesson-report <lesson id>` → exit 0 and the path; exit 1 and the rule on a bad report.
6. `the teacher calls small or large after the diagnostic` (read): the definition's `## Small or large` names the bar, `report`/`here`, and the resolution naming the path.
7. `a forced report ends the lesson off the deck` (look): at the walkthrough, `report` → lesson resolved with the path, 0 steps.

Rewrite check: replacing the line scan with a markdown parser keeps results 1-5.
Misses: whether Sonnet judges "large" well; QA's walkthrough and the user read that.
