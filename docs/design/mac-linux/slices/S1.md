# S1 The gate runs on three OSes on a labelled PR (walking skeleton)

Feature `mac-linux` · delivers spec 1 · source: `../architecture.md` §2, §5 L7, L10 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the triggers (L10) carry a visibility condition no run here has exercised, and a workflow is a process start on GitHub's runners.

## Files owned

- `.github/workflows/gate.yml`: an `os` matrix and L10's triggers and job condition, on top of main-never-red's job.
- `scripts/test/gate-workflow.test.mjs`: the pins move with the file.

## Interface

```
on: pull_request (branches [main]; opened, synchronize, reopened, ready_for_review, labeled)
    push (branches [main]) · schedule (weekly cron) · workflow_dispatch
jobs.gate.strategy: { fail-fast: false, matrix.os: [ubuntu-latest, macos-latest, windows-latest] }
jobs.gate.runs-on: ${{ matrix.os }}
// ubuntu: push, or a non-draft PR (main-never-red L8 unchanged)
// macos and windows: every PR when the repository is public; while private: schedule, workflow_dispatch, or a PR labelled `all-os` (drafts included)
permissions: { contents: read }   // ADR 0156 L4; no secret, no pull_request_target
```

## Tests

1. `the gate job runs on three OSes without failing fast`: `jobs.gate.strategy` → the matrix lists the 3 OSes, and `fail-fast` is false.
2. `macos and windows run on every PR when public, else only on the label, the schedule or a dispatch`: the job `if` admits macos and windows when `github.event.repository.private == false`, on `all-os`, `schedule` and `workflow_dispatch`, and on nothing else.
3. `ubuntu keeps main-never-red's triggers`: `on` → a non-draft PR and a push to main admit ubuntu, and a draft without the label does not.
4. `no job gains a write permission or a secret`: `permissions` → `contents: read` only, and the file names no `secrets.`.

Rewrite check: rewriting the job `if` as a separate job per OS keeps every result above.

## Done

- **Expected**: on this private repository, labelling a PR to main `all-os` starts 3 gate jobs, while an unlabelled PR starts ubuntu only; the pinned condition admits every PR once the repository is public.
- **Verification**: `node --test scripts/test/gate-workflow.test.mjs`; `npm test`.
- **Evidence**: the pins red before and green after. The first labelled run of the feature PR (QA) shows the 3 jobs and the macOS minutes.
- **Prohibited**: no `pull_request_target`; no second workflow file; no `continue-on-error` to hide a red OS.
- **Done when**: the pins pass and the gate is green.

## Seam change (co-pilot)

- **A3. The gate also runs on PRs to `feat/**`.** `pull_request.branches` is `[main, 'feat/**']`; `push` stays `[main]`. Without it a slice PR into `feat/mac-linux` starts no job, labelled or not, and `workflow_dispatch` cannot reach a file not on main, so the first three-OS evidence would wait for QA. Slice PRs are drafts, so an unlabelled one starts nothing, which a pin holds. Every clause of spec 1 still holds. Assumed by the co-pilot; default taken from S1's implementer.
