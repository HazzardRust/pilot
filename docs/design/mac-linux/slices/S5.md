# S5 claude resolves from absolute PATH entries on POSIX

Feature `mac-linux` · delivers spec 2, 9 · source: `../architecture.md` §2, §3 F6 · after: S4 (`hooks/lib/platform.js`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a binary lookup on the process-start path is the security trigger.

## Files owned

- `hooks/lib/platform.js`: adds `claudeBin`.
- `hooks/test/platform-claude.test.js` (new): the planted-binary pins.
- `deck/run.mjs`: the `CLAUDE` constant goes; `run()` resolves through `claudeBin` (101, 659).
- `scripts/pilot-branch.mjs`: `onSearchPath` walks absolute entries on POSIX too (60), keeping only executable files.

## Interface

```
claudeBin(env?: NodeJS.ProcessEnv, platform?: string): string | null
  // 'claude.exe' on win32, 'claude' elsewhere, looked up by onSearchPath: an absolute file or null
onSearchPath(name: string, env?: NodeJS.ProcessEnv, platform?: string): string | null
  // POSIX: absolute PATH entries only, an executable regular file; win32 unchanged
```

## Tests

1. `a claude planted in the repository is not run`: `claudeBin` → with `PATH=.:<tmp>/bin` and the cwd holding `claude`, the `<tmp>/bin/claude` path.
2. `no absolute hit is null`: `claudeBin` → null when only `.` has it.
3. `a non-executable file is skipped`: `onSearchPath` → null for a 0644 `claude` (skipped on win32).
4. `windows names claude.exe`: `claudeBin` → the absolute `claude.exe` under a fake win32 env.

Rewrite check: replacing the PATH walk with `which -a` filtered to absolute paths keeps every result above.
