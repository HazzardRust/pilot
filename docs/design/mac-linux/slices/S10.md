# S10 The 500-log test holds under load (added)

Feature `mac-linux` · delivers spec 10 (added: every `pilot integrate` of this run is green on a green tree) · source: co-pilot, found issue · after: –
Reviewers: `pilot:typescript-reviewer`
Model: opus — a flake under load needs a diagnosis before a fix, and the fix may sit in the daemon, not the test.

## Why

`deck/test/daemon-lifecycle.test.mjs:110` "a 500 writes the same one line, then its stack, and the deck serves on" fails `one line per 500` with `2 !== 1` in about half of this run's full-suite integrates (logs under `~/.claude/pilot/logs/`, e.g. `20261018T052902168Z-slice-mac-linux-s8.log`), and passes 5 of 5 alone. Each red costs a 5-minute integrate rerun.

## Interface

Unchanged. The daemon's contract stays: one `[deck] 500 <METHOD> <path>: <message>` line per failed request, then its stack.

## Work

1. Find why a single `GET /` under load leaves two `[deck] 500 ` lines: a second request (the harness's `healthAt` poll, a daemon timer, a retry) hitting the corrupt `deck.json`, or one request logged twice. One probe per hypothesis.
2. If the daemon logs one request twice, fix the daemon. If a second request legitimately 500s, make the test count the lines for `GET /` only, or stop the competing reader for the corrupt window; never loosen the assertion to `>= 1`.

## Verification

- A test that reproduces the second line deterministically (an injected second reader, or a forced timer tick) fails before and passes after.
- `node --test deck/test/daemon-lifecycle.test.mjs` 10 runs in a row with `npm test` of another worktree running alongside: 0 fails.

## Files owned

`deck/test/daemon-lifecycle.test.mjs`, and the logging line of `deck/daemon.mjs` only if the daemon is at fault.
