# S8 A Mac install writes the login profile and the TCC note

Feature `mac-linux` · delivers spec 4, 7 · source: `../architecture.md` §2, §3 F7, §5 L5 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the install writes the user's shell profile, and the TCC wording rests on an unverified Apple fact.

## Files owned

- `scripts/install-path.mjs`: `profileFor` takes `platform`; darwin bash picks the login file (L5).
- `scripts/install-command.mjs`: `describe()` pushes the TCC note on darwin.
- `scripts/test/install-path.test.mjs`: darwin cases beside the linux `posix` helper.
- `scripts/test/install-command.test.mjs`: the darwin notes pin.
- `scripts/test/install.test.mjs`: the README and INSTALL.md wording pins.
- `README.md`: Install names the CI OSes and carries the TCC note, with no new fence.
- `docs/INSTALL.md`: the changes-table row names the darwin files; step 4 carries the TCC note.

## Interface

```
profileFor(shell: string, home: string, platform?: string): string | null
  // darwin bash: first existing of .bash_profile, .bash_login, .profile, else .bash_profile
persistPath(dir: string, options?: { platform?, env?, home?, dryRun?, registry? }): PathResult
describe(result, { onPath, windows, darwin }): string[]   // darwin adds the TCC note
TCC note: "macOS asks before a terminal reads ~/Desktop, ~/Documents, ~/Downloads or iCloud Drive: keep repositories elsewhere, or give your terminal Full Disk Access in System Settings > Privacy & Security."
```

## Tests

1. `darwin bash writes .bash_profile when no login file exists`: `profileFor` → `~/.bash_profile`.
2. `darwin bash keeps an existing .profile`: `profileFor` → `~/.profile` when only it exists, and `~/.bash_login` before it.
3. `darwin zsh and linux are unchanged`: `profileFor` → `.zshrc` on darwin, and `.bashrc` and `.zshrc` on linux.
4. `a Mac install prints the TCC note`: `describe` → the notes include the TCC sentence on darwin and not on linux or win32.
5. `README and INSTALL carry the note`: `TCC note` → both match `/Full Disk Access/` and README Install still has exactly two fences.

Rewrite check: replacing the existence probe with a `bash -lc` probe keeps every result above.

## Done

- **Expected**: a Mac bash user who installs opens a new Terminal and `pilot` is found, and is told about TCC.
- **Verification**: `node --test scripts/test/install-path.test.mjs scripts/test/install-command.test.mjs scripts/test/install.test.mjs`; `npm test`.
- **Evidence**: tests 1, 2 and 4 red before and green after. Before committing the wording, check it against Apple's "Control access to files and folders on Mac" page.
- **Prohibited**: no write to more than one profile; no new README fence; no linux behaviour change.
- **Done when**: the pins pass and `check-references` exits 0.
