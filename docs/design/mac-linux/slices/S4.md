Feature `mac-linux` · delivers spec 2, 3 · source: `../architecture.md` §2, §3 F4, §5 L4 · after: S3 (`hooks/lib/platform.js`)

## Interface

```
killTree(pid: number, opts?: { platform?: string, group?: boolean,
  table?: ProcessRow[], exec?: typeof execFileSync, signal?: typeof process.kill }): void
  // win32: exec('taskkill', ['/PID', pid, '/T', '/F']); POSIX + group: signal(-pid, 'SIGKILL');
  // POSIX: descendants of pid in table deepest first, then pid; ESRCH swallowed, other errors thrown
landingSpawnOptions(platform?: string): SpawnOptions   // detached off win32
S3's isWindows
```

## Tests

1. `a detached tree is gone after a group kill`: `killTree` → a detached `sh` and its two `sleep`s answer ESRCH to `kill(pid, 0)` (skipped on win32).
2. `a tree is gone by its descendants without a group`: `killTree` → with a `table` from `processTable`, the same three pids are gone (skipped on win32).
3. `a gone pid is not an error`: `killTree` → no throw for a pid that has exited.
4. `windows runs taskkill over the tree`: `killTree` → a fake `exec` receives `taskkill /PID <pid> /T /F`.
5. `landing spawns a group leader off Windows`: `landingSpawnOptions` → `detached` false on win32, true on darwin and linux.

Rewrite check: replacing the descendants walk with a `pgrep -P` walk keeps every result above.
