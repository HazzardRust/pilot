## Files owned

- `scripts/reach.mjs`: `NOT_CHOSEN` reads `nothing` (A1); everything else unchanged.
- `scripts/test/reach.test.mjs`: the pins for the default.
- `scripts/install-settings.mjs`: `repairSettings` removes the plugin's own user settings once (through `removeOwnSettings`) when the reach is below `everything` and they are still there; today it only skips repairing them (:603).

## Interface

```
readReach({ home }) -> { level: 'nothing' | 'rules' | 'everything', chosen: boolean }
// no reach.json -> { level: 'nothing', chosen: false }
repairSettings({ home, pluginRoot }) -> result   // below `everything`: strips the plugin's own user settings if present
```

## Behaviours

1. `no reach file reads nothing` (test): `readReach` → an empty temp home returns `{ level: 'nothing', chosen: false }`; a written `everything` still reads `everything`.
2. `an old install is cleaned once` (test): `repairSettings` → with a temp home whose user settings carry the plugin and no reach file, the repair path leaves `enabledPlugins["pilot@pilot"]` unset and the status lines gone; a second run changes 0 bytes.
3. `pilot sessions keep everything` (run): `node --test deck/test/pilot-start.test.mjs deck/test/start-session.test.mjs` passes unedited.
4. `a plain session is plain` (look): in QA's config (§9) after the update, a plain `claude` shows no deck, no pilot status line, and its `--first-turn` row has 0 pilot sections; a `pilot start` crew agent still lists the deck tools.

Rewrite check: any reach store whose absent state means no plugin in user settings passes 1 and 2.
Misses: a user who wanted pilot everywhere; `pilot reach everything` restores it, and the A1 answer decides the default.
