# S2 Each prompt section of both starts is listed and a trim is measured

Feature `handoff-cache` · delivers spec 2, 5 · source: `../architecture.md` §2, §3, §5 L3, §6 A5 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: opus — a probe of an undocumented mod hook, whose reading is a judgement.

## Files owned

- `docs/design/handoff-cache/probes/sections/` (new): a scratch plugin whose mod logs every `prompt.section` (name, bytes, sha256) and, with `TRIM=<names>`, returns `text: null` for those; and `run.mjs`, which starts the scratch sessions.
- `docs/design/handoff-cache/probes/sections.md` (new): the section table and the trim rows.

## Interface

```
probes/sections/mod.mjs: register(on)   // logs prompt.section {name, bytes, sha256}; TRIM env removes named sections
probes/sections/run.mjs: node run.mjs --start cold|after-clear [--trim <a,b>] --model sonnet -> JSON lines on stdout
```

## Behaviours

1. `both starts are listed section by section` (run): `node probes/sections/run.mjs --start cold` and `--start after-clear`, each with `--plugin-dir` for the pilot plugin and the probe; `sections.md` gets 1 row per section with bytes and hash in each start, and 0 sections unaccounted for against the first turn's input tokens (within 5%).
2. `the parts that differ are named` (read): `sections.md` marks each row same or differs, naming the cause of every difference (a date, a git status, a hook's text).
3. `a trim is measured` (run): for each pilot-session section the probe can remove, the start's tokens with and without (from `turn.complete` usage and `claude plugin details pilot@pilot`), and whether a pilot first turn still runs `deck_status`, 3 of 3.
4. `the verdict is written` (read): `sections.md` ends with `verdict: trim <names>, saves <n> tokens` or `verdict: ruled out, <number>`, against the 1,000-token bar.

Rewrite check: not applicable, a probe ships no interface; its table must read the same if rerun by hand.
Misses: interactive sessions may carry sections a headless one lacks (A5); QA's walkthrough reads one interactive start.

## Done

- **Expected**: the user can read which parts of a pilot session's start differ between a cold start and a hand-off, and what trimming each would save.
- **Verification**: the three runs above; `claude plugin validate docs/design/handoff-cache/probes/sections`.
- **Evidence**: the run output pasted in `sections.md` with the version of `claude` and the date.
- **Prohibited**: no run in the user's live session; no change under `hooks/`; no `--model` other than sonnet except for the 3 first-turn checks; no section text (only names, sizes, hashes) in the file.
- **Done when**: `sections.md` holds the full table and a verdict line, and validate passes.
