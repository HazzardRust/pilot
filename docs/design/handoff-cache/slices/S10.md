# S10 `pilot update` updates from the terminal

Feature `handoff-cache` · delivers spec 11, 12 · source: `../architecture.md` §2, §3, §5 L6 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a new CLI verb that starts processes, the security trigger.

## Files owned

- `scripts/update.mjs` (new): reads the installed version, refuses on a live run, runs `claude plugin marketplace update pilot` then `claude plugin update pilot@pilot`, reads the version again.
- `scripts/test/update.test.mjs` (new): the pins, with an injected runner.
- `bin/pilot.mjs`: the `update` verb and its usage line.

## Interface

```
update({ run, home, deckLive }) -> { before: string, after: string, changed: boolean, refused?: 'live run' }
// run(argv: string[]) -> Promise<{ exitCode: number, stdout: string, stderr: string }>, no shell
CLI: pilot update   // prints `pilot <before> -> <after>` or `pilot <v> is up to date`; exit 0, or 1 on a refusal or a failed call
```

## Behaviours

1. `an update prints both versions` (test): `update` → a runner whose second version read is newer returns `changed: true`; the CLI prints `pilot 0.9.9 -> 0.9.10`, exit 0.
2. `nothing to update says so` (test): `update` → same version before and after: `pilot 0.9.9 is up to date`, exit 0.
3. `a live run refuses` (test): `update` → `deckLive` true: `refused: 'live run'`, exit 1, 0 calls to `run`.
4. `a failed call is said` (test): `update` → the runner exits 1 on `plugin update`: its stderr line printed, exit 1.
5. `it runs for real` (run): `node bin/pilot.mjs update` in QA's config (§9: a temp config dir by default) prints one of the lines above.

Rewrite check: any updater that reads the version around the CLI calls and refuses on a live run passes 1-4.
Misses: a marketplace that serves a broken build; the next `pilot start` shows it.

## Done

- **Expected**: the user updates pilot from the terminal without opening Claude Code.
- **Verification**: `node --test scripts/test/update.test.mjs`; behaviour 5; `npm test`.
- **Evidence**: tests 1-4 failing before and passing after; the printed line from 5.
- **Prohibited**: no `shell: true`; no downloading or copying into the plugin cache; no update while a run is live.
- **Done when**: the tests pass, the real run prints a version line, and the gate is green.
