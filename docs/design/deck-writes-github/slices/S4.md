# S4 `pilot integrate --dir`

Feature `deck-writes-github` · delivers spec 5 · source: `../architecture.md` §2, A3 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument on a pushing verb, the security trigger.

## Files owned

- `scripts/integrate.mjs`: `main` takes `--dir <worktree>` anywhere in argv and runs there.
- `scripts/test/integrate-dir.test.mjs` (new): the pins.

## Interface

```
pilot integrate [<slice-branch>] [--trial|--no-push] [--trailer "<line>"]... [--dir <worktree>]
main(argv, inject?) -> number   // --dir resolves before integrate(); a missing or non-directory path exits 2
```

## Tests

1. `--dir runs the integration in that worktree`: `main` → integrate's cwd is the named worktree, from a cwd elsewhere.
2. `--dir with no directory is a usage error`: `main` → exit 2, `pilot integrate: --dir <path> is not a directory`, nothing run.
3. `--dir after the branch parses the same`: `main` → the same options as before the branch.

Rewrite check: passing the directory as `cwd` instead of a chdir keeps all three results.

## Done

- **Expected**: the pilot or QA runs `pilot integrate <branch> --dir <worktree>` as one command, and the existing
  `Bash(pilot integrate *)` rule matches it.
- **Verification**: `node --test scripts/test/integrate-dir.test.mjs`; `npm test` once.
- **Evidence**: test 1 red before (`--dir` a usage error), green after.
- **Prohibited**: a global allow rule; a shell; changing `pilot --dir`'s global form.
- **Done when**: three tests and the gate are green and `pilot help` shows `--dir`.
