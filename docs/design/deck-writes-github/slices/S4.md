# S4 `pilot integrate --dir`

Feature `deck-writes-github` · delivers spec 5 · source: `../architecture.md` §2, A3 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument on a pushing verb, the security trigger.

## Files owned

- `scripts/integrate.mjs`: `main` (:548) takes `--dir <worktree>` anywhere in argv, beside a branch or `--trial`, and runs there.
- `scripts/test/integrate-dir.test.mjs` (new): the pins.

## Interface

```
pilot integrate [<slice-branch>] [--no-push] [--trailer "<line>"]... [--dir <worktree>]
pilot integrate --trial [--dir <worktree>]
main(argv, inject?) -> number   // --dir resolves before integrate(); a missing or non-directory path exits 1
```

## Tests

1. `--dir runs the integration in that worktree`: `main` → integrate's cwd is the named worktree, from a cwd elsewhere.
2. `--dir with no directory is a usage error`: `main` → exit 1, `pilot integrate: --dir <path> is not a directory`, nothing run.
3. `--dir after the branch parses the same`: `main` → the same options as before the branch.
4. `--trial takes --dir and nothing else`: `main` → `--trial --dir <wt>` runs the trial there; `--trial --no-push` still exits 1.

Rewrite check: passing the directory as `cwd` instead of a chdir keeps all four results.
Misses: Claude Code's permission matcher itself; that `Bash(pilot integrate *)` admits the command is read in the live run.

## Done

- **Expected**: the pilot or QA runs `pilot integrate <branch> --dir <worktree>` as one command, and the existing
  `Bash(pilot integrate *)` rule matches it.
- **Verification**: `node --test scripts/test/integrate-dir.test.mjs`; `npm test` once.
- **Evidence**: test 1 red before (`--dir` a usage error today, :560-561), green after.
- **Prohibited**: a global allow rule; a shell; changing `pilot --dir`'s global form (`bin/pilot.mjs:208`).
- **Done when**: four tests and the gate are green and `pilot help` shows `--dir`.
