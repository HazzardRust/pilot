# S3 QA's comment rides on its posts

Feature `deck-writes-github` · delivers spec 3 · source: `../architecture.md` §2, §5 L3, L6, A2 · after: S1 (`syncFeaturePr`), S2 (`server-tools.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — user text to a public PR, the security trigger.

## Files owned

- `deck/items.mjs`: `comment` allowed on walkthrough and gate2, bounded.
- `deck/tools.mjs`: `comment` on the `deck_post` schema.
- `deck/runs.mjs`: `qaComment` in `RECORD_ORDER`.
- `deck/store-runs.mjs`: set `qaComment` on the ticket's record.
- `deck/server-tools.mjs`: copy `comment` to the record, then `deps.prWrite`.
- `scripts/feature-pr.mjs`: upsert the marked comment from `record.qaComment`.
- `deck/test/qa-comment.test.mjs` (new), `scripts/test/feature-pr-comment.test.mjs` (new): the pins.

## Interface

```
deck_post { kind: 'walkthrough' | 'gate2', comment?: string }   // ≤ 20000 chars, refuseCredentials
Record.qaComment?: string                                       // the newest comment for the ticket
QA_MARKER = '<!-- pilot:qa -->'
S1's syncFeaturePr: also upserts the one comment carrying QA_MARKER when record.qaComment is set
```

## Tests

1. `a walkthrough comment lands in the record`: `deck_post` → the ticket's record `qaComment` equals it, one `prWrite`.
2. `a gate2 comment replaces it`: `deck_post` → the newer text in `qaComment`.
3. `a credential in comment is refused`: `deck_post` → DeckRefusal, nothing stored.
4. `first text posts one comment`: `QA_MARKER` → 1 `gh pr comment <n> --body-file`, the body starting with it.
5. `changed text edits it once`: `QA_MARKER` → 1 PATCH of the marked comment's id; 0 writes for the same text.

Rewrite check: storing the comment elsewhere than the record keeps tests 1, 2, 4 and 5.
