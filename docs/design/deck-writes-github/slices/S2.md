# S2 The deck runs `pilot pr` on gate1 and every status

Feature `deck-writes-github` · delivers spec 2, 7 · source: `../architecture.md` §2, §5 L1, L4, L5 · after: S1 (`pilot pr` argv)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Interface

```
startPrWrite(ticketId: string, repo: string, deps?: { spawn, env, clock, note }) -> void
  // spawns process.execPath [PILOT_BIN, 'pr', '--ticket', ticketId] in repo, no shell,
  // env carries the deck's PILOT_DECK_PORT and PILOT_DECK_DIR; one in flight per ticket, one rerun queued
callTool(name, args, deps?: { prWrite?, ...landingDeps }) -> result
  // deck_post gate1 and deck_status of a ticket with a gate1 call deps.prWrite(ticket, repo)
```

## Tests

1. `a gate1 post spawns one pilot pr`: `callTool` → 1 spawn, argv `[PILOT_BIN, 'pr', '--ticket', <id>]`, cwd the repo, `shell: false`.
2. `three statuses during a write coalesce`: `startPrWrite` → 2 spawns in total, the second after the first exits.
3. `a status for a ticket with no gate1 spawns nothing`: `callTool` → 0 spawns; with `PILOT_DECK_NO_LAND` set, 0 spawns either way.
4. `a failure notes one line`: `startPrWrite` → the ticket thread gains `feature PR not updated: <line>` once for two identical failures.
5. `a credential in the line is withheld`: `startPrWrite` → the note names the step, not the token.
6. `an opened PR is named on the ticket`: `startPrWrite` → the ticket thread gains `feature PR #<n> opened`.

Rewrite check: replacing the spawn with an in-process call behind `startPrWrite` keeps every count and note above.
