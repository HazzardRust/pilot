# S1 `pilot pr` writes the feature PR from the record

Feature `deck-writes-github` · delivers spec 2 · source: `../architecture.md` §2, §5 L1–L3, L7 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument and a GitHub write, the security trigger.

## Files owned

- `deck/host.mjs` (new): the one `gh` process start and its verb table (spec 8; S8 moves the old runners onto it).
- `scripts/feature-pr.mjs` (new): render the body; find, open or edit the feature PR through an injected `hostIn`.
- `bin/pilot.mjs`: dispatch `pr` and one help entry.
- `scripts/test/feature-pr.test.mjs` (new): the pins, over a fake `gh` and a git fixture.

## Interface

```
HOST_VERBS: pr create|edit|comment|ready|view|close|list; api user (GET); api PATCH|POST (issue comments)
hostIn(cwd) -> (args: string[]) => string   // execFileSync('gh', args), no shell; throws on a verb outside HOST_VERBS
pilot pr --ticket <itm_id>          // exit 0 written, skipped or nothing to do; 1 a failure, one line
featureBody(spec: string, record: Record, footer?: string) -> string   // §2 text, slice | state | PR table, footer
syncFeaturePr({ gh, git, record }) -> { line: string, number?: number, wrote: 'created' | 'edited' | 'none' }
main(argv, inject?: { gh, git, readRecord }) -> number
// lines: `feature PR #<n> opened` | `feature PR #<n> updated` | `feature PR #<n> unchanged`
//        `no PR yet: origin has no feat/<slug>` | `no PR: run remote <name>`
```

## Tests

1. `the first run opens one draft PR against pilot`: `syncFeaturePr` → 1 `gh pr create --draft --base pilot --head feat/<slug>`, title `feat(<slug>): <feature>`, line `feature PR #<n> opened`.
2. `a changed row edits the body once`: `syncFeaturePr` → 1 `gh pr edit <n> --body-file`, line `updated`.
3. `the same record writes nothing`: `syncFeaturePr` → 0 write calls, line `unchanged`.
4. `the body is the spec and the slice table`: `featureBody` → the fixture §2 verbatim, one table row per slice, the brief's PR footer last.
5. `no branch on origin is quiet`: `syncFeaturePr` → 0 gh writes, `no PR yet: origin has no feat/<slug>`, exit 0.
6. `a run remote other than origin opens nothing`: `syncFeaturePr` → `no PR: run remote <name>`, 0 gh calls.
7. `a gh failure is one line and exit 1`: `main` → stdout one line naming the step, exit 1.
8. `a verb outside the table is refused`: `hostIn` → `pr merge` throws naming the verb, 0 processes started.

Rewrite check: replacing `gh` with the REST API behind the same seam keeps every count and line above.

## Done

- **Expected**: in a checkout whose `feat/<slug>` is pushed, `pilot pr --ticket <id>` opens or updates the draft
  feature PR with the artefact's spec and the record's slice table, and a second run changes nothing.
- **Verification**: `node --test scripts/test/feature-pr.test.mjs`; `npm run test:changed -- --since=<base>`;
  `npm test` in the background once.
- **Evidence**: tests 1–3 red before the module exists, green after; the fake `gh`'s call list in the output.
- **Prohibited**: a shell (`execFileSync` argv only); a `gh` process start outside `deck/host.mjs`; the body through argv
  (a body file); storing the PR number anywhere.
- **Done when**: all eight tests and the gate are green, and `pilot help` names `pilot pr`.
