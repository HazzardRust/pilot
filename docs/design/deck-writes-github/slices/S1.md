# S1 `pilot pr` writes the feature PR from the record

Feature `deck-writes-github` · delivers spec 2 · source: `../architecture.md` §2, §5 L1–L3, L7' · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument and a GitHub write, the security trigger.

## Files owned

- `deck/host.mjs` (new): the one `gh` process start (`execFileSync('gh', …)`, so `pilot gh-stub` intercepts) and its verb table.
- `scripts/feature-pr.mjs` (new): render the body; find, open, edit or retarget the feature PR through an injected `gh`.
- `bin/pilot.mjs`: dispatch `pr` beside `integrate` (:307) and one help entry.
- `scripts/test/feature-pr.test.mjs` (new): the pins, over a fake `gh` and a git fixture.

## Interface

```
assertHostVerb's allowlist: pr create|edit|comment|view|list; api user (GET); api PATCH (an issue comment)
hostIn(cwd) -> (args: string[]) => string   // execFileSync('gh', args), no shell; throws on a call off the allowlist
pilot pr --ticket <itm_id>          // exit 0 written, skipped or nothing to do; 1 a failure, one line
featureBody(spec: string, record: Record, footer?: string) -> string   // §2 text, slice | state | PR table, footer
syncFeaturePr({ gh, git, record }) -> { line: string, number?: number, wrote: 'created' | 'edited' | 'none' }
main(argv, inject?: { gh, git, readRecord }) -> number
// lines: `feature PR #<n> opened` | `feature PR #<n> updated` | `feature PR #<n> unchanged`
//        `no PR yet: origin has no feat/<slug>` | `no PR: run remote <name>`
```

## Tests

1. `the first run opens one draft PR against the record's base`: `syncFeaturePr` → 1 `gh pr create --draft --base <record.base> --head feat/<slug>`, title `feat(<slug>): <feature>`, line `opened`; with a PR already open for the head, 0 creates.
2. `a changed row edits the body once`: `syncFeaturePr` → 1 `gh pr edit <n> --body-file`, line `updated`.
3. `a changed base retargets once`: `syncFeaturePr` → 1 `gh pr edit <n> --base pilot` when GitHub reads `feat/<N>` and the record `pilot`.
4. `the same record writes nothing`: `syncFeaturePr` → 0 write calls, line `unchanged`.
5. `the body is the spec and the slice table`: `featureBody` → the fixture §2 verbatim, one table row per slice, the brief's PR footer last.
6. `no branch on origin is quiet`: `syncFeaturePr` → 0 gh writes, `no PR yet: origin has no feat/<slug>`, exit 0.
7. `a run remote other than origin opens nothing`: `syncFeaturePr` → `no PR: run remote <name>`, 0 gh calls.
8. `a gh failure is one line and exit 1`: `main` → stdout one line naming the step, exit 1.
9. `a verb outside the table is refused`: `hostIn` → `pr merge` throws naming the verb, 0 processes started.

Rewrite check: replacing `gh` with the REST API behind the same seam keeps every count and line above.
Misses: GitHub's own rendering of the body and a real `gh` auth failure's wording; the live run under L9 covers them.

## Done

- **Expected**: in a checkout whose `feat/<slug>` is pushed, `pilot pr --ticket <id>` opens or updates the draft
  feature PR with the artefact's spec and the record's slice table on the record's base, and a second run changes nothing.
- **Verification**: `node --test scripts/test/feature-pr.test.mjs`; `npm run test:changed -- --since=<base>`;
  `pilot pr --ticket <fixture>` under `eval "$(pilot gh-stub)"`, its `calls.jsonl` read; `npm test` once.
- **Evidence**: tests 1–4 red before the module exists, green after; the stub's call list.
- **Prohibited**: a shell (`execFileSync` argv only); a `gh` process start outside `deck/host.mjs`; the body through argv
  (a body file); storing the PR number anywhere.
- **Done when**: all nine tests and the gate are green, and `pilot help` names `pilot pr`.
