# S10 Friction rows append and survive the hand-off

Feature `yellow-lane` · delivers spec 20, 21 · source: `../architecture.md` §2, §3 Findings "Record", §5 L8, §6 A6 · after: S2 (deck/server-tools.mjs), S7 (deck/tools.mjs)
Reviewers: `pilot:typescript-reviewer`

## Files owned

- `deck/runs.mjs`: `friction` joins `RECORD_ORDER`, is validated in `recordFields` and appended in `nextRecord`, keeping the newest 40.
- `deck/tools.mjs`: the `deck_status` schema gains `friction`.
- `deck/server-tools.mjs`: `deck_status` passes `friction` through and says when rows were dropped.
- `deck/test/record-friction.test.mjs` (new): the deck pins.
- `scripts/test/handoff-friction.test.mjs` (new): the committed run.json pin.

## Interface

```
deck_status({ ..., friction?: FrictionRow[] })
FrictionRow = { agent, what, evidence, size? } | { kind: 'drain', what, size }
recordFields(args) -> validated fields      // a row of neither shape is refused
nextRecord(previous, given) -> record       // friction = previous.friction ++ given.friction, newest 40
```

## Tests

1. `rows append across calls`: `nextRecord` → two calls' rows, in order.
2. `a malformed row is refused`: `recordFields` → refusal naming the row; a drain without `size` is refused.
3. `past 40 the oldest go`: `nextRecord` → 40 rows, and the reply says how many were dropped.
4. `the hand-off commits them`: `deck_status` → after it, `pilot handoff` commits a run.json holding every row.

Rewrite check: any store behind the record keeps the rows appended, bounded and committed as above.
