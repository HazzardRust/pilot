# S2 Both lanes on every lane line

Feature `yellow-lane` · delivers spec 2, 3 · source: `../architecture.md` §2, §3 Findings "Notice regex" · after: S1 (deck/lanes.mjs)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `deck/lanes.mjs`: the `co-pilot` line reads `co-pilot: empty → next <id>` when queued; a new `yellowClause`.
- `deck/server-tools.mjs`: the `deck_ticket` co-pilot, release and need replies carry `yellowClause` and `mainClause`.
- `hooks/session-handoff.js`: `CO_PILOT_LINE` accepts the new spelling.
- `deck/test/ticket-tool-yellow.test.mjs` (new): the reply pins.
- `hooks/test/session-handoff-yellow.test.js` (new): the notice pin.

## Interface

```
lanesFrom(...) -> { main, co-pilot, mainClause, yellowClause, refusal }
  co-pilot:      'co-pilot: itm_x' | 'co-pilot: empty → next itm_y' | 'co-pilot: none'
  yellowClause: 'Yellow: itm_x' | 'Yellow: empty, next itm_y' | 'Yellow: empty'
deckTicketReply('co-pilot'|'release'|'need', id) -> "Co-pilot X: released. <yellowClause>. <mainClause>."
CO_PILOT_LINE = /^co-pilot: (none|empty → next itm_\w{1,40}|itm_\w{1,40})$/
```

## Tests

1. `the queued yellow lane names its next`: `lanesFrom` → `co-pilot: empty → next itm_…` and `Yellow: empty, next itm_…`.
2. `release answers both lanes`: `deckTicketReply` → `Co-pilot X: released. Yellow: empty, next itm_…. Main: …`.
3. `co-pilot and need answer both lanes`: `deckTicketReply` → both clauses on one line for each action.
4. `the notice keeps the Lanes block`: `CO_PILOT_LINE` → the SessionStart notice shows `co-pilot: empty → next itm_…`.

Rewrite check: any spelling change inside `lanesFrom` reaches the replies, the hand-off body and the notice together; otherwise test 4 fails.
