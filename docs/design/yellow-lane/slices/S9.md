# S9 `pilot handoff` carries owed threads and refuses unanswered ones

Feature `yellow-lane` · delivers spec 9, 10 · source: `../architecture.md` §2, §6 A3 · after: S7 (S7's owed on /api/record)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `scripts/handoff.mjs`: refuses before landing anything while an owed thread is `unanswered`; the item body lists the `promised` ones.
- `scripts/test/handoff-owed.test.mjs` (new): the pins.

## Interface

```
handoff({ cwd, env, trailers }) -> { ok, line }
  // ok false: "NOT handed off: user thread(s) unanswered: <ids>; reply first; no handoff item posted"
  // ok true: item body gains "Owed: <id> promised: <line>" per promised thread
S7's owedThreadsOf: read as `owed` from GET /api/record
```

## Tests

1. `an unanswered chat refuses`: `handoff` → `ok: false`, the line names the id, nothing is committed and nothing is posted.
2. `answered, it posts`: `handoff` → `ok: true` once the pilot has replied.
3. `a promised thread rides the item`: `handoff` → the posted body carries its id and line.

Rewrite check: whatever the deck's rule for owed, `handoff` refuses on `unanswered` and carries `promised` exactly as served.
