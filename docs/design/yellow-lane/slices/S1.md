## Files owned

- `deck/lanes.mjs`: `lanesFrom` adds the yellow lane's refusal after the main lane's, under the same open-hand-off exemption.
- `deck/test/lanes-yellow.test.mjs` (new): the pure pins on `lanesFrom`.
- `deck/test/wait-yellow-lane.test.mjs` (new): `pilot wait` through a test daemon.
- `hooks/test/stop-gate-yellow-lane.test.js` (new): the Stop hook through a test daemon.

## Interface

```
lanesFrom(items, repo, { switching, co-pilot }) -> { main, co-pilot, mainClause, refusal }
  refusal: the main lane's line, else "yellow lane empty; <id> is planned — deck_ticket co-pilot it first", else null
  // yellow refusal when coPilotStateOf(items, repo, <live co-pilot ticket>, switching) === 'queued'
wait({ kind: 'pilot', ... }) -> exit code      // prints lanes.refusal and returns; code unchanged
stopGate -> { decision: 'block', reason }      // reason is lanes.refusal; code unchanged
```

## Tests

1. `yellow with no co-pilot is refused`: `lanesFrom` → `refusal` names the yellow ticket and `deck_ticket co-pilot`.
2. `a live co-pilot, or no yellow ticket, refuses nothing`: `lanesFrom` → `refusal` is null.
3. `an open hand-off suppresses it`: `lanesFrom` → `refusal` is null while a `handoff` item is open.
4. `the main lane's refusal comes first`: `lanesFrom` → the main line when both lanes are idle.
5. `pilot wait exits on it`: `wait` → prints the yellow line and exits before parking.
6. `the Stop hook blocks with it`: `stopGate` → `decision: 'block'` with the yellow line.

Rewrite check: replacing `coPilotStateOf` with any other reading of the lane keeps the refusals above for all four cases.
