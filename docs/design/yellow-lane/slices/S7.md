Feature `yellow-lane` · delivers spec 11 · source: `../architecture.md` §2, §4 "Owed thread", §5 L6, §6 A2, A3 · after: S4 (deck/tools.mjs), S5 (deck/store-items.mjs)

## Files owned

- `deck/owed.mjs` (new): `owedThreadsOf`, pure.
- `deck/store-items.mjs`: the pilot's reply writer stores `promise: true` on the message.
- `deck/tools.mjs`: the `deck_reply` schema gains `promise`.
- `deck/server-routes.mjs`: `GET /api/record` adds `owed`.
- `deck/test/owed.test.mjs` (new): the pins.

## Interface

```
deck_reply({ id, text, promise?: true })     // the message stores promise: true
owedThreadsOf(items, repo) -> [{ id, line, why: 'unanswered' | 'promised' }]
  // open chat and user threads of repo; line is the last message, one line, clipped to 120 chars
GET /api/record?repo=… -> { …, lanes, owed }
```

## Tests

1. `a user's last word is unanswered`: `owedThreadsOf` → `{why: 'unanswered'}` with the user's line, read through a pass.
2. `a promise is owed until the next pilot reply`: `deck_reply` → a reply with `promise` makes `owedThreadsOf` list it as `promised`; a later plain reply clears it.
3. `a closed or answered thread is not owed`: `owedThreadsOf` → [].
4. `the record route serves it`: `GET /api/record` → `owed` matches `owedThreadsOf`.

Rewrite check: replacing the stored flag with any other marker keeps tests 1-4.
