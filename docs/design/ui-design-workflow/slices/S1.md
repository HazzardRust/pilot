## Interface

```
surface.json: { name: string, tokens: string, screens: { [name]: string },   // paths relative to the file
                open: { kind: 'web', page: string } | { kind: 'command', argv: string[] } }  // argv holds {route} {mode} {out}
readSurface(file: string): Surface                       // throws on a missing key, an absolute path or a `..` escape
snap(surface, screen: string, mode: 'light'|'dark', out: string, spawn = spawnSync): { status: number, out: string }
look(argv: string[]): number                             // pilot look snap <surface.json> <screen> [--mode m] [--out f]; 2 on bad args
```

## Behaviours

1. `an unknown screen is refused before any process starts` (test): `snap` → throws naming the screens; the injected `spawn` is never called.
2. `the web adapter starts one headless browser with an argv` (test): `snap` → `spawn` gets a Chromium path, `--headless`, `--screenshot=<out>`, a temp `--user-data-dir`, the dark flag only for `dark`, and `shell` unset.
3. `a command adapter substitutes only its placeholders` (test): `snap` → `{route}`, `{mode}`, `{out}` replaced; a route holding `;` reaches the argv as one element.
4. `a surface.json escaping its directory is refused` (test): `readSurface` → throws on `../x` or an absolute path.
5. `two real PNGs of the fixture` (look): `pilot look snap fixtures/surface-web/surface.json home --mode light` and `--mode dark` leave two PNGs, visibly light and dark.

Rewrite check: replacing Chromium with any headless browser keeps 1, 3, 4; 2 names only what the adapter passes.
Misses: browsers at paths the lookup does not know; QA's run on another machine reads that.
