# S7 The Rune gate checks format

Feature `ui-design-workflow` · delivers spec 11 · source: `../architecture.md` §2, §3.1, §3.3 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the gate starts processes, the security trigger.

## Files owned

- `scripts/gate.mjs`: `cargoStep` returns two steps; `runeDeck` runs them in order, red on the first failure.
- `scripts/test/gate-cargo.test.mjs` (new): the pins.

## Interface

```
cargoStep(env, which, platform): { steps: { command: string, args: string[] }[] } | { skip: string }
runGate(argv, { spawn, which, homeStore, ... }): number   // existing; exit 1 when a cargo step fails
// steps: [cargo fmt --check --manifest-path deck/rune/Cargo.toml, cargo test --manifest-path deck/rune/Cargo.toml]
```

## Behaviours

1. `fmt runs before test` (test): `cargoStep` → on win32 with cargo found, two steps, `fmt --check` first.
2. `an unformatted file makes the gate red` (test): `runGate` → an injected spawn failing the fmt step gives exit 1 and starts no test step.
3. `skips stay skips` (test): `cargoStep` → no cargo, non-Windows and the inner gate each give one `skip`.
4. `the real gate` (run): `npm test` prints the fmt step, then cargo test, both green.

Rewrite check: running fmt through any formatter keeps 1-3.
Misses: rustfmt version drift between machines; the lander's gate reads it.

## Done

- **Expected**: every gate on Windows checks the Rune deck's format beside its tests.
- **Verification**: `node --test scripts/test/gate-cargo.test.mjs`; `npm test` once.
- **Evidence**: 1-3 red before, green after; behaviour 4's output.
- **Prohibited**: no `cargo fmt` that writes; no shell; no change to the node half.
- **Done when**: four behaviours hold and the gate is green. Estimate about 70 lines.
