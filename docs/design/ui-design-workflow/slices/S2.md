This supersedes the `--mode` lines below: tests 1 and 2 are now `a route parses into the start query` and `rune reads every flag but the route`, and `pilot-deck` no longer refuses a bad mode itself, which `pilot look snap --mode` still does.

## Interface

```
pub struct Start { pub query: Query, pub dark: Option<bool> }     // None: the system's mode, as today
Start::from_args(args: impl IntoIterator<Item = String>) -> Result<Start, String>
// pilot-deck --open "screen=thread&id=itm_x" --mode light|dark [--snap out.png]; rune's own flags pass through
S1's snap: { kind: 'command', argv: ['target/release/pilot-deck', '--open', '{route}', '--mode', '{mode}', '--snap', '{out}'] }
```

## Behaviours

1. `a route and a mode parse into the start query` (test): `Start::from_args` → `--open screen=thread&id=itm_1 --mode dark` gives that query and `dark: Some(true)`.
2. `an unknown flag value is refused` (test): `Start::from_args` → `--mode sepia` is `Err` naming light and dark; rune's `--snap` passes untouched.
3. `the snap draws the chosen screen in light on a dark system` (look): `pilot look snap deck/rune/surface.json thread --mode light` on a dark system gives a light PNG of the thread screen.
4. `no window takes focus during a snap` (run): the foreground window before and after the snap is the same handle.

Rewrite check: replacing the argument parser with any other keeps 1 and 2.
Misses: a screen whose data the scratch deck lacks draws empty; QA's seeded deck reads it.
