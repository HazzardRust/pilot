# S1 The builder makes a one-commit repo that `pilot base` accepts

Feature `fresh-public-repo` · delivers spec 2, 3, 6 · source: `../architecture.md` §2, §3 Seams, §5 L1-L3, §6 A1 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer` (a process start: it spawns git; CLI arguments)
Model: opus — spec 2 rests on assumed A1, and the slice hits the security trigger.

## Files owned

- `scripts/fresh-repo.mjs` (new): `buildOrphan` and the CLI around it; never pushes to a remote.
- `scripts/test/fresh-repo.test.mjs` (new): the pins, each on a temp git repo with a temp bare `--out`.

## Interface

```
node scripts/fresh-repo.mjs --from <ref> --pilot <ref> --email <addr> [--name <name>] --out <dir>
  // stdout on success: "fresh-repo: <sha> in <out>; push with: git -C <out> push <url> main"
  // exit 1, reason on stderr, <out> not created, on any refusal below

buildOrphan({ cwd: string, from: string, pilot: string, email: string, name?: string, out: string })
  -> { sha: string, tree: string }
  // out: a new bare repo whose only ref is main = one parentless commit with from's tree
  // author and committer are <name> <email>, env-set; the repo's user.email is never read
  // refusal "fresh-repo: <pilot> has changes <from> lacks" when the two trees differ
  // refusal "fresh-repo: <email> is not a GitHub noreply address" unless it ends @users.noreply.github.com (A1)
  // refusal "fresh-repo: <out> exists" when out is present
```

## Tests

1. `the orphan has one commit and the source tree`: `buildOrphan` → `git rev-list --count main` in `out` is 1, its tree equals `from`'s.
2. `the commit carries only the given address`: `buildOrphan` → `%ae` and `%ce` both the noreply email though the source repo's user.email is another.
3. `pilot ahead of main is refused and nothing is built`: `buildOrphan` → throws the pilot refusal; `out` absent.
4. `a personal address is refused`: `buildOrphan` → throws the noreply refusal.
5. `pilot base accepts the result`: `node scripts/fresh-repo.mjs` → in a clone of `out`, `scripts/base.mjs`'s `base` returns 0 and prints `created from main`.

Rewrite check: building the orphan by `git commit-tree` or by `checkout --orphan` keeps tests 1-5.

## Done

- **Expected**: the user runs one command from the real checkout and gets a local bare repo holding one commit, the tree of `main`, signed with the noreply address, ready to push; it refuses while `pilot` holds unlanded work.
- **Verification**: `node --test scripts/test/fresh-repo.test.mjs`; `npm test`; live: the CLI against this worktree's `origin/main` and `origin/main` as `--pilot`, into a scratch `--out`, then `git clone` it and `pilot base` there.
- **Evidence**: tests red before, green after; the live run's stdout, `git log --format='%H %ae %ce'` of the clone, and `pilot base`'s line.
- **Prohibited**: any `git push`, `gh` call or network fetch in the script; reading or writing the repo's git config; a `--force` past a refusal; tests that touch the real checkout.
- **Done when**: tests 1-5 and the suite are green and the live clone shows one commit that `pilot base` accepts.
