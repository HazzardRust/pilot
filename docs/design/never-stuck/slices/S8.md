# S8 Lane lines say why nothing runs

Feature `never-stuck` · delivers spec 9, 19 · source: `../architecture.md` §2, §5 L7 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the SessionStart hook's regexes gate what reaches the model, the security trigger.

## Files owned

- `deck/lanes.mjs`: reasons on the co-pilot line (`blocked on`, `orphaned`, `draining`); `(re-cut)` on the planning pick; an orphan is never `next`.
- `hooks/session-handoff.js`: `PLANNING_LINE`, `CO_PILOT_LINE` (:370-373) accept exactly the new shapes.
- `deck/test/lanes-why.test.mjs` (new): one case per reason, and the hook regexes over each line.

## Interface

```
lanesFrom(items, repo, ...).coPilot ->
  "co-pilot: none runnable: <id> <reason>(; <id> <reason>){0,4}"   reason: blocked on itm_… | orphaned | draining
  "co-pilot: <id> draining"
lanesFrom(...).planning -> "planning: empty → next <id> (re-cut)" for a ticket with `recut`
runnableYellowOf(items, repo)   // skips an orphan: open yellow, plan.grantedAt set, no live slot
CO_PILOT_LINE, PLANNING_LINE   // hooks/session-handoff.js: exactly the shapes above
```

## Tests

1. `an orphan is named and never next`: `runnableYellowOf` → excludes it; `lanesFrom` → `orphaned`.
2. `each reason reads on the line, at most 5`: `lanesFrom` → one pair per skipped ticket, capped.
3. `a re-cut ticket reads (re-cut)`: `lanesFrom` → `planning: empty → next <id> (re-cut)`.
4. `the hook echoes every new shape and nothing else`: `CO_PILOT_LINE` → matches the new lines, rejects a newline-bearing one.

Rewrite check: computing reasons in the daemon instead of lanes keeps the four results.
Misses: a reason for a red ticket other than re-cut.
