# S13 `pilot wait` listens and says what could run

Feature `never-stuck` · delivers spec 7, 11 · source: `../architecture.md` §2, §5 L8; ADR 0143 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI's output becomes model input, and it overrides ADR 0143 L2.

## Files owned

- `deck/wait.mjs`: the refusal is printed once per distinct text and the wait parks (:244-265); `NO REPLY` (:271) appends the lanes and owed rows from `/api/record`.
- `deck/test/wait-yellow-lane.test.mjs`: the listen pin replaces the exit pin.
- `deck/test/wait-no-reply.test.mjs` (new): the runnable lines.

## Interface

```
waitForReply(opts) -> exit code
  // refusal: printed once, then parks; exits 0 only on REPLY, NO SESSION or NO REPLY
  // NO REPLY: "NO REPLY after <n> minutes" + "\nLanes now:\n<planning>\n<concluding>\n<co-pilot>" + "\nOwed:\n<id> <why>: <line>" per row
```

## Tests

1. `the idle lane refusal is said once and the wait listens`: `waitForReply` → the line once, then exits on a later reply with `REPLY`.
2. `NO REPLY names the lanes and owed rows`: `waitForReply` → 3 lane lines and each owed row after the timeout line.
3. `a lane text of the wrong shape is not echoed`: `waitForReply` → the timeout line alone.

Rewrite check: serving the runnable text from the daemon keeps the three results.
Misses: a pilot that ignores the lines; S18's prose and the Stop hook carry that.

## Done

- **Expected**: a waiting pilot keeps hearing the user while a lane is idle, and every quiet timeout tells it what could run.
- **Verification**: `node --test deck/test/wait*.test.mjs`; `npm test`; one real `pilot wait` against a scratch deck with an idle lane.
- **Evidence**: tests red before, green after; the real wait's output pasted in the PR.
- **Prohibited**: no unvalidated text echoed; no exit on the refusal; no change to the Stop hook.
- **Done when**: the three tests, the real wait and the gate are green.
