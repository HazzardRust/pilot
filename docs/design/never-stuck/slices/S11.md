# S11 A landing closes its own questions

Feature `never-stuck` · delivers spec 5 · source: `../architecture.md` §2 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — one function, its filter and resolution text fixed below, no input, process or assumed line.

## Files owned

- `deck/closing-report.mjs`: `closeLanded` (:117) first resolves the landing's own questions, then the gate2.
- `deck/test/landed-closes.test.mjs` (new): the pins.

## Interface

```
closeLanded(gate2Id): Item | null
  // before the gate2Blockers check: each open blocking question naming the gate2's ticket, author 'deck' or 'lander',
  // resolved "Moot: landed <sha7>" in one write; any other blocking item still keeps the gate2 open
```

## Tests

1. `the conflict question closes on landed`: `closeLanded` → the question resolved `Moot: landed <sha7>`, the gate2 resolved.
2. `a user-owed blocking item still holds the gate2`: `closeLanded` → null, that item open.
3. `another ticket's question is untouched`: `closeLanded` → it stays open.

Rewrite check: closing in `startLanding` instead keeps the three results.
Misses: a landing question the pilot posted itself (it closes those, ADR 0178).

## Done

- **Expected**: once a feature lands, the questions about landing it are gone from the deck.
- **Verification**: `node --test deck/test/landed-closes.test.mjs deck/test/closing-report.test.mjs deck/test/landing-conflict.test.mjs`; `npm test`.
- **Evidence**: tests red before, green after.
- **Prohibited**: no closing of a question another author posted; no change to `gate2Blockers`.
- **Done when**: the three tests and the gate are green.
