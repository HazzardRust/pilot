# S16 A deck restart re-adopts its land child

Feature `never-stuck` · delivers spec 21, 22 · source: `../architecture.md` §2; itm_0a2eca54e2f7 · after: S10 (`store-items.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — process control on a recorded pid, the security trigger.

## Files owned

- `deck/store-items.mjs`: `beginLanding` (:447) records `pid`; `interruptLandings` (:507) skips a landing whose pid is alive.
- `deck/landing.mjs`: `adoptLandings` waits on a live recorded pid and reads its land dir's output, or stops it past 40 minutes; `Land again` refused while a pid holds the dir.
- `deck/daemon.mjs`: `adoptLandings()` before `interruptLandings()` (:218).
- `deck/test/land-adopt.test.mjs` (new): a stub child that sleeps, then prints a landed line.

## Interface

```
beginLanding(gate2Id, { worktree, pid }) -> landing { state: 'running', startedAt, pid, dir }
export function adoptLandings(deps?): Promise<void>
  // per running landing: pid alive and its command line names `land` -> wait, settle from its output file; else interruptLandings' path
landAgain(gate2Id) -> refused "landing <pid> still holds <dir>" while that pid is alive
```

## Tests

1. `a restart re-adopts a live child and reads its line`: `adoptLandings` → the gate2 `landed`, 0 `interrupted`.
2. `a dead pid is interrupted as today`: `adoptLandings` → `landing interrupted`.
3. `a reused pid that is not a land is never adopted or stopped`: `adoptLandings` → interrupted, the process untouched.
4. `Land again is refused while the child lives`: `landAgain` → refusal naming the pid and dir; after exit, it lands.

Rewrite check: replacing the pid probe with a lock file in the land dir keeps the four results.
Misses: a child that hangs past 40 minutes without output; it is stopped and reported.

## Done

- **Expected**: a deck restart mid-landing never leaves a land running unseen, and never starts a second one.
- **Verification**: `node --test deck/test/land-adopt.test.mjs deck/test/landing*.test.mjs deck/test/land-again.test.mjs`; `npm test`.
- **Evidence**: tests red before, green after; a scratch deck restarted mid-landing with the stub.
- **Prohibited**: no kill of a pid whose command line is not the deck's land; no change to ADR 0035's rule for other pids.
- **Done when**: the four tests and the gate are green.

## Seam changes (Run 2)

The daemon makes one start-up sweep, inside `adoptLandings`, instead of `adoptLandings()` before `interruptLandings()`, so a child that exits between two sweeps is never read as interrupted. The land child's helpers live in deck/land-child.mjs, with a deck/README.md row. Decided by the co-pilot; moves no spec line or locked decision.

The child's pid is written by `holdLanding` (deck/land-child.mjs) once it is spawned, not by `beginLanding`, which takes `{ worktree }` only; the landing stores no `dir`, which `landDir(gate2Id)` computes (step-7 principles round, F3).
