# S8 The log can be turned off

Feature `usage-telemetry` · delivers spec 13 · source: `../architecture.md` §2, L13, L14, A11 · after: S3

## Files owned

- `deck/telemetry.mjs`: a tick reads the switch first; off writes nothing, and the first window after on starts where it was turned on.
- `deck/usage-switch.mjs` (new): the switch file, its reader and its writer.
- `bin/pilot.mjs`: the verb `pilot usage on|off|status`.
- `deck/daemon.mjs`: the start line says `off` when the switch is off.
- `deck/test/usage-switch.test.mjs` (new): the pins.
- `docs/INSTALL.md`: the `~/.claude/pilot/` row (`:20`) names `usage.jsonl`, what it records, and `pilot usage off`.

## Interface

```
// deck/usage-switch.mjs
export function usageSwitchFile(): string                       // <storeDir()>/usage-log.json
export type UsageSwitch = { enabled: boolean, at: string }      // at: ISO time it was last set
export function readUsageSwitch(): UsageSwitch                  // absent or unparseable file: { enabled: true, at: '' }
export function setUsageSwitch(enabled: boolean, now?: () => number): UsageSwitch
// bin/pilot.mjs
pilot usage on | off | status      // one line: "usage log on|off, <path>"; any other word is a usage error, exit 2
// deck/telemetry.mjs
S1's tick: readUsageSwitch() first; when off, return without reading a transcript or appending
S3's first window after on: [max(lastWindowEnd, switch.at, boundary - MAX_BACKFILL_MS), boundary)
// deck/daemon.mjs
"[deck] usage log <path>" when on, "[deck] usage log off (pilot usage on)" when off
```

## Tests

1. `a tick with the switch off appends nothing and reads no transcript`.
2. `pilot usage off then a tick, with no restart, writes nothing`: the daemon's running schedule sees the file.
3. `the first line after on starts at the time it was turned on`: nothing from the off period is counted.
4. `an absent or torn switch file means on`.
5. `pilot usage status prints the state and the log's path; an unknown word exits 2`.
6. `the install guide names the log and the switch`: `docs/INSTALL.md` holds `usage.jsonl` and `pilot usage off`.

## Done

- **Expected**: `pilot usage off` stops the log from the next half hour without restarting the deck, `pilot usage on` resumes it, and what was spent while it was off is never recorded.
- **Verification**: `node --test deck/test/usage-switch.test.mjs deck/test/telemetry-resume.test.mjs`; `npm test`; on a scratch deck, `pilot usage off`, a boundary passes, no new line.
- **Evidence**: tests 1 and 3 red before, green after; the scratch deck's `usage.jsonl` before and after a boundary with the switch off.
- **Prohibited**: no environment variable as the switch (the daemon keeps the environment of the session that spawned it, `deck/client.mjs:145-148`); no key in `deck.json` (the verb would race the daemon's writes); no route, tool, tab or section (spec 9); no deleting or truncating the log on off.
- **Done when**: the suite is green and a scratch deck with the switch off passes a boundary without a line.
