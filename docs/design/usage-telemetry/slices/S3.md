# S3 Restarts leave no gap and a tick never stalls the deck

Feature `usage-telemetry` · delivers spec 6, 7 · source: `../architecture.md` §2, L5, L7, A5 · after: S2

## Files owned

- `deck/telemetry.mjs`: the first window starts at the last line's `to`; ticks yield per file and never overlap.
- `deck/test/telemetry-resume.test.mjs` (new): the pins.

## Interface

```
// deck/telemetry.mjs
export const MAX_BACKFILL_MS: number                 // 7 days (A5)
export function lastWindowEnd(file: string): number | null   // reads the file's tail only; null when absent or unparseable
S1's startUsageLog: its first window is [max(lastWindowEnd, boundary - MAX_BACKFILL_MS), boundary)
```

## Tests

1. `a second start continues from the last line's to`: write one line, restart with the clock two hours on, the next line's `from` is the first's `to`.
2. `the backfill stops at seven days`.
3. `a log whose last line is torn starts a fresh window and appends after it`: earlier bytes unchanged.
4. `a tick still running when the next is due skips it`: stubbed schedule fires twice during a pending read; one line.
5. `the deck answers during a tick`: a started daemon on a scratch port with a fixture of large files answers `/api/health` before the tick's line is written.
6. `an append that fails goes to stderr and the daemon stays up`: log path is a directory.

## Done

- **Expected**: stopping the deck for an afternoon and starting it again leaves one longer line covering the gap, and the deck page stays responsive while a line is gathered.
- **Verification**: `node --test deck/test/telemetry-resume.test.mjs`; `npm test`.
- **Evidence**: tests 1 and 4 red before, green after; test 5's timing printed.
- **Prohibited**: no reading the whole log to find its end; no rewriting or truncating the log; no worker thread (L5); no `sleep` in tests, the clock is stubbed.
- **Done when**: the suite is green and two starts of the daemon against one log give contiguous windows.
