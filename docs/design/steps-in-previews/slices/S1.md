## Interface

```
isQueued(item) -> boolean        // open, not a chat, and not standing unless it is a steps thread
STEPS_WAITING = 'waiting on your steps'
standingOf(ticket, items, coPilot) -> string   // STEPS_WAITING where 'human steps' was
OWED_KINDS = [KIND_GATE1, KIND_GATE2, KIND_SIGNOFF, KIND_STEPS]   // module-private in status.mjs

```

## Behaviours

1. `two open steps threads are two cards, none folded` (test): `isQueued` → on a store with green tickets A (in hand) and B, each with an open steps thread, `shownOf(queueOf(items), items)` holds both, `foldedOf` none, the strip's count is 2 and the notifications view's `open` has 2; after Done on A's, 1 each.
2. `the card counts the steps and names the ticket` (test): `renderKind` → a 3-step thread's view card `kind` reads `human steps · 3 steps`; its HTML home card carries the ticket's title.
3. `the row says waiting on your steps` (test): `ticketLabelOf` → `waiting on your steps` with an open steps thread; with none, the label today's code gives.
4. `the Stop gate holds no turn on a steps thread` (test): `isQueued` → true for an open steps thread, while `hooks/stop-gate.js` with that thread posted this session lets the turn end.
5. `the cause is in the ADR` (read): ADR 0216 cites `items.mjs:123`, `:522`, `status.mjs:494`, `:498`.
6. `the HTML deck shows both cards` (look): a scratch deck served locally, two seeded steps threads, both cards above any fold.
