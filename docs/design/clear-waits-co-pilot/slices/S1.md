# S1 A hand-off waits for the co-pilot's release (walking skeleton)

Feature `clear-waits-co-pilot` · delivers spec 1, 2 (deck half), 3, 5, 6 (wrapper half), 7 · source: `../architecture.md` §2, L3 to L8, L11 · after: –

## Files owned

- `deck/store.mjs`: `setCoPilot`, `coPilotFor` beside `storedBudget`; `needTicket` (:1128) and the yellow gate2 post (:623) release the entry for their ticket.
- `deck/server.mjs`: `deck_ticket` actions `co-pilot`, `release` (:907 block); `GET /api/record` adds `co-pilot`.
- `deck/chain.mjs`: `chainNext(repo, { atStart: true })` releases the directory's entry.
- `deck/run.mjs`: `clearOnce` holds any hand-off, chain or context; `coPilotFor(cwd)` reads `/api/record`; the held reply.
- `deck/test/co-pilot.test.mjs` (new): the store and chain pins.
- `deck/test/run.test.mjs`: the wrapper pins.

## Interface

```
deck.coPilots: { [repoKey]: { ticket: string, live: boolean, at: string /* ISO */ } }
setCoPilot(ticketId: string, live: boolean): { ticket, live, at }   // refuses a ticket that is not open and yellow when live
coPilotFor(dir: string): { ticket, live, at } | null              // live is false unless the named ticket is open and yellow
deck_ticket { id, action: 'co-pilot' | 'release' } -> "Co-pilot <id>: live." | "Co-pilot <id>: released."
GET /api/record?repo=<dir> -> { record, yellow, budget, co-pilot: coPilotFor(dir) }
clearOnce({ ..., co-pilot = () => coPilotFor(cwd) })             // async reader, injected by tests
```

## Tests

1. `co-pilot.test.mjs` `a co-pilot is live once set and released by release`.
2. `needTicket releases its ticket's co-pilot`; `a gate2 on the yellow ticket releases it`; `another ticket's need leaves it live`.
3. `a pilot run start releases the directory's co-pilot`.
4. `the stored deck gains co-pilots and no other key`.
5. `run.test.mjs` `a chain hand-off with a live co-pilot types nothing, and gives the claim back`.
6. `a released co-pilot lets the /clear through after the next turn end` (turn ended before `at`: nothing; after: `HANDED_OFF`).
7. `a co-pilot set again before the turn ends holds it again` (re-read after the turn wait).
8. `a context hand-off with a live co-pilot types nothing until the release` (spec 6, L11).
9. `a held hand-off says so once on its thread`.
10. `a /clear typed by hand reaches the pty while a co-pilot is live` (`fakePty`, stdin `data`).

## Done

- **Expected**: on a scratch deck, a hand-off with a live co-pilot leaves the terminal untouched and its thread says it is held; `deck_ticket release` (via `POST /api/tool`) and a turn end later, the `/clear` and prompt go in.
- **Verification**: `node --test deck/test/co-pilot.test.mjs deck/test/run.test.mjs deck/test/chain.test.mjs`; `npm test`.
- **Evidence**: tests 5, 6, 8, 9 failing before and passing after; a scratch `pilot run` (L10) seen holding, then clearing after a release.
- **Prohibited**: no timer or poll for the release, and no time bound on the hold (A4); no change to the pty input path; no `deck_read` with a `repo` from the wrapper; no store key but `co-pilots`; never the live daemon.
- **Done when**: the ten tests and the suite are green and the scratch hold-then-clear was watched.
