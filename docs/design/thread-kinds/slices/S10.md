# S10 The auditor owns its thread

Feature `thread-kinds` · delivers spec 4, 5, 6 · source: `../architecture.md` §2, F3-F5, L3, L14, L16 · after: S7, S9

## Files owned

- `deck/items.mjs`: `auditor` in `AUTHOR_KINDS` and `OWNER_KINDS`.
- `deck/server.mjs`: the refused-wait message (`:888`) and the fallback note (`:550-552`) name the owner kind, not QA.
- `deck/ui/deck.css`: a `by-auditor` byline colour.
- `agents/pilot-auditor.md`: tools add `deck_post`, `deck_wait`, `deck_reply`, `deck_resolve`; a new section "Owning the thread": message the skill's session when measured, post the audit item once handed the diff lines, park on `deck_wait`, answer replies, run the pick and post the tickets, resolve, then hand back (L16).
- `skills/audit/SKILL.md`: "Post" and "Picking" move to the auditor; the skill keeps both snapshots and `audit save`, and hands the auditor the `.deck.md` path and the differing lines.
- `docs/adr/0058-the-auditor-owns-its-thread.md` (new): amends 0041 and 0053.
- `deck/test/auditor-owner.test.mjs` (new); `deck/test/author.test.mjs:31` and `hooks/test/owner-hooks.test.js:48` lists.

## Interface

```

skills/audit/SKILL.md -> auditor (SendMessage): { deck: <.deck.md path>, report: <json path>, differs: string[] }
agents/pilot-auditor.md headings: ... "## Owning the thread" (new) ... "## Report"
```

## Tests

1. `an audit posted by a pilot-auditor is owned by auditor`.
2. `a reply on it is heard by the auditor's deck_wait and not the pilot's`.
3. `the pilot takes it back with to: "pilot"`.
4. `an auditor quiet past the fallback window hands the reply to the pilot, and the note names the auditor`.
5. `a ticket posted by the auditor carries it as author`.
6. `pilot-auditor.md lists the four deck tools and the skill no longer posts the item` (prose pin).
