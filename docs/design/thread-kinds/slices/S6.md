# S6 The tab's table holds one run

Feature `thread-kinds` · delivers spec 7, 8, 9 · source: `../architecture.md` §2, F6, L9 · after: S3, S5

## Files owned

- `deck/store.mjs`: `setSlices` lays the call's rows over the record's table when the slug has one, over `[]` when it has none (never over `run.slices` from another slug), and sets `run.slices = []` once the call carries `finished`; the record keeps the full table.
- `agents/pilot.md`: the TEMPORARY paragraph in "Ending a run" (`:602-608`) deleted.
- `deck/test/status-run.test.mjs` (new).

## Interface

```
// deck/store.mjs (signature unchanged)
export function setSlices(runId, slices, feature, given = {}): { deckNumber, slices, record }
// slices returned: the tab's table after the call; [] when given.finished is set
// record.slices: the run's full table, kept after finished
```

A call with no `slug` (no record fields) keeps today's rule: rows laid over `run.slices`.

## Tests

1. `a first call for a new slug leaves only its rows on the tab` (an earlier slug's rows in `run.slices` are gone).
2. `the earlier slug's record still lists its rows`.
3. `a later call for the same slug merges over its record's table` (independence spec 22.2 holds).
4. `a call with finished empties the tab's table and the tree drawn from it`.
5. `the finished record keeps every row`.
6. `pilot.md has no TEMPORARY paragraph`.
