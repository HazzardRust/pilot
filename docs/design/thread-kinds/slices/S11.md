# S11 A crashed run is recovered from its record

Feature `thread-kinds` · delivers spec 22, 23, 24 · source: `../architecture.md` §2, F15, L11, L12, A9 · after: S8

## Files owned

- `hooks/session-handoff.js`: a recovery branch after `pickup` finds no open hand-off: `recordFor(cwd)` unfinished, no live run in the directory but this session's (`deck.runs()`), claim `recovered-<slug>-<updatedAt>`, then the hand-off payload shape under a recovered notice. Never the chain branch.
- `hooks/test/session-handoff.test.js`: the recovered-notice sentence pin and the branch's cases.
- `agents/pilot.md`: step 1 sends the first `deck_status` (slug, feature, `next` naming the open items and the design branch) before the architect is spawned (`:536-546` moves earlier); every `deck_status` that moves a row carries the current `next`; a recovered notice is answered as a hand-off is, without a thread to reply on.
- `scripts/test/pilot-agents.test.mjs`: the two pins for those sentences.

## Interface

```
// hooks/session-handoff.js
function recoveredNotice(record): string   // "SYSTEM NOTICE: you are recovering a run nobody handed off ..."
// lane result for a recovery: { claimed: ['recovered-<slug>-<updatedAt>'], payload }
// payload: the shape payloadFor gives a hand-off, record + openThreads, no item id
S8's notice(item, record): unchanged for a real hand-off
```

## Tests

1. `an unfinished record with no open hand-off and no live run is delivered as recovered`.
2. `a finished record is not delivered`; `no record delivers nothing`.
3. `an open hand-off wins over recovery` (the existing branch is taken).
4. `a live run in the directory by another session blocks recovery`.
5. `one record state is delivered once; a newer updatedAt is delivered again`.
6. `the recovered notice says recovered, not handed off, and carries next` (sentence pin).
7. `pilot.md sends deck_status with next at step 1 and with every row move` (prose pins).
