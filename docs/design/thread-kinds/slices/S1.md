# S1 Gate threads post as their own kinds

Feature `thread-kinds` · delivers spec 10, 11 · source: `../architecture.md` §2, F7, L5 · after: – ·
walking skeleton: a new kind end to end, tool schema → daemon check → store → a card on the page.

## Files owned

- `deck/items.mjs`: `KIND_GATE1`, `KIND_GATE2`; both in `KINDS`, `GATED_KINDS`, `RUN_KINDS`; `SPECS` entries with their required fields and Sign off / Not yet buttons; a `PROMPTS` and `GATE_NOTES` line each.
- `deck/store.mjs`: `detailOf` enforces the required fields by name; a `signoff` carrying `gate` is refused naming `gate1`/`gate2`.
- `deck/tools.mjs`: the `deck_post` description and fields for the two kinds (the kind enum is `POSTABLE_KINDS` already).
- `deck/ui/render.mjs`: `KIND_RENDERERS` entries for both kinds (signoff's choices, its confirm step at `:255` keyed on a gate kind too); no evidence block yet (S4).
- `deck/test/gate-kinds.test.mjs` (new), and the existing tests that deep-equal `KINDS` (`items.test.mjs:100`, `types.test.mjs:22`).

## Interface

```
// deck/items.mjs
export const KIND_GATE1 = 'gate1';
export const KIND_GATE2 = 'gate2';
// SPECS[gate1].fields: artefact (path), sha, locked (integer >= 0), slices (string, the slice table)
// SPECS[gate2].fields: pr (url or #n), sha; walkthrough (item id) optional — L19
// deck_post { kind: 'gate1' | 'gate2', title, body, ...fields } -> stored item | refusal naming the missing field
```

## Tests

1. `a gate1 missing each required field is refused naming that field` (four cases).
2. `a gate2 missing each required field is refused naming that field` (two cases: `pr`, `sha`); `a gate2 without walkthrough is stored` (L19).
3. `a complete gate1 and gate2 are stored with options Sign off and Not yet`.
4. `a signoff with gate "1" is refused naming gate1; with gate "2" naming gate2`.
5. `a gate1 is refused while a question is open in its repo` (ADR 0029 holds).
6. `full auto resolves a gate1 at post` (it is in `KINDS`).
