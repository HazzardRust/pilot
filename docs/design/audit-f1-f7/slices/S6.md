# S6 `pilot deck --scratch` starts an isolated deck

Feature `audit-f1-f7` · delivers spec 8 · source: `../architecture.md` §2, L6 · after: #445 on pilot · model: Opus (judgement on a guard or a budget)

## Files owned

- `deck/scratch.mjs` (new): `startScratch`, which picks the port, spawns the daemon detached, polls health and writes the registry.
- `bin/pilot.mjs`: `deck` parses `--scratch` and `--port N`, and the usage text names them.
- `docs/INSTALL.md`: one line naming `pilot deck --scratch` and `--stop`.
- `deck/test/scratch.test.mjs` (new): the pins. Each test stops what it starts.

## Interface

```
startScratch({ port?: number }): Promise<{ url: string, pid: number, dir: string }>
  // env PILOT_DECK_DIR=<mkdtemp pilot-scratch->, PILOT_DECK_PORT=<port>, PILOT_DECK_NO_OPEN=1; detached, unref
registry: <os.tmpdir()>/pilot-scratch-<pid>.json  { pid, port, dir }
pilot deck --scratch [--port N]  -> stdout: url, pid, dir; exit 0
```

## Tests

1. `a scratch deck answers on its own port`: `startScratch` → `/api/health` answers 200 with the printed pid, on a port other than 4321.
2. `it outlives its starter`: `pilot deck --scratch` → health still answers 200 after the CLI process exits.
3. `the user's store is untouched`: `startScratch` → its `dir` is under os.tmpdir(), and deck.json is written there.
4. `a taken port is refused`: `pilot deck --scratch` → `--port` with a held port exits 1 and names the port.

## Done

- **Expected**: An agent runs one command and has its own deck, and never touches the user's 4321 deck or `~/.claude/pilot`.
- **Verification**: `node --test deck/test/scratch.test.mjs`; `npm test`. By hand: `node bin/pilot.mjs deck --scratch`, close that shell, then `curl <url>/api/health`.
- **Evidence**: The curl run after the shell closed. `stat -c %Y ~/.claude/pilot` before and after.
- **Prohibited**: Do not use `ensureDaemon`, which reuses 4321. Do not kill by process sweep in the tests. Write nothing under the user's home.
