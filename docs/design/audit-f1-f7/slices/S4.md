# S4 `npm run test:quiet` prints dots and failures

Feature `audit-f1-f7` · delivers spec 5 · source: `../architecture.md` §2, L4 · after: – · model: Sonnet (mechanical against this file)

Diff limit: 200 changed lines. Past it, stop and ask `main`.

## Files owned

- `package.json`: `scripts["test:quiet"]`.
- `scripts/test/test-quiet.test.mjs` (new): writes one passing and one failing file into a mkdtemp and runs the script's command over them, never over the whole suite. Nothing goes under `test/`, because node's default glob collects every file there.

## Interface

```
npm run test:quiet  ==  node --test --test-reporter=dot --test-timeout=60000
fixtures: <mkdtemp>/{pass,fail}.test.mjs, written by the test
```

## Tests

1. `the dot reporter names a failure`: `npm run test:quiet` → over the failing fixture, the output holds the test's name and its diff, and the exit is non-zero.
2. `a green run is short`: `npm run test:quiet` → over the passing fixture, the output is under 1 KB.

## Done

- **Expected**: An agent runs the full gate and reads under 10 KB when it is green, but still sees which test failed and why.
- **Verification**: `node --test scripts/test/test-quiet.test.mjs`; `npm run test:quiet | wc -c` (under 10240), and its pass count against `npm test`'s.
- **Evidence**: Put both counts and the byte count in the PR.
- **Prohibited**: Do not change `scripts.test`'s reporter. Do not add a custom reporter file. Do not commit a failing fixture into the tree.
- **Done when**: The two tests pass, the green suite prints under 10 KB, and its count equals `npm test`'s.

Rewrite check: Any reporter that prints failures with their names and keeps green output small passes these tests.
