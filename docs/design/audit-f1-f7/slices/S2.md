# S2 A brief read lists the deck in one line per item

Feature `audit-f1-f7` · delivers spec 2, 3 · source: `../architecture.md` §2, L1, L2 · after: S1 · model: Opus (judgement on a guard or a budget)

Diff limit: 200 changed lines. Past it, stop and ask `main`.

## Files owned

- `deck/read.mjs`: `selectItems` takes `brief`, and `briefLine` shapes one item.
- `deck/tools.mjs`: deck_read's schema gains `brief` and still stays at or under 467 bytes.
- `deck/test/read-brief.test.mjs` (new): the pins.

## Interface

```
selectItems(items, { id?, open?, limit?, brief?: boolean }): Item[] | BriefItem[]
briefLine(item: Item): BriefItem  // { id, kind, state, owner, replies: number, title }; no body, no messages
deck_read { brief?: boolean, ... } -> { url, seq, total, items: BriefItem[] }
```

## Tests

1. `a brief item carries no body`: `briefLine` → only the six fields, with no `body` and no `messages`.
2. `brief combines with open and limit`: `selectItems` → the same ids as the full read with the same options.
3. `twenty open items are under 3 KB`: `deck_read` → `{brief:true, open:true}` over 20 long-bodied items is under 3000 chars.
4. `the schema stays in its bytes`: `deck_read` → a schema of at most 467 bytes, with both properties.
