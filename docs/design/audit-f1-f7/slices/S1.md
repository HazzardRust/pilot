## Files owned

- `deck/server.mjs`: `callTool`'s deck_read branch (`:841-877`) calls `selectItems`. The hand-off stays here.

## Interface

```
selectItems(items: Item[], options: { id?: string, open?: boolean, limit?: number }): Item[]
  // id given: [that item], or throws DeckRefusal naming the id; no id: today's newest-`limit` rule
deck_read { id?: string, limit?, open?, repo?, author? } -> { url, seq, total, items }
deck_read schema bytes: JSON.stringify(the deck_read entry of TOOLS).length <= 467
```

## Tests

1. `one item by id`: `deck_read` → `{id}` returns exactly that item with its messages, and `total` is unchanged.
2. `an unknown id is refused by name`: `selectItems` → throws a DeckRefusal naming the id.
3. `a read by id hands over only that owned thread`: `deck_read` → `{id, repo}` called by the owner marks that thread's replies delivered, as a newest-N read does.
4. `the schema stays in its bytes`: `deck_read schema bytes` → at most 467.
5. `newest-N reads are unchanged`: `selectItems` → without `id`, returns the same items as before for `limit` and `open`.
