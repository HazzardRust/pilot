# S4 The deck knows the co-pilot's agent id

Feature `handoff-no-wait` · delivers spec 3 · source: `../architecture.md` §3 F3, F5, §5 L4 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the stamp is written from a heartbeat route's input, an API boundary on the security trigger.

## Files owned

- `deck/store-tickets.mjs`: `noteCoPilotAgent` (new) writes the stamp (`store-runs.mjs` was at the 800-line bar); `deck/store-runs.mjs`: `coPilotFor` serves `agent`.
- `deck/server-routes.mjs`: the heartbeat route (:702) calls `noteCoPilotAgent` after `noteAgent`, inside its existing try.
- `deck/test/co-pilot-agent.test.mjs` (new): the pins, on a scratch store.

## Interface

```
noteCoPilotAgent(cwd: string, agentId: string, agentType: string, now?: number) -> boolean
  // true when it wrote: type 'pilot:pilot-co-pilot', cwd's repo entry live, now after entry.at, agentId differs
coPilotFor(dir) -> { ticket, live, at, agent?: string } | null   // agent: the stamp, absent before any heartbeat
GET /api/record?repo= -> { …, coPilot: coPilotFor(repo) }      // unchanged route, wider entry
```

## Behaviours

1. `a co-pilot heartbeat after the grant stamps the entry` (test): `noteCoPilotAgent` → `true`, and `coPilotFor(repo).agent` equals the id.
2. `nothing else stamps it` (test): `noteCoPilotAgent` → `false` for an implementer's type, a released entry, a heartbeat older than `at`, and the same id twice (1 store write in all).
3. `a worktree heartbeat counts for its repository` (test): `noteCoPilotAgent` → `true` for a cwd inside a worktree of the repo.
4. `the id is served` (test): `coPilotFor` → `agent` present in `GET /api/record`'s `coPilot` on a scratch deck.

Rewrite check: however the stamp is stored, the latest co-pilot heartbeat after the grant is the id the record serves.
Misses: a predecessor co-pilot still making calls after its successor's grant wins the stamp until the successor's next call; `pilot.md`'s release-before-grant order orders the deck's state, not the predecessor process, so it does not rule this out.

## Done

- **Expected**: within one tool call of a co-pilot's start, the deck's record names its agent id.
- **Verification**: `node --test deck/test/co-pilot-agent.test.mjs deck/test/agents.test.mjs`; `npm run test:quiet`.
- **Evidence**: cases 1 and 4 red before and green after.
- **Prohibited**: no read of the hook's prompt or tool result; no stamp from the in-memory roster alone (it forgets after 90 s); no store write per heartbeat when nothing changed.
- **Done when**: four behaviours hold and the gate is green.
