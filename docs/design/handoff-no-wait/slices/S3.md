# S3 The mod arms no hold timer

Feature `handoff-no-wait` · delivers spec 6 · source: `../architecture.md` §3 F1, §5 L3 · after: S1 (the `turn` Outcome)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a named deletion, but in `hooks/`, on the security trigger.

## Files owned

- `hooks/handoff-mod.mjs`: `HOLD_LOOK_MS`, `hold`, `endHold`, `onTimer` and the `held` branch of `decide` go.
- `hooks/test/handoff-mod.test.mjs`: the hold-timer cases go; one no-timer case is added.

## Interface

```
register(on) -> void   // turn.complete: look, then clear and submit, or nothing; no $.clock.every
decide($, mod, due)    // due.act 'clear' hands off; anything else does nothing
```

## Behaviours

1. `no timer is armed` (test): `register` → a fake host records 0 `$.clock.every` and 0 `$.clock.after` other than the 60 s started check, for each of `clear`, `none` and an unknown `held`.
2. `a clear still clears and submits` (test): `register` → `$.command.run('clear')` then `$.prompt.submit` once, as today.

Rewrite check: any mod that clears on `clear` and arms nothing else passes both.
Misses: the host's real timer behaviour; QA's scratch run reads the first prompt under 60 s.

## Done

- **Expected**: the mod clears at a turn end and never waits on a timer.
- **Verification**: `node --test hooks/test/handoff-mod.test.mjs`; `claude plugin validate .`; `npm run test:quiet`.
- **Evidence**: case 1 red before (an `every` armed on `held`) and green after.
- **Prohibited**: no new host call; no change to the argv or the prompt regexes.
- **Done when**: both behaviours hold, validate passes and the gate is green.
