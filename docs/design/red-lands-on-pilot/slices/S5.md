# S5 pilot land merges the feature into pilot

Feature `red-lands-on-pilot` · delivers spec 1, 3 · source: `../architecture.md` §2, §3 "What land.mjs changes", §5 L2 · after: S4 (mergeIntoPilot)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `scripts/land.mjs` (:1-89): doc, imports, `conflicts()` removed; the loop pushes `head` (never forced), then calls S4's `mergeIntoPilot` with the head's sha and `Merge <head> into pilot`, retrying once when the push to `pilot` is rejected because `pilot` moved.
- `scripts/test/land.test.mjs`: the fast-forward cases rewritten to the merge shape, plus the pins below.

## Interface

```
land({ cwd, git, gh, test }) -> { head, sha /* pilot's tip after */, retried, already?: boolean, mergeFirst, unknown? }
main(argv, inject) stdout: "landed <head> on pilot at <sha7>" | "<head> already on pilot at <sha7>", then "merge first: …"
S4's mergeIntoPilot
```

## Tests

1. `land merges the feature into pilot`: `land` → `origin/pilot`'s tip is `Merge feat/a into pilot` with `feat/a`'s tip as second parent.
2. `a fix on a landed feature lands as a second merge on top of a later one`: `land` → A, then B (cut on A), then A's fix: three merges, and `feat/a` contains no commit of B.
3. `a red run leaves pilot unmoved and says why`: `main` → exit 1, `NOT landed: … red`.
4. `a feature already on pilot merges nothing`: `main` → `already on pilot`, exit 0.
5. `no landing rewinds pilot`: `land` → every reflog entry of `origin/pilot` in tests 1–2 is a fast-forward.

Rewrite check: replacing `mergeIntoPilot` with any merge-test-push keeps all five results.

## Done

- **Expected**: landing a feature never brings `pilot`'s other features into it; `pilot` grows by merge commits only.
- **Verification**: `node --test scripts/test/land.test.mjs`; `npm test`.

- **Done when**: the five tests pass and `npm test` is green.
