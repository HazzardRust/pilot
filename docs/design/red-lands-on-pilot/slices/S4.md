## Files owned

- `scripts/sync.mjs`: `sync.mjs:58-97` (worktree, merge, install, test, push, cleanup) moves behind an exported `mergeIntoPilot`; `sync()` calls it with the default branch's tip.
- `scripts/test/merge-into-pilot.test.mjs` (new): the seam's pins on a scratch bare origin.

## Interface

```
mergeIntoPilot({ cwd, git, source: string /* sha */, message: string, test?: string })
  -> { sha: string, merged: boolean, line: string, counts?: string }
// merged false when source is already an ancestor of origin/pilot; the push is `<sha>:refs/heads/pilot`, never forced
// throws Error & { exitCode: 3, paths: string[] } on a conflict, { exitCode: 1 } on red, install or push failure; nothing pushed
```

## Tests

1. `a source merges into pilot as a new merge commit`: `mergeIntoPilot` → `origin/pilot`'s tip has parents (old pilot, source) and `message`.
2. `a red run leaves pilot unmoved`: `mergeIntoPilot` → throws exit 1; `origin/pilot` unchanged.
3. `a conflict names its paths and pushes nothing`: `mergeIntoPilot` → throws exit 3 with `paths`.
4. `a source already on pilot merges nothing`: `mergeIntoPilot` → `merged: false`.

Rewrite check: replacing the temporary worktree with an in-memory merge (`merge-tree`) keeps all four results; `sync.test.mjs` stays green unchanged.

## Seam change (co-pilot, 2026-10-10)

`mergeIntoPilot` takes one optional field beyond the Interface, `label?: string`, defaulting to the source's short
SHA, which names the source in `line` and in errors, so `pilot sync`'s output stays byte-identical
(`main@abc1234`). It refuses a `source` that is not a full SHA, exit 1. S5 may pass `label` or leave it out.
