# S6 A landing conflict keeps its worktree, and the next land pushes the resolution

Feature `red-lands-on-pilot` · delivers spec 3, 5 · source: `../architecture.md` §2, §5 L5 · after: S5 (scripts/land.mjs)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `scripts/sync.mjs`: S4's `mergeIntoPilot` gains `keep`, a directory left in place on a conflict instead of removed.
- `scripts/land.mjs`: on a conflict, keep the land worktree at `<repo>-land-<slug>` beside the checkout and name it; on the next run, a committed, conflict-free merge there whose parents are `origin/pilot`'s current tip and the feature's tip is tested and pushed; anything else is removed and the merge redone.
- `scripts/test/land-conflict.test.mjs` (new): the pins below.

## Interface

```
mergeIntoPilot({ …, keep?: string }) -> as S4; on conflict throws { exitCode: 3, paths, dir: keep }
main(argv, inject) stdout on conflict: "NOT landed: <head> conflicts with pilot in <paths>; resolve in <dir>, commit, and land again"  // exit 3
```

## Tests

1. `a conflict keeps the land worktree and names it`: `main` → exit 3, the line names `<dir>`, `<dir>` exists mid-merge, `origin/pilot` unchanged.
2. `a resolved land worktree is tested and pushed`: `main` → after a resolving commit in `<dir>`, `landed … on pilot`, and `<dir>` removed.
3. `a stale land worktree is redone`: `main` → with `origin/pilot` moved since, the kept merge is discarded and the merge redone on the new tip.
4. `a red resolution pushes nothing`: `main` → exit 1, `origin/pilot` unchanged, `<dir>` kept.

Rewrite check: replacing the kept directory with a pushed `land/<slug>` ref keeps all four results.

## Done

- **Expected**: a conflict at the gate2 press leaves a place QA can resolve, and the next Sign off lands that resolution, with the feature branch untouched.
- **Verification**: `node --test scripts/test/land-conflict.test.mjs scripts/test/land.test.mjs`; `npm test`.
- **Evidence**: tests 1–4 failing before and passing after.
- **Prohibited**: pushing an untested resolution; a kept worktree outside the repository's parent directory; touching `feat/<slug>`.
- **Size**: over 200 changed lines, stop and ask `main`.
- **Done when**: the four tests pass and `npm test` is green.

## Seam change (co-pilot, 2026-10-10)

S5 retries a landing only when `mergeIntoPilot`'s error text starts `NOT synced: the push failed (`, matching on
S4's wording. Since S6 touches both `scripts/sync.mjs` and `scripts/land.mjs` anyway, it replaces that match with a
structured field on the thrown error (`pushRejected: true` when the push to `pilot` was rejected), and has `land`
read the field. No spec line or locked decision moves. Count it inside S6's diff limit.

## Seam change 2 (co-pilot, 2026-10-10, for the fix round)

"Anything else is removed" would wipe a half-done resolution if Sign off is pressed before QA commits. A kept land
worktree verified as this repository's that is dirty or mid-merge, while `origin/pilot`'s tip and the feature's tip
are unchanged, is refused with exit 3, "finish and commit the resolution in <dir>", never removed. Spec 3 ("QA
resolves there … and commits") is unchanged. It lands in the step-7 fix round, with a test.
