## Interface

```
PIN block    // a test( that requires a phrase in prose: deleted
MIXED block  // phrase assertions deleted; lint or behaviour assertions kept
lint         // doesNotMatch(<prose>, <forbidden>) or a heading/step/field exists; kept, `// lint: <rule>` beside it
| file | tests cut | asserts cut | lints kept | rule each lint keeps |   // the PR's table, one row per owned file
```

## Tests

1. `the owned files stay green`: `lint` → `node --test` over the owned files passes.
2. `a kept lint still bites`: `lint` → on a scratch copy, adding its forbidden pattern or deleting its step turns it red (shown, not committed).
3. `no phrase pin is left`: `PIN block` → the reviewer's re-classification of the owned files finds 0 PIN and 0 MIXED blocks.

4. `the trees are clean`: `PIN block` → the PR body's classification table lists every test file that reads prose, each with 0 PIN and 0 MIXED after the cut.


Rewrite check: rewording any agent, skill, rule or doc keeps the owned files green unless it adds a forbidden pattern or drops a linted step.
Misses: a prose pin written in a way the classification does not recognise, such as a phrase read through a helper in another file.
