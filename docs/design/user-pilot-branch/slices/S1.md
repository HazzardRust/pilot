# S1 `pilot base` names and creates your pilot branch (walking skeleton)

Feature `user-pilot-branch` · delivers spec 1, 3, 5, 6, 8, 9 · source: `../architecture.md` §2, §5 L1-L8, L10, §6 A2, A4 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a config value and a host login become a ref and a push; the security trigger.

## Files owned

- `scripts/pilot-branch.mjs`: `pilotBranch`, `namePilotBranch`, `isPilotBase`, `landingSubjects`, `LEGACY_PILOT`; `ensurePilotBranch` takes the name and the legacy copy; `PILOT_BRANCH` kept for unfolded consumers until S6.
- `deck/host.mjs`: the `Host` typedef gains `login`.
- `deck/host-github.mjs`: `login()` from `api user --jq .login`.
- `deck/host-gitlab.mjs`: `login()` from `glab api user`'s `username`.
- `scripts/base.mjs`: derives through `namePilotBranch` and prints the stored name.
- `scripts/gate.mjs`: `gateEnv` sets `PILOT_BRANCH` to `LEGACY_PILOT` when unset (L7).
- `scripts/test/pilot-branch-name.test.mjs` (new): the pins.
- `docs/adr/0218-user-pilot-branch.md` (new): L1-L12.

## Interface

```
LEGACY_PILOT: 'pilot'
pilotBranch(git: (args: string[]) => string): string          // env PILOT_BRANCH, else pilot.branch; else throws NO_NAME; once per runner
namePilotBranch({ git, host: Host | null }): { name: string, source: 'env' | 'stored' | 'derived' }  // derives `${login.toLowerCase()}-pilot`, stores --local
isPilotBase(base: string | undefined, name: string): boolean  // base === name || base === LEGACY_PILOT
landingSubjects(head: string, name: string): string[]         // `Merge ${head} into ${name}` and `… into pilot`
ensurePilotBranch({ git, host }): { sha, created, from?: string, runs }  // from: LEGACY_PILOT | default branch
Host.login(): string | null                                    // null when signed out
NO_NAME: 'no pilot branch name: run `gh auth login` (or `glab auth login`), or `git config pilot.branch <login>-pilot`'
```

## Behaviours

1. `the login names the branch and is stored` (test): `namePilotBranch` → login `HazzardRust` gives `{ name: 'hazzardrust-pilot', source: 'derived' }`, `git config pilot.branch` reads it, a second call makes 0 `login()` calls.
2. `no login, no name, nothing written` (test): `namePilotBranch` → `login()` null or `host` null with no stored name throws `NO_NAME`; 0 config keys and 0 refs written.
3. `a login git would not take is refused` (test): `namePilotBranch` → `a..b`, `x.`, `x.lock`, `a b` each throw `NO_NAME`, nothing stored.
4. `a hand-set name off the shape is refused` (test): `pilotBranch` → `pilot.branch` set to `main`, `feat/x`, `-x-pilot` throws naming the key.
5. `the move copies the legacy tip` (test): `ensurePilotBranch` → origin with `pilot` and no `*-pilot`: `hazzardrust-pilot` created at `pilot`'s sha, `from: 'pilot'`; `pilot` unchanged.
6. `a later user starts from the default` (test): `ensurePilotBranch` → origin with `pilot` and `a-pilot`, login `b`: `b-pilot` at the default tip.
7. `pilot base prints it` (run): in a scratch clone signed in, `pilot base` under `pilot.host none` with `pilot.branch` set prints `base hazzardrust-pilot <sha>`.

Rewrite check: storing the name in a file instead of git config keeps 1-6's answers.
Misses: a real `gh` account switch mid-run; S7's doctor row and QA read that.
