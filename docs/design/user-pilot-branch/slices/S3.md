# S3 `pilot land` and the release PR name your pilot branch

Feature `user-pilot-branch` · delivers spec 1, 3 · source: `../architecture.md` §2, §5 L5, L8 · after: S1 (`pilotBranch`, `landingSubjects`, `isPilotBase`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the landing pushes and retargets PRs; a wrong name lands on someone else's line.

## Files owned

- `scripts/land.mjs`: every `PILOT_BRANCH` becomes the name `main` gets from `namePilotBranch`; legacy test through `isPilotBase`; `retarget` edits to the name.
- `scripts/release.mjs`: `LANDING` replaced by `landingSubjects`; `byHand`, `reviews({ head })`, `open({ head })` take the name.
- `deck/closing-report.mjs`: `byHand === 'pilot'` and the two lines name the branch passed in.
- `deck/store-items.mjs`: `LANDING_INTERRUPTED` names "your pilot branch", no literal.
- `scripts/test/land-user-branch.test.mjs` (new): the pins.

## Interface

```
land({ cwd, git, host, ... }): unchanged; names namePilotBranch({ git, host }).name throughout
releasePr({ git, host, name, already }): ...           // name added
mainLine({ number, opened, why, byHand, none, host }): string   // byHand is the name, compared by isPilotBase
retarget({ host, head, name }): number[]            // PRs on head edited to base name
releaseNotes({ git, pilotRef, mainRef, prs }): string   // lists landings by any of landingSubjects
S1's namePilotBranch, isPilotBase, landingSubjects
```

## Behaviours

1. `a landing pushes the user's branch` (test): `land` → with `pilot.branch` `hazzardrust-pilot`, `refs/heads/hazzardrust-pilot` moves on origin; `pilot` unchanged.
2. `a landed PR moves to the user's branch` (test): `retarget` → a chained PR is edited to base `hazzardrust-pilot`.
3. `release notes see pre-move landings` (test): `releaseNotes` → a `Merge feat/x into pilot` merge is listed.
4. `the closing report names the branch` (test): `mainLine` → `byHand: 'hazzardrust-pilot'` reads "Push hazzardrust-pilot, then open a PR from hazzardrust-pilot to main".

Rewrite check: finding a landing by first-parent ancestry instead of subject keeps 3.
Misses: GitHub's own display of a retargeted PR; QA's scratch repo (A1) reads it.
