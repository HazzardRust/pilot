## Interface

```
SHELL_RULES: readonly string[]   // two sentences, verbatim in each shell agent:
  // worktree: never write, check out, stash, reset or restore a tracked file in a worktree you did not create;
  //   a red-then-green proof runs in a detached throwaway worktree you create and remove
  // stop: stop only a process you started, by its id (TaskStop on a background run, or its PID),
  //   in a call of its own; never by name or pattern (pkill -f, taskkill /IM)
shellAgents(dir: string): string[]                      // definitions whose tools: line has Bash or PowerShell
missingShellRules(dir: string): { agent: string, rule: string }[]
```

## Behaviours

1. `every shell agent carries both rules` (test): `missingShellRules` → `[]` on `agents/`.
2. `a shell agent without a rule is named` (test): `missingShellRules` → `[{ agent, rule }]` on a fixture missing one.
3. `an agent with no shell needs none` (test): `shellAgents` → leaves out a fixture whose `tools:` has neither.
4. `every prompt stays within its pin` (run): `node scripts/measure-prompt.mjs` within each pin, raises dated.
5. `references hold` (run): `node scripts/check-references.mjs` exit 0.

Rewrite check: any check reading `tools:` lines and the two sentences keeps 1-3.
Misses: whether an agent obeys the prose under pressure; QA's reviewer proof and test stop (§9 items 3, 4) read that.
