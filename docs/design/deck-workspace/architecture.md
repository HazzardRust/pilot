# Deck — a workspace that holds still, and a crew that keeps its own rules

## 1. Problem

The deck is where the user works a run, and the workspace fights them. Opening
one widget moves another. A widget opened on its own runs off the bottom of the
screen. A deep tree breaks its names mid-word instead of scrolling. The reading
column is a narrow strip with blank space either side while the panels fight
over the same edge. A button that wipes a run sits in the panel the user reads
most. Nothing in the deck says *which* run is which except a directory name, so
there is no way to say "that slice, in that run" and be understood.

And three pieces of crew discipline slipped in the last run: an agent that was
told it was running out of context finished its slice instead of handing off; an
explorer's wrong diagnosis was taken as a verdict when one `grep` refuted it;
and the interview asked questions strictly one at a time even where the answers
had nothing to do with each other.

## 4. Ubiquitous language

| Term | Means exactly |
| --- | --- |
| **Deck** | One working directory's tab on the page and everything under it — its runs, items, tree and status rows. Keyed on the **path**, never on a session or a run row. This is the thing `D4` numbers. |
| **Deck number** | The integer minted once for a directory path, written `D4`, monotonic and never reused. A slice inside it is `S2`, so `S2 in D4` addresses one slice of one run. |
| **Tab group** | One edge's rail of bookmarks plus the panels that open from it. A panel hangs from the **group's** top, never from its own bookmark. |
| **Panel** | The box a tab opens. Its width and height are the user's, remembered per deck. |
| **Live agent** | An agent whose hook has reported a tool call inside the liveness window. **Observed, never declared** — an agent that is killed cannot deregister itself. |
| **Hand-off** vs **delivery** | Two senses collided. **Hand-off** is now only the context sense: an agent stashing and handing its work on (the hook's own `handoff` item kind). **Delivery** is the deck sense the last run called hand-off: `deck_wait`/`deck_read` giving a user's reply to a session, stored as `deliveredAt`. |
| **Locked decision** | Numbered `L1, L2…` from this run on, because `D` now belongs to decks. `A‹n›` still numbers an assumed one. |
| **Panel stack** | The open panels as one column (line 22): the first at the tab group's top, every next one's top edge on the bottom edge of the one above. Heights are each panel's own; widths are each panel's own and are never shared. |
| **Layer** | One step down the tree **as drawn**, not one `after` hop. Under L22 a step down opens a new layer only where a node has more than one child, and a slice's `delivers` leaves are a layer of their own. |
| **View root** | The node the tree is drawn from, carried in the address as `node=` (L19); the run's own root when there is none. Distinct from a **fold** (line 24), which hides a branch's children and leaves the root where it is. |

**The mechanism decision worth recording, because the word for it did not
exist.** Line 26's amendment was specified as marking a thread seen "at its
current last-message seq". There is no such number for the messages that
matter: `addPilotMessage` gives a pilot message no sequence number, on purpose
— "a sequence number is what wakes a waiting session, and no session may be
woken by its own words" — and only a user's reply carries one. A mark kept
against the last message's seq could not make a new pilot message resurface a
thread, and a mark kept against the message *count* would be moved by the
user's own reply, resurfacing a thread they had just written on. So the mark is
kept against **`pilotWrites`** (`items.mjs`): the post, plus each `from ===
'pilot'` reply, rendered onto each notice line as `data-said`. It moves when,
and only when, the pilot says something. No store field and no migration, so
L24's decision stands as written.
