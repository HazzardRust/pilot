# S2 A gate2 lists the questions it waits on

Feature `deck-press-feedback` · delivers spec 4 · source: `../architecture.md` §2, L4 · after: S1

## Files owned

- `deck/ui/render.mjs`: `renderAsked`, called from the gate2 detail on the thread page and from `renderCard`.
- `deck/test/gate-render.test.mjs`: the pins.

## Interface

```
renderAsked(item, items): string   // gate2 with a ticket: '<div class="asked">Waits on: <a href="/thread/<id>">title</a>, …</div>'; else ''
items.mjs openQuestionsOf(items, ticketId): the one source (unchanged)
```

The thread page passes `items` to the gate detail; `renderCard` takes `items` through its options.

## Tests

1. `a gate2 on a ticket with two open questions lists both as links on its page`: both ids, escaped titles.
2. `the same gate's card lists both`.
3. `with none open there is no list`: no `class="asked"`.
4. `a question on another ticket is not listed`.
5. `a gate1 draws no list`.

## Done

- **Expected**: before pressing Sign off, the user sees which questions the gate waits on and can open each one.
- **Verification**: `node --test deck/test/gate-render.test.mjs`, then `npm test`.
- **Evidence**: tests 1–3 fail before and pass after. A screenshot from a scratch deck of the gate's card and thread showing the list.
- **Prohibited**: no stored list on the gate; no new query beside `openQuestionsOf`; no unescaped title.
- **Done when**: the five tests and `npm test` are green and the screenshot shows both links.
