# S3 Every card names its ticket

Feature `deck-press-feedback` · delivers spec 5 · source: `../architecture.md` §2, L5 · after: S2

## Files owned

- `deck/ui/render.mjs`: `renderCard`'s kind line gains the ticket link. `GATE_ROWS.ticket` shows the title.
- `deck/test/card.test.mjs`: the pins.

## Interface

```
renderTicketOf(item, items): string   // '<a class="ticket" href="/thread/<ticket id>">ticket title</a>' or '' (no ticket, missing, merged)
renderCard(item, { tab, back, all, items })   // items: the list the page already holds (S2's option)
```

## Tests

1. `cards of two tickets each name their own ticket's title`: overview HTML.
2. `an unticketed card names none`.
3. `a card whose ticket is missing or merged names none`.
4. `a ticket title is escaped on the card`.
5. `the gate's Ticket row shows the title and links the id`.

## Done

- **Expected**: on the overview the user reads which ticket each card belongs to and can open the ticket.
- **Verification**: `node --test deck/test/card.test.mjs deck/test/gate-render.test.mjs`, then `npm test`.
- **Evidence**: tests 1, 2 and 5 fail before and pass after. A scratch-deck overview screenshot with two tickets and one unticketed thread.
- **Prohibited**: no title copied onto stored items; no read of the store from the renderer.
- **Done when**: the tests and `npm test` are green and the screenshot shows the ticket names.
