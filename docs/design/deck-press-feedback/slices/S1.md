# S1 A refused press lands on its thread with the reason (walking skeleton)

Feature `deck-press-feedback` · delivers spec 1, 2, 3, 6 · source: `../architecture.md` §2, L1–L3, A1, A2 · after: –

## Files owned

- `deck/server.mjs`: `landRefusedPress` used by `/reply`, `/close`, `/reopen` and `/dismiss-item`. The thread GET passes `refused` only under `Sec-Fetch-Site: same-origin`.
- `deck/ui/render.mjs`: `renderThreadPage` takes `refused`. `renderRefusal` draws it above the reply slot.
- `deck/test/press-refused.test.mjs` (new): the pins.
- `docs/adr/0075-a-refused-press-lands-on-its-thread.md` (new): L1–L3.

## Interface

```
landRefusedPress(request, response, item, err): void   // 303 to the item's thread on navigate; rethrows otherwise
// Location: /thread/<encodeURIComponent(item.id)>?refused=<encodeURIComponent(reason ≤ 300 chars)>#reply
renderThreadPage(item, items, runs, agents, numbers, all, added, refused = null): string
renderRefusal(reason: string | null): string   // '<p class="refused" role="alert">The deck refused that press: …</p>' or ''
```

seam corrected 2026-10-07: no `modes` on feat/deck-press-feedback

## Tests

1. `a navigation Sign off on a gate2 with an open question lands on its thread`: 303, the Location is the gate's thread with `refused`, and nothing is stored.
2. `a card press with back=/ that is refused still lands on the thread`: the Location ignores `back`.
3. `the same press without Sec-Fetch-Mode navigate is the 400 it always was`: status and text are unchanged.
4. `an unknown id is a 400, never a redirect`.
5. `Close, Reopen and Dismiss refused under navigate land the same way`: one case each.
6. `the thread page draws the reason escaped and capped, only same-origin`: `<script>` is escaped; 400 characters are cut to 300; `Sec-Fetch-Site: cross-site` draws nothing.
7. `the existing refusal suites pass unchanged`: run `red-grilling`, `gate-resolve` and `skeleton`.

## Done

- **Expected**: Sign off on a gate2 that waits on a question returns the user to the gate's thread with the reason over the reply box, from the thread or from the overview card.
- **Verification**: `node --test deck/test/press-refused.test.mjs deck/test/skeleton.test.mjs deck/test/red-grilling.test.mjs deck/test/reply.test.mjs`, then `npm test`.
- **Evidence**: tests 1, 2 and 6 fail before and pass after. On a scratch deck in a real browser, Sign off from the card and from the thread lands on the thread with the reason visible. Paste a screenshot.
