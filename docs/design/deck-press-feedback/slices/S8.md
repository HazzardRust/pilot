# S8 Walkthrough fields are general and carry a working directory

Feature `deck-press-feedback` · delivers spec 17, 18 (deck side) · source: `../architecture.md` §2, L10, L11 · after: S7

## Files owned

- `deck/items.mjs`: `dir` joins `WALKTHROUGH_FIELDS` (`:~287`) as an absolute path.
- `deck/tools.mjs`: the descriptions of `url` (any locator), `login` (how to reach it), `screens` (one step per action) and `dir`, and the top line's "in their browser" (`:140`, `:165-178`).
- `deck/ui/render.mjs`: `renderWalkthroughDetail` draws "working directory:" first, in `<code>`, only when given.
- `deck/test/walkthrough-fields.test.mjs` (new): the pins.

## Interface

```
deck_post { kind: 'walkthrough'|'report', dir?: string /* absolute path its commands run from */, url?: string /* any locator */ }
renderWalkthroughDetail(item): '<dl class="detail"><dt>working directory:</dt><dd><code>…</code></dd>…</dl>'
```

## Tests

1. `a walkthrough posted with dir is stored and shows working directory first`.
2. `one posted without dir shows no empty row`.
3. `a relative dir is refused with a reason`.
4. `a file-path url renders as escaped text`.
5. `the deck_post schema says nothing of browser or http`: a description pin.
6. `the pilot and QA prompt pins hold`: `measure-prompt` and `qa-preview` are unchanged.
