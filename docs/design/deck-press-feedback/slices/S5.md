# S5 The tab counts at first paint and is highlighted while unseen

Feature `deck-press-feedback` · delivers spec 9, 12 · source: `../architecture.md` §2, L8 · after: S4

## Files owned

- `deck/ui/render.mjs`: the Notifications `<summary>` carries `data-count` from `noticesOf`, the way `renderTabSummary` does for reports.
- `deck/ui/js/notifications.mjs`: `recount` adds the unseen open threads and sets `data-highlight` from the `deck.notificationsOpenedAt` stamp.
- `deck/ui/deck.css`: the highlight, a dot plus the count, readable in greyscale.
- `deck/test/notifications.test.mjs`: the pins.

## Interface

```
<summary data-count="N" data-highlight>Notifications</summary>   // count in served HTML; highlight set by script
localStorage 'deck.notificationsOpenedAt': ISO string            // written when the tab is opened and when it is shut
S4's noticesOf: the server count's source
```

## Tests

1. `two pending notices put count 2 in the served HTML`: no script runs.
2. `clearing one serves count 1`.
3. `a notice newer than the opened stamp sets data-highlight, on any tab`.
4. `opening the tab clears the highlight, and the next notice brings it back`.
5. `the highlight carries a marker, not only a colour`: CSS pin on the `::before` content or count.

## Done

- **Expected**: the user, on another tab, sees the Notifications tab light up with a count the moment a notice arrives, with no reload.
- **Verification**: `node --test deck/test/notifications.test.mjs deck/test/live.test.mjs`, then `npm test`.
- **Evidence**: tests 1, 3 and 4 fail before and pass after. A scratch deck in a browser: a notice raised while another tab is open changes the tab. Paste a greyscale screenshot.
- **Prohibited**: no colour-only highlight; no server write when the tab is opened; no polling beside `/events`.
- **Done when**: the tests and `npm test` are green and the greyscale screenshot shows the marker.
