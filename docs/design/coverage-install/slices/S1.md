## Behaviours

1. `the runner installs before its first check` (test): `## Before the first run` → names `npm ci --ignore-scripts` under a scratch `HOME`, its lockfile-and-no-`node_modules` condition, and comes before `## The command table`.
2. `a failed install is named, not run around` (test): `## What you return` → names an `install` row and `not run: install failed (exit`; the six-check table and its no-override test stay green.
3. `one installer` (test): `## Where you work` → the fundamentalist's has no `npm ci`, and its `## The evidence pass` names `install failed`.
4. `a fresh worktree measures` (run): a detached worktree of `feat/coverage-install` with no `node_modules`, the runner spawned on it by hand: an `install` row with exit 0, then a `Diff coverage:` row with a percentage.
5. `a broken lockfile is reported` (run): a scratch repo whose `package-lock.json` disagrees with `package.json`: the runner returns `install` with a non-zero exit and two `not run: install failed (exit <n>)` rows.

Rewrite check: rewording either section keeps the install before the table, one installer, and the failed-install phrase.
Misses: whether Haiku follows the order under load, and whether auto mode allows `npm ci` from the runner; behaviours 4-5 and the next Gate 2's evidence line read those.
