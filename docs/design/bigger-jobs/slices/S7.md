# S7 The auditor's rows are argued down before the pick

Feature `bigger-jobs` · delivers spec 10, 11, 12 · source: `../architecture.md` §2, §5 L7, §6 A4 · after: S6 (`deck/audit.mjs`, `agents/pilot-auditor.md`, `skills/audit/SKILL.md`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer` (agent configuration: `agents/`, `skills/`)

## Files owned

- `deck/audit.mjs`: `validateReport` accepts an optional `verdict { call, reason }` per row; `renderReport` lists kept rows, then a "Cut" section with each reason.
- `deck/test/audit-body.test.mjs`: the render and validation pins.
- `skills/audit/SKILL.md`: the fundamentalist step between measuring and posting.
- `agents/pilot-auditor.md`: `## The fundamentalist's brief` (one shape); the spawn before step 2's post; `pilot:pilot-fundamentalist` in the child list.
- `scripts/test/audit-agent.test.mjs`: the spawn, the brief and the child list pinned.

## Interface

```
row.verdict?: { call: 'keep' | 'unnecessary' | 'overengineering', reason: string }
validateReport(report) -> problems  // a verdict outside the three calls, or without a reason, is a problem
renderReport(report) -> text        // kept rows, then "Cut" with call and reason per row
agents/pilot-auditor.md ## The fundamentalist's brief: the report path; argue each row down, removal first; one verdict per row
```

## Tests

1. `cut rows render below the kept ones with reasons`: `renderReport` → kept first, a Cut section after, each reason shown.
2. `a malformed verdict is refused`: `validateReport` → a problem naming the row.
3. `the auditor spawns the fundamentalist before it posts`: `## The fundamentalist's brief` → the brief fields and the order matched; the child list names it.

Rewrite check: a different store for verdicts keeps test 1 as long as the item text shows kept, then cut with reasons.
