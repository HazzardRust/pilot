# S6 An audit posts one ticket per surface

Feature `bigger-jobs` · delivers spec 6 · source: `../architecture.md` §2, §3 "The audit", §6 A3 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer` (CLI argument; agent configuration: `agents/`, `skills/`)

## Files owned

- `deck/audit.mjs`: `specFor` takes several ids; `audit spec <report> <id> [<id>...]` prints them as one body under the report path.
- `deck/test/audit-pick.test.mjs`: the CLI and `specFor` pins.
- `skills/audit/SKILL.md`: picks are grouped by surface, one ticket each.
- `agents/pilot-auditor.md`: step 7 posts one ticket per surface group, `sliceCount` the sum of its rows' efforts.

## Interface

```
specFor(reportJson: string, ids: string[]) -> string  // each row's spec under "### <id>: <finding>", in pick order
pilot audit spec <report.json> <id> [<id>...]          // prints the body, then "Audit report: <path>"
agents/pilot-auditor.md step 7: group the picked ids by surface (the files a fix touches); one ticket per group
```

## Tests

1. `two ids give one body with both specs`: `specFor` → both rows present, in pick order.
2. `the body passes the ticket shape`: `pilot audit spec` → `ticketShapeGaps` is `[]` on its output.
3. `an unknown id among several is named`: `specFor` → the error names it and the report's ids.
4. `the auditor posts one ticket per surface`: `agents/pilot-auditor.md step 7` → "per surface" and the summed `sliceCount` matched.

Rewrite check: storing the body some other way keeps tests 1-3 as long as both specs and the report path arrive.
