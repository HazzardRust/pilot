# S2 The crew writes short and does not narrate

Feature `crew-voice-rules` · delivers spec 2, 3, 4 · source: `../architecture.md` §2, L3, L10 · after: S1

## Files owned

- `agents/pilot.md`: "Writing to the user" grows the voice rule; nothing else in the file.
- `agents/pilot-architect.md`, `pilot-implementer.md`, `pilot-qa.md`, `pilot-explorer.md`,
  `pilot-teacher.md`, `pilot-auditor.md`: one `## Voice` section each, or the rule folded into the
  existing Report section where one exists.
- `scripts/test/crew-voice.test.mjs` (new): the pins.

## Interface

```
## Writing to the user (pilot.md)   -- no narration; short by default; detail on request; when longer is right
## Voice (each crew definition)     -- same three rules, one paragraph, naming its own longer-is-right cases
```

Longer is right for: a security risk, irreversible data, the Gate 1 walk, a pushback
(spec 8), and a refusal or failure the reader must act on. Nothing else.

## Tests

1. `every crew definition forbids narrating steps`: each of the seven files has a sentence matching `narrat` + `never|not|no`.
2. `every crew definition makes short the default and detail on request`.
3. `every crew definition names when longer is right`: the sentence names at least security and irreversible.

## Done

- **Expected**: a reader of any crew definition finds, in one paragraph, that the agent prints state,
  questions and results, keeps deck text short unless asked, and when to go longer.
- **Verification**: `node --test scripts/test/crew-voice.test.mjs`; `npm test`; `node scripts/measure-prompt.mjs` (prompt cost per agent, before and after).
- **Evidence**: the tests red before the edit; the measure-prompt delta, which must not grow by more than 150 tok per agent.
- **Prohibited**: restating the rule in a skill or rules file; touching pilot.md outside "Writing to the user".
- **Done when**: the three tests pass and no definition grew by more than 15 lines.
