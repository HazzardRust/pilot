# S7 Install brings an earlier machine to the current rules

Feature `crew-voice-rules` · delivers spec 13 · source: `../architecture.md` §2, L13, L19 · after: –

## Files owned

- `scripts/build-rules-ledger.mjs` (new): writes the ledger from `git log` over `rules/`.
- `scripts/shipped-rules.json` (new): `{ "<path under rules/>": ["<sha256>", …] }` for every version ever shipped, `common/` included.
- `scripts/install-rules.mjs`: replaces a shipped copy, deletes a shipped file no longer in `rules/`; `RETIRED_RULES` folds into the ledger.
- `scripts/test/install.test.mjs`: the pins.
- `docs/INSTALL.md`: the rules row and §6 say what an update does.

## Interface

```
node scripts/build-rules-ledger.mjs [--check]     // --check exits 1 when the ledger is stale
installRules(opts) -> { written, identical, updated, differing, pruned, failed, changed, notes, ... }
  updated: target matched a ledger hash for its path and differed from source -> replaced
  pruned:  target path absent from source and its hash in the ledger -> deleted (empty dirs removed)
  differing: target matched no ledger hash -> left alone, named
```

## Tests

1. `a copy of an older shipped version is replaced`: fixture holds 7df34ba's `orchestration.md`.
2. `a hand-edited file is left alone and named`.
3. `a shipped file since removed is deleted`: fixture holds a `common/` file and a fake removed path in a test ledger.
4. `every current rules file's hash is in the ledger`: `build-rules-ledger --check` is clean.
5. `a second install changes nothing`.

  them as updated; a file the user edited is reported and untouched.

- **Prohibited**: overwriting by mtime or by a normalised comparison; any write outside the target; running a non-dry install from the test.
