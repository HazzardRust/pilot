# S11 check-references fails on a dead rules reference

Feature `crew-voice-rules` · delivers spec 11, 12 · source: `../architecture.md` §2, L14 · after: S10

## Files owned

- `scripts/check-references.mjs`: three new checks on `rules/` files.
- `scripts/test/pilot-agents.test.mjs`: the planted-reference pins (this is where check-references is tested today).

## Interface

```
node scripts/check-references.mjs [<path> ...]   // unchanged CLI; exits 1 on any of:
  rules file names CLAUDE.md                      -> "defers to a CLAUDE.md a fresh install does not have"
  rules file links a relative .md that does not resolve beside it
  rules file names `skill: <x>` and skills/<x>/SKILL.md does not exist
```

The existing shape-only allowance (`rules/…` prose, `<name>` placeholders) still applies.

## Tests

1. `a planted CLAUDE.md reference in a rules file goes red`.
2. `a planted dead relative link goes red`.
3. `a planted unshipped skill: goes red`.
4. `the real tree is green`.

## Done

- **Expected**: a future re-sync that brings back `../common/` links or an unshipped skill pointer fails
  the check before it ships.
- **Verification**: `node --test scripts/test/pilot-agents.test.mjs`; `node scripts/check-references.mjs`; `npm test`.
- **Evidence**: the three planted cases red with their messages; the real tree green.
- **Prohibited**: an allow-list entry for a real dead reference; scoping the check off `rules/`.
- **Done when**: the four tests pass and the real tree is green.
