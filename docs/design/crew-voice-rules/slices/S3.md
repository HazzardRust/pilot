# S3 The fundamentalist argues the case against

Feature `crew-voice-rules` · delivers spec 1 · source: `../architecture.md` §2, L2 · after: S1

## Files owned

- `agents/pilot-fundamentalist.md`: the Why, the Report section and the description.
- `scripts/test/fundamentalist-case.test.mjs` (new): the pins.

## Interface

```
## Report (pilot-fundamentalist.md), items in order:
0. The case against   -- strongest argument the design is wrong; the design you would have built; what could go
1. The verdict        -- clean only with "attacked: <what>, held because <why>" per attack
2. Tools table  3. Findings table  4. Friction   (unchanged)
```

The stance sentence: the default is that the design is wrong until the diff shows it is
not; agreeing with the artefact is not a finding and is not evidence.

## Tests

1. `the report opens with The case against`: it is the first numbered item under `## Report`.
2. `a clean verdict names what was attacked`: a sentence ties `clean` to `attacked` and `held`.
3. `the definition states the adversarial default`: a sentence contains `wrong until` (or equivalent pinned wording) and `design`.

## Done

- **Expected**: the fundamentalist's next report starts by arguing against the feature's design and
  never says clean without naming what it tried to break.
- **Verification**: `node --test scripts/test/fundamentalist-case.test.mjs`; `npm test`.
- **Evidence**: the tests red before the edit and green after.
- **Prohibited**: lengthening the report cap past about 65 lines; dropping the subtraction pass or the tools.
- **Done when**: the three tests pass and the definition grows by no more than 15 lines.
