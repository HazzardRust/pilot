# S2 A reply shows who has seen it

Feature `crew-waits` · delivers spec 9, 10 · source: `../architecture.md` §2, L7 · after: –

## Files owned

- `deck/ui/render.mjs`: `renderMessage` draws a seen mark under a user reply that carries `deliveredTo`.
- `deck/ui/deck.css`: the mark's style, if `type-note` does not already serve.
- `deck/test/seen-by.test.mjs` (new): the pins.

## Interface

```
renderMessage(message): string
  // a user message with deliveredTo 'qa' draws: Seen by qa · <time of deliveredAt>
  // deliveredTo ['qa','pilot'] draws: Seen by qa and pilot
  // no deliveredAt, or a non-user message: no mark
  // each name passes through OWNER_KINDS, and anything else is dropped, never written raw
```

## Tests

1. `a taken reply shows Seen by its kind and the time`.
2. `a Sign off delivered to qa and pilot shows both names`.
3. `an untaken reply shows no mark`.
4. `a deliveredTo outside the owner kinds is not rendered`: no injection through a hand-edited store.
5. `a reply taken while the page is open gets its mark in the swapped live region`: this uses the existing
   `/events` swap, with no reload.

## Done

- **Expected**: on a thread page, a user reply that a wait or a read has taken reads "Seen by qa" under it,
  and a Sign off reads "Seen by qa and pilot". The mark appears without a reload.
- **Verification**: `node --test deck/test/seen-by.test.mjs`; `npm test`.
- **Evidence**: the tests failing before and passing after. A scratch deck on a spare port, seeded with three
  replies (untaken, taken by qa, a Sign off taken by both), seen in a browser. Then a fourth reply is taken
  through `deck_wait` while the page is open, and its mark appears in place.
- **Prohibited**: changing `threadState`'s words (L7); storing a new field; unescaped names.
- **Done when**: the tests are green and the four marks have been seen in a browser, the last of them live.
