# S3 The teacher and the auditor wait in the background on their own item

Feature `crew-waits` · delivers spec 5 · source: `../architecture.md` §2, L4, L5, L9, L12 · after: S1

## Files owned

- `agents/pilot-teacher.md`: `Bash` added to `tools:` and `deck_wait` removed (L12). The lesson wait becomes
  `pilot wait --as teacher --item <lesson id>` in the background, with the turn ended. One sentence limits
  Bash to that command.
- `agents/pilot-auditor.md`: step 3 becomes the same wait, `--as auditor --item <audit id>`, restarted on each
  exit while the item is open. `deck_wait` comes out of `tools:`.
- `skills/grilling/SKILL.md`, `skills/wizard/SKILL.md`, `skills/diagnosing-bugs/SKILL.md`: "any other agent
  parks on `deck_wait`" becomes "the pilot and the crew keep a background `pilot wait --as <kind>`; any other
  agent parks once on `deck_wait`". One clause each, and each skill's provenance header is kept.
- `scripts/test/crew-waits.test.mjs`: extended.

## Interface

```
pilot-teacher tools: Read, Grep, Glob, Bash, SendMessage, deck_post, deck_reply, deck_resolve
pilot-auditor tools: unchanged but for deck_wait removed
S1's `pilot wait --as <kind> --item <id>`
```

## Tests

1. `no crew agent file tells its agent to wait inside deck_wait`: across `agents/pilot-*.md`, in prose and in
   `tools:`.
2. `the teacher waits on its lesson with pilot wait --as teacher --item, in the background`.
3. `the auditor waits on its audit item with pilot wait --as auditor --item, restarted while open`.
4. `the teacher's Bash is limited to pilot wait in its prose`.
5. `grilling, wizard and diagnosing-bugs name the crew's background wait`.

## Done

  on the lesson wakes only the teacher, and a second lesson's teacher does not take it.

  `node scripts/check-provenance.mjs`; `npm test`.

  teacher subagents on two lessons: each one's reply wakes only its own teacher.

  editing a vendored skill beyond the one clause.
