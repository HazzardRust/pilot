# S9 The landing readies the feature PR

Feature `clean-landing` · delivers spec 13 · source: `../architecture.md` §2, §5 L9 · after: S4 (`scripts/land.mjs`), S8 (`noteLanding`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer` (process start: `gh`)

## Files owned

- `scripts/land.mjs`: `ready` beside `comment`, on each open PR whose head is the feature, against the default branch.
- `scripts/test/land-ready.test.mjs` (new): the pins.

## Interface

```
// Marks each open draft PR with head `head` and base the default branch ready; answers the numbers readied.
function ready(opts: { gh: (args: string[]) => string, head: string, base: string }): number[]
land(...) // answers `readyFailed?: string`; main prints `pr ready failed: <why>` and keeps exit 0 (landed)
S8's noteLanding carries the `pr ready failed` line to the row
```

## Tests

1. `a landed feature's draft PR is marked ready`: `ready` → `gh pr ready <n>` called once.
2. `a refused ready still lands and says why`: `ready` → `pr ready failed: <why>` printed, exit 0.
3. `a slice PR against feat/ is never readied`: `ready` → only base-default PRs touched.
4. `an already-ready PR is left alone`: `ready` → no call.

Rewrite check: reading the PR through the GitHub API instead of `gh` keeps all four.

## Done

- **Expected**: after a press the feature PR is ready for review, or the row says why not.
- **Verification**: `node --test scripts/test/land-ready.test.mjs scripts/test/land.test.mjs`; `npm test`.
- **Evidence**: tests 1 and 2 red before, green after.
- **Prohibited**: readying before the merge into pilot is pushed; `gh pr merge`; readying a slice PR.
- **Done when**: the four tests and `npm test` are green.
