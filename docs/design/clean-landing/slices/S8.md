## Interface

```
// Sets the ticket's record's feature row to `landed` or `refused`, with land's line (its last 300 chars) as the note.
// Also carries a `pr ready failed: <why>` line from a landed run (S9). Never throws for a ticket with no record.
export function noteLanding(repo: string, ticketId: string, outcome: { ok: boolean, line: string }): void
```

## Tests

1. `a refused landing writes its line on the feature row`: `noteLanding` → the record's feature row reads `refused` with the line, failing names included.
2. `a landed landing writes landed`: `noteLanding` → `landed` with the SHA.
3. `a ticket with no record is a no-op`: `noteLanding` → nothing written, no throw.
4. `the settle reaches the row`: `noteLanding` → through `startLanding` with a stubbed `land` exiting 1, the row and the gate2 both carry the line.

Rewrite check: storing the note outside the record keeps tests 1, 2 and 4.
