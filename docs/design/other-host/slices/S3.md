# S3 `pilot pr` writes the feature review through Host

Feature `other-host` · delivers spec 2, 3 · source: `../architecture.md` §2, §3 · after: S1 (`Host`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a host write moves under a new seam, the security trigger.

## Files owned

- `scripts/feature-pr.mjs`: deck-writes-github's `syncFeaturePr` takes `host` in place of `gh`; find, open, edit
  and the marker comment become `host.reviews`, `open`, `view`, `editBody`, `upsertComment`.
- `scripts/test/feature-pr-host.test.mjs` (new): the pins over a fake host.

## Interface

```
S1's Host: the injected writer
syncFeaturePr({ host, git, record }) -> { line: string, number?: number, wrote: 'created' | 'edited' | 'none' }
line at none: `no review: host none`
```

## Tests

1. `the first sync opens one draft review`: `syncFeaturePr` → 1 `open({ draft: true, base: 'pilot', head: 'feat/<slug>' })`, line `feature PR #<n> opened`.
2. `the same record writes nothing`: `syncFeaturePr` → 0 writes when `view` returns the same body.
3. `QA's comment upserts by marker`: `syncFeaturePr` → 1 `upsertComment(n, '<!-- pilot:qa -->', file)`.
4. `at none nothing is written`: `syncFeaturePr` → line `no review: host none`, exit 0, 0 writes.

Rewrite check: a GitLab host behind `Host` keeps every count and line above.
