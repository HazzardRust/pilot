Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer` (a process start: PowerShell)

## Interface

```
type PathResult = { action: 'added' | 'present' | 'would-add' | 'failed', where: string, why?: string }
type Registry = {
  read(): { user: string | null, userKind: 'String' | 'ExpandString' | null, machine: string }  // raw, unexpanded
  write(value: string, kind: 'String' | 'ExpandString'): void   // throws when refused
  broadcast(): void                                             // WM_SETTINGCHANGE "Environment"
}
persistPath(dir: string, options?: { platform?, env?, home?, registry: Registry (required on win32), dryRun?: boolean }): PathResult
powershellRegistry(spawn = spawnSync): Registry   // spawn injected so a test records the call, never runs it
installCommand(options & { path?: object }) → report & { path?: PathResult }
```

## Tests

1. `a directory in neither registry value is appended to the user value`: `persistPath` → `added`, write called once with the old value plus `;<dir>`, kind kept, broadcast once.
2. `a directory only on the process PATH is still added`: `persistPath` → `added` (the user's temp-variable case).
3. `a directory already in the user or machine value, %VAR% expanded, writes nothing`: `persistPath` → `present`, no write, no broadcast.
4. `a refused write is a failed result naming the directory`: `persistPath` → `failed`, `why` set.
5. `a dry run writes nothing`: `persistPath` → `would-add`, no write.
6. `the directory reaches PowerShell as data, not script text`: `powershellRegistry` → given a recording `spawn` and a value containing `'; $(calc)`, the value appears only in the spawn's `env`, never in its arguments.
7. `the report says what was written and to open a new terminal; a failure keeps ok`: `installCommand` → note `Added <dir> to your user PATH (HKCU\Environment\Path). Open a new terminal…`; with a refusing registry `ok: true` and the hand-add note.
8. `a refused install writes no PATH`: `installCommand` → no `path` result, adapter untouched.

Rewrite check: replacing PowerShell with `reg.exe` or a native binding behind `Registry` keeps every result above.

## Done

- **Expected**: on Windows, an install whose command directory is not in the registry PATH adds it, keeps the value's kind, broadcasts the change, and says so; a second run says it is already there.
- **Verification**: `node --test scripts/test/install-path.test.mjs scripts/test/install-command.test.mjs scripts/test/scripts.test.mjs`; `npm test`; then live: `node scripts/install-command.mjs --prefix <scratch> --dir <scratch2>`, `reg query HKCU\Environment /v Path`, a new terminal's `echo %PATH%`, a second run, then remove `<scratch>` from the value by hand.
- **Evidence**: test 2 failing before (today's `onPath`) and passing after; the live output of both runs and the `reg query` before and after; the kind unchanged.
- **Prohibited**: no `setx`; no `[Environment]::SetEnvironmentVariable`; no directory interpolated into the PowerShell text (spec 4, A4); no test that writes the real registry; no exit 1 on a PATH failure.
- **Done when**: the tests and `npm test` are green and the live run added, then reported present, a scratch directory in this machine's user PATH.
