# S1 A wait on a file ends by itself and says so

Feature `wait-deadlines` · delivers spec 3 · source: `../architecture.md` §2, §5 L2, L8, §6 A4 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a new CLI verb takes an agent-given path and regex (a CLI argument, the security trigger), and its 50-min cap is the user's (A4).

## Files owned

- `deck/wait-for.mjs` (new): the bounded wait, its argument parsing and its `main`.
- `deck/test/wait-for.test.mjs` (new): the pins, with an injected clock and reader, plus one real-process run.
- `bin/pilot.mjs`: the `wait-for` verb dispatching to `main`, and its line in `usage()`.

## Interface

```
pilot wait-for --file <path> --match <regex> --timeout <minutes>
  // exit 0: prints the first line matching <regex>; exit 2: prints `timed out waiting for <regex> in <path> after <minutes> min`;
  // exit 1: usage, a missing or bad --timeout (<= 0 or > 50), a --match over 200 chars or not a valid RegExp
MAX_WAIT_MINUTES = 50   // inside the one-hour prompt cache (A4)
waitFor({ file, match, timeoutMin, read, now, sleep, pollMs }) -> Promise<{ line: string } | { timedOut: true, waitedMin: number }>
  // read(file) -> string | null (null: not there yet); polls every pollMs (default 2000) until match or deadline
main(argv: string[], { out, err }) -> Promise<0 | 1 | 2>
```

## Behaviours

1. `a marker that comes is printed` (test): `waitFor` → `{ line }` holding the first matching line once `read` returns it on the third poll.
2. `a marker that never comes times out` (test): `main` → 2 and stdout `timed out waiting for ^exit in /tmp/x.log after 0.02 min` with a clock past the deadline.
3. `no deadline, no wait` (test): `main` → 1 for no `--timeout`, `--timeout 0`, `--timeout 51`, a 201-char `--match`, and `--match "("`.
4. `a missing file is not a match` (test): `waitFor` → keeps polling while `read` returns null, times out at the deadline.
5. `the real command ends` (run): `node bin/pilot.mjs wait-for --file <tmp> --match never --timeout 0.02` exits 2 within 5 s.

Rewrite check: replacing polling with `fs.watch` keeps 1-4: the line, the exit codes and the timeout text.
Misses: an agent choosing the wrong marker (wait B's `# fail`); the S2 refusal reason and S5's rule read that.

## Done

- **Expected**: an agent waiting on a log runs `pilot wait-for`, and it ends by itself with a line that says which.
- **Verification**: `node --test deck/test/wait-for.test.mjs`; the run in behaviour 5; `npm test`.
- **Evidence**: behaviours 1-4 red before the module exists, green after; behaviour 5's output pasted.
- **Prohibited**: no default `--timeout`; no shell spawned; no write to the watched file; no `eval` or `new Function`.
- **Done when**: the four tests, the real run and `npm test` are green.
