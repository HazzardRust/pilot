# S2 An unbounded wait loop is refused before it runs

Feature `wait-deadlines` · delivers spec 2, 8 · source: `../architecture.md` §2, §3 cause table, §5 L2-L4, L8, §6 A3 · after: S1 (the deny reason names `pilot wait-for`, which check-references needs dispatched; seam change by the co-pilot, 2026-11-20)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a PreToolUse hook (agent configuration, the security trigger) that can misfire on every crew shell call.

## Files owned

- `hooks/shell-write-guard.js`: `unboundedWaits` export on the existing tokeniser; `decide` denies on it as on a write.
- `hooks/test/wait-guard.test.js` (new): the denials, the allowances, the four recorded commands, fail-open.
- `scripts/test/wait-deadline-lint.test.mjs` (new): no file under `agents/ skills/ rules/ scripts/` shows an unbounded wait.

## Interface

```
unboundedWaits(command: string) -> Array<{ form: 'until' | 'while', marker: string | null }>
  // each until/while loop whose body runs `sleep`, not under `timeout <n>` with n <= 3000 s (A4); marker: the first grep/test pattern in the condition
decide(payload, deps) -> PreToolUse deny | null
  // deny when isPilotLane(payload) and unboundedWaits(tool_input.command) is non-empty; tool_input.timeout is never a bound (L2)
  // reason: names `pilot wait-for --file F --match RE --timeout M`; a condition reading a subagent's *.output file adds "a subagent
  // reports by message, not its output file: end your turn"; ends "This is not a blocked step: post nothing and carry on."
```

## Behaviours

1. `the recorded loops are refused` (test): `decide` → deny for waits A and B's commands copied verbatim from their transcripts (§3) and C's as the ticket records it.
2. `unbounded shapes are refused` (test): `unboundedWaits` → one entry each for `until …; do sleep 5; done`, `while ! grep …; do sleep 1; done`, a `||` condition, a nested `$(…)`, a heredoc-free one-liner after `cd x &&`, and one with `; echo done` after.
3. `bounded shapes run` (test): `decide` → null for `pilot wait-for …`, `timeout 600 bash -c 'until …'` (but `timeout 7200 …` denied), `for i in $(seq 60); do …; sleep 1; done`, a loop with no `sleep`, and the same unbounded loop with `tool_input.timeout: 300000` still denied.
4. `only pilot lanes, and it fails open` (test): `decide` → null for a non-pilot lane, a malformed payload and an unparseable command.
5. `the repository shows no unbounded wait` (test): `unboundedWaits` → empty for every fenced or inline command under the four directories.

Rewrite check: replacing the tokeniser with another parser keeps 1-5: the same commands denied and allowed.
Misses: a PowerShell or Monitor loop (L9); a loop disguised past the tokeniser; S3's scan is the backstop for both.

## Done

- **Expected**: a crew agent typing an endless `until grep` is told at once to use `pilot wait-for`, and nothing runs.
- **Verification**: `node --test hooks/test/wait-guard.test.js hooks/test/shell-write-guard.test.js scripts/test/wait-deadline-lint.test.mjs`; `npm test`.
- **Evidence**: behaviours red before, green after; the existing `shell-write-guard.test.js` unedited and green.
- **Prohibited**: no second tokeniser; no new hook file or matcher; no reading `tool_input.timeout` as a bound; no deny on a parse error.
- **Done when**: the five tests and `npm test` are green with `shell-write-guard.test.js` unedited.
