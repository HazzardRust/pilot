## Files owned

- `deck/tools.mjs`: deck_post's `inputSchema.required` becomes `['kind']`; the body description says a report with a ticket may omit it.
- `deck/closing-report.mjs`: `postFilled` treats a blank body (`""`, whitespace) on a report with a ticket as absent.
- `deck/test/report-post-body.test.mjs`: the pins below, beside the existing ones.

## Interface

```
TOOLS[deck_post].inputSchema.required: ['kind']
postFilled(fields) -> item
  // fields.kind === 'report', typeof fields.ticket === 'string', body undefined or blank -> filled from the record
  // any other kind, blank or no body -> the store's "body must be a non-empty string"; no title -> its title refusal
callTool('deck_status', { slug, slices: [], finished, run }) -> text   // slices required by schema and store (deck/tools.mjs:349, deck/status.mjs:295); [] keeps the stored rows. Seam change, co-pilot 2026-10-21
```

## Tests

1. `the deck_post schema asks only for kind`: `TOOLS[deck_post].inputSchema.required` → deepEqual `['kind']`, so `{kind:'report', ticket}` satisfies it.
2. `a report with an empty body is filled from the record`: `postFilled` → `callTool('deck_post', {kind:'report', ticket, repo, body:''})` stores 1 report whose body equals `closingReportOf(record, gate).body`; whitespace `'  \n'` the same.
3. `a question with a blank body or no title is still refused`: `postFilled` → `body: ''` throws /body must be a non-empty string/; no `title` throws the store's title refusal.
4. `the lander's post then finished closes the record`: `callTool` → after the bodiless post, `deck_status {slug, slices: [], finished:'closing report posted'}` leaves `recordForTicket(repo, ticket).record.finished === 'closing report posted'` and the ticket closed.

Rewrite check: replacing `postFilled` with a store-side fill keeps all four results, because each is read through `callTool` and the schema.
