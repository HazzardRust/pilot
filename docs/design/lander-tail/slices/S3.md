# S3 The landing leaves no land dir

Feature `lander-tail` · delivers spec 4 · source: `../architecture.md` §2, §3, L6 · after: – · diff limit 300 lines
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — precise: one removal step in `clear()`, a boolean result, three fixed tests; no assumed line, no security trigger.

## Files owned

- `scripts/land.mjs`: `clear()` removes `keptDir(checkout, head)` after the prune when it exists, and adds `removed <dir>` or `NOT removed <dir>: <why>`.
- `scripts/sync.mjs`: `removeWorktree` answers whether the directory is gone; its callers ignore it as before.
- `scripts/test/land-clear.test.mjs`: the pins below.

## Interface

```
removeWorktree(cwd, dir) -> boolean   // true when dir no longer exists after the force remove, rmSync and prune
land output after `landed`: `removed <land dir>` | `NOT removed <land dir>: <why>`   // only when the dir existed
```

## Tests

1. `a landing leaves no land dir, node_modules and all`: `removeWorktree` → a landing over a prepared land dir holding `node_modules/x/y.js` prints `landed`, and `fs.existsSync(dir)` is false.
2. `an already-landed feature's prepared land dir goes too`: `removeWorktree` → with the source already on pilot and a prepared land dir present, the dir is gone after land.
3. `a land dir that will not go is named`: `removeWorktree` → with the dir kept by a stubbed failing removal, land's output carries `NOT removed <dir>: ` and the landing still exits 0.

Rewrite check: replacing `removeWorktree`'s git and rmSync steps with another removal keeps all three results, read from disk and land's lines.
