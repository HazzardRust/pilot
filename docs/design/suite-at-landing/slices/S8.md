# S8 The crew's gate steps run the selection

Feature `suite-at-landing` · delivers spec 6 · source: `../architecture.md` §2, L2, L4 · after: S1 (the `test:changed` command)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — agent configuration (the security trigger), and four prompts within their headroom.

## Files owned

- `agents/pilot-implementer.md`: the phase gate and the fix round run `npm run test:changed -- --since=origin/feat/<slug>`.
- `agents/pilot-co-pilot.md`: integrate runs the selection; the full suite is the landing's.
- `agents/pilot-qa.md`: the read-only pass runs `--since=<run remote>/pilot`, not the full suite.
- `agents/pilot-lander.md`: the resolution runs `--since=<pilot tip>`; the landing's run is the full one.
- `scripts/test/suite-at-landing-wording.test.mjs` (new): the pins below.

## Interface

```
crew gate command: `npm run test:changed -- --since=<ref>`, the ref named per agent
landing sentence: "the full suite runs once, at `pilot land`", in each of the four
```

## Tests

1. `each crew gate names test:changed`: `crew gate command` → present in the implementer, QA and lander prompts, each with its ref.
2. `no crew gate runs the full suite`: `landing sentence` → present in all four, and `npm test` absent from their gate steps.

Rewrite check: any wording that keeps the command and the sentence keeps both results.

## Done

- **Expected**: a fresh implementer, QA or lander runs the selection at its gate.
- **Verification**: `node --test scripts/test/suite-at-landing-wording.test.mjs`; `node scripts/check-references.mjs`; `node scripts/measure-prompt.mjs` for each of the four; `npm test`.
- **Evidence**: test 1 red before, green after; each prompt's measure within its headroom.
- **Prohibited**: raising a prompt pin without the measure; touching `agents/pilot.md`'s trivial-path full gate.
- **Done when**: both tests, check-references and `npm test` are green.
