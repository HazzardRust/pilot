# S4 A selected run takes no gate slot

Feature `suite-at-landing` · delivers spec 4 · source: `../architecture.md` §2, L9 · after: S1 (`gate.mjs`'s `--since` branch)
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — one branch on `files`, the slot call moved behind it; the tests name every case.

## Files owned

- `scripts/gate.mjs`: `runGate` calls `slot` only when the run is full (no `--since`, or `files: null`).
- `scripts/test/gate-slot-scope.test.mjs` (new): the pins below, `slot`, `select` and `spawn` injected.

## Interface

```
runGate(args, { select, slot, spawn, ... }) -> number
  // full run: slot() taken and released red or green, as today
  // selected run (files is an array): slot never called; PILOT_GATE_SLOT not set for the suite
```

## Tests

1. `a selected run never asks for a slot`: `runGate` → with `--since` and 2 files selected, an injected `slot` that throws is never called.
2. `a fallback takes a slot`: `runGate` → `--since` with `files: null` calls `slot` once and releases it.
3. `a plain run still takes a slot`: `runGate` → no `--since` calls `slot` once.
4. `a selected run beside two holders starts at once`: `runGate` → with the real `takeSlot` over a temp dir whose 2 slots are held by live pids, it exits without printing `gate: waiting for a slot`.

Rewrite check: moving the slot decision into another module keeps all four results.
