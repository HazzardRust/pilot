# S10 The selector replays the last slice merges

Feature `suite-at-landing` · delivers spec 8 · source: `../architecture.md` §2, A4 · after: S3 (`select-tests.mjs`)
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — a loop over `git log` calling S1's `selectTests`; the output shape is fixed below.

## Files owned

- `scripts/select-tests.mjs`: `replay` and the `--replay <n>` CLI.
- `scripts/test/select-replay.test.mjs` (new): over a fixture with three slice merges.

## Interface

```
replay({ cwd, count: number, git? })
  -> { rows: { sha: string, subject: string, selected: number | 'full', total: number }[], median: number }
  // the last `count` first-parent merges whose subject starts `Merge S<n>`; each one's selection
  // is its diff from its first parent; the median counts a full row as total
node scripts/select-tests.mjs --replay <n>   // one row per merge, then `median <k> of <m> (<pct>%)`
```

## Tests

1. `three merges, three rows`: `replay` → a fixture with three `Merge S<n>` merges answers three rows in log order.
2. `a full row counts as the whole suite`: `replay` → a merge touching package.json is `full` and its total enters the median.
3. `the CLI prints the median line`: `replay` → `--replay 3` prints `median <k> of <m> (<pct>%)` last.

Rewrite check: replaying through temporary worktrees instead of trees keeps all three.

## Done

- **Expected**: `node scripts/select-tests.mjs --replay 20` on pilot prints 20 rows and a median at most 60%.
- **Verification**: `node --test scripts/test/select-replay.test.mjs`; `npm test`; `node scripts/select-tests.mjs --replay 20` in the slice worktree.
- **Evidence**: the replay's output pasted into the PR body.
- **Prohibited**: checking out the merges in the caller's worktree; a hard-coded median.
- **Done when**: the three tests and `npm test` are green and the replay output is in the PR.
