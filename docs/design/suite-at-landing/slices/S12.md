# S12 The spawn ceiling names the tests that spent it (added)

Feature `suite-at-landing` · delivers spec 10 (added at step 7, the fundamentalist's thread 1, kept by the pilot) · source: `../architecture.md` §2 · after: the step 7 fix round (`gate.mjs`'s `SPAWN_CEILING` at 12100)
Reviewers: `pilot:typescript-reviewer`
Model: opus — the attribution has to follow a test's spawns through the node children it starts, and a wrong owner misleads the lander.

## Why

The full suite now runs only at `pilot land`, so `spawns over <ceiling>` is the lander's red, and today it names no test.
A lander given an anonymous count cannot tell which fixture pushed it over.

## Files owned

- `scripts/count-spawns.mjs`: each spawn line also carries the test file that owns it.
- `scripts/gate.mjs`: `spawnLines` prints the top owners when the count is over the ceiling.
- `scripts/test/gate-spawns.test.mjs`: the pins.
- `scripts/test/suite-at-landing-docs.test.mjs`: kept finding N2b, carried here: line 48 stops pinning `| proposed |` in the ADR index and matches any status cell, so accepting ADR 0166 does not turn it red.

## Interface

```
// count-spawns.mjs: a spawn line is `<parent pid> <file> <owner>`; <owner> is the repo-relative test file whose
// process (or an ancestor node of it) made the spawn, carried down by env PILOT_GATE_OWNER, set once in the first
// node process whose argv[1] matches TEST_GLOB; `-` when none. Old two-field lines still parse.
spawnCount(file) -> { total, node, git, other, owners: Map<owner, n> }
// gate.mjs, over the ceiling only:
spawns over <ceiling>; most: <owner> <n>, <owner> <n>, <owner> <n>
```

## Tests

1. `spawnCount attributes a line to its owner`: a spawn file with three-field and two-field lines gives `owners` counts, the two-field lines under `-`.
2. `over the ceiling the gate names the top three owners`: `runGate` with a stub spawn file over a low `ceiling` prints `spawns over <c>; most: a.test.mjs 5, b.test.mjs 3, c.test.mjs 1`; under the ceiling it prints the count line alone, as today.
3. `a test's node child inherits its owner`: one fixture test file that spawns `node -e` which spawns `git --version`, run under the counter; both lines carry that test file.

## Done

- **Expected**: under the ceiling the gate's output is unchanged; over it, the line names three files.
- **Verification**: `npm run test:changed -- --since=<feat tip before the merge>`; `node --test scripts/test/gate-spawns.test.mjs`.
- **Evidence**: the `most:` line from test 2, and the full suite's `spawns` line, in the PR body.
- **Prohibited**: patching `child_process`; raising `SPAWN_CEILING`; any change to what is counted.
- **Done when**: the three pins and the selection are green, within the 40-line limit if it can be, the per-slice limit otherwise.
