# S4 Integration and the fundamentalist call it when a slice did not

Feature `security-reviewer` · delivers spec 3, 4 · source: `../architecture.md` §2, A2, A4 · after: S1
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `agents/pilot.md`: step 5 does not integrate a slice whose Reviewers line names security without a security verdict in its report, and spawns the reviewer on the slice PR; step 7 spawns it on a "consider calling" row.
- `agents/pilot-fundamentalist.md`: `## Report` gains the "consider calling" row, written when the feature diff hits S1's trigger in files no slice's security verdict covered; "You do not spawn agents" stays.
- `scripts/test/security-trigger.test.mjs`: the step-5, step-7 and fundamentalist pins.

## Interface

```
Fundamentalist report, last row when it applies:
  | consider | <file>, <file> | consider calling `pilot:security-reviewer` on these files: <trigger hit> | spawn it at step 7 |
pilot.md step 5: "no security verdict, no integration" for a slice named for security
pilot.md step 7: a "consider calling" row is acted on by spawning `pilot:security-reviewer` (not triaged away)
S1's security trigger: the list both rules read
```

## Tests

1. `step 5 holds a slice named for security until its verdict is in`: the step-5 paragraph names the verdict and the spawn.
2. `the fundamentalist says to consider calling the security reviewer`: the Report section carries "consider calling `pilot:security-reviewer`".
3. `the fundamentalist still spawns nothing`: no `Agent` in its tools; "You do not spawn agents" intact.
4. `step 7 spawns the security reviewer on a consider row`: the step-7 paragraph says so.

## Done

- **Evidence**: tests red then green; the co-pilot reads steps 5 and 7 from `pilot.md`, so no co-pilot edit.

- **Done when**: `npm test` is green and the four pins hold.
