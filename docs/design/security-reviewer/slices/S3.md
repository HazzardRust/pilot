# S3 The reviewer checks agent configuration

Feature `security-reviewer` · delivers spec 6 · source: `../architecture.md` §2, §3.1, §4, L4, L7 · after: S2
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `agents/security-reviewer.md`: a `## Agent configuration` section, the config checklist, applied when the diff touches agent configuration; header `adapted:` says it was added.
- `VENDOR.md`: the `agents/security-reviewer.md` row records the added section.
- `vendor/toolbox.md`: the same row.
- `scripts/test/security-reviewer.test.mjs`: the checklist pins.

## Interface

```
agents/security-reviewer.md
  ## Agent configuration       // when the diff touches agents/, hooks/, skills/, settings*.json, .mcp.json, CLAUDE.md
    - Hook commands            // what each runs, on what input, whether tool input reaches a shell
    - Permission allow-lists   // wildcards, Bash(*), rules wider than the ticket needs
    - MCP servers and args     // unpinned packages, remote URLs, args carrying secrets
    - Secrets                  // tokens or keys in settings or CLAUDE.md
    - Skills that run commands // what a skill tells an agent to execute
  One report row per item checked; an item with nothing wrong is a row whose Finding reads "clean"
S1's security trigger: the agent-configuration list this section reads
```

## Tests

1. `the security reviewer carries the agent-configuration checklist`: the section exists and names all five items.
2. `the checklist applies on agent configuration`: the section names the agent-configuration paths of S1's trigger, worded as S1 words them.
3. `every checked item is a row`: the section says one report row per item, inside `## Report format`'s table.
4. `the checklist runs nothing`: the section contains no `npx`, `npm install` or third-party scanner name.

## Done

- **Expected**: a reviewer spawned on a slice that changes `agents/` or `hooks/` returns a row for each of the
  five checklist items, beside its OWASP rows.
- **Verification**: `node --test scripts/test/security-reviewer.test.mjs scripts/test/report-format.test.mjs scripts/test/toolbox.test.mjs`; `npm test`.
- **Evidence**: tests red then green; this slice's own PR body carries the security reviewer's checklist rows
  (the slice touches `agents/`), the real review spec 6 asks for.
- **Prohibited**: touching `## Report format` (pinned); a checklist item without its row; any download or
  scanner; editing `pilot-implementer.md` (S1's).
- **Done when**: `npm test` is green and the slice PR shows one checklist row per item from a real review.
