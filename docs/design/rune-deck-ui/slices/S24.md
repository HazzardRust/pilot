# S24 A press posts off the UI thread, and its answer settles in one place (added)

Model: opus — a new seam (`act::send`) that later regions move onto; the settle order in `app::poll` is judgement.

Added by the co-pilot (2026-11-20) from the step 7 review: `act.rs` offers only the blocking `Client::act`, so each
region built its own off-thread post (queue.rs:141-183, history.rs:51-87, chat.rs:83-160, reply.rs:198-235) or posts
on the UI thread under the 5 s timeout (tickets.rs:64,100, strip.rs:131, notifications.rs:64, tabs.rs:152), against
spec 5's one-frame press. Two bugs come of it: a refused run dismiss leaves its button disabled for good
(history.rs:81, :115: `dismissed` is cleared only when the thread fails to start), and a refused notice clear is
dropped silently while any error reads "deck not running" (notifications.rs:63-68).

## Interface

- `act::send(sender, key, action)`: posts on a thread of its own and leaves `(key, Result<Acted>)` for the UI
  thread, waking the window.
- `act::Pending`: the window's one table of posts in flight, keyed; `settle(&mut self)` returns the answered posts,
  taken once in `app::poll`; `is_sent(key)` for a control's disabled state.

## Files owned

- `deck/rune/src/act.rs`: `send`, `Pending`.
- `deck/rune/src/app.rs`: `poll` settles `Pending` once; `queue::settle`'s own call goes.
- `deck/rune/src/regions/queue.rs`, `regions/history.rs`, `regions/notifications.rs`: post through `act::send`;
  delete queue's `press` thread, history's copy of it and its `refused` Arc; a refusal shows on the control that sent it.
- `deck/rune/tests/history.rs`, `tests/notifications.rs`: the pins.

## Behaviours

1. `a refused dismiss can be pressed again` (test): scratch deck, a run dismiss the deck refuses: the refusal's words
   drawn and `run-<id>-dismiss` enabled again. Red today (F5, T2).
2. `a refused notice clear says so` (test): a clear the deck refuses: its words drawn, not "deck not running" (F9).
3. `a press is drawn before the deck answers` (test): with a deck that holds the post, the pressed control is
   drawn disabled in the next frame and the UI thread never waits on the post.
