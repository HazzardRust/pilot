## Interface

```
theme::tokens(dark: bool) -> Tokens
Tokens { by: { pilot, architect, implementer, fundamentalist, qa, teacher, explorer, auditor, other },
         state: { waiting, pilot, resolved, unacknowledged }, accent: { green, yellow, red, blue, plain },
         usage: { fine, warm, high, critical, critical_bg }, rule, quiet, font: Mono 13px/1.6 }
theme::motion: { panel: Spring, card: Spring, press: Spring }
theme::space: { s0..s8: 0,2,4,8,12,16,24,32,48 px; within: s2, pad: s3, between: s5, panels: s6,
  row: 20, card_line: 24, cols: StatusCols { state: 12ch, time: 7ch, gap: s5 } }
```

## Behaviours

1. `every colour is deck.css's` (test): `theme::tokens` → for both modes, each value equals the one parsed from `deck/ui/deck.css` (the `color-mix` at 35% and the `light-dark` pairs computed).
2. `the font is the deck's` (test): `theme::tokens` → monospace stack led by Cascadia Mono, 13 px, line 1.6.
3. `the motion is springs` (test): `theme::motion` → each a `Spring` that settles under 300 ms.
4. `between is at least twice within` (test): `theme::space` → `between >= 2 * within` and `panels >= between`, every step on the 4 px grid but s1.
5. `no region spaces by hand` (test): `theme::space` → a scan of `src/regions/*.rs` finds 0 numeric literals passed to gap, padding, margin or height.

Rewrite check: any theme read from deck.css's values keeps 1-2.
Misses: whether the springs feel right; the user's look.
