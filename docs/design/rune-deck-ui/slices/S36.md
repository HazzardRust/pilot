# S36 theme.rs takes its values from one JSON file (added)

Feature `rune-deck-ui` · delivers spec 23 (added), keeps spec 2's colours · source: the user's pick on itm_2d4d885b5e13 (the token playground); `deck/DESIGN.md` §6 · after: the pivot, run beside S26 (main, so the playground reaches the user sooner). Model: sonnet — one file format and one loader; every token is already named in theme.rs.

## Files owned

- `deck/rune/theme.json` (new): every value `theme.rs` defines at your base, keyed 1:1 to theme.rs's field names (colours light and dark as `#rrggbb` hexes and their 35% hue, font, sizes, the space scale, radius, hover tint, springs). This is the file the playground (S37) exports.
- `deck/rune/src/theme.rs`: reads `theme.json` at build time (`include_str!`), parsed once (`std::sync::LazyLock`). Assumed A-R2: build time, no runtime reload. The public API `tokens(dark)`, `space::*`, `motion::*`, `radius`, `size` keeps its names, so no region changes. A malformed file fails `cargo build` or the first test, never the window at runtime.
- `deck/rune/tests/theme.rs`: the colour parity with deck.css now runs through the JSON. New `theme json` test.
- `deck/DESIGN.md` §4: "the values live in deck/rune/theme.json".

From here on every new token lands in theme.json, never as a literal in theme.rs.

## Behaviours

1. `theme json` test: every key in theme.json is read, and every theme.rs value comes from one. A key renamed or removed fails the test by name.
2. The colour parity with deck.css stays green unchanged (spec 2).
3. Every existing test stays green, with no region edited.
