# S6 Deck actions post their form routes and change the store

Feature `rune-deck-ui` · delivers spec 3 · source: `../architecture.md` §2, §3 Actions, §5 L3 · after: S5 (`act::post`)
Reviewers: `pilot:rust-reviewer`, `pilot:security-reviewer`
Model: opus — writes that change a whole deck (add, remove, start a session) at an API boundary.

## Files owned

- `deck/rune/src/act_deck.rs`: `DeckAction`.
- `deck/rune/tests/act_deck.rs` (new): the pins, against a scratch daemon.

## Interface

```
enum DeckAction { Create { name, repo }, AddDeck { path }, RemoveDeck { repo }, StartSession { repo },
                  Move { id, up: bool }, Switch { repo, to }, CancelSwitch { repo, to },
                  Alerts { weekly: bool }, ClearNotice { id }, ClearNotices }
impl Form for DeckAction   // each to its route in §3 Actions, with `back`
S5's Client::act, Acted
```

## Behaviours

1. `create, move, switch and cancel land` (test): `DeckAction` → posted through `Client::act`, each store change equals its form POST's on a scratch daemon.
2. `add and remove deck land` (test): `DeckAction` → `AddDeck` of a temp repo adds a tab; `RemoveDeck` of an ended one removes it.
3. `alerts and notices land` (test): `DeckAction` → `Alerts { weekly: false }` reads back off; `ClearNotice` and `ClearNotices` empty the notices.
4. `start is refused in the suite` (test): `DeckAction` → `StartSession` on a scratch daemon is `Acted::Refused` or `Taken` with no terminal opened (the deck's own test guard).

Rewrite check: any client posting the form routes keeps 1-3.
Misses: Start opening a real terminal; QA's walkthrough on Windows.
