# S37 The token playground: one page that exports theme.json (added)

Feature `rune-deck-ui` · delivers spec 23 (added) · source: the user's pick on itm_2d4d885b5e13, its question body as the scope · after: S36 (theme.json's keys)
Reviewers: `pilot:typescript-reviewer`
Model: opus — the page is the user's design tool, and its colour mix has to match Rune's to the byte.

## Files owned

- `deck/rune/playground/index.html`: one self-contained page, no build step and no network fetch. It holds:
  - a mock of the deck's layout: title bar, icon bar and side area, tabs, a queue card, an open thread with its kind line, the right strip;
  - a control per token in theme.json (about 60 colours with light and dark values, font, sizes, space scale, radius, hover tint, springs);
  - a light/dark preview toggle;
  - **Import** (load the current theme.json) and **Export** (JSON keyed 1:1 to theme.json, downloadable and copyable).
  The page reproduces `color-mix(in srgb, <text> 35%, <hue>)` exactly as `theme.rs` `hue_over` does, so an exported hex equals what Rune draws.
- `deck/rune/playground/README.md`, a few lines: open the page, export, replace `deck/rune/theme.json`, `cargo build --release`. A native Rune screenshot is the final check.
- `deck/rune/tests/theme.rs`: one `playground mix` test. It runs the page's mix on fixed inputs (vectors pinned from the page's JS) and checks them against `hue_over`.

## Behaviours

1. Opened in a browser, the page draws the mock in light and dark. Moving a colour, a radius and a space step changes the mock at once.
2. Round trip: the default import, exported untouched, is byte-equal to theme.json. One changed colour exported into theme.json builds, and shows in a `--snap` PNG.
3. `playground mix` test: the page's mixed hexes equal `hue_over`'s for all eight author hues, light and dark.
