## Interface

```
enum Action { Reply { id, text, choice: Option<String> }, Close { id }, Reopen { id },
              DismissItem { id }, DismissRun { id } }
Client::act(&self, a: &impl Form) -> Result<Acted>
enum Acted { Taken { location: String }, Refused { reason: String } }   // 303 -> Taken; 400/403 text -> Refused
act::post(client, path: &str, fields: &[(&str, &str)]) -> Result<Acted>
  // urlencoded; Authorization: Bearer; Origin: http://<host:port>; no redirect followed
trait Form { fn route(&self) -> &'static str; fn fields(&self) -> Vec<(&'static str, String)>; }
```

## Behaviours

1. `a reply lands` (test): `Client::act` → given `Action::Reply`, `/api/items?id=` shows the text as the user's newest message.
2. `an option press lands as the choice` (test): `Client::act` → given `Action::Reply` with a `choice`, the newest message is the choice; a gate's Sign off is taken (Origin sent).
3. `close, reopen, dismiss and dismiss run land` (test): `Client::act` → each item's state as its form POST makes it.
4. `a refusal comes back with its reason` (test): `Client::act` → `Acted::Refused` with the deck's text for a reply on a closed item.

Rewrite check: any client posting the form routes with the secret keeps 1-4.
Misses: double presses; each region guards its own (S9, S15).
