# S3 `pilot open` opens the Rune deck when it is built

Feature `rune-deck-ui` · delivers spec 1 · source: `../architecture.md` §2, §6 A2 · after: S1 (the binary's path `deck/rune/target/release/pilot-deck[.exe]`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a process start (security trigger) and A2 is assumed.

## Files owned

- `deck/open.mjs`: `openerFor` takes the built binary's path; `openDeck` finds it.
- `deck/test/open.test.mjs`: the pins.

## Interface

```
runeBinary(root: string, platform: string): string | null   // the built pilot-deck binary, or null
openerFor(platform, url, rune: string | null): { command, args }
  // rune set: { command: rune, args: [] }; else the browser opener as today
```

## Behaviours

1. `a built binary is opened` (test): `openerFor` → given a `rune` path, `{ command: rune, args: [] }`, no `cmd /c start`.
2. `no binary opens the browser` (test): `openerFor` → given `null`, today's opener per platform, unchanged.
3. `only the release binary counts` (test): `runeBinary` → `null` for a missing file and for a debug build.
4. `the window opens from pilot` (run): `pilot open` with the binary built shows the window; renamed away, the browser tab.

Rewrite check: any opener choosing on the built file keeps 1-3.
Misses: macOS and Linux paths are built, not run; out of scope.

## Done

- **Expected**: the user's usual way into the deck opens the Rune window once it is built, and the page otherwise.
- **Verification**: `node --test deck/test/open.test.mjs deck/test/no-open.test.mjs`; `npm test`; `pilot open` both ways.
- **Evidence**: 1-3 red before, green after; both opens seen.
- **Prohibited**: no shell in the spawn; no `windowsHide` dropped (ADR 0155); no binary path from an environment variable or a request.
- **Done when**: 1-4 hold and `npm test` is green.
