# S2 A post appears live, and a stopped daemon is said and survived

Feature `rune-deck-ui` · delivers spec 4, 6a, 10 · source: `../architecture.md` §2, §3 · after: S1 (`app.rs`, `Client::view`)
Reviewers: `pilot:rust-reviewer`
Model: opus — threads, reconnect timing and Rune's `AppHandle::update` are judgement calls.

## Files owned

- `deck/rune/src/live.rs` (new): the `/events` reader thread and its backoff.
- `deck/rune/src/app.rs`: starts `live` in `AppSpec::setup`; draws the down banner.
- `deck/rune/tests/live.rs` (new): the pins.

## Interface

```
live::start(client: Client, handle: AppHandle<State>)   // reads GET /events; on `changed` or reconnect, refetches View
State.down: bool          // true while /events or /api/view fails
live::BACKOFF: [Duration] // 250 ms doubling to 2 s
```

## Behaviours

1. `a post shows without input` (test): `live::start` → after a `deck_post` via `/api/tool` on a scratch daemon, the view's `seq` advances and the card text is in `rt.elements()` within 1 s.
2. `a refresh keeps the user's place` (test): `live::start` → with a draft in `State.regions.reply` and a scroll offset set, a refresh leaves both unchanged.
3. `a stopped daemon is said` (test): `live::start` → stopping the scratch daemon sets `State.down`; the tree shows `deck not running`.
4. `a restarted daemon comes back` (test): `live::start` → restarting it clears `State.down` within 2 s and the view is fresh.
5. `every region moves together` (test): `live::start` → after a heartbeat to `/api/agents` on a scratch daemon, the agents region holds it within 1 s and every region's data is from the one `View.seq`.

Rewrite check: any transport that refetches one whole view on change and backs off on failure keeps 1-5.
Misses: how a refresh feels; QA's walkthrough.

## Done

- **Expected**: the window follows the deck without a reload and rides out a daemon restart.
- **Verification**: `cargo test --manifest-path deck/rune/Cargo.toml --test live`; `npm test`.
- **Evidence**: 1-5 red before, green after.
- **Prohibited**: no per-region fetch; no polling loop in place of `/events`; no panic on a refused connection; no sleep-based test waits (ADR 0121).
- **Done when**: 1-5 hold and `npm test` is green.

## Seam change (co-pilot, 2026-11-20)

Rune 7cba77c's `App::headless_runtime` drops the queue `AppHandle::update` writes to (playground/testing.rs:16)
and draining it is pub(crate), so a handle-driven `live::start` cannot be tested. Replaced, moving no spec line
and no locked decision:

```
live::start(client: Client, query: Query, wake: Waker) -> live::Inbox  // thread reads GET /events; on `changed` or reconnect refetches View; keeps the newest Feed and wakes
live::Inbox::take(&self) -> Option<live::Feed>                        // Feed::View(View) | Feed::Down
app::setup(&mut State, Waker) / app::poll(&mut State, f64, &mut Tx) -> bool  // AppSpec.setup/.poll; poll applies the Feed
live::BACKOFF: [Duration; 4] // 250, 500, 1000, 2000 ms
```

`main.rs` (~3 lines) and `Client::events()` change outside the files owned. Behaviours as built, while the
regions are S1 stubs:

- 1: a post to a new repo shows its tab ("beta") in `rt.elements()` and `View.seq` advances within 1 s; card
  text on a live post is shown by S7.
- 2: `reply::Local` gains `draft` with S9's type (`TextEdit`); scroll is pinned by the scroll container's key
  set when `rt.elements()` exposes it, else by a read of the code (only `State.view` is replaced); QA checks
  scroll live.
- 5: a heartbeat brings a fresh View within 1 s, replaced whole in one step; the agents region holding it is
  shown by S14.
