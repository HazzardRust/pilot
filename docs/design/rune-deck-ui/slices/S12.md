# S12 The status table and its ticket selector

Feature `rune-deck-ui` · delivers spec 2 · source: `../architecture.md` §2, §3 · after: S1 (`viewOf`)
Reviewers: `pilot:rust-reviewer`, `pilot:typescript-reviewer`
Model: sonnet — rows mirror `renderRunStatus`; the selector is a `?ticket=` change in `State.query`.

## Files owned

- `deck/view/status.mjs`: held tickets, the chosen one, its slice rows.
- `deck/test/view-status.test.mjs` (new): the view pins.
- `deck/rune/src/regions/status.rs`: selector and table.
- `deck/rune/tests/status.rs` (new): the pins.

## Interface

```
regions::status::draw   // S1's draw signature
statusView(reads, query: { run, ticket }): { tickets: { id, name, lane, chosen }[],
  rows: { slice, state, branch?, pr?, href?, after: string[] }[] }
```

## Behaviours

1. `the rows are the page's` (test): `statusView` → the slices, states and links `renderRunStatus` draws for a fixture record.
2. `a foreign ticket id is dropped` (test): `statusView` → a `ticket` naming no held lane gives the default lane's rows.
3. `the selector switches the record` (test): `regions::status::draw` → choosing a ticket sets `State.query.ticket` and the next view's rows.

Rewrite check: any status view of the held lanes keeps 1-2.
Misses: wide-table overflow; the user's look.

## Seam change (co-pilot, 2026-11-20)

S2's reader froze its `Query` at setup, so a region that changes the query was undone by the next `changed`.
S12 adds, in `deck/rune/src/live.rs` (S2's file, ~20 lines): `live::Inbox::ask(&Query)`, a query shared with
the reader, which refetches with it. It is the one way a region changes what the reader fetches; S8 and later
screen slices call it. Moves no spec line and no locked decision. S12 also exports `heldTicketsOf` from
`deck/ui/render-rail.mjs`.
