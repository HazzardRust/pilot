# S22 The overview shows one status table per tab (added)

Feature `rune-deck-ui` · delivers spec 13 (added) · source: `../architecture.md` §2 (spec 2), §3 · after: S12 (`statusView`, `regions::status::draw`)
Reviewers: `pilot:rust-reviewer`, `pilot:typescript-reviewer`
Model: opus — the overview's layout has to be read off the page's renderer and held to it.

Added by the co-pilot (2026-11-20) from S12's review: the Rune overview draws a single status table, while the
HTML page's overview shows one per tab (spec 2: where each feature sits is kept).

## Files owned

- `deck/view/status.mjs`: on the overview, one `{ tab, tickets, rows }` group per tab, in the page's order.
- `deck/test/view-status.test.mjs`: the view pins.
- `deck/rune/src/regions/status.rs`: draws each group with its tab's name.
- `deck/rune/tests/status.rs`: the drawing pin.

## Behaviours

1. `the overview's tables are the page's` (test): `statusView` on the overview query → the same tabs, in the same order, each with the slices and states the page's overview draws, for a fixture of two decks.
2. `a deck tab keeps one table` (test): `statusView` on a deck tab's query → S12's single table, unchanged.
3. `each table is drawn under its tab's name` (test): `regions::status::draw` → both tab names and both tables' rows in `rt.elements()`.

Rewrite check: any overview status view listing the page's tables keeps 1-2.
Misses: the user's look.
