## Interface

```
replyView(reads: DeckReads, query: { id }): { mode: 'reply'|'reopen'|'none', options: { label, confirm }[],
  dismiss: bool }
reply::Local { draft: TextEdit, confirming: Option<String>, refused: Option<String>, sent: Option<String> }
```

## Behaviours

1. `the options are the page's` (test): `replyView` → the same labels and confirm flags as `renderReplySlot` for a gate, a question and a walkthrough.
2. `a confirm takes two presses` (test): `reply::Local` → Sign off sets `confirming`; Confirm posts once; Escape clears it.
3. `a refused reply keeps its words` (test): `reply::Local` → after `Acted::Refused`, `draft` still holds the typed text and `refused` the reason (ADR 0096 bug).
4. `a sent reply empties the box` (test): `reply::Local` → after `Acted::Taken`, `draft` is empty.
5. `the press answers in its frame` (look): the button shows pressed before the post returns.

Rewrite check: any reply box that keeps text until the deck takes it keeps 3-4.
Misses: IME and paste edge cases; QA's walkthrough.
