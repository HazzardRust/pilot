# S21 Escape and left-arrow go back without a Tab first (added)

Feature `rune-deck-ui` · delivers spec 12 (added) · source: `../architecture.md` §2, S8's report · after: S8 (`regions::thread::back`)
Reviewers: `pilot:rust-reviewer`
Model: sonnet — the handler exists in `regions/thread.rs`; only where the key reaches it changes.

Added by the co-pilot (2026-11-20) from S8's review: `regions/thread.rs` puts `.on_key(back(..))` on the thread
element, which receives keys only once it holds focus, so Escape and ← are dead until a Tab moves focus there.
On the page they work as soon as the thread opens.

## Files owned

- `deck/rune/src/regions/thread.rs`: where the back keys are caught.
- `deck/rune/src/app.rs`: only if the key has to be routed from the window root.
- `deck/rune/tests/thread.rs`: the pin.

## Behaviours

1. `Escape goes back with nothing focused` (test): a thread just opened, no Tab, Escape → `State.query` is the owning deck's view.
2. `left-arrow goes back with nothing focused` (test): as 1, with ←.
3. `a key typed into a field is not stolen` (test): with a text field focused (the reply box once S9 lands, else any focused input in the tree), ← moves the caret and does not go back.
