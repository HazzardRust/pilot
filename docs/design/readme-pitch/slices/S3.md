## Files owned

- `README.md`: a numbered walkthrough (≤ 11 lines) directly above the mermaid fence in `## How it fits together`; any sentence the claim pass finds stale, fixed.
- `scripts/test/readme-flow.test.mjs`: the walkthrough pins; the graph pins unchanged.
- `scripts/test/readme-pitch.test.mjs`: the link and name pins.


## Tests

1. `the walkthrough is short and above the graph`: `walkthrough` → 1–11 steps, before the fence, in the same section.
2. `every step is a node`: `walkthrough` → each step names a node label of `readFlow`'s graph (ticket, grilling, Gate 1, co-pilot, QA, Gate 2, land).
3. `every relative link resolves`: `links` → each target exists in the tree.
4. `every command and agent named exists`: `section` → each `pilot <cmd>` in README.md is in `pilot help`, each `pilot:<agent>` is a file in `agents/`.

Rewrite check: rewording the steps keeps tests 1–2 while each still names a node; renaming a command breaks test 4 by design.

Seam (co-pilot, 2026-10-17): the principles are six (spec 6 and 10; S2 at 78763d86), so the claim table reads six. A5 is *assumed* relaxed to about 60 lines of pitch above the graph: README.md is 237 lines after S2 and the 200-line ceiling is not a gate; keep the walkthrough within its 11 lines and add nothing else.

## Done

- **Expected**: a reader sees the average run in under twelve lines, then the same steps drawn as the graph; every sentence on the page holds at the tip.
- **Verification**: `node --test scripts/test/readme-flow.test.mjs scripts/test/readme-pitch.test.mjs`; the full gate; the rendered README with the walkthrough above the graph.
- **Evidence**: tests 1–4 red on S2's tip, green after; the claim table in the PR body (sentence | mechanism | path | holds/stale) with no stale row left.
- **Prohibited**: changing the graph's nodes or edges; dropping a sentence instead of checking it; a committed claim file (L5); more than 300 changed lines.
- **Done when**: the four tests and the gate are green and the claim table has no stale row.
