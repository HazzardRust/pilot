# S1 `pilot worktrees remove` keeps or removes one tree

Feature `prune-worktrees` · delivers spec 5, 8 · source: `../architecture.md` §2, §3 F5, §5 L1-L6 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the deletion rule itself; a CLI argument names a path to delete (security trigger).

## Files owned

- `scripts/worktree-remove.mjs` (new): `removeTree` and `keptLine`, the one guarded removal.
- `scripts/worktrees.mjs`: the CLI gains `remove <path>`; usage line.
- `scripts/test/worktree-remove.test.mjs` (new): one case per state, the junction, the run.json rule.
- `docs/adr/NNNN-prune-worktrees.md` (new): L1-L7, amending ADR 0081 and 0171.

## Interface

```
removeTree(repo: string, dir: string, opts?: { landed?: boolean, holder?: (dir: string) => string | null, remove?: (home: string, dir: string, force: boolean) => { ok: boolean, err: string } })
  -> { removed: true, branch: string | null } | { kept: KeptState }
type KeptState = 'dirty' | 'unpushed' | 'locked' | 'nested' | `live ${string}` | 'leftover' | 'main' | 'not a worktree'
keptLine(dir: string, state: KeptState) -> string          // `kept <state> <dir>`
pilot worktrees remove <path>                               // exit 0 removed, 1 kept (one line), 2 usage
```

## Behaviours

1. `a junction is unlinked, never followed` (test): `removeTree` → `{ removed: true }` for a tree whose `node_modules` is a junction into a sibling tree; the dir gone, the sibling's files byte-identical.
2. `dirt keeps a tree` (test): `removeTree` → `{ kept: 'dirty' }` for a tracked edit, and for an untracked non-ignored file; the tree intact.
3. `the deck's run.json is not dirt` (test): `removeTree` → `{ removed: true }` with only `docs/design/x/run.json` modified, or untracked.
4. `unpushed work keeps a tree` (test): `removeTree` → `{ kept: 'unpushed' }` on a commit no remote ref, `pilot` or `feat/*` reaches; the branch kept.
5. `a locked tree, a held tree and the main checkout are kept` (test): `removeTree` → `locked`, `live 4242`, `main` respectively.
6. `a dir left on disk is leftover` (test): `removeTree` → `{ kept: 'leftover' }` with the remove step stubbed to leave the dir.
7. `the CLI prints one line` (run): `pilot worktrees remove <dirty tree>` prints `kept dirty <dir>` and exits 1.

Rewrite check: any implementation keeps every tree whose loss would lose a tracked, untracked or unpushed change, and never deletes through a link.
Seam (co-pilot, 2026-11-25): `opts.remove` is the stub point B6 names, defaulting to git's removal; a safe head excludes the tree's own branch; a git refusal of the removal reads `kept leftover`. `nested` (security review, HIGH): a tree holding another registered worktree inside it is kept.

Misses: a Windows handle held by a process the table does not show; QA's real removal on Windows reads that.

## Done

- **Expected**: one command removes a finished tree, links first, or says in one line why it kept it.
- **Verification**: `node --test scripts/test/worktree-remove.test.mjs scripts/test/worktrees.test.mjs`; `npm run test:quiet`.
- **Evidence**: case 1 red before and green after on Windows (a real junction via `fs.symlinkSync(…, 'junction')`); the CLI line run once.
- **Prohibited**: no `fs.rmSync` of a tree dir before git's removal; no `--force` outside `landed`; no killing a holder; no change to `prune` here (S2 folds it).
- **Done when**: the seven behaviours hold and the gate is green.
