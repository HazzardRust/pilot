# S5 Gate 1 and abandon prune the run's trees

Feature `prune-worktrees` · delivers spec 2, 4 · source: `../architecture.md` §2, §3 F4, §6 A3, A4 · after: S2 (`scripts/worktrees.mjs`, `runWorktrees`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a new deck child process (security trigger) and two assumed rules.

## Files owned

- `scripts/worktrees.mjs`: `prune --run <slug> --stage planned|abandoned`.
- `deck/run-prune.mjs` (new): `startRunPrune`, a detached `pilot` child like `startPrWrite`, one note on the ticket.
- `deck/server-tools.mjs`: `deck_status` with `finished` `planned` or `abandoned…` calls `startRunPrune`.
- `deck/test/run-prune.test.mjs` (new): the spawn, its argv and its note, spawn injected.
- `scripts/test/worktrees-stage.test.mjs` (new): the two stage rules on a temp repo.

## Interface

```
pilot worktrees prune --run <slug> --stage planned    // design/<slug> trees only, once feat/<slug> holds their head
pilot worktrees prune --run <slug> --stage abandoned  // every runWorktrees tree, S1's mid-run rule
startRunPrune(ticket: string, repo: string, slug: string, stage: 'planned' | 'abandoned', deps?) -> void  // never throws
```

## Behaviours

1. `the design tree goes after Gate 1` (test): `pilot worktrees prune --run <slug> --stage planned` → the design tree gone and the feat tree intact, with `feat/x` cut from `design/x`.
2. `a design tree ahead of feat stays` (test): `pilot worktrees prune --run <slug> --stage planned` → `kept unpushed <dir>` with a design commit feat lacks.
3. `abandon takes pushed clean trees` (test): `pilot worktrees prune --run <slug> --stage abandoned` → a pushed clean slice tree gone, an unpushed one `kept unpushed`.
4. `the deck starts it on finished` (test): `startRunPrune` → one spawn with argv `worktrees prune --run <slug> --stage planned` and `windowsHide: true` on `deck_status` `finished: "planned"`; 0 spawns on `"closing report posted"`.
5. `the deck notes the outcome` (test): `startRunPrune` → one ticket note carrying the kept line its child printed.

Rewrite check: any trigger that runs after `finished` keeps behaviours 1-3; the press itself never deletes.
Misses: a re-cut after `planned`; S6's architect re-add line and QA read that.
