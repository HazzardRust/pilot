# S10 Prune and removeTree start less git

Feature `prune-worktrees` · delivers spec 13 (added) · source: the spawn ceilings in `scripts/gate.mjs`, and the per-file census on 768684d · after: S8
Reviewers: `pilot:typescript-reviewer`, then `pilot:security-reviewer`
Model: opus — a production change to the code that decides what is deleted; a cached read that should be fresh would delete the wrong tree.

Spec 13 (added): one prune resolves its remote and fetches its base once, and reads each tree's history and status in as few git calls as the guards allow.

## Files owned

- `scripts/worktrees.mjs`: one remote lookup and one fetch per `pilot worktrees prune`; the trees' reflogs read in one walk; a record-only tail stripped only when the head itself is not yet in the base, and each hop of it one git call.
- `scripts/worktree-remove.mjs`: `safeHead` asks `for-each-ref --contains` of the head first and strips the record-only tail only when that is not enough, each hop one git call; a landed removal reads its tracked status once, after the safe-head walk and right before `--force`, where it read it before and after.
- `scripts/test/worktrees-pin.test.mjs` (new): the git count of one sweep on a fixed fixture.
- `scripts/gate.mjs`: `SPAWN_CEILING` and `GIT_CEILING` as the measured full count allows.

## Interface

```
prune(repo, base, { ..., fetched })   // scripts/worktrees.mjs, unchanged: the CLI passes fetched once it has fetched
removeTree(repo, dir, options)        // scripts/worktree-remove.mjs, unchanged
```

## Behaviours

1. `one sweep spawns at most its pin` (test): `main(['prune', '--repo', work])` on the sweep fixture (main, a landed tree, a live tree, a fresh tree) spawns git at most the pin, against 30 on 768684d.
2. `behaviour does not change` (run): every existing test of the eight files the census names passes with its own expected values; no test or assert removed.
3. `the census falls` (run): the per-file spawn count of the eight files before and after, and the full suite's spawn line.

Rewrite check: removeTree still lists the worktrees fresh before each removal, and the dirty and unpushed checks still run right before it; only selection reads, the fetch and the record-tail walk are folded.
Misses: git that tests start themselves; integrate's own git in `integrate-prune.test.mjs`.

## Done

- **Expected**: one prune starts fewer git processes, with the same trees removed and kept.
- **Verification**: `node --test scripts/test/worktrees-pin.test.mjs`; the per-file count (`PILOT_GATE_SPAWNS` with `scripts/count-spawns.mjs` preloaded); `npm test`.
- **Evidence**: behaviour 1 red before and green after; the per-file table; the full spawn line.
- **Prohibited**: no cached worktree listing, head, lock or nesting carried into a removal; no batched dirty or unpushed check before a forced removal; no assert's expected value changed; no test or assert removed.
- **Done when**: the three behaviours hold and the gate is green.
