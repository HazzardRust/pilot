## Interface

```

missingShellRules(dir) -> { agent, rule }[]                                   // unchanged
agentWorktreeLines(dir) -> { agent, line, kind: 'add' | 'remove' }[]           // test helper in the new test file
S2's `pilot worktrees add --run <slug>`; S1's `pilot worktrees remove <path>`
```

## Behaviours

1. `every creating line tags` (test): `agentWorktreeLines(dir)` → 0 bare `git worktree add` in `agents/*.md`, each tree created by `pilot worktrees add --run`.
2. `no agent removes by hand` (test): `agentWorktreeLines(dir)` → 0 `git worktree remove`, `Remove-Item`, or `rm -rf` on a worktree path.
3. `the shell rule holds everywhere` (test): `missingShellRules(dir)` → `[]` for `agents` with the new wording.
4. `the re-cut re-adds the design tree` (read): the architect's Re-cut paragraph names the re-add from `<remote>/design/<slug>`.

Rewrite check: any wording that routes every crew creation and removal through the two commands passes 1-3.
Misses: an agent improvising a removal off-text; S1's guards and S7's orphan count read that.
