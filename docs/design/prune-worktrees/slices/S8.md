## Files owned

- `scripts/worktrees.mjs`: `prune` without `--run` judges a tree landed when its head is in the run remote's `pilot` or in `main`.
- `scripts/test/worktrees-sweep.test.mjs` (new): the landed, unlanded and unmoved cases.

## Interface

```
pilot worktrees prune [--dry-run]   // no --run: every tree moved since creation and in pilot or main, through S1's removeTree
```

## Behaviours

1. `a tree landed on pilot goes` (test): `pilot worktrees prune` → `removed <dir>` for a clean moved tree whose head is in `origin/pilot` but not `origin/main`.
2. `a live run's tree stays` (test): `pilot worktrees prune` → `kept open` for a tree at an unlanded sha, and for one just added at `pilot`'s tip.
3. `the dry run names them here` (run): `pilot worktrees prune --dry-run` on this checkout names the landed leftovers and no live run's feat or design tree.

Rewrite check: any sweep that requires moved, landed and clean keeps every live run's tree.
Misses: a landed tree holding work its owner still wants untracked; ADR 0081's untracked rule keeps those, and the doctor row names them.
