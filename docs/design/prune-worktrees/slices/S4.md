# S4 Integrate removes the slice's tree

Feature `prune-worktrees` · delivers spec 1 · source: `../architecture.md` §2, §5 L1 · after: S1 (`removeTree`)
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — one call site in `pruneSlice`, its line and its rule fixed by S1.

## Files owned

- `scripts/integrate.mjs`: `pruneSlice` removes the tree on the slice branch through S1's `removeTree` before `deleteMerged`.
- `scripts/test/integrate-prune.test.mjs` (new): the removed and kept lines.

## Interface

```
pilot integrate <slice-branch> -> one line ending `; removed <dir>` or `; kept <state> <dir>`, then `; deleted <slice>` or `; kept <slice>: <why>`
S1's removeTree
```

## Behaviours

1. `an integrated slice's tree goes` (test): `pilot integrate` → a line with `; removed <dir>` then `; deleted <slice>` for a pushed slice with a clean tree; `git worktree list` names 0 trees on the branch.
2. `a dirty slice tree is kept and named` (test): `pilot integrate` → `; kept dirty <dir>` with an untracked file in the slice tree; the tree intact, the merge pushed.
3. `red removes nothing` (test): `pilot integrate` → a red line and the slice tree intact.

Rewrite check: any integrate that removes only after a green push keeps a red slice's tree.
Misses: a slice tree whose implementer still runs a dev server in it; S1's holder case and QA read that.

## Done

- **Verification**: `node --test scripts/test/integrate-prune.test.mjs scripts/test/integrate*.test.mjs`; `npm run test:quiet`.
- **Evidence**: behaviour 1 red before and green after.
- **Prohibited**: no removal before the push succeeds; no `--force`; no edit to `deleteMerged`.
- **Done when**: the three behaviours hold and the gate is green.
