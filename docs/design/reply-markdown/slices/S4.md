## Behaviours

1. `Tab, Shift+Tab and Return move between cells` (test): `Table::size` → in `box_drawn`, Tab from (0, 0) focuses `cell-0-0-1`, Shift+Tab back to `cell-0-0-0`, Return from (1, 1) adds a row (size (3, 2)) and focuses `cell-0-2-1`; Return never posts an `Action`.
2. `Up from the header and Down from the last row leave the grid` (test): `Table::size` → Up in row 0 focuses the prose part before, Down in the last row the prose part after.
3. `the controls change the grid and keep the caret in it` (test): `Table::add_row` → + row, + column, − row, − column from cell (1, 1) of a 2 × 2 leave sizes (3, 2), (3, 3), (2, 3), (2, 2) and a focused cell; delete table leaves `tables` empty and the two prose parts joined.
4. `a cell without the caret renders its markdown` (test): `preview::spans` → a cell holding `**b** _i_ `c``, unfocused: bold, italic and mono spans; focused: none.
5. `the grid works by hand` (look): the live window on a scratch deck: walkthrough steps 8-9 of `../architecture.md` §9.

Rewrite check: any key routing that keeps one focused cell after each move keeps 1-3.
Misses: how the caret feels crossing from prose into a grid, and the controls' look on both themes; QA's walkthrough reads them.
