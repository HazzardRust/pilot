## Behaviours

1. `Table inserts a 2 × 2 grid at the caret` (test): `Local::insert_table`: the text before the caret stays above the grid, the text after it goes below; the Table press focuses `cell-0-0-0`.
2. `no controls under a grid` (test): `box_drawn`, the caret in a cell: no `table-<t>-*` control key is drawn.
3. `right-click on a cell opens a menu whose items reshape the grid at that cell` (test): `Runtime::secondary_down/up` on `cell-0-1-1`, then `resolve_popup` with each id: add row (3, 2), add column (2, 3), delete row (1, 2), delete column (2, 1), delete table (no grid, prose joined); live look at the open menu.
4. `Tab, Return and Shift+Return move and break the Obsidian way` (test): Tab from (0, 0) focuses (0, 1); Tab in the last cell adds a row and focuses its first cell; Return moves down a row, adding one under the last; Shift+Return puts a line break in the cell; nothing posts.
5. `the sent table is valid GFM` (test): `Table::markdown` writes a cell's break as `<br>` and `|` as `\|`; pulldown-cmark with tables reads back one table with the same cell count.

Rewrite check: any menu routing that lands the same reshape keeps 3; any key routing that keeps one focused cell keeps 4.
Misses: the native menu's look on Windows in both themes and how it feels; the live look and QA's walkthrough read it. Known gap, closed by S7 (thread tables): until S7 lands, `a<br>b` in a sent cell shows as "ab" in the Rune thread, because rune-kit `markdown/parser.rs:409` drops inline HTML.
