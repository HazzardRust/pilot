## Interface

```
readPower({ platform, run }): { source: 'ac'|'battery'|null, lid: { ac, dc }, button: { ac, dc }, modernStandby: boolean|null }
  // lid/button values: 'nothing'|'sleep'|'hibernate'|'shutdown'|null
  // as built, win32: powercfg /qh SCHEME_CURRENT SUB_BUTTONS LIDACTION|PBUTTONACTION; GetSystemPowerStatus (source) and GetPwrCapabilities
  //   (Modern Standby, LidPresent -> `lidless: true` on the result, no lid) via PowerShell; not `powercfg /q` or `powercfg /a`
  // darwin: pmset -g batt; linux: busctl get-property ... HandleLidSwitch(ExternalPower), and the source from UPower's OnBattery via busctl, not /sys/class/power_supply
powerRow({ power, awake, platform }): { name: 'Power', verdict, detail, steps }
probeDeck(url) -> { ..., awake?: { held, since } }
```

## Behaviours

1. `plugged in, lid does nothing` (test): `powerRow` → `pass`, detail names held/not held and the power button action.
2. `plugged in, lid sleeps` (test): `powerRow` → `fail`, a step naming Control Panel > Power Options > "Choose what closing the lid does".
3. `on battery` (test): `powerRow` → `fail`, the battery lid action, and on Modern Standby the 5-min note.
4. `unreadable` (test): `powerRow` → `cannot tell`, never `fail`.
5. `macOS and Linux` (test): `powerRow` → macOS says lid close sleeps unless clamshell on power; Linux names `HandleLidSwitch` in `/etc/systemd/logind.conf`.
6. `parses the real powercfg output` (test): `readPower` → a captured `powercfg /q` fixture gives `lid: { ac: 'nothing', dc: 'sleep' }`.
7. `no write anywhere` (test): `readPower` → the scan of `deck/awake.mjs` and `deck/power.mjs` finds 0 write forms (spec 9's list).
8. `the real row on this laptop` (run): `pilot doctor` prints the Power row with the deck up.

Rewrite check: replacing the parsers keeps behaviours 1-5, which read `powerRow` alone.
Misses: settings layouts on non-English Windows (GUIDs are parsed, not labels); QA reads the row on the laptop.
