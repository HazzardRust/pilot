# S4 The gate's census counts a leftover holder

Feature `stay-awake` · delivers spec 7 · source: `../architecture.md` §2 spec 7, §8 · after: S1 (added while integrating S1)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it changes which processes the census and `pilot gc` count and stop, where a wrong match kills the user's own deck's holder.

## Files owned

- `deck/procs.mjs`: `pilotProcesses` lists a keep-awake holder as kind `holder`, owner the deck it watches, recognised by its image and argv exactly as `holderFor` builds them.
- `scripts/gate.mjs`: `leftovers` counts a holder whose deck is a leftover or gone; `census` spares the user's deck's holder, and a leashless daemon's when the deck probe is unanswered.
- `deck/test/procs.test.mjs`, `scripts/test/gate-census.test.mjs`: the cases below.

## Interface

```
pilotProcesses(table, { userDeckPid, exists?, holderFor? }): Owned[]   // + { kind: 'holder', owner: <watched pid>, worktree: null, orphan }
leftovers(before, after, cwd, platform?): Owned[]                       // + holders of a leftover deck or of a gone pid
census(before, opts): { red, lines }                                    // signature unchanged
```

## Behaviours

1. `a test deck's holder left running is counted, and one whose deck is gone` (test): `census` → a holder watching a leftover test deck, and one watching a gone pid, are stopped and named `holder`.
2. `the user's deck's holder is not counted` (test): `census` and `pilotProcesses` → the holder whose watched pid is the user's deck is neither stopped, named nor an orphan; one watching a deck outside the suite is not counted.
3. `a PowerShell or caffeinate row that is not a holder is not listed` (test): `pilotProcesses` → a PowerShell row carrying the reason but not the holder's script, and a `caffeinate -i -w <pid>` whose parent is not that pid, are not listed.
4. `npm test`'s census still reports 0 leftovers (run): the gate's last census line is `left running: none` on the final state.

Rewrite check: a holder of another shape (S2's darwin and linux rows) is recognised once `holderFor` builds it, with no change here.
Misses: Linux's `tail` child of `systemd-inhibit` is not listed (it holds no lock and exits with its watched pid).

## Done

- **Expected**: a holder a test deck leaves running makes the census stop it and, if it survives, red; the user's deck's holder is never touched.
- **Verification**: `node --test deck/test/procs.test.mjs scripts/test/gate-census.test.mjs`; `npm test` once.
- **Evidence**: behaviours 1-3 red before, green after (2 and 3's guards shown red by a mutation, since before the change no holder row existed); behaviour 4's census line.
- **Prohibited**: no `process.platform` read (use `hostPlatform()`); no shell string spawn; no kill by name or pattern; no power-setting write; `SPAWN_CEILING` unchanged; no edit to `deck/awake.mjs`.
- **Done when**: four behaviours hold and `npm test` is green.
