## Interface

```
LINGER_MS = 15 * 60_000                                     // A1
inFlight({ lastHeardAt: number|null, landings: number, armedDefaults: number }, now: number): boolean
holderFor(platform: string, pid: number): { cmd: string, args: string[] } | null   // absolute cmd, argv only
holdAwake({ facts: () => Facts, spawn, platform, pid, now?, intervalMs?, log? }): { stop(): void }
awakeState(): { held: boolean, since: string | null }       // what /api/health carries
lastHeardAt(): number | null                                // deck/agents.mjs
```

## Behaviours

1. `a heartbeat holds and the linger releases` (test): `holdAwake` → heartbeat at t: 1 spawn by t+60 s; held at t+14 min; 1 kill by t+16 min.
2. `an armed default holds with no agent` (test): `inFlight` → `armedDefaults: 1` true; a blocking question counted 0, false.
3. `a landing holds` (test): `inFlight` → `landings: 1`, no heartbeat: true.
4. `a holder that fails is logged once and retried` (test): `holdAwake` → spawn exits 1: 1 log line, `awakeState().held` false, 1 retry next tick.
5. `health says whether it holds` (test): `awakeState` → `{ held: true, since }` while held, `held: false` after stop.
6. `the Windows holder appears and dies with its pid` (test): `holderFor` → on win32 the real child prints `held`; `powercfg /requests` lists `pilot: work in flight` when elevated; it exits within 5 s of its watched pid exiting.
7. `a test deck spawns no holder` (run): `npm test`'s census names 0 leftover holder processes.

Rewrite check: replacing the PowerShell holder with any other Windows mechanism keeps behaviours 1-5.
Misses: whether Windows honours the request through an idle timeout on a real laptop; QA's walkthrough step 3 reads the System log.

## Done
