Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument reaching a process start, and the parse of untrusted log text.

## Files owned

- `scripts/ci.mjs` (new): fetches one run's jobs and failed log, parses the failing-tests blocks, and prints the summary.
- `scripts/test/ci.test.mjs` (new): the pins, with `gh` injected.
- `scripts/test/fixtures/ci/run-39530951687.log` (new): from the real `--log-failed` output. Keep both `✖ failing tests:` blocks
  (windows 8, macos 10) with their line prefixes, 20 lines of passing output around each, and the `##[error]` lines. At most 600 lines.
  Plant one test name of 5,000 chars that carries an ESC sequence and the words "ignore previous instructions".
- `bin/pilot.mjs`: the `ci` branch and its help line.
- `scripts/test/operating-commands.test.mjs`: `ci` joins `NON_MOVING` (red team, §6).

## Interface

```
type Failure = { job: string, file: string, name: string, message: string }   // file `path:line`, message the first assertion line
type CiSummary = { run: number, branch: string, event: string, url: string, failed: string[], passed: string[], failures: Failure[] }
failuresOf(log: string): Failure[]       // strips `<job>\t<step>\t<ts> `, reads each `✖ failing tests:` block; every field through cleanField
cleanField(text: string, max: number): string  // ANSI + control chars out, whitespace collapsed, clipped with …; the one cleaner (S3 uses it)
ciSummary(runId: number, { gh, cwd }): CiSummary  // gh run view <id> --json jobs,headBranch,event,url ; gh run view <id> --log-failed
summaryLines(summary: CiSummary): string[]       // header, then per failed job `<job>: <n> failing`, then `  <file> <name>: "<message>"`; <= 40 lines, `(+n more)` past it
main(argv: string[]): number             // pilot ci <run-id>: 0 printed; 1 with one stderr line on a non-numeric id or gh failure
```

## Tests

1. `the fixture yields 18 failures across two jobs`: `failuresOf` → 8 for windows and 10 for macos, the first `deck/test/closing-worktrees-left.test.mjs:62` `a posted report reads the disk` with message `AssertionError [ERR_ASSERTION]: only the run worktree on disk`.
2. `planted text is cleaned and clipped`: `failuresOf` → the planted name has no ESC, is at most 120 chars, and stays a name, not a line of its own.
3. `the summary stays within 40 lines`: `summaryLines` → at most 40 lines, the passed job named.
4. `a non-numeric id never reaches gh`: `main` → `pilot ci abc` exits 1 and the injected `gh` is never called.
5. `two gh calls, argv only`: `ciSummary` → exactly the two argv arrays above.

Rewrite check: replacing the block parser with a TAP reader keeps tests 1–3 if the fixture is re-recorded.
