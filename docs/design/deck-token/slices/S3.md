# S3 The browser gets in through the open file, and pilot deck --rotate replaces the secret

Feature `deck-token` · delivers spec 3, 4, 7 · source: `../architecture.md` §2, §5 L7, §6 A1, A2, A3 · after: S1 (server-routes.mjs, scratch.mjs, deck secret)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — A2 and A3 are assumed, and a cookie is a credential on a route.

## Files owned

- `deck/launch.mjs` (new): the open file and the cookie.
- `deck/server-routes.mjs`: `GET /open?key=`.
- `deck/daemon.mjs`: `main` writes the open file once the port is bound, beside `deck.pid`.
- `deck/open.mjs`: `openDeck` opens the open file, not the URL.
- `deck/scratch.mjs`: the scratch result carries `open`, the scratch open file's path.
- `bin/pilot.mjs`: `pilot deck` and `--scratch` print an `open <path>` line; `pilot deck --rotate`.
- `deck/README.md`: the `launch.mjs` row.
- `deck/test/open.test.mjs`, `deck/test/launch.test.mjs` (new): the pins.

## Interface

```
// deck/launch.mjs
openFile(dir?: string): string                                // <dir>/deck-open.html
writeOpenFile(dir: string, url: string, secret: string): string
  // writes the forward to `${url}/open?key=<secret>` (meta refresh), mode 0o600, returns its path
rotateSecret(dir?: string, port?: number): string
  // deletes deck.secret, S1's ensureSecret() anew, writeOpenFile with the port deck.pid names (else deckPort()); returns the open file
openCookie(port: number, secret: string): string
  // `${S1's cookieName(port)}=<secret>; HttpOnly; SameSite=Strict; Path=/; Max-Age=34560000`
GET /open?key=<secret> -> 200 text/html with Set-Cookie openCookie(...), a same-origin forward to / (meta refresh
  and a link) whose body holds no key; wrong or missing key -> 401
pilot deck            -> "The deck is up at <url>" then "open <path>"
pilot deck --scratch  -> url, pid, dir, then "open <path>"
pilot deck --rotate   -> "rotated; open <path>", and openDeck on that file
```

Seam change, made during S3 (was a 303 to `/`): a file:// start is cross-site, so SameSite=Strict withholds the cookie on a redirect's landing, which S5's guarded `GET /` would 401; seen in Chrome.

## Tests

1. `the right key sets the cookie and forwards home`: `openCookie` → `GET /open?key=` answers 200 with that Set-Cookie and a forward to `/` whose body holds no key.
2. `a wrong key sets nothing`: `GET /open?key=` → 401 with no Set-Cookie, and no echo of the key.
3. `the open file forwards with the key and is 0600`: `writeOpenFile` → the file names `/open?key=`, mode 0o600 on POSIX.
4. `openDeck never puts the key in argv`: `openFile` → the recorded opener's args name the file path only.
5. `two decks' cookies stand side by side`: `openCookie` → a scratch deck's cookie is refused by the user's deck's guard, and its own is taken.
6. `rotation replaces the secret and the open file`: `rotateSecret` → a new value, the old one 401 on a running deck, the new 200, the open file holds the new key, stdout no secret.
7. `pilot deck prints the open line, not the secret`: `openFile` → stdout holds `open <path>` and no secret.

Rewrite check: replacing the meta-refresh file with any forward that keeps the key off argv keeps all seven results.
