# S2 pilot run, pilot budget and pilot handoff send the secret

Feature `deck-token` · delivers spec 2, 8 · source: `../architecture.md` §2, §5 L3, L6, L7 · after: S1 (deck secret)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it carries a secret across three clients' requests, the security trigger, though each change is one line on S1's seam.

## Files owned

- `deck/run.mjs`: all six requests (three POSTs, `/api/record`, `/api/runs?live=1`, `/events?wrapper=`) spread S1's `bearer()`.
- `deck/budget.mjs`: `POST /api/budget` spreads it.
- `scripts/handoff.mjs`: its `fetch` spreads it on every request.
- `deck/test/run.test.mjs`, `deck/test/budget.test.mjs`, `scripts/test/handoff.test.mjs`: one pin each.

## Interface

```
S1's bearer(dir?): { authorization: string }    // read on every request, never cached
S1's createDeckHttpServer({ secret })           // the pins pass a string to get a guarded server
pilot budget / pilot run / pilot handoff        // unchanged flags and output
```

## Tests

1. `pilot budget is taken by a guarded deck`: `bearer` → `pilot budget --main 3` against `createDeckHttpServer({ secret })` exits 0.
2. `pilot run's requests are taken by a guarded deck`: `bearer` → each of run.mjs's six requests carries the header and answers 200.
3. `pilot handoff is taken by a guarded deck`: `bearer` → its post answers 200 and the hand-off item is listed.
4. `a missing secret file is named, not guessed`: `createDeckHttpServer` → with no `deck.secret`, `pilot budget` exits 1 naming the file.

Rewrite check: replacing the bearer header with any other credential S1 accepts keeps all four results.
