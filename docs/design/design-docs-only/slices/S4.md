# S4 Every after carries its reason

Feature `design-docs-only` · delivers spec 5, 7 · source: `../architecture.md` §2, §4 Wait reason, L8 · after: –

## Files owned

- `scripts/check-slices.mjs`: `checkSlice` gains the `after-reason` rule, reading the header line's `after:` field.
- `scripts/test/check-slices.test.mjs`: the pins.
- `scripts/test/fixtures/slices/*.md`: each fixture's header `after: S1` becomes ``after: S1 (`lookup`)``, so the existing pins stay green under the new rule (seam change, co-pilot, 2026-10-10).
- `skills/vertical-slicing/SKILL.md`: "Ordering" states the width rule (no line between slices sharing no file or seam) and the reasoned `after`; the worked example's header becomes `after: S1 (<file or seam>), S2 (<file or seam>)`; the Dependencies row of the anatomy table names the reason.

## Interface

```
checkSlice(text: string): Array<{ line: number, rule: string, message: string }>
// new rule 'after-reason': each blocker in the header's `after:` field is `S<n>\w* (<reason>)`;
// `after: –` (none) passes; a bare `S<n>` or an empty `()` is a problem on the header line
WidthRule: skills/vertical-slicing/SKILL.md "Ordering", the sentence pinned
```

## Tests

1. `a bare blocker is refused`: `checkSlice` → an `after-reason` problem for `after: S1`.
2. `a reasoned blocker passes`: `checkSlice` → no `after-reason` problem for `after: S1 (scripts/x.mjs), S2 (\`pilotLineage\`)`.
3. `no blocker passes`: `checkSlice` → no problem for `after: –`.
4. `one bare blocker among reasoned ones is named`: `checkSlice` → the problem names `S2` in `after: S1 (a), S2`.
5. `the skill's worked example passes`: `checkSlice` → no problems over `skills/vertical-slicing/SKILL.md`.
6. `the skill carries the width rule`: `WidthRule` → "Ordering" matches the no-line-without-a-shared-file-or-seam sentence.

Rewrite check: were the header parsed by a different tokenizer, tests 1-5 hold, since they read only `checkSlice`'s problems.
