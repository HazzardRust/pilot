# S1 Integrate's base failure counts pilot's copies (walking skeleton)

Feature `design-docs-only` · delivers spec 3 · source: `../architecture.md` §2, L3, L7 · after: –

## Files owned

- `scripts/pilot-branch.mjs`: gains `pilotLineage`, the one reader of a branch's lineage against `origin/pilot`.
- `scripts/integrate.mjs`: the base-take failure line (:213) gains the copy count when it is not 0.
- `scripts/test/integrate-copies.test.mjs` (new): the pins, on real git repos in temp dirs with a local bare origin.

## Interface

```
// null when the repository has no refs/remotes/origin/pilot; throws when `ref` does not resolve
pilotLineage(cwd: string, ref: string): { tip: boolean, copies: number } | null
//   tip: origin/pilot's tip is an ancestor of ref; copies: ref's commits patch-equivalent (`git patch-id --stable`) to pilot's commits not reachable from ref's fork points; not `git cherry`, which marks every copy `+` once ref has merged pilot (seam change, co-pilot, 2026-10-10)
integrate(branch?: string, options?): { ok, line, failing }   // unchanged signature
// base failure line: `base NOT taken: taking base pilot stopped (<first line>); not pushed; <n> of <branch>'s commits are copies of pilot's`
```

## Tests

1. `a branch cut from pilot's tip has no copies`: `pilotLineage` → `{ tip: true, copies: 0 }`.
2. `a branch with one pilot commit cherry-picked onto an older base`: `pilotLineage` → `{ tip: false, copies: 1 }`.
3. `a branch that merged pilot after a replay still counts its copies`: `pilotLineage` → `tip: true`, `copies` 1.
4. `a repository with no origin/pilot`: `pilotLineage` → null.
5. `a base conflict on a branch carrying copies names the count`: `integrate` → line ends `; 2 of feat/x's commits are copies of pilot's`, nothing pushed.
6. `a base conflict on a clean branch names no count`: `integrate` → line has no `copies of pilot's`.

Rewrite check: were `pilotLineage` re-implemented on `git log --cherry-mark` or `git patch-id`, tests 1-6 hold unchanged, since they read only its answer and integrate's line.

## Done

- **Expected**: `pilot integrate` on a feature branch that carries pilot's commits as copies fails with one line ending in how many of them there are; a clean branch's failure line is unchanged.
- **Verification**: `node --test scripts/test/integrate-copies.test.mjs scripts/test/integrate.test.mjs scripts/test/integrate-base.test.mjs`; `npm test`; then `pilot integrate --no-push` in a scratch clone (L2) on a branch with a replayed pilot commit and a conflicting base.
- **Evidence**: tests 2, 3 and 5 red before, green after; the scratch run's failure line pasted in the PR.
- **Prohibited**: no string-matching of commit subjects to find copies (patch equivalence only); no fetch inside `pilotLineage`; no change to integrate's success lines or exit codes; never this repository's own branches as fixtures. Small-diff limit: 200 changed lines; past it, stop and ask `main`.
- **Done when**: the six tests and `npm test` are green and the scratch failure line shows the count.
