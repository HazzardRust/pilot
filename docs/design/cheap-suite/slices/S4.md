# S4 A green CI run proves the tree it tested

Feature `cheap-suite` · delivers spec 5 · source: `../architecture.md` §2, §3 F8, F9, Seams, §5 L7, §6 A2 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — CI output becomes an input the landing trusts and the host's `gh` allowlist widens (the security trigger); A2 is assumed.

## Files owned

- `.github/workflows/gate.yml`: a last step `Name the tested tree` printing `::notice title=tested-tree::<HEAD^{tree}>`; the job `if` also runs draft PRs to `main` (A2).
- `deck/host-github.mjs`: `testedTrees(sha)`; the allowlist admits a GET of `check-runs/<id>/annotations` and nothing wider.
- `deck/host-gitlab.mjs`: `testedTrees(sha)` answers `[]`, so a GitLab landing has no proof and runs full.
- `deck/host.mjs`: the `Host` typedef gains `testedTrees`.
- `scripts/checks.mjs`: `provenTree`, beside `checksGate`.
- `scripts/test/checks-proof.test.mjs` (new): the proof's pins, host and git faked.
- `deck/test/host-contract.test.mjs`: the allowlist and `testedTrees` pins, both hosts.

## Interface

```
Host.testedTrees(sha) -> { name: string, conclusion: string, tree: string | null }[]
  // one row per latest check run on sha named `gate (<os>)`; tree from its `tested-tree` annotation
provenTree({ host, git, sha, base }) -> { tree: string, line: string } | { tree: null, line: string }
  // proof: >= 3 rows, every conclusion success, every tree the same 40- or 64-hex value
  // none when: host null or throws; fewer rows; a row not success; trees missing or differing;
  //   base...sha touches .github/, package.json, package-lock.json or a FULL_TRIGGERS file
  // line: `ci proved <tree7> on <n> jobs` | `no ci proof: <reason>`
```

## Behaviours

1. `a three-job green run proves its tree` (test): `provenTree` → given three `gate (...)` rows, all success, all tree T, `{ tree: T }` and `ci proved <T7> on 3 jobs`.
2. `anything short of that proves nothing` (test): `provenTree` → `{ tree: null }` with its reason for each of: no host, `testedTrees` throwing, two rows, one row failed, trees differing, a tree missing, a feature diff touching `.github/workflows/gate.yml`, one touching `scripts/gate.mjs`.
3. `the host reads annotations and nothing more` (test): `testedTrees` → a fake `gh` answering check runs and annotations yields the rows; the allowlist refuses a POST to annotations and a GET of `actions/runs/<id>/logs`.
4. `CI names the tree` (run): this branch's draft PR shows the `tested-tree` notice on each Gate job; the run URL in the slice report.

Rewrite check: reading the tree from an uploaded artifact instead keeps 1-2, which go through `testedTrees`.
Misses: a test that prints a forged `::notice title=tested-tree::` line in the same job; §6 A2 names it, and the trigger rule keeps a gate or workflow change on a full run.

## Done

- **Expected**: every Gate job annotates the tree it tested, and `provenTree` turns a green three-OS run into that tree or one line saying why not.
- **Verification**: `node --test scripts/test/checks-proof.test.mjs deck/test/host-contract.test.mjs`; the PR's Gate jobs.
- **Evidence**: 1-3 red before, green after; the annotation on all three jobs.
- **Prohibited**: no shell for `gh` or `git`; no proof from a sha other than the exact tip; no `permissions:` widened in the workflow; no `gh api` path beyond the annotations GET.
- **Done when**: 1-3 green and the annotation seen on a real run. Estimate 200 lines.
