## Found

`pilot integrate` of S1 died before its gate ran: `Error: EPERM: operation not permitted, mkdir '...\pilot-gate-slots\slot-0.json.takeover'` at `takeOver` (`scripts/gate-slots.mjs:55`), called from `takeSlot` (`:98`) while it waited for a slot (log `~/.claude/pilot/logs/20261123T065306341Z-slice-cheap-suite-s1.log`). On Windows, `mkdir` of a directory another waiter is removing at that moment answers `EPERM`, not `EEXIST`; `takeOver` rethrows everything but `EEXIST`, so the waiter crashes instead of waiting.

## Files owned

- `scripts/gate-slots.mjs`: `takeOver` treats a lock `mkdir` answering `EPERM` (or `EACCES`) as held by another waiter, as `EEXIST` is: no takeover this round.
- `scripts/test/gate-slots.test.mjs`: the pin.

## Behaviours

1. `a takeover lock being removed reads as held` (test): `takeSlot` → with an injected `mkdir` answering `EPERM` once for the lock, it does not throw and takes the slot on a later round; red before the change (it throws EPERM).
2. `any other mkdir error still throws` (test): `ENOSPC` from the lock `mkdir` is rethrown.

Misses: an `EPERM` that is a real permission fault on the slot directory now waits rather than fails; the `wx` slot write on the same directory still throws it on the next round.
