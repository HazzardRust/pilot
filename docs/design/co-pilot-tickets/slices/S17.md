## Why

S3's codemod run flipped stored spellings that `STORED` did not hold, broke a binding silently and mangled CSS, costing ~60 of its 200 hand-fix lines for `foreman` alone (PR #719 friction):

- `foreman:` object keys, `.foreman` member reads and quoted `'foreman'` values flipped in the default mode; only `.foremen` was held.
- `{ ...foremen }` (`deck/store-runs.mjs:380`) was held while its declaration was renamed: a `ReferenceError` `node --check` cannot see.
- `.foreman-held` in CSS became `.coPilot-held` through the member rule.
- In `'\nforeman: x'` the lookbehind read the `n` of `\n`, so the word was not renamed.

## Files owned

- `scripts/vocabulary.mjs`, `scripts/test/vocabulary.test.mjs`.

## What it adds

1. **Default mode keeps every property-shaped `task`**: an object key (`task:`, `"task":`), a member read (`.task`, `['task']`, `?.task`), and a quoted `'task'`/`"task"`/`` `task` `` whole-string literal stay as written; `--stored` flips each of them. The same for `tasks`. A held literal that is not a stored spelling (the `pilot tasks` CLI word, a route segment) is S4's hand-fix, named in its PR.
2. **A binding is never renamed apart from its use**: a shorthand property or destructuring (`{ task }`, `{ task } = item`) becomes `{ task: ticket }` in the default mode and `{ ticket }` under `--stored`; a spread of a held name (`{ ...x }`) follows its declaration.
3. **CSS reads as prose-with-kebab**: in `.css` (and a `<style>`/class string in `.html`/`.mjs` UI), a class or custom property renames kebab (`.task-row` → `.ticket-row`), never camelCase.
4. **Escapes are not letters**: `\n`, `\t` and `\r` before the word do not block it.
