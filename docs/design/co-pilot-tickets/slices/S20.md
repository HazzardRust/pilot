## What it adds

1. L10: before the v3 write the daemon copies the store to `deck.v<from>-<YYYY-MM-DD>.json` beside it, once, the day by the **local** date.
2. A backup already there with other bytes (a truncated write, another store the same day) is kept, and the copy goes to `deck.v<from>-<day>-<n>.json`; never silently kept as the only copy.
3. The copy is written atomically; a failure is an `unreadableStore` naming the backup path, and the v3 write does not happen.
4. A real v1 store with kind `task` goes through `readDeck` to v3 with its kinds flipped and its backup `deck.v1-<day>.json` (the existing v1 fixture was codemodded to `ticket`).
