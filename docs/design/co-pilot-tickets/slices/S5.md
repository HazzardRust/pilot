Feature `co-pilot-tickets` · run Live · delivers spec 3, 4, 8 · source: `../architecture.md` §2, §3 Seams, L4, L6, L9, L10, L11, L13, A5 · after: S18 (deck/**, after S4), S4 (hooks/**), S2 (S2's STORED)

- `deck/test/store-v3.test.mjs` (new), `deck/test/run-record-legacy.test.mjs` (new).
- `package.json`, `.claude-plugin/plugin.json`: the patch version bump, by `npm run bump` (spec 8, added at Gate 1), in its own commit `chore(co-pilot-tickets): bump version to <x.y.z+1>`.

## Tests

1. `an old store reads back unchanged but its spelling`: `upgradeStore` → a planted v2 store's open tickets have equal ids, states and array order, `kind: 'ticket'`, a `ticket` field, untouched bodies and authors.
2. `the co-pilot's lane survives`: `upgradeStore` → `foremen` and `switches[*].foreman` read back as `coPilots` and `switches[*].coPilot` with their ticket.
3. `the backup is written once, before`: `readDeck` → `deck.v2-<date>.json` equals the old bytes; a second read writes no second backup; a v3 store is never backed up.
4. `the migration is one-way`: `readDeck` → a v3 store is refused by the previous release's version check (pinned as the number).
5. `a legacy run record still reads`: `recordTicket` → `{ task: 'itm_1' }` and `{ ticket: 'itm_1' }` both give `itm_1`.
6. `the hooks follow the deck`: `STORED` → S2's pin stays green with the flipped values.

Rewrite check: replacing the in-place step with a copy-then-swap keeps ids, states, order, bodies and the single backup above.
