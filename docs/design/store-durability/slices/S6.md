# S6 Restore sees a deck on any port serving this store (added)

Feature `store-durability` · delivers spec 9 (added) · source: S3's security review (PR #789, medium: the port-only probe), `../architecture.md` §6 A5 · after: S3 (deck/store-recovery.mjs), S4 (deck/daemon.mjs)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it closes a security reviewer's finding on a fail-closed path; a wrong probe lets restore swap under a live writer.

Added by the co-pilot as a found issue (build-now rule). It moves no locked decision: A5 already says restore refuses while a daemon serves; S3's probe asks only `PILOT_DECK_PORT`'s port, so a deck serving this store on another port slips past.

## Files owned

- `deck/daemon.mjs`: once listening, write `deck.pid` (`<pid> <port>`, decimal, through `atomicWriteFileSync`) into `storeDir()`, unless `storePid` finds another live deck answering on the port the present line names; on a clean shutdown remove it only if it still holds that line.
- `deck/store-restore.mjs` (moved out of `store-recovery.mjs` by the principles fix round): `storePid` asks the port `deck.pid` names for its pid and returns it when the same pid answers, undefined when the port cannot tell; a `deck.pid` whose port answers nothing or another pid, or that is not `<pid> <port>`, is stale and ignored, and then, as with none, the configured port is asked. `main` resolves it and passes it to `restoreStore`.
- `deck/test/store-restore.test.mjs`: the pins.
- `deck/test/` daemon test the slice needs (import `./no-open.mjs`, per `deck/test/open.test.mjs:97`).

## Interface

```
// deck/store-restore.mjs
storePid(options?: { dir?: string, probe?: (port: number) => Promise<number | null | undefined> }): Promise<number | null | undefined>
restoreStore(options?)   // unchanged signature; `main` passes `storePid()`'s resolved answer as `daemonPid`
```

## Tests

1. `storePid: a deck.pid whose port answers its pid refuses restoreStore`: `storePid` → that pid; `restoreStore` → refused naming it; no file changed.
2. `storePid: a deck.pid whose port cannot tell refuses restoreStore`: `storePid` → undefined; `restoreStore` → refused.
3. `storePid and restoreStore: a stale deck.pid is ignored`: `storePid` → null for a port answering nothing or another pid, and for a malformed file; `restoreStore` proceeds.
4. `storePid: with no deck.pid, or a stale one, the configured port is asked`: `storePid` → the configured port's answer.
5. `storePid: an unreadable deck.pid refuses restore`: `storePid` → rejects with a DeckRefusal.
6. `the daemon writes and removes deck.pid`: `storePid` → a scratch daemon on a temp `PILOT_DECK_DIR` and free port, named by the `<pid> <port>` it wrote; stopped, its deck.pid is gone.
7. `the daemon keeps another live deck in deck.pid`: `storePid` → another pid answering on the port deck.pid names, so a scratch daemon leaves that line, and its exit leaves it too.

Rewrite check: replacing the `/api/health` probe with any other question to the port that returns its pid keeps every result above.

## Done

- **Expected**: restore refuses while any deck serves this store dir, whatever port it listens on.
- **Verification**: `node --test deck/test/store-restore.test.mjs`; `npm test`; on a scratch store dir with a scratch daemon on a non-default port and `PILOT_DECK_PORT` unset, `node bin/pilot.mjs store restore` is refused; after stopping that daemon (only the pid you started), it restores.
- **Prohibited**: no change to the refusal's wording beyond the pid it names (spec 4's evidence); no path argument; never touch the user's real store or deck.
- **Done when**: the three tests pass red-first, the gate is green and the scratch run has been read.
