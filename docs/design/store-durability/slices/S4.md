## Interface

```
// deck/store-archive.mjs
archiveOld(options?: { now?: Date, writeLive?: (deck) => void }): { moved: string[] }
  // moves items with resolvedAt older than 30 days (A1), except: open, notice === true, a ticket an unmoved item names
  // by `ticket` or `mergedInto`; writes each `deck.archive-YYYY-MM.json` (by resolvedAt month) first, deduped by id,
  // then the live store through writeLive (default writeDeck); a live item's id and relative order never change
archivedItem(id: string): object | null   // newest month file first
```

## Tests

1. `old closed items leave and open ones keep their order`: `archiveOld` → moved ids are in the month file only; live ids in the same order as before minus the moved.
2. `an open item, a notice and a named ticket stay`: `archiveOld` → none of the three moves, however old.
3. `a failed live write loses nothing`: `archiveOld` → with a throwing `writeLive`, every item is in the archive or the live store; a second pass leaves one copy of each.
4. `seq, runs and records stay live`: `archiveOld` → the live store's top-level fields are unchanged.
5. `an archived item reads back by id`: `archivedItem` → the moved item, whole.
6. `the daemon archives on start`: `archiveOld` → a planted store with a 40-day-old closed item, after the daemon's `main` start path, holds it in the archive only.

Rewrite check: replacing the month files with any other archive layout keeps tests 1 to 5.
