# S3 pilot store restore swaps the backup in and back

Feature `store-durability` · delivers spec 4 · source: `../architecture.md` §2, §5 L2, §6 A5 · after: S1 (deck/store-recovery.mjs)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a CLI argument (the security trigger) and A5 is assumed.

## Files owned

- `deck/store-recovery.mjs`: `restoreStore` and its `main`.
- `bin/pilot.mjs`: the `store restore` subcommand and its usage line.
- `deck/test/store-restore.test.mjs` (new): the pins.

## Interface

```
// deck/store-recovery.mjs
restoreStore(options?: { daemonPid?: () => number | null | undefined }): { restored: string, kept: string }
  // refuses (DeckRefusal) while daemonPid() names a pid, naming `pilot deck --stop <pid>`;
  // refuses when .bak does not parse as a deck; sets deck.json aside as `deck.json.replaced-<date>[-n]`;
  // when deck.json parses, swaps it and .bak; when it does not, .bak's bytes go in and .bak stays
main(argv: string[]): Promise<number>   // `pilot store restore`; one line out, exit 0 or 1
S1's keepBackup, recoverStore: reused for the parse check and the set-aside naming
```

## Tests

1. `restore swaps the backup in`: `restoreStore` → deck.json holds the old `.bak`, `.bak` the old store, `deck.json.replaced-<date>` kept.
2. `a second restore puts it back`: `restoreStore` → deck.json byte-identical to before the first.
3. `a serving daemon refuses it`: `restoreStore` → refused naming the pid and `pilot deck --stop`; no file changed.
4. `an unparseable backup refuses it`: `restoreStore` → refused; no file changed.
5. `the command prints one line`: `main` → `pilot store restore` exits 0 with the restored and kept paths.

Rewrite check: replacing the swap with copies through a temp file keeps every result above.

## Done

- **Expected**: a user who sees a bad change stops the deck, runs `pilot store restore`, and has the store one write back; running it again undoes it.
- **Verification**: `node --test deck/test/store-restore.test.mjs deck/test/store-recovery.test.mjs`; `npm test`; on a scratch store dir, run `node bin/pilot.mjs store restore` twice.
- **Evidence**: tests red before and green after; the two command outputs read.
- **Prohibited**: no restore while a daemon serves; no deleting the replaced store; no path argument (the store dir comes from `storeDir()` only).
- **Done when**: the five tests pass, the gate is green and the command has been run twice by hand.
