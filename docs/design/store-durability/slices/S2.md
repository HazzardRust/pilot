# S2 The rename retries, and alert-switch writes through it

Feature `store-durability` · delivers spec 1, 5 · source: `../architecture.md` §2, §5 L8, §6 A6 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — `hooks/lib/` is agent configuration (the security trigger) and A6 is assumed.

## Files owned

- `hooks/lib/atomic-write.js`: the rename retries on EPERM, EBUSY, EACCES; the header comment says so.
- `hooks/test/atomic-write.test.js` (new): the pins.
- `deck/alert-switch.mjs`: `setAlertSwitch` writes through `atomicWriteFileSync`.
- `deck/test/alert-switch.test.mjs`: a pin that the module names no `.tmp`.

## Interface

```
// hooks/lib/atomic-write.js (CommonJS)
atomicWriteFileSync(targetPath: string, contents: string | Buffer,
  options?: { renameSync?: (from, to) => void, sleep?: (ms: number) => void }): void
  // retries EPERM | EBUSY | EACCES at 15, 30, 60, 120, 240, 480 ms (~945 ms), then rethrows the first error
setAlertSwitch({ weekly }): { weekly: boolean }   // unchanged signature
```

## Tests

1. `a rename that fails twice then succeeds writes`: `atomicWriteFileSync` → the target holds the new contents; two sleeps were taken.
2. `a rename failing past the budget throws the original error`: `atomicWriteFileSync` → the first error's code, total sleep ≥ 900 ms, no `.tmp` left.
3. `another error code is not retried`: `atomicWriteFileSync` → ENOENT throws at once with no sleep.
4. `alert-switch keeps no tmp of its own`: `setAlertSwitch` → the module source names no `.tmp`, and the switch round-trips.

Rewrite check: replacing the doubling schedule with any other totalling about a second keeps every result above.
