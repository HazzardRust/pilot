# S4 Pass a thread, and a non-owner is refused

Feature `thread-ownership` · delivers spec 3, 4 · source: `../architecture.md` §2, A3, A4, A5, A6 · after: S3

## Files owned

- `deck/store.mjs`: `addPilotMessage` takes `to` and refuses a non-owner; `resolveItem` refuses a non-owner.
- `deck/server.mjs`: passes `to` through from `deck_reply`.
- `deck/tools.mjs`: `to` on `deck_reply`; one clause in the reply and resolve descriptions.
- `agents/pilot.md`: a thread QA owns is QA's to answer; send the point to QA, or take the thread with `to`.
- `agents/pilot-qa.md`: you own your walkthrough; pass it with `to: "pilot"` when the pilot must answer, or relay.
- `deck/test/pass.test.mjs` (new): the pins.

## Interface

```
deck_reply inputSchema: + to?: 'pilot' | 'qa'    // "pass the thread: this agent gets its replies from now"
addPilotMessage(id, text, author, to?): item     // one writeToThread: message pushed and owner set together;
                                                 //   a pass renumbers undelivered user replies past every cursor
                                                 //   and records them as message.carries: seq[] (spec 5)
resolveItem(id, resolution, author): item        // refused unless the author kind is the owner
HELPER_KINDS: readonly ['teacher', 'explorer']   // items.mjs; may reply on a pilot-owned thread
refusal text: `item <id> is owned by <owner>; send your point to <owner>, which says it here`
```

## Tests

1. `the owner passes a thread and the next reply wakes the new owner only`.
2. `the pilot may take a qa thread with to pilot`.
3. `qa may not pass a pilot-owned thread`: refused, naming the pilot.
4. `the pilot's reply on a qa thread is refused naming qa`.
5. `the pilot's resolve on a qa thread is refused`.
6. `a teacher and an explorer may reply on a pilot thread and not on a qa thread`.
7. `a pass to a kind outside OWNER_KINDS is refused`.
8. `a pass writes the message and the owner in one write`: a failing write leaves neither.

## Done

- **Expected**: QA says "passing this to the pilot" with `to: "pilot"`, and the thread header's
  owner shows `pilot`. The pilot answering on a QA thread is refused with the owner's name.
- **Verification**: `node --test deck/test/pass.test.mjs deck/test/teach.test.mjs deck/test/reply.test.mjs`; `npm test`.
- **Evidence**: tests 1 and 4 fail before and pass after. `teach.test.mjs` is green unchanged,
  which proves ADR 0020's path holds. On a scratch deck, a pass is seen changing the owner
  label live.
- **Prohibited**: no new tool; no exception for the pilot writing on a QA thread; no helper
  reply on a QA thread; no two-write pass.
- **Done when**: the three test files and the full suite are green, and a live pass has been
  seen changing the label.
