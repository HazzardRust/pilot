# S5 A reply its quiet owner leaves unclaimed or unanswered falls back to the pilot

Feature `thread-ownership` · delivers spec 5 · source: `../architecture.md` §3 "Nothing on the deck says an agent has ended", L6, L7 (superseding L4), A7, A9 · after: S4

## Files owned

- `deck/agents.mjs`: `noteActive` and `lastActive` per repository and kind, fed by roster heartbeats; `holdWait` and `quietAt` (fix round, L6).
- `deck/store.mjs`: `fallbackDue` and `fallBack`.
- `deck/server.mjs`: a wait holds its kind active while parked and notes it as it returns; the pilot's parked wait sets one timer at the `nextAt` its last `fallbackDue` returned, and when it fires (or on a wake) hands overdue replies over through `fallBack`.
- `deck/ui/render.mjs`: the thread header's live `kind` region (S4) named `owner: pilot · qa has ended; the pilot has this thread now` while `item.fellBack` was set; at Gate 2 the user called the note bloat (itm_8dc56c0d58cd), so the header shows only the owner changing to `pilot`, in its colour, and the fix round after Gate 2 removed `fellBack`, which was written and never read. No message is written, so no `from: 'deck'` rendering comes back (main's decision C, relayed during S5: a line stored in the thread would either sit out of time order or stop being the thread's last message, which `threadState` and `hooks/stop-gate.js` read as "the pilot replied").
- `deck/test/fallback.test.mjs` (new): the pins.

## Interface

  : { overdue: Reply[], nextAt: number | null }         //   a reply on an open thread whose owner != pilot is due at
                                                        //   max(timeUp, quietAt(owner)); timeUp is repliedAt + OWNER_PICK_UP_MS

## Tests

All clock-driven tests use `mock.timers.enable({ apis: ['setTimeout', 'Date'] })`. The pure
functions take `now`.

1. `L6: an unclaimed reply with qa quiet goes to the pilot 30 s after it arrived`: not a millisecond before; no `fellBack` stored.
2. `L6: a qa that made a tool call inside the window keeps its reply until it has been quiet 90 s`.
3. `a qa holding a wait is at work for as long as it holds it`: a 2-minute wait, then 90 s after it returns.
3a. `L7: a reply qa picked up and left unanswered goes to the pilot 5 min after the pick-up`: once, `deliveredTo` `['qa', 'pilot']`, and not to QA again.
3b. `L7: a reply qa answered on the thread stays qa's`; `L7: an owner still working after 5 min keeps its thread until it has been quiet 90 s`; `a sign off qa picked up is never taken back for the pilot`.
4. `an unclaimed reply is found although the pilot's cursor is past it`: with `since` above its seq, it is still returned once overdue.
5. `the inbox hook's 1 ms wait receives an overdue reply`: an authorless `deck_wait` with `timeout: 1`, as `hooks/inbox-alert.js:156` sends it.
6. `a fallen-back reply is not handed to a qa that returns` (A9).
7. `an old walkthrough with author qa falls back` (A2).
8. `fallback writes once`: two parked pilot waits produce one hand-over and no line.
9. `a restarted daemon counts an unseen kind from its own start`: an old reply does not fall back at once.
10. `after a fallback the header shows the new owner, pilot, in its colour, live` (renamed at Gate 2, when the note went).

## Done

- **Expected**: with QA ended, a reply on its walkthrough wakes the pilot within about 30 to 90
  seconds, and the thread header's owner reads `pilot`. A QA still making tool calls or holding a
  wait keeps its reply; one that picked a reply up and left it unanswered 5 minutes loses it.
- **Verification**: `node --test deck/test/fallback.test.mjs deck/test/agents.test.mjs`; `npm test`.
- **Evidence**: tests 1, 2 and 4 fail before and pass after. On a scratch deck (`PILOT_DECK_PORT`,
  `PILOT_DECK_DIR`), the real fallback is seen flipping the owner live.
- **Prohibited**: no fallback decided when a reply arrives; no daemon-wide sweep timer; no second
  90 s constant and no environment override of either period; no persisted `lastActive`; no `SubagentStop` hook.
- **Done when**: both test files and the full suite are green, and the fallback has been seen live.
  Size is about 360 changed lines: about 160 of code and 200 of tests.
