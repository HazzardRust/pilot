# S1 Walking skeleton: a QA-owned thread wakes only QA's wait

Feature `thread-ownership` · delivers spec 1, 2 (the `deck_wait` path) · source: `../architecture.md` §2, §3, A1, A2, A8 · after: –

## Files owned

- `deck/items.mjs`: `OWNER_KINDS`, `ownerOf`, the kind a caller waits as.
- `deck/store.mjs`: `postItem` stores `owner`; `ownerFilter`, composed beside `forRun` (`server.mjs:498`).
- `deck/server.mjs`: `runTool` composes the owner predicate into `heard`.
- `deck/client.mjs`: `cursor` and `handed` keyed by the caller's owner kind.
- `deck/tools.mjs`: `author` (the existing `AUTHOR`) declared on `deck_read` and `deck_wait`.
- `hooks/deck-author.js`: header names the five tools it now stamps.
- `hooks/hooks.json`: matcher widened to `deck_(post|reply|resolve|read|wait)`.
- `deck/ui/render.mjs`: `owner: <kind>` on the thread page's header line.
- `deck/test/owner.test.mjs` (new): the pins.
- `hooks/test/deck-author.test.js`: the matcher covers read and wait.
- `docs/adr/0041-a-thread-has-one-owner-kind.md` (new): A1, A2, A3, L3, L4 (with A7 as its mechanism), A9, and 0020's "the pilot stays every thread's only reader" amended.

## Interface

```
OWNER_KINDS: readonly ['pilot', 'qa']                 // items.mjs
ownerOf(item): 'pilot' | 'qa'                         // item.owner ?? author-kind if an owner kind ?? 'pilot'; chat and created threads always 'pilot'
waiterKind(author: string | undefined): 'pilot' | 'qa' | null   // undefined/'' -> 'pilot' (A8); a non-owner kind -> null
item.owner: 'pilot' | 'qa'                             // written by postItem from authorKind(author)
ownerFilter(kind: 'pilot' | 'qa'): (reply) => boolean  // store.mjs; reads the deck fresh per reply
deck_wait / deck_read inputSchema: + author (set by the plugin)
client: cursors: Map<'pilot'|'qa', number>; handed: Map<'pilot'|'qa', Set<number>>
```

## Tests

1. `a QA walkthrough is stored with owner qa and a pilot question with owner pilot`: posting as each author stores that owner.
2. `an item with no owner reads as its author kind, else pilot`: an old item with `author: 'qa'` reads `qa`; one without an author reads `pilot`.
3. `a chat and a created thread are the pilot's whatever posted them`.
4. `a reply on a qa thread is heard by a qa wait and not by a pilot wait`: two parked waits, one reply, and only QA's returns it.
5. `a pilot wait keeps its own reply after a qa wait moved past it`: through `waitForReply`, a QA wait returns first, then the pilot's wait still gets a pilot-thread reply with a lower seq.
6. `a wait with no author is the pilot's`.
7. `the thread page names the owner`.
8. `deck-author stamps deck_wait and deck_read` (hooks test): the matcher regex matches both, and the stamp overwrites an agent-supplied author.

## Done

- **Expected**: a QA walkthrough's header shows its owner, `qa`. A user reply on it returns from QA's
  `deck_wait` only, and the pilot's wait in the same session stays parked and later still
  receives its own replies.
- **Verification**: `node --test deck/test/owner.test.mjs hooks/test/deck-author.test.js`; `npm test`.
- **Evidence**: test 5 fails before the per-kind cursor and passes after. A live deck on
  `PILOT_DECK_PORT=4399` with `PILOT_DECK_DIR` set to a scratch directory: post as QA (author
  `pilot:pilot-qa`), reply in the browser, and see the thread header's `owner: qa`.
- **Prohibited**: no author read from the message body; no filter in the client alone (the
  daemon decides who hears); no migration pass over stored items; no `any`-shaped default that
  makes an unknown author an owner.
- **Done when**: both test files and the full suite are green, and the owner label has been
  seen on a live thread page.
