# S3 Rules repair themselves after an upgrade

Feature `audit-fixes` · delivers spec 5, 6, 7 · source: `../architecture.md` §2, §5 L4, §6 Q1–Q2 · after: S2 (`hooks/hooks.json`, `docs/INSTALL.md`)

## Files owned

- `scripts/install-rules.mjs`: a `--repair` mode over the existing `installRules`.
- `hooks/hooks.json`: a SessionStart entry `start:any:rules-repair`, beside `statusline-repair`.
- `scripts/test/rules-repair.test.mjs` (new): the pins.
- `docs/INSTALL.md`: the rules row says the copy is kept current at session start.
- `docs/adr/0079-the-rules-copy-repairs-itself-at-session-start.md` (new).

## Interface

```
node scripts/install-rules.mjs --repair [--target <dir>] [--state <dir>]
// prints nothing when nothing changed and no new edited rule; else one systemMessage-shaped JSON line
repairRules(options?: { target?, source?, ledger?, stateDir? }): { changed: boolean, message: string | null }
// installRules underneath (ADR 0055 ledger); remembers the edited set in <stateDir>/rules-edited.json
```

## Tests

1. `a shipped copy of an old version is replaced`: target seeded from a ledger version → `cmp`-identical to source after.
2. `a retired shipped copy is deleted`: `README.md` matching its shipped hash is gone.
3. `an edited rule keeps its bytes and is named once`: first run's message names it; second run prints nothing.
4. `a new edited file is named again`: adding a second edit names both.
5. `nothing changed prints nothing`: a current target produces no output, exit 0.
6. `a link out of the target is not written through` (the existing `landsInside`, now through `--repair`).
7. `the hook entry runs --repair at SessionStart with a 5 s timeout`.

## Done

- **Expected**: the first session after an upgrade brings `~/.claude/rules` up to the package, says what it changed, and names an edited rule once.
- **Verification**: `node --test scripts/test/rules-repair.test.mjs scripts/test/install.test.mjs`; `node scripts/check-references.mjs rules/`; `npm test`.
- **Evidence**: tests 1–4 red first; a run with `--target` a scratch dir seeded with 0.7.10's rules (`git show <0.7.10>:rules/...`) then `cmp` exit 0 on both rule files; never the real home (L8).
- **Prohibited**: no comparison looser than the ledger's sha256; no writes outside `--target`; no deletion of a file not in the ledger; no message on an unchanged run.
- **Done when**: the repair runs at SessionStart, every test above is green, and the scratch-home `cmp` exits 0.
