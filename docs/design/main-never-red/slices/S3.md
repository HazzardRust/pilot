# S3 The gate rebuilds the ledgers and fails naming a stale one

Feature `main-never-red` · delivers spec 1 · source: `../architecture.md` §2, §3 F1-F3, Seams, §5 L1 L2 · after: S2 (`rulesLedgerText`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the gate's entry point starts processes (the security trigger).

## Files owned

- `scripts/ledgers.mjs` (new): `rebuildLedgers`.
- `scripts/gate.mjs`: `runGate` takes `ledgers`, and the entry point passes `rebuildLedgers`.
- `scripts/test/ledgers.test.mjs` (new): the seam on a temp git repo.
- `scripts/test/gate.test.mjs`: `runGate` with a stale and a throwing `ledgers`.

## Interface

```
rebuildLedgers(root: string): string[]
  // writes scripts/shipped-rules.json (S2's rulesLedgerText) and VENDOR.md (buildLedger)
  // under root; returns the repo-relative paths whose bytes changed, [] when both were current
runGate(args, { ledgers = () => [], cwd, spawn, slot, read, ... }): number
  // before the slot: ledgers(cwd); a stale path prints `ledger stale: <path>, rebuilt; commit it`
  // and returns 1 without the suite; a throw prints `ledgers: <message>` and returns 1;
  // [] prints `ledgers current` and runs as before
```

## Tests

1. `an edited rule makes the rules ledger stale and rebuilds it`: `rebuildLedgers` → `['scripts/shipped-rules.json']` on a temp repo with an edited rule, and the file now holds the new hash.
2. `a current tree rebuilds nothing`: `rebuildLedgers` → `[]` on a second call, with the bytes unchanged.
3. `a stale fragment makes VENDOR.md stale`: `rebuildLedgers` → `['VENDOR.md']` after a row is added to a `vendor/` fragment.
4. `a stale ledger fails the gate before the suite`: `runGate` → 1, the `ledger stale:` line names the path, and neither `spawn` nor `slot` is called.
5. `a ledger that cannot build fails the gate`: `runGate` → 1 and `ledgers: <message>` when `ledgers` throws.
6. `current ledgers run the suite`: `runGate` → `ledgers current`, then the suite runs as in the existing test.

Rewrite check: replacing how either ledger is built keeps all six results above.

## Done

- **Expected**: `npm test` on a tree with a stale ledger stops within seconds, naming the file it rebuilt; on a current tree it runs the suite as before.
- **Verification**: `node --test scripts/test/ledgers.test.mjs scripts/test/gate.test.mjs`. Live, in your worktree: append a line to `rules/typescript/testing.md`, run `npm test`, then `git checkout -- rules scripts/shipped-rules.json`. Then the full gate (brief.md).
- **Evidence**: tests 1 and 4 red before and green after; the live run's `ledger stale: scripts/shipped-rules.json, rebuilt; commit it` and its exit code 1; the clean gate's `ledgers current` and its pass count beside the base's.
- **Prohibited**: no default `ledgers` that writes the real repo from a test; no running the suite after a stale ledger; no `--check`-only step; no edit to the builders' CLIs.
- **Done when**: the six tests and the gate are green, and the live stale run has been seen failing with the named file.
