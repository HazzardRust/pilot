## Files owned

## Interface

```
.github/workflows/gate.yml
  name: Gate
  on: pull_request (branches: [main]; types: opened, synchronize, reopened, ready_for_review)
      ; push (branches: [main])                                     # L8
  permissions: contents: read
  concurrency: group gate-${{ github.ref }}, cancel-in-progress: true
  jobs.gate.if: github.event_name == 'push' || !github.event.pull_request.draft
  jobs.gate.runs-on: ubuntu-latest                                  # L8
  steps: checkout (fetch-depth: 0) ; setup-node (node-version: 26, cache: npm)
         ; npm ci ; npm test ; node scripts/check-references.mjs
         ; node scripts/check-provenance.mjs agents/ skills/ rules/
workflowText(): string   # the file's text, read by the pin test
```

## Tests

1. `the gate workflow runs on non-draft PRs to main and pushes to main`: `workflowText` → the `pull_request` and `push` triggers both name `main`, the four PR types include `ready_for_review`, the job's `if` skips a draft, and there is no `pull_request_target`, `issue_comment` or `workflow_run`.
2. `the gate workflow runs on ubuntu and cancels a superseded run`: `workflowText` → `runs-on: ubuntu-latest`, and `concurrency` per ref with `cancel-in-progress: true`.
3. `the gate workflow runs the full gate`: `workflowText` → the four run steps, in order.
4. `the gate workflow holds no secret and a read-only token`: `workflowText` → `contents: read` is its only permission, and no `secrets.` appears.
5. `the gate workflow checks out whole history`: `workflowText` → `fetch-depth: 0`.

Rewrite check: rewording or reordering the YAML keys keeps all five results above.

## Done

- **Expected**: a non-draft PR to `main` carries a `gate` check that runs the full gate on `ubuntu-latest` and goes red when any of its four steps fails; a draft carries none.
- **Verification**: `node --test scripts/test/gate-workflow.test.mjs`; the full gate (brief.md). The first hosted run comes when the Sign off marks the feature PR ready: `gh pr checks <feature PR>`, then `gh run view <id> --log` for the step times.
- **Evidence**: the five pins red before the file exists and green after; the gate's pass and fail lines. The first Linux run's result and minutes are reported to `main`. An OS-bound test red on Linux is a found issue, built in this run as its own slice; do not fix it in this one.
- **Prohibited**: no `pull_request_target`; no secret; no `continue-on-error`; no step that skips or filters the suite; no edit to `claude.yml`.
- **Done when**: the pins and the gate are green locally, and the file matches the Interface block.
