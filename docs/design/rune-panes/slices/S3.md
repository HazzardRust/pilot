# S3 Open notifications end with their tab's name

Feature `rune-panes` · delivers spec 2 · source: `../architecture.md` §2, §3 Notifications, §5 L3 · after: –
Reviewers: `pilot:rust-reviewer`, `pilot:typescript-reviewer`
Model: sonnet — one field from an existing derivation (`tabFor`) and one text; every choice is fixed here.

## Files owned

- `deck/view/notifications.mjs`: each open entry gains `tab`, `tabFor(tabsOf(...), item.repo)?.name ?? ''`.
- `deck/test/view-notifications.test.mjs`: the `tab` pin.
- `deck/rune/src/regions/notifications.rs`: `Open` gains `tab`; the row draws " · <tab>" after the title when non-empty.
- `deck/rune/tests/deck/notifications.rs`: the Rune pin on a seeded view.

## Interface

```
notificationsView(reads) -> { open: [{ id, title, href, writes, tab: string }], ... }
pub fn draw(v: &Value, l: &Local, cx: &mut Cx<State>) -> El
```

## Behaviours

1. `an open notice carries its tab's name` (test): `notificationsView` → a seeded notice on repo `kettle` has `tab: 'kettle'`; one on an unknown repo has `tab: ''`.
2. `the row ends with the tab` (test): `draw` → the seeded row's texts end with " · kettle"; the empty-tab row ends with its title.

Rewrite check: computing the tab from any other derivation keeps both behaviours if it names the same tab.
Misses: whether the name clips at narrow widths; the walkthrough.
