# S17 The archive's lag, measured and then fixed (added)

Feature `archive-page` · delivers spec 11 · source: `../architecture.md` §2 (spec 9, spec 11), §6 A5 · after: the drift merge of `origin/pilot` (the centre is now one scrolling viewport, ADR 0217 L4)
Reviewers: `pilot:rust-reviewer`
Model: opus — a measurement whose number decides the fix, and a frame-time bar.

The user: "it is very laggy but that could be because of all the other processes running ... i think the lag is coming from this archive. make it less laggy." Measurement comes before any fix, and its numbers go in the report.

## Files owned

- `deck/rune/src/regions/archive.rs`: the fix, whatever the measurement names.
- `deck/rune/src/app.rs`: only if the fix must hold parsed archive rows in `State` (a cache keyed to the view it was built from).
- `deck/rune/tests/deck/archive_lag.rs` (new) and its `mod` line in `deck/rune/tests/deck/main.rs`: the frame-time pins.
- `scripts/archive-timing.mjs`: only to add the measurement if it belongs there.

## Measure first (report these before the fix lands)

On a copy of `~/.claude/pilot` (about 6,855 rows, 14 kinds), release build, 3 runs each, with the machine's CPU load noted beside each run:

1. Frame time of the Archive screen (Today open; and with every section open) vs the home screen in the same session: separates the archive from machine load.
2. Frame time of one search keystroke and one sort press on the Archive screen.
3. The `screen=archive` view's size and serve time, and how often it is refetched while the screen is open (a live change refetches the whole view, A5).
4. Where the frame goes: per-frame `Archive::deserialize` of the region `Value`, the `filter_rows`/`sort_rows` clones, rows drawn in sections that are folded or off-screen (the archive list's own `scroll` now nests inside the centre's viewport since the merge, so it may draw every open row).

## Behaviours

1. `the archive frame is as cheap as home's` (Rust test, release bar): over a recorded view of 10,000 rows with Today open, a frame draws in under 16 ms, 3 runs, and a search keystroke's frame in under 16 ms.
2. `an unchanged view is not re-parsed per frame` (Rust test): two frames over the same view parse its rows once (a counter or the cache's key), and a new view parses again.
3. Spec 4 and spec 9's pins stay green (`archive_filter`, the 10,000-row frame test).
