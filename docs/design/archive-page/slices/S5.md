# S5 Run records and friction rows

Feature `archive-page` · delivers spec 3, 6 · source: `../architecture.md` §2, §3 Seams, §5 L4 · after: S1 (record-kind seam)
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — two adapters over `deck.json`'s `records[]`, fields named here.

## Files owned

- `deck/archive-kinds/runs.mjs` (new): one row per run record.
- `deck/archive-kinds/friction.mjs` (new): one row per friction row of every record.
- `deck/test/archive-runs.test.mjs` (new): the pins.

## Interface

```
S1's ArchiveKind, S1's ArchiveRow, S1's ArchiveSource
runs     : ArchiveKind  // kind 'run'; source.records; id `<repo>:<slug>`; at updatedAt ?? finishedAt
         // fields Feature, Ticket, Branch, Base, Artefact, Slices (n, states), Next, Finished, Updated
friction : ArchiveKind  // kind 'friction'; one row per record.friction[i]; id `<repo>:<slug>:<i>`; at the record's updatedAt
         // fields Feature, Agent (or 'drain'), What, Evidence, Size
```

## Behaviours

1. `a run record reads as its fields` (test): `runs` → a seeded record gives one row with Feature, Branch and Slices labels and its slice states as text, no `{"`.
2. `friction rows are rows` (test): `friction` → a record with one agent row and one drain row gives 2 rows, the drain's Agent reading `drain`.
3. `a record with no friction adds none` (test): `friction` → 0 rows for a record without `friction`.

Rewrite check: moving friction to its own file keeps 2-3 with the same labels.
Misses: whether the slice-state summary is the useful one; the walkthrough reads it.

## Done
