## Interface

```
S1's ArchiveKind, S1's ArchiveSource
backups : ArchiveKind   // kind 'backup', files ['deck.v*-*.json']
        // one row per `deck.v<version>-<day>.json` and `deck.v<version>-<day>-<n>.json` in source.dir (store-core.mjs backUp)
        // id `backup:<file>`; at the file's day; fields File, Version, Day, Items (the `items` list length, as the month-file kind reads it)
        // a file that does not parse or has no `items` list is no row, never a throw
switches : ArchiveKind  // FILES gains 'defender-advised.json' (deck/doctor.mjs ADVISED_FILE), fields Where, At
```

## Behaviours

1. `an upgrade backup reads as its fields` (test): `backups` → a store upgraded from version 2 with 4 items gives one row, Version 2, Items 4.
2. `a numbered backup is read too` (test): `backups` → a truncated same-day backup beside the real one leaves the `-2` file as its own row.
3. `a malformed backup is skipped` (test): `backups` → unparseable and list-less files give no row and no throw.
4. `the defender marker is a switch row` (test): `switches` → a marker written by `markAdvised` gives one row of named fields, none starting with `{`.
5. `every store file is viewed or never shown` (test): S10's coverage test is green with `SHOWN_THROUGH_ANOTHER` gone.

Misses: a backup of a kind other than deck.json; a later writer of another backup name (the coverage test reads the writers).
