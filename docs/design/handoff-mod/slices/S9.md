# S9 The deck's Start opens the pilot directly

Feature `handoff-mod` · delivers spec 11 · source: `../architecture.md` §2, §3 (launcher duties), §5 L12, L15, §6 A4, A9 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a process start from the daemon on a command line built by hand (A4), and spec 11 rests on A9.

## Files owned

- `deck/session.mjs`: `openPilot` (new, the one window builder `startSession` (105-152) and S12's `pilot start` share) opens `claude` itself: `cmd /d /c start "pilot" "<claude>" --add-dir "<rules root>" --agent pilot:pilot --settings "<settings file>"`, no prompt; `claude` from `claudeBin()` (`hooks/lib/platform.js`); a missing one is a 500 refusal naming it.
- `deck/run-env.mjs`: `startArgs(reach, { settingsFile })` beside `claudeArgs` (61): writes the reach's settings to `~/.claude/pilot/start-settings.json` and answers the argv; `runEnv` (74) is the child's env.
- `deck/test/start-session.test.mjs`: the command line and env against a fake spawn.

## Interface

```
// deck/run-env.mjs
export function startArgs(reach: { level }, { settingsFile?: string, home?: string }?): string[]   // no prompt (L12)
// deck/session.mjs
export function openPilot(repo, { spawn?, platform?, env?, claude?, reach? }?): void   // detached, unref'd; throws DeckRefusal
startSession(repo, deps): void   // the latch and refusals, then openPilot
// refused before any spawn, as today: PILOT_DECK_NO_START, not win32, `"` or `%` on any word, a missing directory, a Start in flight
```

## Tests

1. `Start opens claude with the reach's args and no prompt`: `startSession` → words are `"pilot"`, the absolute `claude`, `--add-dir`, the rules root, `--agent`, `pilot:pilot`, `--settings`, the file; no `run`, no prompt.
2. `the settings file holds what --settings carried`: `startArgs` → the file parses to `runSettings(level).settings`.
3. `a claude path or rules root with a quote is refused before any spawn`: `startSession` → 400, 0 spawns.
4. `no claude on the PATH is said`: `openPilot` → refusal naming it, 0 spawns.
5. `the child env is runEnv's`: `startSession` → `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1`, no parent markers.

Rewrite check: any other way to open the window keeps tests 1, 3 and 4's words and spawn counts.
Misses: the window really opening on Windows; the live check below.

## Done

- **Expected**: pressing Start (or Resume) on a deck tab opens a terminal window with the pilot running in that directory, idle until the user types.
- **Verification**: `node --test deck/test/start-session.test.mjs`; the gate in `../brief.md`; live: `pilot deck --scratch`, open the page, press Start on a scratch tab, see the window.
- **Evidence**: tests 1-5 red before, green after; the window seen with the pilot's banner.
- **Prohibited**: no `pilot run` or other launcher on the line; no JSON string on the line (A9); no deck text on the line; no `shell: true`.
- **Done when**: the five tests and the gate are green and the live Start opened the pilot.
