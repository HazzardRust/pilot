# S3 The Tickets rail marks both live tickets

Feature `three-lanes` · delivers spec 6 · source: `../architecture.md` §2, §3 Seams · after: S1 (`laneOf`)
Reviewers: `pilot:typescript-reviewer`

## Files owned

- `deck/ui/render-rail.mjs`: the Tickets panel reads `laneOf` for both stages: `marked` holds both live tickets, each stage's queue carries its own `next`, and pending switches come per lane; `data-planning-state` and `data-concluding-state` replace `data-deck-state`.
- `deck/tabs.mjs`: `tab.holding` is true for a live ticket of either stage.
- `deck/tickets.mjs`: `queueView`'s `live` is the live planning ticket (`liveTicketOf(items, repo, 'red')`).
- `deck/ui/deck.css`: the attribute selectors follow the rename.
- `deck/test/three-lanes-rail.test.mjs` (new): the pins.

```
S1's laneOf: the rail's one source for state, live ticket, next and pending per lane

```

## Tests

1. `both live tickets wear the in-hand mark`: `laneOf` → the rendered rows for the live red and the live green both carry `in-hand`.
2. `each queue carries its own next`: `laneOf` → the red queue's `next` is the red head, the green queue's is the green head.
3. `the panel names both stage states`: `laneOf` → `data-planning-state="held"`, `data-concluding-state="queued"`.

Rewrite check: rendering the marks from a precomputed lane list keeps every result above.
