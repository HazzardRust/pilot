# S7 Only the pilot posts a gate1 and only the pilot or QA a gate2

Feature `three-lanes` · delivers spec 14 · source: `../architecture.md` §2, §3 Authors, L14 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `deck/store-items.mjs`: `POSTERS` and the refusal in `postItem`, before the store is read.
- `deck/server-tools.mjs`: the `deck_ticket` dispatch refuses a stamped author other than the pilot, except the architect's `merge`.
- `hooks/hooks.json`: the deck-author matcher adds `deck_ticket`.
- `hooks/deck-author.js`: no change unless its test needs the new tool named.
- `deck/test/posters.test.mjs` (new): the pins.

## Interface

```
deck/store-items.mjs
  export const POSTERS: { gate1: ['pilot'], gate2: ['pilot', 'qa'] }   // kinds absent: anyone stamped
  postItem(given): Item   // throws "a <kind> is posted by <list>, not <author>"
deck/server-tools.mjs
  deck_ticket { id, action, author }   // stamped; non-pilot refused but architect `merge`
hooks/hooks.json matcher: ^mcp__plugin_pilot_deck__deck_(post|reply|resolve|read|wait|ticket)$
```

## Tests

1. `a gate2 from QA is accepted and from the architect refused`: `postItem` → accepted for `pilot:pilot-qa`, refused for `pilot:pilot-architect`.
2. `a gate1 from QA is refused`: `postItem` → throws naming `pilot`.
3. `an unstamped gate1 is the pilot's`: `postItem` → accepted.
4. `the architect may merge and may not need`: `deck_ticket` → `merge` accepted, `need` refused.
5. `deck_ticket is stamped`: `deck_ticket` → its call through the hook arrives with the stamped author.

Rewrite check: moving `POSTERS` into the tool layer keeps every result above.
