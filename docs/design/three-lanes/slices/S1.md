# S1 A planning and a concluding ticket are live at once (walking skeleton)

Feature `three-lanes` · delivers spec 1, 2, 3, 4 · source: `../architecture.md` §2, §3, L2, L3, L4 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `deck/items.mjs`: `LANE_STATES` gains `planning: ['red']` and `concluding: ['green']`; `liveTicketOf` and `nextTicketOf` take a state; `inHandOf`, `deckStateOf`, `isBehind` and `standingOf` work per stage; `switchOf` reads a legacy `main` record as its `to`'s lane.
- `deck/lanes.mjs`: `laneOf` (new); `lanesFrom` returns `planning`, `concluding` and `co-pilot` lines, a per-lane `refusal`, and `mainClause` carrying both stages' words.
- `deck/store-tickets.mjs`: `takeTicket` and `takeIn` are one-live-per-stage; `mergeTicket`'s host is the live planning ticket.
- `hooks/session-handoff.js`: `PLANNING_LINE` and `CONCLUDING_LINE` replace `MAIN_LINE`; `lanesNotice` prints three lines.
- `scripts/handoff.mjs`: appends the three lines.
- `deck/test/three-lanes.test.mjs` (new): the pins.

## Interface

```
deck/items.mjs
  export const LANE_STATES: { planning: ['red'], concluding: ['green'], co-pilot: ['yellow'] }
  export function liveTicketOf(items, dir, state?: 'red' | 'green'): Ticket | undefined  // no state: first live, as today
  export function nextTicketOf(items, repo, state: 'red' | 'green'): Ticket | undefined  // asked first, then the stage's head
  export function isBehind(item, items): boolean                                   // behind only its own stage's hand
deck/lanes.mjs
  export function laneOf(items, repo, lane: 'planning' | 'concluding', { switching }): { state: 'held' | 'queued' | 'empty' | 'switching', ticket?: Ticket, next?: Ticket, pending?: string }
  export function lanesFrom(items, repo, { switching, co-pilot }): { planning: string, concluding: string, co-pilot: string, mainClause: string, yellowClause: string, refusal: string | null }
deck/store-tickets.mjs
  export function takeTicket(id): Ticket   // refuses `<live> is live in planning|concluding` for a same-stage second take
Hook line shapes: `planning: empty | planning: empty → next itm_… | planning: itm_…`, the same for `concluding:`
```

## Tests

1. `a concluding take leaves the planning ticket live`: `takeTicket` → both tickets carry `live: true`.
2. `a second planning take is refused naming the live one`: `takeTicket` → throws naming the live planning id.
3. `each lane fills from its own queue`: `nextTicketOf` → the red head for `'red'`, the asked green for `'green'`.
4. `an empty concluding lane with a green queued is refused`: `lanesFrom` → `refusal` names the concluding lane and the green id.
5. `the hook prints three lane lines`: `lanesFrom` → `planning:`, `concluding:`, `co-pilot:` lines that `session-handoff`'s notice echoes.
6. `a live concluding ticket's question is not behind a live planning ticket`: `isBehind` → false for both.

Rewrite check: replacing the `live` flag with a stored lane field keeps every result above.
