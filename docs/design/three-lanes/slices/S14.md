# S14 A landed gate2 stays signed

Feature `three-lanes` · delivers spec 18 · source: `../architecture.md` §2, A8 · after: S11 (`deck/store-items.mjs`)
Reviewers: `pilot:typescript-reviewer`

## Files owned

- `deck/store-items.mjs`: `dismissItem` on a gate2 whose `landing` has settled stores `landed <sha7>` or `landing refused` as its resolution, not `DISMISSED_BY_USER`; the report check accepts it.
- `deck/test/gate2-stays-signed.test.mjs` (new): the pins.

## Interface

```
deck/store-items.mjs
  export function dismissItem(id): Item   // a settled landing's gate2 resolves as `landed <sha7>` or `landing refused`
  postItem({ kind: 'report', ticket }): Item   // accepted after such a resolve
```

## Tests

1. `a Dismiss after a landed landing keeps the gate2 signed`: `dismissItem` → resolution `landed <sha7>`; the replies are untouched.
2. `the closing report posts against it`: `postItem` → accepted, the ticket closed.
3. `a Dismiss on an unlanded gate2 is still a dismissal`: `dismissItem` → `DISMISSED_BY_USER`.

Rewrite check: storing a `signed` flag on the gate2 instead of reading `landing` keeps every result above.

## Done

- **Expected**: the user dismisses a landed gate2 and the pilot's closing report still posts.
- **Verification**: `node --test deck/test/gate2-stays-signed.test.mjs deck/test/dismiss.test.mjs`; `npm test`.
- **Evidence**: tests failing before and passing after.
- **Prohibited**: letting Dismiss move the ticket; touching `landing`.
- **Done when**: the tests and the suite are green.
