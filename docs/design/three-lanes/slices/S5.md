# S5 One Status tab draws the implementing ticket's record

Feature `three-lanes` · delivers spec 12 · source: `../architecture.md` §2, §3, A5, A6 · after: S3 (`deck/ui/render-rail.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:react-reviewer`

## Files owned

- `deck/ui/render-rail.mjs`: `statusTicketOf` (new) picks the held lane's ticket (implementing, then concluding, then planning); `renderStrips` draws that ticket's newest record from `tab.runs` (`run.ticket`) as one `STATUS` panel, table then graph, falling back to today's newest run with a table.
- `deck/ui/strips.html`: one `<details id="status">` bookmark, `data-live="status"`, `data-name="Status"`, replaces `tree` and `table`.
- `deck/ui/deck.css`: the bookmark stack loses one tab.
- `deck/ui/js/live.mjs`, `deck/ui/js/size.mjs`: the `status` region in place of `tree` and `table`.
- `deck/test/status.test.mjs`, `deck/test/tabs.test.mjs`: the Graph pins become the one Status pin.

## Seam note (co-pilot, A-f6)

A stored run never carries `ticket`: `deck_status`'s `ticket` lives only on the record in `deck.records` (`deck/store-runs.mjs` `recordOf`), and a directory's one run holds whichever table was posted last. So the record is chosen by ticket id, not by run, as the rewrite check already says. S5 also owns about five lines in `deck/store-runs.mjs` (`deckLanes()` returns `records: { [repoKey]: record[] }` from the same read) and `deck/tabs.mjs` (`tab.records`); `renderStrips` draws the held ticket's newest record with slices (`record.ticket === ticket.id`) as `{ ...record, repo: tab.repo }`, else today's newest run with a table. Tests 1 and 2 build `tab.records`, never `run.ticket`. S11 later edits `repliesSince` in the same `store-runs.mjs`, a different function.

## Tests

1. `the Status tab draws the implementing ticket's record`: `statusTicketOf` → the yellow ticket; the panel holds its record's `slices` table and graph.
2. `no held lane falls back to the newest run with a table`: `statusTicketOf` → undefined; the panel draws as today.
3. `there is no Graph bookmark`: `renderStrips` → no `<summary>Graph</summary>`, and one `data-live="status"`.

Rewrite check: choosing the record through `recordForTicket` instead of `tab.runs` keeps every result above.
