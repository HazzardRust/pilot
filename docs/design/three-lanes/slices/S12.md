# S12 A gone worktree is recreated and landed

Feature `three-lanes` · delivers spec 16 · source: `../architecture.md` §2, §3 Landing · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `deck/landing.mjs`: `worktreeFor`, on ENOENT, fetches and recreates the record's worktree at the same path with `git worktree add -B feat/<slug> <path> origin/feat/<slug>`, refusing unless the tip equals the gate2's `sha`; the landing line opens `recreated <path> at <sha7>`.
- `deck/test/landing-recreate.test.mjs` (new): the pins, against a scratch repository with a bare origin.

## Interface

```
deck/landing.mjs
  function worktreeFor(gate): { worktree: string, recreated: boolean }   // throws notRun on a tip ≠ gate.sha
Landing line: "recreated <path> at <sha7>; " + the land output
```

## Tests

1. `a removed worktree is recreated and the landing runs`: `worktreeFor` → `recreated: true`, and the line names it.
2. `a branch tip that is not the gate2's sha refuses`: `worktreeFor` → `NOT landed: … origin/feat/<slug> is at <x>, the gate2 signed <y>`.
3. `a present worktree is used as it is`: `worktreeFor` → `recreated: false`.

Rewrite check: recreating with a detached checkout at the sha keeps every result above.

## Done

- **Expected**: a gate2 pressed after its worktree was deleted lands, and the thread says it recreated the worktree.

- **Evidence**: tests failing before and passing after; the landing line.
- **Prohibited**: recreating at any sha but the gate2's; a shell string built from the record's path (use an argument array).
- **Done when**: the tests and the suite are green.
