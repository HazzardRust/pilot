# S2 A guessed tree keeps its untracked files

Feature `prune-run-trees` · delivers spec 4 · source: `../architecture.md` §2, §3 F5, §6 A2 · after: S1 (`scripts/worktrees.mjs`, `runTrees`' `by`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the rule decides whether a tree holding untracked work is force-removed, and A2 is assumed.

## Files owned

- `scripts/worktrees.mjs`: `prune`'s removal passes `landed` to `removeTree` only for a run tree whose `by` is not `name`.
- `scripts/test/worktrees-run-trees.test.mjs`: the guessed and tagged untracked-file pins.

## Interface

```
S1's runTrees: the `by` each run tree carries
prune(repo, base, { run, landed }) -> { removed, kept, failed }  // a by 'name' tree: removeTree's strict rule, never --force
```

## Behaviours

1. `a guessed tree with an untracked file is kept` (test): `prune` → with `landed`, a clean `fix/<slug>-drift` tree holding one untracked file is in `kept` as `dirty`, and the file is still on disk.
2. `a tagged tree in the same state still goes` (test): `prune` → with `landed`, a tagged tree holding one untracked file is in `removed`, as ADR 0171 says.

Rewrite check: any implementation keeps untracked work in a tree whose ownership is only guessed.
Misses: ignored files (a `.env`, build output) in a guessed clean tree go with it, as under every rule; QA's walkthrough reads that.

## Done

- **Expected**: after a landing, a guessed fix tree with scratch files is named `kept dirty <dir>` and left in place; tagged and exact-branch trees go as before.
- **Verification**: `node --test scripts/test/worktrees-run-trees.test.mjs scripts/test/worktrees*.test.mjs`; `npm run test:quiet`.
- **Evidence**: behaviour 1 red before and green after; behaviour 2 green before and after.
- **Prohibited**: no change to `removeTree`'s rules in `scripts/worktree-remove.mjs`; no new state name; no `--force` path for `by: 'name'`.
- **Done when**: both behaviours hold and the gate is green.
