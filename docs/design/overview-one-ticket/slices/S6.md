## Interface

```
nextTicketOf(items, repo, 'autonomous')  // the first yellow ticket that is not live; a blocking question no longer skips it
nextTicketOf(items, repo, 'attended')    // the first red-or-asked ticket that is not yellow, else the first green; never a yellow ticket
isBehind(item, items, modes)           // no isBlocking exception
CHAINING_FINISHES.autonomous           // [FINISHED_CLEAN]
pilot.md, Modes, autonomous run:  ends when QA's walkthrough is posted: `deck_ticket need`, then "Autonomous, red hands on".
                                  With no yellow ticket left: `deck_status` `finished: "needed"` with `ticket` and `qa`, and stop.
pilot.md, Modes, Needed:          "… or a blocking question stops everything left — `deck_ticket need`."
pilot.md, Modes, Red, attended:   answers the queued questions, takes the walkthrough to sign-off, then posts the `gate2`
                                  (its body the run's report).
```

`blocking: true` keeps its two deck rules: it refuses its ticket's `gate2` post, and it is never answered for the user.
