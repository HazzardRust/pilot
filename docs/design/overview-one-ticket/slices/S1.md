# S1 The overview lists only the ticket in hand's threads

Feature `overview-one-ticket` · delivers spec 1–8 · source: `../architecture.md` §2, §4, L2–L4, L6 · after: –

## Files owned

- `deck/items.mjs`: `inHandOf`, `modeOf`, `isBehind` beside `nextTicketOf`.
- `deck/status.mjs`: `shownOf`, the shown queue beside `queueOf`.
- `deck/ui/render.mjs`: home queue, strip counts and thread arrows read `shownOf`; `modeIn` calls `modeOf`; every ticket row with open threads gets its `threads` disclosure.
- `deck/test/overview-one-ticket.test.mjs` (new): the pins.
- `docs/adr/0065-the-overview-feeds-the-ticket-in-hand.md` (new): the decision (L2–L4), amending 0060.

## Interface

```
modeOf(modes: Record<string,{mode}>, repo: string): 'attended' | 'autonomous'   // the one spelling (L6)
inHandOf(items: Item[], repo: string, mode: Mode): Item | undefined             // liveTicketOf ?? nextTicketOf (L2)
isBehind(item: Item, items: Item[], modes): boolean   // either mode (L16): names an open ticket of its repo that is not in hand
shownOf(queue: Item[], items: Item[], modes): Item[]  // queue less what is behind; status.mjs
renderPreviews(ticket, items)                           // now on every row with open threads naming it
```

## Tests

1. `two red tickets with questions: the overview lists only the first's`: spec 1.
2. `a green ticket ahead of a red one: the red one's threads are listed`: spec 2.
3. `a live green ticket is in hand over a waiting red one`: spec 3.
4. `closing the ticket in hand lists the next one's threads`: spec 4, re-render after a report.
5. `an unticketed question is listed whatever is in hand`: spec 5.
6. `a hidden ticket's question is linked from its Tickets row`: spec 6.
7. `the arrows and the tab count walk the shown queue`: spec 7.
8. `autonomous: a parked ticket's question is hidden until that ticket is taken`: spec 8, L16.

## Done

- **Expected**: in either mode (L16) the overview and the tab list the ticket in hand's threads and the unticketed ones; every other ticket's threads are a press away on its Tickets row.
- **Verification**: `node --test deck/test/overview-one-ticket.test.mjs`; `npm test`.
- **Evidence**: tests 1–8 red before, green after; a scratch deck (`PILOT_DECK_DIR`, `PILOT_DECK_PORT`, never 4321) seeded per §9, its overview seen in a browser, and a live swap seen bringing the next ticket's question after the first is closed.
- **Prohibited**: no stored flag on threads (L3); no second head function beside `nextTicketOf`; no change to `queueOf` itself (the Stop hook and `/items` read it); no filtering in `/items`.
- **Known test churn**: render tests that hold questions on several tickets under default modes (`red-grilling`, `next-ticket`, `tabs`); update their expectations, never delete an assertion.
- **Merge-first**: no overlap.
- **Done when**: `npm test` is green and the scratch deck's overview has been seen listing one ticket's threads and swapping to the next.
