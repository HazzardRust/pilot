# S4 `deck_ticket need` and `pivot`

Feature `overview-one-ticket` · delivers spec 15–18 · source: `../architecture.md` §2, L7, L8, L10, L15 · after: – (beside S1)

## Files owned

- `deck/store.mjs`: `needTicket`, `pivotTicket`, each one write.
- `deck/tools.mjs`: `deck_ticket`'s action enum gains `need` and `pivot`; its description says what they do.
- `deck/server.mjs`: the `deck_ticket` handler answers each in one line.
- `deck/test/ticket-need.test.mjs` (new): the pins.
- `docs/adr/0066-red-means-the-user-is-needed.md` (new): amends ADR 0060's "red once its gate2 is posted".

## Interface

```
needTicket(id: string): Item    // open yellow ticket -> red; refused unless an open question, walkthrough or gate2 names it
pivotTicket(id: string): Item   // red ticket -> yellow; its open gate2 resolved 'superseded by pivot', unsigned, same write
deck_ticket { id, action: 'up'|'down'|'take'|'park'|'merge'|'need'|'pivot', author? }
  -> "Needed itm_…: red." | "Pivoted itm_…: yellow, gate2 itm_… superseded."
```

## Tests

1. `need turns a yellow ticket with an open walkthrough red`: spec 15.
2. `need is refused by name with nothing open naming the ticket`: spec 15.
3. `need is refused on a ticket that is not yellow`: spec 15.
4. `posting a walkthrough leaves its ticket yellow`: spec 16.
5. `pivot turns a red ticket yellow and supersedes its open gate2`: spec 18.
6. `a gate2 posts after a pivot and turns the ticket red again`: spec 17, 18.
7. `pivot is refused on a ticket that is not red`: spec 18.

## Done

- **Expected**: the pilot can say the user is needed before any gate2 exists, and can send a ticket back to implementing after a pivot.
- **Verification**: `node --test deck/test/ticket-need.test.mjs deck/test/ticket-state.test.mjs deck/test/ticket-tool.test.mjs`; `npm test`.
- **Evidence**: tests red before, green after; on a scratch deck, `deck_ticket need` and `pivot` called through the MCP tool and the ticket row's state seen change.
- **Prohibited**: `pivot` must not call `resolveItem` (merge-first L12 refuses unsigned resolves); no new state value; no state write outside the store.
- **Merge-first**: adjacent hunk in `server.mjs`'s `deck_ticket` handler (its `mergeTicket(id, author)`); whichever lands second rebases.
- **Done when**: `npm test` is green and both actions have been seen moving a ticket on the scratch deck.
