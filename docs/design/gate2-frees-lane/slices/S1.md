# S1 Skeleton: the press frees the concluding lane

Feature `gate2-frees-lane` · delivers spec 1, 2 · source: `../architecture.md` §2, L1, L2, L8 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the `/reply` route is an API boundary, and the fill takes tickets live in the press's write.

## Files owned

- `deck/items.mjs`: `isLanding`, and its use in `liveTicketOf`, `nextTicketOf` and `standingOf`.
- `deck/chain.mjs`: `fillLanes` extracted from `chainNext`'s under-the-mark branch, which then calls it.
- `deck/store-items.mjs`: `beginLanding`'s line reads `landing started in <worktree>`; `noteLaneFilled` (new).
- `deck/server-routes.mjs`: `/reply` runs `fillLanes` after a gate2 Sign off is stored, then `noteLaneFilled`, then `land`.
- `deck/test/press-frees-lane.test.mjs` (new): the pins.

## Interface

```
deck/items.mjs
  isLanding(ticket, items): boolean   // open, green, its newest gate2 holds the user's Sign off
  liveTicketOf(items, dir, state)     // never a landing ticket, whatever its stored `live`
  nextTicketOf(items, repo, state)    // never a landing ticket
  standingOf(ticket, items, coPilotTicket) -> 'closed' | 'co-pilot' | 'landing' | 'in hand' | 'parked'
deck/chain.mjs
  fillLanes(repo): string[]           // each queued stage lane's head taken in place, concluding first; no hand-off
deck/store-items.mjs
  noteLaneFilled(gate2Id, taken: string[])  // one from:'deck' line with a seq naming each id taken live; none when empty
  beginLanding(gate2Id, { worktree })       // thread line `landing started in <worktree>`
```

## Tests

1. `a signed ticket is landing`: `isLanding` → true for an open green ticket whose newest gate2 has a Sign off; false before the press, and false once pivoted to yellow.
2. `a landing ticket holds no lane`: `liveTicketOf` → undefined for a landing ticket still stored `live: true`.
3. `the rail reads landing`: `standingOf` → `'landing'`.
4. `the press fills the concluding lane first`: `fillLanes` → `[nextGreen]` with a green queued; with none, the planning head when that lane is empty; `[]` when both are held.
5. `the press wakes the pilot once`: `noteLaneFilled` → one thread line with `from: 'deck'` and a `seq` naming the ids; nothing for `[]`.
6. `the thread reads landing started`: `beginLanding` → the line `landing started in <worktree>`.

Rewrite check: storing a `landing` mark on the ticket instead of deriving it keeps all six results.
