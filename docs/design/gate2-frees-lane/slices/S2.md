# S2 A deck finish never stops a pilot that holds a lane

Feature `gate2-frees-lane` · delivers spec 8 · source: `../architecture.md` §2, §3 Stop, L3 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: opus — the stop rule decides when a pilot stops listening, and a wrong read silences a live run.

## Files owned

- `deck/server-tools.mjs`: `stopReason` counts a `finished` record only while no lane of the directory holds a ticket.
- `deck/test/stop-holds-lane.test.mjs` (new): the pins.

## Interface

```
deck/server-tools.mjs
  stopReason(runId, ours, repo, since): string | null
    // 'the run is finished (...)' only when lanesFrom(...) names no held stage lane and no live co-pilot
deck/lanes.mjs  lanesFrom(items, repo, { switching, coPilot })   // read only; L8
```

## Tests

1. `a finish beside a live green ticket does not stop`: `stopReason` → null with the newest record finished and another green ticket live.
2. `a finish beside a live co-pilot does not stop`: `stopReason` → null with a live co-pilot entry.
3. `a finish with every lane empty stops as today`: `stopReason` → `the run is finished (closing report posted)`.

Rewrite check: reading the lanes from the store instead of `lanesFrom` keeps all three results.
