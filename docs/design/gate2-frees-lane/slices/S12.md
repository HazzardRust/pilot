# S12 A landing row and a report due read as what they are (added)

Feature `gate2-frees-lane` · delivers spec 10 · source: `../architecture.md` §2 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — two display conditions in files already read by S1 and S4, each with a pin; nothing is left to choose.

Found while building: S1 (PR #765) left the ▶ Continue (switch) control on a landing ticket's Tickets row, where a
switch is refused `already live`; S4 (PR #767) noted that `threadState` (`deck/items.mjs`, near :784) reads any
trailing deck line as `landing ended short`, so a report reads that way until the pilot's `Findings:` reply.

## Files owned

- `deck/ui/render-rail.mjs`: a ticket that `isLanding` reads offers no Continue control.
- `deck/items.mjs`: `threadState` reads a report whose last line is the deck's `report due` (S4's `REPORT_DUE`) as
  awaiting findings, never `landing ended short`; a gate2's short-landing line still reads as today.
- Their existing test files, or one new `deck/test/landing-display.test.mjs`: the pins.

## Interface

```
deck/ui/render-rail.mjs
  renderTicketQueue(queue, head, ...)  // no switch control on a ticket isLanding reads
deck/items.mjs
  threadState(item, now)               // a report ending in REPORT_DUE awaits findings
```

## Tests

1. `a landing ticket offers no Continue`: `renderTicketQueue` → the Tickets row of a ticket whose newest gate2 holds a Sign off renders no switch control; a plain queued ticket still does.
2. `a report due is not a short landing`: `threadState` → a report item ending in the `report due` deck line is not `landing ended short`; a gate2 ending in a short-landing deck line still is.

Rewrite check: dropping Continue in `renderSwitchForm` instead of `renderTicketQueue` keeps both results.
