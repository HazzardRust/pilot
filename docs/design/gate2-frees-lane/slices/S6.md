# S6 A second press queues instead of refusing

Feature `gate2-frees-lane` · delivers spec 7 · source: `../architecture.md` §2 · after: S5 (`deck/landing.mjs`), S4 (`deck/store-items.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it changes what the press route accepts and when a process starts.

## Files owned

- `deck/store-items.mjs`: `refuseLanding` no longer refuses another gate2's running landing; `queueLanding` (new) stores it `queued`.
- `deck/landing.mjs`: `startLanding` queues while one runs in the repository; each settle starts the oldest queued one.
- `deck/test/landing-queue.test.mjs` (new): the pins.

## Interface

```
deck/store-items.mjs
  queueLanding(gate2Id)   // landing { state: 'queued', pressedAt }, thread line 'landing queued behind <gate2 id>'
  refuseLanding(items, gate2, signing)   // still refuses this gate2's own landed or running landing
deck/landing.mjs
  startLanding(gate2Id, deps)   // queued while another runs; settle → the oldest queued in the repo starts
```

## Tests

1. `a second press is queued`: `startLanding` → with one running, the second gate2 reads `queued`, and nothing is spawned.
2. `the settle starts the queued one`: `startLanding` → the first's close spawns the second, which reads `running`.
3. `a press on its own running landing is still refused`: `refuseLanding` → the refusal as today.
4. `a restart starts a queued landing`: `startLanding` → after `interruptLandings` and `closeOwed`, a queued landing is started once.

Rewrite check: holding the queue in memory instead of on the gate2 keeps results 1 to 3.

## Done

- **Expected**: pressing two gate2s close together lands both, one after the other, with no second press.
- **Verification**: `node --test deck/test/landing-queue.test.mjs deck/test/landing.test.mjs`; `npm test`; two presses on a scratch deck.
- **Evidence**: the pins red before, green after; both threads read on the scratch deck.
- **Prohibited**: two `land` children at once in one repository (gate2-lands A4); the live deck on 4321.
- **Done when**: the pins and the suite are green and both landings were seen in order.

## Seam changes

- Co-pilot, during S6: `queueLanding(gate2Id, behindId)` takes the id it waits on, for its `landing queued behind
  <behindId>` line. `startLanding` also queues while a `pr ready` retry chain of another gate2 runs in the repository,
  tracked in an in-memory Set in `deck/landing.mjs`, since a stored owed ready can outlive its chain. A new export
  `startQueued(deps)` starts the oldest queued gate2 per repository when nothing there runs; `deck/daemon.mjs` calls it
  after `closeOwed()` at start (about 4 lines outside the owned files). No spec line or locked decision moves.
