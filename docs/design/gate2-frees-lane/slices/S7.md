# S7 A conflict is recorded and handed over past the limit

Feature `gate2-frees-lane` · delivers spec 5 · source: `../architecture.md` §2, L7, A1 · after: S6 (`deck/landing.mjs`, `deck/store-items.mjs`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a path parsed from a child's output is stored and later handed to an agent as a worktree.

## Files owned

- `deck/landing.mjs`: the settle passes land's exit code.
- `deck/store-items.mjs`: `settleLanding` stores `conflict: { dir }` on exit 3 when `dir` is an absolute worktree of the gate2's repository.
- `deck/server-wait.mjs`: `armConflicts()` beside `armHandoffs()`; past `CONFLICT_TURN_MS` with no `Resolving`, one blocked question.
- `deck/test/landing-conflict.test.mjs` (new): the pins.

## Interface

```
deck/store-items.mjs
  CONFLICT_TURN_MS = 15 * 60_000   // A1
  settleLanding(gate2Id, { ok, sha, line, code })   // code 3 → landing.conflict { dir, at }
deck/server-wait.mjs
  armConflicts()   // one timer per conflict without the pilot's Resolving; an overdue one fires at once
    // fire: question { blocking, ticket: gate.ticket, title 'Resolve the landing conflict in <dir>' }
```

## Tests

1. `exit 3 stores the kept worktree`: `settleLanding` → `conflict.dir` equal to the dir in land's line.
2. `a dir outside the repository is not stored`: `settleLanding` → no `conflict`, the line kept.
3. `no Resolving within the limit asks once`: `armConflicts` → with the clock past `CONFLICT_TURN_MS`, one blocked question on the signed ticket; armed again, none.
4. `a restart fires an overdue conflict`: `armConflicts` → the question at once.

Rewrite check: reading the conflict from the thread line instead of a stored field keeps results 3 and 4.
