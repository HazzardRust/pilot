# S1 A feature PR opens with its overview

Feature `pr-overview` · delivers spec 1, 2, 4, 7 · source: `../architecture.md` §2, §3 Seams, §5 L2-L5 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — pure functions with fixed signatures and byte-level tests; no assumed spec line shapes its code (A3's list is data passed in).

## Files owned

- `scripts/pr-overview.mjs` (new): the overview's parse, its rules and the built line.
- `scripts/feature-pr.mjs`: `featureBody` takes the overview block first; `syncFeaturePr` passes it.
- `scripts/test/pr-overview.test.mjs` (new): the module's pins.
- `scripts/test/feature-pr.test.mjs`: the body and write pins.

## Interface

```
overviewOf(markdown: string) -> string | null
  // the `## Overview` section's body, heading excluded, to the next `## ` outside a fence; null when absent
overviewProblems(text: string, roles: string[]) -> { line: number, rule: string, message: string }[]
  // rules: overview-token (S<n>, itm_, A<n>, L<n>, ADR \d{4}, a role word), overview-long (> 150 words),
  // overview-sentences (average > 20 words per sentence); a token inside a code span counts
whatChangesOf(overviewText: string) -> string | null   // the text after `- **What changes**:`; overviewProblems adds overview-label when null
crewRoles(agentsDir: string) -> string[]       // agents/pilot-*.md basenames minus `pilot-` (A3)
builtLine(record) -> string                    // `Built so far: <k> of <n> parts.`; n = rows whose slice starts `S<digits>`; k = those whose state starts `integrated`
overviewBlock(markdown: string, record) -> string | null
  // `## Overview\n\n<overviewOf>\n\n<builtLine>`; null when overviewOf is null
featureBody(spec: string, record, footer: string, overview?: string | null) -> string
  // overview first when given, then today's parts unchanged
syncFeaturePr({ host, git, record }) -> { line, number?, wrote }   // unchanged; now passes overviewBlock
```

## Behaviours

1. `the body opens with the overview` (test): `featureBody` → first line `## Overview`, its section holding the seeded text and `Built so far: 1 of 3 parts.`.
2. `the tables are untouched` (test): `featureBody` → with the overview block cut off, byte-equal to `featureBody(spec, record, footer)`.
3. `no overview, no change` (test): `overviewBlock` → null for an artefact with none, and the body equals today's.
4. `an edit carries a new overview` (test): `syncFeaturePr` → exactly 1 `edit` with the changed overview on a second call; 0 with nothing changed.
5. `the built line follows the record` (test): `builtLine` → `1 of 3`, then `2 of 3` with one more `integrated` state.
6. `ids are refused` (test): `overviewProblems` → one `overview-token` per `S2`, `itm_ab12`, `A3`, `L1`, `ADR 0190`, `implementer`; none for `pilot`.

Rewrite check: reading the overview from a separate file instead of a section keeps 1-6 if `overviewOf` still answers.
Misses: whether the text reads well to a manager; the user's Gate 2 read.

## Done

- **Expected**: the draft feature PR's top is the artefact's overview and a built count; the tables below are as today.
- **Verification**: `node --test scripts/test/pr-overview.test.mjs scripts/test/feature-pr.test.mjs`; `npm run test:quiet`.
- **Evidence**: each behaviour red before, green after; existing `feature-pr.test.mjs` cases unedited.
- **Prohibited**: no edit to an existing `feature-pr.test.mjs` expectation; no `gh` or network in a test; no slice id in the built line; no change under `deck/`.
- **Done when**: the six behaviours and the gate are green.
