## Interface

```
shownOf(queue: Item[], items: Item[]) -> Item[]
  // the cards: queue items not behind, or a gate1/gate2/signoff; non-user first, not-behind before behind, queue order
foldedOf(queue: Item[], items: Item[]) -> Item[]
  // the fold: queue items behind and not a gate1/gate2/signoff, queue order; shownOf ∪ foldedOf = queue, disjoint
<details class="fold"><summary>N waiting on other tickets</summary> …cards… </details>   // drawn only when N > 0
```

## Behaviours

1. `a parked ticket's gate2 is a card, its question folded` (test): `foldedOf` → with green A in hand and green B parked, B's question; `shownOf` keeps B's gate2 as a card after A's; the page's fold line reads 1, on the overview and the tab.
2. `counts and arrows count cards and fold` (test): `foldedOf` → strip counts equal each scope's queue length; the arrows' N equals cards plus fold.
3. `a landing ticket's gate2 stays a card after landing ended short` (test): `shownOf` → a signed gate2 with a `deck` message is a home card.
4. `the sweep finds nothing missing and no press folded` (test): `shownOf` → one thread per queued kind × standing (in hand, parked, landing, paused, co-pilot, unticketed, merged-away ticket); fails naming every id neither a card nor in the fold, and every gate1, gate2 or signoff in the fold.
5. `the ADR index lists the amendment` (read): `node scripts/adr-index.mjs --check` exits 0 and README lists NNNN-nothing-hidden.
6. `the live deck shows the gate as a card and the question folded` (look): on a scratch deck served locally, the gate2 card sits below the in-hand cards, the fold reads "1 waiting on other tickets" and opens to the question, and the Overview count includes both.

Rewrite check: computing the fold as a filter inside the renderer keeps 1-4 unchanged.
Misses: whether the fold line is noticed on a busy deck; the user's look at Gate 2 reads that.
