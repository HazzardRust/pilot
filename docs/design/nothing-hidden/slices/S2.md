## Files owned

- `deck/ui/render-cards.mjs`: `renderCard` takes `lanes` and draws `renderTicketStanding` where it drew `renderTicketOf`.

## Interface

```
renderCard(item, { tab?, back?, all?, items?, lanes? = { coPilots: {}, switches: {} } }) -> string
renderTicketStanding(item, items?, lanes) -> string
  // ` · <a class="ref ticket" …>title</a> <span class="standing">word</span>`; '' with no items,
  // no ticket, or a ticket merged away
```

## Behaviours

1. `a card says its ticket and standing` (test): `renderCard` → a thread of the in-hand ticket carries the ticket link and `<span class="standing">in hand</span>`; a yellow ticket held by the co-pilot reads `co-pilot`; a paused one `paused on <id>`.
2. `a merged-away or itemless card names nothing` (test): `renderCard` → no `class="ref ticket"` and no `standing` span; no throw without `items`.
3. `the card and the thread page say the same word` (test): `renderTicketStanding` → one output for a card and its thread page header.
4. `the standing reads on the live deck` (look): on a scratch deck served locally, an in-hand and a co-pilot ticket's cards each show their standing word beside the ticket title.

Rewrite check: replacing the span with a badge element keeps the word and its order after the title.
Misses: whether the word reads well at a glance among many cards; the user's look reads that.
