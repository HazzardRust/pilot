Feature `crew-handoff-trace` · delivers spec 1, 2, 3, 7, 8, 10 · source: `../architecture.md` §2, §3.1, §3 Seams, §5 L1, L6, §6 A1 · after: –

## Interface

```
step(row: { step, kind, item?, ticket?, agent?, session? }): void   // stamps `at`; drops any other field; never throws
traceFile(): string                                                 // <deckDir()>/handoff-trace.jsonl
STEPS = { crew: [posted, stopped, released, granted, resolved, spawned, failed],   // L3: the grant writes resolved
          pilot: [posted, handed, cleared, submitted, resolved, failed] }          // done at crew spawned/failed, pilot resolved/failed
timeline(rows, id, now): { rows: Row[], tail: 'done' | `waiting: ${step}, ${age}` | 'no hand-off' }  // id: an item or ticket id
trace(argv): Promise<number>     // pilot trace <itm_id>; prints rows then the tail; exit 0, 2 on a bad id
```

## Behaviours

1. `a posted crew-handoff leaves one row` (test): `step` → one JSONL line with `at`, `step: posted`, `kind`, `item`; no body.
2. `a row never carries free text` (test): `step` → a row given `body`, `title` or `prompt` writes none of them (spec 7).
3. `the file rotates at 512 KB` (test): `step` → a 512 KB file moves to `.old` and the row starts a new file (spec 8).
4. `an unfinished hand-off says what it waits on` (test): `timeline` → rows `posted` at t, now t+3m: tail `waiting: stopped, 3m`.
5. `the 11-19 sequence reads as released with no grant` (test): `timeline` → the §3.1 fixture at 09:13:19 ends `waiting: granted, 1h05m` (spec 10).
6. `pilot trace on a scratch deck` (run): a real `deck_post` of a crew-handoff, then `pilot trace <item>` prints the row and its tail.
7. `the cause is written down` (read): the ADR holds §3.1's table and C1-C3.

Rewrite check: replacing the JSONL file with any store keeps behaviours 1-5, because they read only `step` and `timeline`.
Misses: rows from writers that later slices add; S2-S4's own tests and QA's run cover them.
