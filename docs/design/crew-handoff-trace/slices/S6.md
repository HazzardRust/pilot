# S6 A fresh session is told a successor is owed

Feature `crew-handoff-trace` · delivers spec 4 · source: `../architecture.md` §2, §3.1 C3, §3 Seams · after: S4 (`hooks/session-handoff.js`), S5 (`deck/crew-handoff.mjs`, the `ticket` field)

Model: opus — the SessionStart lane echoes deck text into a fresh session, which is the security trigger.

## Files owned

- `deck/crew-handoff.mjs`: `successorOwedOf`.
- `deck/owed.mjs`: `OWED_WHY` gains `successor owed`. `owedThreadsOf` takes the co-pilot entry and adds one entry per owed item, its line the ticket id.
- `hooks/session-handoff.js`: `OWED_WHY` (`:425`) gains it. `owedNotice` says what to do: `deck_ticket co-pilot` the ticket, then spawn its successor.
- `hooks/test/successor-owed.test.js` (new).

## Interface

```
successorOwedOf(items, repo, coPilot: { ticket, live } | null): Item[]  // open crew-handoffs whose ticket is open, yellow, not the live co-pilot's
owedThreadsOf(items, repo, coPilot?): [{ id, line, why }]               // why 'successor owed', line the ticket id
owedNotice(owed): string | null                                         // the row: `<item> successor owed: "<ticket>"`
```

## Behaviours

1. `an open crew-handoff with no live co-pilot is owed` (test): `successorOwedOf` → one item; with its ticket's co-pilot live, none.
2. `a fresh session hears it` (test): `owedNotice` → a SessionStart against a stub deck prints the item id and ticket and the two moves.
3. `a closed or another repo's item is not owed` (test): `successorOwedOf` → none for either.
4. `a session started on 11-19's state would have been told` (test): `owedThreadsOf` → the §3.1 state at 08:08:57 without S5's close yields `itm_7df7fdd3e4a3 successor owed`.

Rewrite check: computing owed in the hook instead keeps 1-4 only if the shape of the echoed line is unchanged.
Misses: whether the session acts on the line; QA's live walkthrough (§9 step 5) reads that.
