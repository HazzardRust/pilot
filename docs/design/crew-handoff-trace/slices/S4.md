# S4 The pilot's own hand-off steps are traced

Feature `crew-handoff-trace` · delivers spec 1 · source: `../architecture.md` §2, §3.2, §5 L1 · after: S1 (`step`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it edits the SessionStart lane and the hand-off mod under `hooks/`, which is the security trigger.

## Files owned

- `scripts/handoff.mjs`: once `pilot handoff`'s post is stored, a row `posted` with kind `handoff`, the item and the session.
- `hooks/session-handoff.js`: at `lane: handed`, a row `handed` with the item and the session.
- `hooks/handoff-mod.mjs`: at `mod: cleared` and `mod: submitted`, rows `cleared` and `submitted`.
- `hooks/test/handoff-trace.test.js` (new): the four rows.

## Interface

```
S1's step(row)    // kind 'handoff'; steps posted, handed, cleared, submitted; S2 writes resolved and failed
```

## Behaviours

1. `a pilot hand-off is posted, handed, cleared and submitted` (test): `step` → the four writers each leave one row for one item, in that order.
2. `a claimed hand-off writes no second handed` (test): `step` → a second SessionStart on the same item writes no row.
3. `the wrapper log is unchanged` (test): `step` → the existing `wrapper.log` lines are still written, word for word.

Rewrite check: replacing where each writer sits keeps 1-3, because they read only the trace file.
Misses: a `/clear` typed by hand where the mod is not loaded writes no `cleared`; the tail names it.

## Done

- **Expected**: after a scratch `pilot handoff` and `/clear`, `pilot trace <handoff id>` lists posted, handed, cleared and submitted.
- **Verification**: `node --test hooks/test/handoff-trace.test.js hooks/test/session-handoff.test.js`; `npm test` once.
- **Evidence**: 1-2 red before, green after; the scratch trace printed.
- **Prohibited**: no change to the lane's notice text; no body or title in a row.
- **Done when**: three behaviours hold and `npm test` is green. Estimate about 60 lines.
