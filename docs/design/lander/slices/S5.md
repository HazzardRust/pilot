## Interface

```
cleanOnPilot(repo, sha, { git }) -> { ok: true } | { ok: false, paths: string[], why?: string }
  // clean: `git merge-tree --write-tree --name-only origin/pilot <sha>` lists only autoResolves paths,
  // or <checkout>-land-<slug> HEAD is a committed merge with <sha> as a parent that merge-trees clean on origin/pilot
refusal: 'NOT posted: <sha> conflicts with origin/pilot in <paths>; the lander resolves it first'
trialOnPilot({ cwd, git, head }) -> { clean: true } | { paths, dir }
mergeIntoPilot({ …, push?: boolean })   // push false: keep the merge in `keep`, run no test and no push
agents/pilot-qa.md   integrate step: a lander line goes to main; the gate2 waits on the lander's 'clean at <sha>'
S2's conflictLine and autoResolves, by reference
```

## Tests

1. `a gate2 whose sha conflicts with pilot is refused naming the lander`: `cleanOnPilot` → `ok: false` with the source path, and the deck_post refusal text.
2. `a conflict only in the ADR index counts as clean`: `cleanOnPilot` → `ok: true`.
3. `a prepared merge of the sha is accepted`: `cleanOnPilot` → `ok: true` when the kept land worktree holds the committed merge.
4. `integrate --default prepares the merge for the lander`: `trialOnPilot` → exit 3 lander line; the dir is mid-merge on pilot's tip, and pilot is unmoved.
5. `QA posts no gate2 over a lander line`: `agents/pilot-qa.md` → names `the lander` and `clean at`.

Rewrite check: replacing merge-tree with a scratch merge keeps tests 1-4.
