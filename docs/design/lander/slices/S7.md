# S7 One press lands: every refused landing goes to the lander

Feature `lander` · delivers spec 4 · source: `../architecture.md` §2, §5 L7 · after: S1 (`deck/landing-replies.mjs`), S2 (`deck/store-items.mjs`)
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — two refusal rules and a render change, fixed here with four tests; about 90 lines; no security trigger.

## Files owned

- `deck/store-items.mjs`: `refuseLanding` (`:501-509`) also refuses a press on a `refused` gate2, naming the lander.
- `deck/landing-replies.mjs`: the lander's `Land again` runs on any `refused` gate2: in the kept dir with a conflict, otherwise fresh.
- `deck/ui/render-parts.mjs`: a refused gate2 draws its Sign off sent, not offered again (`:316`).
- `deck/test/landing-guard.test.mjs`: the old "Sign off after NOT landed starts a new landing" case becomes its refusal.
- `deck/test/lander-one-press.test.mjs` (new): pilot moves between the press and the merge.

## Interface

```
refuseLanding(thread)   // a refused gate2: 'gate2 <id> did not land; the lander lands it again, not a second press'
landingReply(item, text, 'lander', at)   // Land again on any refused landing -> running
```

## Tests

1. `a second press on a refused gate2 is refused naming the lander`: `refuseLanding` → a DeckRefusal; nothing is stored or spawned.
2. `the lander lands a red-gate refusal again`: `landingReply` → `running` with no conflict.
3. `pilot moves between press and merge and the feature lands on one press`: `landingReply` → land's exit 3, the lander's commit, `Land again`, and `landed`; the thread holds one Sign off.
4. `a refused gate2 offers no second Sign off`: `refuseLanding` → the rendered page has no live Sign off button.

Rewrite check: any landing state machine keeps all four, as long as only the lander re-runs a refused landing.
