# S3 A sync conflict is kept for the lander and resumes

Feature `lander` · delivers spec 2 · source: `../architecture.md` §3, §5 L3 · after: S2 (`scripts/land.mjs`, `conflictLine`)
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — the keep path, the resume and three tests are fixed here; about 90 lines; no security trigger.

## Files owned

- `scripts/sync.mjs`: on a conflict `sync` keeps `<checkout>-sync` and prints `conflictLine`; a later `pilot sync` resumes a committed merge there.
- `scripts/land.mjs`: the sync-first refusal (`:186`) carries the sync's lander line.
- `scripts/test/sync.test.mjs`: the conflict case now keeps its worktree.
- `scripts/test/sync-resume.test.mjs` (new): the resume and the refusal.

## Interface

```
sync({ cwd, git, test, keep?: string }) -> { line, code }   // keep defaults to <checkout>-sync
  // exit 3: 'NOT synced: main@<sha7> conflicts with pilot in <paths>; the lander resolves in <dir>'
mergeIntoPilot({ …, keep, reuse })   // signature unchanged; sync now passes keep and reuse
```

## Tests

1. `a conflicting main keeps the sync worktree for the lander`: `sync` → exit 3; the dir exists mid-merge and pilot is unchanged.
2. `a committed resolution in the sync worktree is tested and pushed`: `sync` → `synced pilot <sha7>`, and the dir is removed.
3. `a sync worktree still mid-merge is refused and kept`: `sync` → exit 3 naming `finish and commit`.

Rewrite check: a resume by any mechanism keeps all three, as long as pilot moves only after a green test.
