# S8 A lander past the cap queues, and the next session spawns it

Feature `lander` · delivers spec 5 · source: `../architecture.md` §2, §5 L5, L9, §6 A1 · after: S1 (`deck/landing-replies.mjs`, `agents/pilot.md`), S7 (`deck/store-items.mjs`); held-handoff landed (`deck/run.mjs` `holdFor`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — the cap reading is assumed (A1), and the slice changes the pilot's prompt.

## Files owned

- `deck/landing-replies.mjs`: `landerDue`, a pure function over items.
- `deck/run.mjs`: `firstPrompt` appends `Spawn pilot-lander <gate2>.` for each due lander after the hand-off; held-handoff's `holdFor` is read, not changed.
- `deck/store-items.mjs`: the press line reads `lander due: spawn pilot-lander <id>`, or `lander queued for the next session` when an open hand-off is in the directory.
- `agents/pilot.md`: one sentence: at your hand-off, or with no room in `pilot budget`, spawn no lander; it queues.
- `deck/test/run.test.mjs`: the queue case.
- `deck/test/lander-queue.test.mjs` (new): `landerDue` and the press lines.
- `scripts/test/measure-prompt.test.mjs`: the pilot pin at the measured number.

## Interface

```
landerDue(items, repo) -> string[]   // signed gate2 ids in repo with no lander Resolving and not landed-and-handed-back, oldest first; one at a time (L5)
firstPrompt(items, cwd) -> string    // 'Pick up the hand-off on the deck.' plus one 'Spawn pilot-lander <id>.' for landerDue's head
S1's landingReply: a lander's Resolving claims the gate2
```

## Tests

1. `a signed gate2 with no lander is due`: `landerDue` → `[id]`; after a lander `Resolving`, `[]`.
2. `with the pilot at its hand-off the press queues the lander`: `landerDue` → the press line reads `lander queued for the next session`, and no spawn line wakes the old session.
3. `the next session's first prompt spawns the queued lander`: `firstPrompt` → it ends `Spawn pilot-lander <id>.`
4. `two due landers name only the oldest`: `landerDue` → the head only in `firstPrompt`.

Rewrite check: storing the queue as a mark instead of deriving it keeps all four.
