## Interface

```
hooks/context-size-guard.js
  pastAdvisoryAt(dir: string, snapshot?: object) -> boolean | null
    // the decks[dir] reading (samePath) as tokens vs marksFor(PILOT_REFERENCE_WINDOW).advisory; null = no reading
  marksFor(size: number | null) -> { advisory, hard, rearm }   // exported for the tests' marks only (seam change, co-pilot)
  PILOT_REFERENCE_WINDOW: number                                // exported for the tests' % conversion only
deck/chain.mjs
  chainNext(repo: string, { atStart?: boolean, pastMark?: (dir: string) => boolean | null })
    -> { handoff: Item | null, reason?: string, taken?: string }
    // reason 'under the mark' with taken = head id when pastMark(repo) === false
deck_status: finish reply `D<n>: <k> slices saved; <mirror>; took <id> live here.`
clearOnce (deck/run.mjs): unchanged; types /clear only for a posted hand-off
```

## Tests

1. `the guard says under and past its own advisory`: `pastAdvisoryAt` → false one token under the mark, true one over, both built from the guard's own `marksFor`.
2. `a finish under the mark takes the head and posts nothing`: `chainNext` → `{ handoff: null, reason: 'under the mark', taken: <head id> }`, no new item, the head live.
3. `the chain follows the guard's mark through the default pastMark`: `chainNext` → the branch flips across snapshots at the guard's advisory minus and plus one token.
4. `the finish reply names the ticket taken in place`: `deck_status` → its finish reply ends `took <id> live here.`
5. `no hand-off, no clear`: `clearOnce` → false after an under-the-mark `chainNext`, nothing typed.
6. `over the mark the hand-off stands`: `chainNext` → with `pastMark` true, a `handoff` titled `Next run: <title>`, the head taken; the pre-existing chain tests green unedited but for the injected reader.
7. `no reading hands off as today`: `chainNext` → with `pastMark` returning null, a `handoff` posted.
8. `no copy of the mark in deck/`: `pastAdvisoryAt` → the only holder of the number; `git grep 225000` under `deck/` is empty.

Rewrite check: replacing the snapshot reader with any other reading keeps tests 1, 2, 5, 6 and 7, which inject `pastMark` or a snapshot object; tests 3 and 4 write the snapshot file through `snapshotAt` and so pin the file path the guard reads.
