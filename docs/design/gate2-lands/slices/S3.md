## Interface

```
GET /api/landing?id=<gate2> -> { state: 'none' | 'running' | 'landed' | 'refused', line?: string }  // 404 for an id that is no gate2
pilot landing <gate2-id> [--timeout <minutes>]   // default 40; prints the line
// exit 0 landed, 1 refused or timed out waiting, 2 the deck will not answer or no such gate2
S1's Landing
```

## Tests

1. `GET /api/landing answers the stored state and line, and 404 for a non-gate2`.
2. `pilot landing prints the landed line and exits 0 once a running landing settles`.
3. `pilot landing exits 1 with the NOT landed line`; `exits 2 with one stderr line when the deck is down`.
4. `step 9 names pilot landing and no longer runs pilot land` (the moved pin).
5. `the pilot prompt stays inside its measured budget` (unchanged bound).
