# S1 A Sign off press on a gate2 lands the feature

Feature `gate2-lands` · delivers spec 1, 4, 5, 8, 9 · source: `../architecture.md` §2, §5 L1–L4, L6, L9–L12 · after: –

## Files owned

- `deck/landing.mjs` (new): the one module that starts `pilot land`; checks the record's worktree, spawns, collects output, settles.
- `deck/store.mjs`: `beginLanding` and `settleLanding`, each one write of the gate2's `landing` field and its thread message.
- `deck/server.mjs`: `/reply` calls `startLanding` after `addReply` stored a pressed Sign off on a gate2.
- `deck/test/landing.test.mjs` (new): the pins below.
- `deck/test/no-open.mjs`: sets `PILOT_DECK_NO_LAND`.
- `docs/adr/0111-a-signed-gate2-lands-from-the-deck.md` (new), `docs/adr/README.md`: spec 9.

## Interface

```
// deck/landing.mjs
startLanding(gate2Id: string, inject?: { spawn?, env?, now? }): void   // never throws; every outcome is a thread line
// deck/store.mjs
type Landing = { state: 'running' | 'landed' | 'refused', pid?: number, startedAt: string, at?: string, sha?: string, line?: string }
beginLanding(gate2Id: string, { worktree: string, pid: number }): Item   // running + "landing: running pilot land in <worktree>"
settleLanding(gate2Id: string, { ok: boolean, sha?: string, line: string }): Item
// thread message shape: { from: 'pilot', author: 'deck', text, repliedAt }
```

## Tests

1. `a Sign off press on a gate2 spawns node <bin>/pilot.mjs land with the record's worktree as cwd and no shell`: argv and options asserted on the injected spawn.
2. `the thread reads running at once and land's two lines on exit 0`: `landing.state` is `landed`, the SHA parsed from `landed … at <sha7>`.
3. `exit 1 settles refused with land's NOT landed line`.
4. `no record, no worktree field, a removed worktree, or another repository's checkout each settle refused by name and spawn nothing`.
5. `GET / answers while the child has not exited` (spec 5).
6. `credential-shaped output is withheld with the exit code` (spec 8); `output past 2000 characters keeps its tail`.
7. `PILOT_DECK_NO_LAND writes "landing is turned off on this deck" and spawns nothing`.

## Done

- **Expected**: the user presses Sign off on a gate2 and, with nobody at a terminal, the thread says the landing started and then what land said; `origin/pilot` moved or not accordingly.
- **Verification**: `node --test deck/test/landing.test.mjs`; `npm test`; the L12 scratch run of acceptance 1, 2 and 5.
- **Evidence**: test 1 red before `/reply` calls `startLanding`; the scratch thread's two lines and `git -C <bare> rev-parse pilot` equal to the feature tip, on the PR.
- **Prohibited**: calling `land()` in the daemon process; `shell: true` or any argv element from the request or the store; a test that lets a real `pilot land` run; skipping the `repoOf` check.
- **Done when**: `npm test` is green and a real press on a scratch deck moved the bare origin's `pilot`.
