# S5 The run record and closing report count the runs

Feature `tested-once` · delivers spec 4, 5 · source: `../architecture.md` §2, §3, §5 L7 · after: S1 (`testRunsFor`)
Reviewers: `pilot:typescript-reviewer`
Model: opus — spec 5's bar is assumed (A4).

## Files owned

- `deck/store-runs.mjs`: `upsertRecord` sets `record.tests` to `testRunsFor({ slug })` rows, trimmed to `{ where, branch, sha, scope, exit, minutes, at }`, on each record write.
- `deck/closing-report.mjs`: `closingReportOf` adds one line `test runs: <n> local, <m> min (<where> <k>, ...)`; nothing when the record has no `tests`.
- `deck/test/record-tests.test.mjs` (new): the pins, on a scratch store and a scratch ledger home.

## Interface

```
upsertRecord(deck, run, table, fields, name) -> record   // record.tests: Array<{ where, branch, sha, scope, exit, minutes, at }>
closingReportOf(record, gate, left, closes, blocked) -> { title, body }   // body gains the test-runs line
S1's testRunsFor
```

## Behaviours

1. `run.json lists the runs` (test): `upsertRecord` → with three ledger rows for slug `x` and one for `y`, a `deck_status` for `x` writes a record whose `tests` has three rows.
2. `the closing report totals them` (test): `closingReportOf` → `test runs: 3 local, 9.5 min (implementer 2, integrate 1)`.
3. `a record with no tests says nothing` (test): `closingReportOf` → no test-runs line.

Rewrite check: storing the rows on the run instead of the record keeps 1-3 through `run.json`.
Misses: whether the next real feature meets ≤ 12 runs; the first closing report after landing reads it.
