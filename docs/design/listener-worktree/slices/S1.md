# S1 A wait in a `pilot run` session listens on the session's repository

Feature `listener-worktree` · delivers spec 4 (keeps 1 green) · source: `../architecture.md` §2, §5 L1–L3 · after: –

## Files owned

- `deck/wait.mjs`: `wait()` takes `env`; the listening repository is `PILOT_RUN_REPO`, else `listeningRepo(cwd)`.
- `deck/test/wait.test.mjs`: the pins; every existing `wait()` call passes an `env` without `PILOT_RUN_REPO`.
- `docs/adr/0104-a-wait-listens-on-its-sessions-repository.md` (new): amends ADR 0091's first bullet.
- `docs/adr/README.md`: regenerated with `npm run adr-index` after the ADR is written (`scripts/test/adr-index.test.mjs` checks it). 0101–0103 are taken on `feat/slice-graph` and `feat/security-reviewer`, which land before this feature.
- `deck/test/wait-as.test.mjs`, `deck/test/orphan.test.mjs`: `env: {}` on their one `wait()` call each (seam change by the co-pilot, 2026-10-09: L3 covers every `wait()` call in the suite, and these two failed with `PILOT_RUN_REPO` set; no spec line or locked decision moves).

## Interface

```
wait({ cwd?, env?: NodeJS.ProcessEnv, repo?, kind?, item?, timeoutMinutes?, pollMs?, say?, warn? }): Promise<number>
  // repo defaults to sessionRepo(env) ?? listeningRepo(cwd)
sessionRepo(env: NodeJS.ProcessEnv): string | null   // PILOT_RUN_REPO trimmed, or null when unset or empty
listeningRepo(cwd: string, git?): string               // unchanged
```

## Tests

1. `a wait in a pilot run session listens on PILOT_RUN_REPO, not on its cwd`: env `PILOT_RUN_REPO` = a linked worktree, cwd the main checkout; line 1 is `listening on <worktree>`; a reply on an item stamped with the worktree wakes it.
2. `a session launched in a worktree hears its own thread from a wait whose shell drifted elsewhere`: cwd a second worktree; the same reply still wakes it.
3. `an empty PILOT_RUN_REPO falls back to the git join`: line 1 is the main checkout.
4. The existing `a wait started in a git worktree takes a reply posted on the main checkout` passes with `env: {}` and no other change.

## Done

- **Expected**: inside a `pilot run` session, `pilot wait` names the session's own repository on line 1 and hears every thread that session posted, wherever the shell is; outside one, it behaves exactly as today.
- **Verification**: `node --test deck/test/wait.test.mjs`; `node --test hooks/test/listener-join.test.js`; `npm test`.
- **Evidence**: tests 1 and 2 failing before the change and passing after; the full suite's output; on a scratch deck (`PILOT_DECK_PORT` not 4321), `PILOT_RUN_REPO=<worktree> pilot wait --timeout 0.05` printing `listening on <worktree>`.
- **Prohibited**: no change to `sameRepo`, `repoKey`, `forRun` or the hooks; no read of `process.env` inside `wait()` past its default; no probing on the live deck at 4321; no edit to `agents/pilot.md`.
- **Done when**: the four tests are green in a suite run with `PILOT_RUN_REPO` set in the shell, and the scratch-deck line has been seen.
