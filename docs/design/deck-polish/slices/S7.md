# S7 Rail panels: a report takes an ×, and panels sit above the thread header

Feature `deck-polish` · delivers spec 6, 8 · source: `../architecture.md` §2, F6, F8, L7, A4 · after: S3 (shares
`deck.css`), S6 (shares `render.mjs`)

## Files owned

- `deck/ui/render.mjs`: `renderReportRow` carries `data-report="<id>"` and a `<button type="button" class="drop">×</button>`, as `renderNotice` does.
- `deck/ui/js/notifications.mjs`: a second localStorage set, `deck.hiddenReports`, whose rows are hidden on load and in `rehide` after each swap. The Closing reports count recounts as Notifications' does.
- `deck/ui/deck.css`: the report `.drop`, reusing the notice's rule; on thread pages the strip stacks above the sticky header (z 2) and below the `h1` (z 3).
- `deck/test/notifications.test.mjs`: the report × pins, in its `aSandbox`.
- `deck/test/resize.test.mjs`: pins the stacking order on thread pages.

## Interface

```
renderReportRow(item)   // <li data-report="ID">…<button type="button" class="drop" title="Take this off the panel">×</button></li>
localStorage 'deck.hiddenReports': string[]   // report ids; not pruned, unlike deck.seenThreads: the panel is one deck's, so pruning on another tab would forget this one's
notifications.mjs -> { rehide, recount, markThisThread }   // rehide now also hides reports
```

## Tests

1. `a report row carries an ×`: render.
2. `pressing × hides the row and it stays hidden after a reload and after a live swap`: sandbox with localStorage.
3. `the Closing reports count drops by the hidden rows`.
4. `the hidden report's thread still opens`: `/thread/<id>` is 200 and the item is untouched.
5. `on a thread page the rail strip stacks above the header and below the title`: the z-index rules read from `deck.css`.
