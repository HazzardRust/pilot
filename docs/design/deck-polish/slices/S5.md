# S5 Close: the deck's button and a user thread's card

Feature `deck-polish` · delivers spec 1, 9 · source: `../architecture.md` §2, F1, F9, L9, A5 · after: S1, S2 (shares
`render.mjs`, `server.mjs` and `close.test.mjs`)

## Files owned

- `deck/ui/render.mjs`: `renderRemove` labels become Close, the confirm button becomes Close deck, and the paragraph is reworded (A5). `renderCard` draws the page's Close confirm and form for a `KIND_USER` card, with a hidden `back`.
- `deck/server.mjs`: `/close` 303s to `backPath(form.get('back'))` when one is given, and to the thread otherwise. The `/remove-deck` 403 text says Close.
- `deck/test/remove-deck.test.mjs`: pins the labels Close and Close deck.
- `deck/test/close.test.mjs`: pins the card's Close and its `back`.

## Interface

```
renderRemove(tab)   // <summary>Close</summary> … <button type="submit">Close deck</button>; route /remove-deck unchanged
renderCard(item, { tab, back, all })   // KIND_USER, open: + renderCloseConfirm(id) + renderCloseForm(item) carrying back
POST /close  form { id, back? } -> 303 to backPath(back) ?? /thread/<id>
```

## Tests

1. `an ended deck's control reads Close and its confirm reads Close deck`.
2. `a user thread's card carries Close with the two-step confirm; a question's card does not`: spec 9 names user threads only.
3. `closing from a card returns to the page it was pressed on`: `/close` with `back=/` 303s to `/`, and the item is closed after a re-read.
4. `/close with no back still lands on the thread`: the page's existing behaviour.
5. `a foreign back is not followed`: `backPath`'s existing rule, pinned on this route.
