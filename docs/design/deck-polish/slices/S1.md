# S1 A + tab adds a deck by path

Feature `deck-polish` · delivers spec 5 · source: `../architecture.md` §2, F5, L3, L4, A3 · after: – · walking skeleton ·
takes user input and a file path: a **security reviewer** runs beside the language reviewer.

## Files owned

- `deck/store.mjs`: `addDeck(path)` validates, canonicalises, mints the number and adds the chat, then appends to `deck.added`. `removeDeck` drops the entry.
- `deck/tabs.mjs`: `tabsOf` takes the added list, and an added directory is a tab even with no run and nothing open.
- `deck/server.mjs`: `POST /add-deck`, guarded by `fromOwnPage`, which 303s to the new or existing tab. A refusal uses the deck's usual refusal page and names the reason. The `tabsOf` callers pass `deck.added`.
- `deck/ui/render.mjs`: `renderStrip` ends in a `+` placeholder: a `<details>` with one path input and Add, with no script needed.
- `deck/ui/deck.css`: the `+` tab and its small form, in the strip's own style.
- `deck/test/add-deck.test.mjs` (new): the pins.
- `docs/adr/0048-an-added-deck-is-a-stored-directory.md` (new): L3 and L4, in the `domain-modeling` ADR format.

## Interface

```
// deck/store.mjs
export function addDeck(path: string): { repo: string, created: boolean }
  // refuses (DeckRefusal, reason in the message): empty; not absolute; a network (UNC) path, never stat'd; does not exist; not a directory; credential-like
  // repo is fs.realpath(path); created=false when a tab for sameRepo already exists (no write)
deck.added: { repo: string, addedAt: string }[]      // persisted in deck.json; absent on old stores = []
// deck/tabs.mjs
export function tabsOf(runs, items, numbers = {}, agents = {}, added = []): Tab[]
POST /add-deck  form { path } -> 303 to the tab's page; refusal -> the usual refusal page with the reason
```

## Tests

1. `an absolute directory is added, numbered and given a chat`: `deck.added`, the D-number and the chat, read back after a fresh `readDeck`.
2. `a relative path, a missing path, a file and a credential-like path are each refused with their reason`: nothing is written.
3. `a path already a tab, or the same directory spelled differently, is not added twice`: `created: false`.
4. `an added deck is a tab with no run and nothing open, and survives a daemon restart`: `tabsOf` and a restarted `deckOnAPort`.
5. `a later registerRun in that directory lands on the same tab`: one tab, same number.
6. `removeDeck drops the added entry and the tab goes`.
7. `POST /add-deck from the page adds and redirects, and a foreign Origin is refused`: via `deckOnAPort`.
8. `the strip ends in a + placeholder holding a path form`.

## Done

- **Expected**: on the preview deck, `+` then a scratch directory path gives a new numbered tab that is still there after
  a deck restart. A file's path is refused with "not a directory".
- **Verification**: `npm test`; `node scripts/check-references.mjs`; the preview-deck flow above.
- **Evidence**: tests 1–8 red before and green after; the flow seen in a real browser, including the refusal page and the restart.
- **Prohibited**: validating in the page only; a run record with a fake pid; a placeholder item; reading, listing or
  executing anything inside the added directory; shelling out to validate the path.
- **Diff limit / done when**: about 250 changed lines, and past 300 stop and ask `main`. Done when the eight pins are
  green and the added tab has been seen surviving a restart.
