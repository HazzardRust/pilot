# S2 The Stop hook refuses an idle main lane

Feature `idle-main-lane` · delivers spec 2, 3 · source: `../architecture.md` §2, L6, A3 · after: S1 (`/api/record` `lanes`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `hooks/stop-gate.js`: in `run`, after the held hand-off and before the hold, read `deck.record(dir)` and block on `lanes.refusal`.
- `hooks/test/stop-gate-idle-lane.test.js` (new): `run` against a deck on a port.

## Interface

```
run(input): Promise<{ decision: 'block', reason: string } | { systemMessage } | null>
  // new: reason = S1's Lanes.refusal, clipped to MAX_REASON_CHARS, when the session is on the deck,
  // no answered thread or held hand-off blocks first, and the record read answers
S1's Lanes (GET /api/record lanes)
```

## Tests

1. `an idle main lane with a green pick refuses the stop`: `run` → `{ decision: 'block' }` whose reason is the refusal naming the green ticket.
2. `a red pick is the one named`: `run` → the reason names the red ticket.
3. `nothing queued lets the turn end`: `run` → null.
4. `a crew agent's stop is never refused`: `run` → null for a payload with `agent_id`.
5. `stop_hook_active lets the second stop through`: `run` → null with a green pick.
6. `an open handoff lets the stop through`: `run` → null with a green pick.
7. `a record read that fails refuses nothing`: `run` → not a block.

Rewrite check: the hook reading the lane from any other daemon answer keeps all seven results.
