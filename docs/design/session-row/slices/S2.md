## Interface

```
deck_read { id?, brief?, limit?, open?, repo?, author?, messages?: integer | "all" }
selectItems(items, { id?, open?, limit?, brief?, messages? }): Item[]
windowOf(item, messages?: number | 'all'): WindowedItem   // default: whole under 5 messages, else last 5
WindowedItem = Item & { body?: string, replies: Reply[], window?: { shown: number, total: number, left: 'earliest' | 'latest' } }
```

## Tests

1. `messages 3 is the last three`: `windowOf` → a 10-message thread gives replies 8-10 (message 1 is the post), `window` { shown 3, total 10, left 'earliest' }, no `body`.
2. `messages -2 is the post and the first reply`: `windowOf` → `body` and reply 1, `left 'latest'`.
3. `all, zero and a word`: `deck_read` → `"all"` whole with no `window`; `0` and `"last"` refused naming `messages`.
4. `under five comes back whole`: `windowOf` → a 4-message thread, no `messages`, whole.
5. `six comes back as its last five`: `windowOf` → 5 of 6; a ~127k-character chat fixture serialises under 3,000 characters.
6. `an open read windows each item`: `selectItems` → `open: true` over a 6-message thread returns its last 5; `brief` unchanged.
7. `a reply windowed out is not handed over`: `deck_read` → as the pilot, an 8-message thread hands over 5 messages and `pilot wait` still takes the 3rd.
8. `the hooks read whole threads`: `deck_read` → `messages: "all"` from `session-handoff`'s read keeps a long hand-off's `body`.

Rewrite check: replacing the slicing in `windowOf` keeps every shown/left/total above and the hand-off of exactly what was shown.
