## Files owned

- `scripts/install-settings.mjs`: `Bash(pilot ps)`, `Bash(pilot gc)` and `Bash(pilot deck --stop *)` join the pilot allow rules, skipped as the others are when a user rule denies or asks.
- `scripts/test/install-allow-gc.test.mjs` (new): the pins.
- `docs/INSTALL.md`: a step that runs `pilot gc` after the command is on the PATH, and the settings table names the three rules.

## Interface

```
PILOT_ALLOW (install-settings.mjs): adds 'Bash(pilot ps)', 'Bash(pilot gc)', 'Bash(pilot deck --stop *)'
INSTALL.md step 4: `pilot gc` run once; its lines in the step-10 report
```

## Tests

1. `the install writes the three rules`: `PILOT_ALLOW` → all three in `permissions.allow` of a fake home's settings.
2. `a user's deny on pilot gc wins`: `PILOT_ALLOW` → the rule is not written and the report says so.
3. `a second install adds nothing`: `PILOT_ALLOW` → the settings are byte-identical after a rerun.

Rewrite check: replacing the merge with a JSON patch keeps the three results.
