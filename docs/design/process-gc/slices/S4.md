# S4 `pilot gc` stops orphans, and a landing runs it

Feature `process-gc` · delivers spec 4 · source: `../architecture.md` §2, §5 L5, L11, L14 · after: S3 (`bin/pilot.mjs`, `pilotProcesses`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `deck/gc.mjs` (new): stops each orphan, a tree for a test root, and returns one line per stop.
- `bin/pilot.mjs`: `pilot gc`, with a usage entry; exit 0 always, lines on stdout.
- `scripts/land.mjs`: after the landing, gc's lines join `cleared` in the output.
- `deck/test/gc.test.mjs` (new), `scripts/test/land-gc.test.mjs` (new): the pins.

## Interface

```
// stops only rows with orphan !== null; lines: `stopped <pid> <kind> <worktree|-> (<why>)`
// or `could not stop <pid>: <reason>`; `gc: nothing to stop` when none
export function gc(owned: Owned[], opts?: { kill?: (pid: number, tree: boolean) => void }): string[]
S3's processTable, pilotProcesses: what gc reads
pilot gc: prints gc's lines; land: the same lines before `landed …`
```

## Tests

1. `only orphans are stopped`: `gc` → with the user's deck, a live-leashed daemon and an orphan, `kill` called once for the orphan.
2. `a test root is stopped as a tree`: `gc` → `kill(pid, true)` for a test root.
3. `a failed stop is a line, not a throw`: `gc` → `could not stop <pid>: …`.
4. `pilot gc stops a real planted orphan`: `gc` → a sleeper whose command names `deck/daemon.mjs` with a dead `--leash` is gone, and its line is printed.
5. `land prints gc's lines and still lands`: `gc` → a scratch land with an injected table carries `stopped …` before `landed`.

Rewrite check: replacing `taskkill` with a job-object kill keeps all five results.

## Done

- **Expected**: `pilot gc` clears what the leash could not (pre-feature daemons, crashed waits and trees), and every landing does it too.
