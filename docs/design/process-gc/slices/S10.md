# S10 An idle daemon reports its RSS under 96 MB

Feature `process-gc` · delivers spec 7 · source: `../architecture.md` §2, §3 "Memory" · after: –
Reviewers: `pilot:typescript-reviewer`

## Files owned

- `deck/server-routes.mjs`: `/api/health` adds `rss`.
- `deck/test/daemon-rss.test.mjs` (new): the pins.

## Interface

```
GET /api/health -> { ok: true, pid: number, url: string, seq: number, rss: number } // rss in bytes
```

## Tests

1. `health reports rss`: `GET /api/health` → a positive integer `rss` from an in-process deck.
2. `a fresh idle daemon stays under 96 MB`: `GET /api/health` → `rss < 96 * 1024 * 1024` from a real daemon (leashed to the test once S1 lands, killed in `t.after` either way) 5 s after start.

Rewrite check: replacing `process.memoryUsage().rss` with `process.memoryUsage.rss()` keeps both results.

## Done

- **Expected**: anyone can read a daemon's memory from its health answer, and a regression past 96 MB idle is red.
- **Verification**: `node --test deck/test/daemon-rss.test.mjs`; `npm test`.
- **Evidence**: the measured idle rss in the PR (about 55 MB working set seen on 2026-10-12).
- **Prohibited**: raising the ceiling to pass; sampling before the daemon has started listening.
- **Done when**: both tests and `npm test` are green.
