# S7 Pilot's own gate runs capped and slotted

Feature `process-gc` · delivers spec 5, 7 · source: `../architecture.md` §2, §5 L7, L8 · after: S6 (`takeSlot`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `scripts/gate.mjs` (new): takes a slot, runs `node --test` with the caps and the caller's flags, and returns its status.
- `package.json`: `test`, `test:quiet` and `coverage` run `node scripts/gate.mjs` with their flags.
- `scripts/test/gate.test.mjs` (new): the pins.

## Interface

```
// ['--test', '--test-timeout=60000', `--test-concurrency=${min(4, max(1, floor(cores / 2)))}`, ...args]
export function gateArgv(args: string[], cores: number): string[]
// NODE_OPTIONS gains --max-old-space-size=512; PILOT_GATE_SLOT set to the slot held
export function gateEnv(env: NodeJS.ProcessEnv, slot: number): NodeJS.ProcessEnv
export function runGate(args: string[], opts?: { cwd?: string, spawn?: typeof spawnSync, slot?: typeof takeSlot }): number
export const MAX_CONCURRENCY = 4, CHILD_HEAP_MB = 512
```

## Tests

1. `the gate caps concurrency`: `gateArgv` → `--test-concurrency=4` on 16 cores, `=1` on 1.
2. `the gate caps each child's heap`: `gateEnv` → `NODE_OPTIONS` keeps what was there and adds the cap once.
3. `flags pass through`: `gateArgv` → `--test-reporter=./scripts/quiet-reporter.mjs` kept after the caps.
4. `the gate holds a slot and releases it red or green`: `runGate` → `slot` called once, released on a non-zero status.

Rewrite check: replacing `spawnSync` with `run()` from `node:test` keeps the four results.

## Done

- **Expected**: `npm test` here never runs wider than 4 files at once, nor with more than 512 MB of heap per child, and queues behind two other gates.
- **Verification**: `node --test scripts/test/gate.test.mjs`; `npm test`; `npm run test:quiet | tail -1`.
- **Evidence**: the counts of `npm test` before and after equal; the wall time before and after in the PR.
- **Prohibited**: dropping `--test-timeout`; a heap cap that a test then raises for itself; `shell: true`.
- **Done when**: the four tests, `npm test` and `npm run test:quiet` are green with the same counts as before.

## Seam from grilling (L16, itm_4ae4ed969233)

The census retries itself: poll every 1 s through the 10 s grace; stop what is still alive with the gc stop (L11) and re-check over a second 10 s grace; red only for a survivor, named by pid, kind and command. A test plants a child that dies 3 s after the suite (green, no kill), one that dies only on the gate's kill (green, line says it was stopped), and one that survives the kill (red).

## Seam from S3's security fix (co-pilot, 2026-10-12)

S3 lists a `node --test` root as pilot-owned only when its command line names an absolute path under a pilot checkout (a directory holding `bin/pilot.mjs`). So `gate.mjs` spawns `node --test` with its test globs made absolute from the checkout root (`path.join(root, glob)`), never relative, so a leaked gate tree is visible to `pilot ps`, `pilot gc` and S8's census. One pin: the spawned argv names the checkout root.
