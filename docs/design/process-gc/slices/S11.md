## Interface

```
type ScannerState = 'off' | 'dev-drive' | 'excluded' | 'not-excluded' | 'unknown' | 'not-windows'
// win32: one `powershell -NoProfile` probe of Get-MpComputerStatus RealTimeProtectionEnabled,
// Get-MpPreference ExclusionPath, and `fsutil devdrv query <drive>` for the root's volume (performance mode → 'dev-drive');
// "N/A: Must be an administrator" → 'unknown'
export function checkScanner(opts: { platform?: NodeJS.Platform, run?: (cmd: string, args: string[]) => string, root: string }): { state: ScannerState, lines: string[] }
step lines, for 'not-excluded' and 'unknown': first `one-time, as administrator: create a Dev Drive in performance mode and move <root> onto it (Settings > System > Storage > Advanced > Disks & volumes > Create Dev Drive)`, then `fallback, as administrator: Add-MpPreference -ExclusionPath "<root>"`
```

## Tests

1. `scanning on and root not excluded names both steps`: `checkScanner` → `not-excluded` with the Dev Drive line first and the exclusion line second.
1b. `root on a Dev Drive in performance mode says so`: `checkScanner` → `dev-drive`, no step.
2. `root excluded says so`: `checkScanner` → `excluded`, no step.
3. `exclusions unreadable says cannot tell`: `checkScanner` → `unknown`, the step and "cannot tell without an administrator".
4. `scanning off and other platforms`: `checkScanner` → `off`; `not-windows` with no probe run.
5. `the README paragraph names pilot doctor and the step`: `checkScanner` → its step line appears in `README.md`.

Rewrite check: replacing PowerShell with a WMI query through another tool keeps the six results.
