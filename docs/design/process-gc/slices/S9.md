# S9 The gate counts spawns against a ceiling

Feature `process-gc` · delivers spec 6 · source: `../architecture.md` §2, §5 L10, A2, A7 · after: S8 (`scripts/gate.mjs`)
Reviewers: `pilot:typescript-reviewer`

## Files owned

- `scripts/count-spawns.mjs` (new): a preload that subscribes to the `child_process` diagnostics channel and appends one line per spawn.
- `scripts/gate.mjs`: sets `NODE_OPTIONS=--import=<abs>` and `PILOT_GATE_SPAWNS`, prints the count, and goes red above `SPAWN_CEILING`.
- `scripts/test/gate-spawns.test.mjs` (new): the pins.

## Interface

```
count-spawns.mjs: on each spawn appends `<parent pid> <file>\n` to env.PILOT_GATE_SPAWNS; no-op when unset
// { total, node, git, other } from the file's lines
export function spawnCount(file: string): { total: number, node: number, git: number, other: number }
gate output: `spawns <total> (node <n>, git <g>, other <o>)`; above SPAWN_CEILING: `spawns over <ceiling>`, exit 1
export const SPAWN_CEILING: number // the full suite's measured total + 10%, set in this slice
```

## Tests

1. `three spawns are counted by kind`: `spawnCount` → `{ total: 3, node: 1, git: 1, other: 1 }` from a fixture suite run through the gate.
2. `a grandchild's spawns are counted`: `spawnCount` → a node child that spawns git adds 2.
3. `over the ceiling is red`: `spawnCount` → the gate on the fixture with a ceiling of 2 exits 1 with `spawns over 2`.

Rewrite check: replacing the diagnostics channel with a `child_process` patch keeps the three results.

## Done

- **Expected**: every gate prints how many processes the suite started, and a change that adds many more is red until its PR raises the pin.
- **Verification**: `node --test scripts/test/gate-spawns.test.mjs`; `npm test` prints `spawns …`.
- **Evidence**: the full suite's count in the PR, which the A2 follow-up ticket is sized from.
- **Prohibited**: a ceiling set without measuring; counting only the root process; a warning in place of red (A7).
- **Done when**: the three tests and `npm test` are green and the count is in the PR.

## Seam (co-pilot, 2026-10-13)

The `child_process` diagnostics channel fires only for async `spawn`/`exec`; a `spawnSync`, `execFileSync` or `execSync` publishes nothing on Node 26.1, and sync calls are most of the suite's spawns (281 call sites against 50). So `count-spawns.mjs` keeps the channel for async spawns and also wraps `process.binding('spawn_sync').spawn`, the native hook every sync spawn goes through. That leaves the `child_process` module and its exports untouched, so L10's rejection of patching `child_process` stands; the cost is `process.binding` (DEP0111, documentation-only). A test pins that a `spawnSync` of git is counted.
