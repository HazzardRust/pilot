# S2 A wait whose session is gone exits

Feature `process-gc` · delivers spec 2 · source: `../architecture.md` §2, §5 L1, L3 · after: S1 (`holdLeash`, `sessionPid`)
Reviewers: `pilot:typescript-reviewer`

## Files owned

- `deck/wait.mjs`: `main` holds a leash on the session and ends the poll loop when it goes.
- `deck/test/wait-session.test.mjs` (new): the pins.

## Interface

```
S1's holdLeash, sessionPid: the leash is { pid: sessionPid(env), paths: [] }; no session, no leash
pilot wait output on a gone session: `NO SESSION: <pid> has exited` and exit 0
export function main(argv: string[], inject?: { env?: NodeJS.ProcessEnv, alive?: (pid: number) => boolean }): Promise<number>
```

## Tests

1. `a wait under a killed session exits with NO SESSION`: `main` → under a fake `CLAUDE_PID` sleeper and a deck that never replies, exit 0 with the line ≤ 10 s after the kill.
2. `a wait with no CLAUDE_PID waits as today`: `main` → still parked after 3 s with a live deck, and exit 0 on a reply.
3. `a reply before the session goes is printed once`: `main` → the reply printed and no `NO SESSION` line.

Rewrite check: replacing the leash poll with an abort signal on the long poll keeps the three results.

## Done

- **Expected**: a background `pilot wait` left by a dead session ends on its own within 10 s instead of living up to 110 minutes.
- **Verification**: `node --test deck/test/wait-session.test.mjs deck/test/wait.test.mjs`; `npm test`.
- **Evidence**: test 1 red before (the wait outlives the kill) and green after.
- **Prohibited**: shortening the default timeout instead; marking a reply delivered when the session is gone; exit 1 for a gone session.
- **Done when**: the three tests and `npm test` are green.
