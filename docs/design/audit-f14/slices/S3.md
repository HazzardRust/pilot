# S3 Its feature PR targets main and shows only its commits

Feature `audit-f14` · delivers spec 4, 5 · source: `../architecture.md` §2, §5 L5 L6 · after: S1 (`scripts/integrate.mjs`), S2 (the record base value, `RUN_BASE`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — it creates the host-facing seam that S4, S7 and S8 stand on, and a branch name crosses into `gh`.

## Files owned

- `scripts/stack.mjs` (new): `prBase`. It is the one rule for a feature PR's base.
- `scripts/feature-pr.mjs`: the base comes from `prBase`, on open and on every edit (:122, :184-189).
- `scripts/integrate.mjs`: in `baseOf`, an unchained run's base is the default branch. A chain ends when N's tip is in the default branch by ancestry, not at N's landing on pilot (:313-317).
- `scripts/test/stack-base.test.mjs` (new), `scripts/test/integrate-main.test.mjs` (new; `integrate-base.test.mjs` already exists, from other-host S2, assumed): the pins.

## Interface

```
prBase({ git, host, base }): string
// base = the run record's. 'pilot' → 'pilot' (legacy, A3); the default branch → itself;
// feat/<N> → feat/<N> while N's own-repo PR does not read merged, else the default branch's name
baseOf(cwd): { ref: string, chained?: string }
```

## Behaviours

1. `a main-cut run's PR targets main` (test): `prBase` → `main` for record base `main`.
2. `a stacked PR targets its lower branch until that merges` (test): `prBase` → `feat/a` while the stub host reads `feat/a`'s PR open, and `main` once it reads merged.
3. `the PR range holds only the feature` (test): `baseOf` → `origin/main` for an unchained run. After `pilot integrate`, `git rev-list origin/main..feat/b` in a temp repo holds 0 commits of pilot's other features and 0 pilot merges.
4. `a chain outlives its landing on pilot` (test): `baseOf` → `origin/feat/a` after `Merge feat/a into pilot` exists, until feat/a's tip is an ancestor of origin/main.
5. `a status write does not undo a retarget` (test): `prBase` → `main` when the record base is `feat/a` and the host reads a's PR merged, so `syncFeaturePr` edits nothing.
6. `a record base of the default branch is not read as a chain` (test): `baseOf` → `{ ref: 'origin/main' }` with no `chained` when the record base is `main`. This closes S2's security MEDIUM: until S3, such a record reaches `baseOf` as if chained and `chainGuard` refuses it (fails closed).

Rewrite check: any implementation that asks the host for a's PR state keeps 2 and 5, because the tests stub only `host.reviews`.
Misses: GitHub's own rendering of the range (commits tab). QA's walkthrough step 2 looks at it.
