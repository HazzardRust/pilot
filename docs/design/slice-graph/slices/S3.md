# S3 deck_status takes a list of blockers

Feature `slice-graph` · delivers spec 4 · source: `../architecture.md` §2, L4, L5, L9, A2 · after: S2

## Files owned

- `deck/status.mjs`: `requireRow` takes `after` as a string or a list and stores a non-empty list. `requireChain` walks every blocker (unknown name, cycle) through S1's resolution by name or identifier. Two rows with one identifier are refused. `delivers` is accepted and discarded (A2).
- `deck/tools.mjs`: `after` becomes an array of strings, `delivers` is removed (A2), and the description reads "after draws the graph".
- `deck/test/tree.test.mjs`: the after and delivers tests are rewritten to lists. The delivers render tests are removed in S2.
- `scripts/test/pilot-agents.test.mjs`: the :393-402 tools pins are re-pointed at the new schema words.
- `scripts/test/measure-prompt.test.mjs`: the pilot pin is lowered to the new measure, with its history line.

## Interface

```
deck_status slices[].after: string[]   // "the rows it comes after, by S<n> or name; omit for a first slice"
stored row.after: string[]             // never empty; absent for a first slice
S1's blockersOf, identifierOf: read and resolve; S1's graphOf draws the stored list
```

## Tests

1. `after takes a list and stores it`: `["S2","S3"]` is stored as given, and `graphOf` draws S4 as a convergence.
2. `a string after is upgraded on the next merge`: a stored 0.7.20 row passed through `mergeSliceTable` comes back as a one-item list.
3. `an entry by identifier resolves`: `"S2"` matches "S2 Some title".
4. `an empty list, a blank entry or a duplicate entry is refused, naming the row`.
5. `an unknown entry or a cycle through any blocker is refused`: the existing refusals, extended to lists.
6. `two rows with one identifier are refused`.
7. `delivers is accepted and not stored`.
8. `the schema's after is a list and delivers is gone`: read off `TOOLS`.
9. `the pilot's share is under its pin`: the lowered pin passes.
