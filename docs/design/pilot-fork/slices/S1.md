# S1 `pilot base` puts `pilot` on the run remote (walking skeleton)

Feature `pilot-fork` · delivers spec 1, 2, 3 · source: `../architecture.md` §2, §3 Seams, L1, L2, L3, L7, L14 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `scripts/remotes.mjs` (new): the one reader of `pilot.remote`; it validates the value (L2).
- `scripts/pilot-branch.mjs`: `ensurePilotBranch` and `pilotLineage` read `runRemote`, and a missing `pilot` is seeded from origin's `pilot` (L7). `defaultBranch`, `remoteDefaultBranch` and `assertPushable` keep reading origin.
- `scripts/base.mjs`: the base line gains ` on <name>` or ` local` when the run remote is not origin.
- `scripts/test/remotes.test.mjs` (new): the four cases.
- `scripts/test/base-remote.test.mjs` (new): base against a scratch bare origin plus a second bare remote, and under `none`.

## Interface

```
runRemote(git: (args: string[]) => string): string | null
  // git config pilot.remote ?? 'origin'; 'none' -> null
  // throws "pilot.remote names <x>: not a remote here" / "...: not a remote name"
runRef(runs: string | null, branch: string): string   // '<runs>/<branch>', or '<branch>' when runs is null
ensurePilotBranch({ git }): { sha: string, created: boolean, from?: string }  // from: 'origin pilot' | default name
base line: "base pilot <sha>[ (created from <from>)][ on <runs> | local]"
```

## Tests

1. `unset means origin`: `runRemote` → `'origin'`.
2. `none means local`: `runRemote` → `null`, and `runRef` → `'pilot'`.
3. `a configured name that is not a remote stops the command`: `runRemote` → throws naming `pilot.remote`, for `--upload-pack=x` and for `nosuch`.
4. `base creates pilot on the second remote from origin's pilot`: `ensurePilotBranch` → the second remote's `pilot` is at origin's `pilot` tip, and origin's refs do not move.
5. `base under none creates a local pilot`: `ensurePilotBranch` → a local `pilot` at origin's `pilot` tip, and nothing pushed.
6. `base with the setting unset prints today's line`: `base line` → byte-identical to the existing `base.test` expectation.

Rewrite check: reading the setting another way (another key, an env var) keeps all six results.
