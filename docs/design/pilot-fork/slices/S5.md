## Files owned

- `scripts/handoff.mjs`: the record push (:76) goes to origin when `HEAD` is `feat/`, else to the run remote. Under `none`, a record on any other branch is committed but not pushed, and the line says so.
- `deck/lineage.mjs`: the base is S1's `runRef(runs, 'pilot')`, and the refusal texts (:15, :35) name that ref.
- `scripts/test/handoff-lineage-remote.test.mjs` (new): both, with a second bare remote and under `none`.

## Interface

```
handoff line clause: "record pushed to <remote>" | "record committed locally (pilot.remote none)"
lineage refusal: "a gate1 needs the pilot base: <repo> has no <runRef(runs, 'pilot')>; ..."
S1's runRemote, runRef
```

## Tests

1. `a design branch's record goes to the run remote`: `handoff line clause` → `record pushed to second`, and origin lists no `design/x`.
2. `under none a design record stays local`: `handoff line clause` → `record committed locally (pilot.remote none)`.
3. `the gate1 lineage reads the local pilot under none`: `lineage refusal` → absent for a design branch cut from the local `pilot`; present, naming `pilot`, for one that is not.

Rewrite check: computing the lineage with `merge-base` instead of `rev-list` keeps all three results.
