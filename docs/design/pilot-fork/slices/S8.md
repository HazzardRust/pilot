# S8 `pilot land` deletes the run's merged design/fix/qa branches

Feature `pilot-fork` · delivers spec 6, 8 · source: `../architecture.md` §2, L4, L5, A2 · after: S4 (land.mjs), S6 (deleteMerged)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `scripts/land.mjs`: after the landing push, it lists the run remote's `design/<slug>`, `fix/<slug>-*` and `qa/<slug>` branches and calls S6's `deleteMerged` with `into` set to `feat/<slug>`. Its output gains `deleted: …` and `kept: <branch> (<why>)` lines. `feat/<slug>` is never passed. Under `none` there is nothing to list (A2).
- `scripts/test/land-prune.test.mjs` (new): with gh injected.

## Interface

```
land(options): { ..., deleted: string[], kept: { branch, why }[] }
pilot land output: "deleted: design/x, fix/x-s1" / "kept: fix/x-s2 (not in feat/x)"
S6's deleteMerged
```

## Tests

1. `land deletes the run's merged design and fix branches`: `land` → `deleted` lists them, and origin lists only `pilot` and `feat/x` from the run.
2. `a planted unmerged fix branch survives and is named`: `land` → `kept: fix/x-s2 (not in feat/x)`.
3. `the gate1 and slice merge shas still resolve`: `land` → `git cat-file -e` on both exits 0 from a fresh clone.
4. `another run's branches are untouched`: `land` → `slice/y-s1` is still on origin.

Rewrite check: computing the run's branch set from the run record instead of the prefix keeps all four results.

## Done

- **Expected**: after `pilot land`, origin holds `pilot` and `feat/<slug>` from the run, plus anything unmerged, which the output names.
- **Verification**: `node --test scripts/test/land-prune.test.mjs scripts/test/land*.test.mjs`; `npm test`.
- **Evidence**: tests 1, 2 and 4 red before, green after.
- **Prohibited**: never `feat/<slug>` or another slug's branch; no deletion when the landing fails.
- **Done when**: the four tests and the suite are green.

## Seam change (co-pilot, 2026-10-12)

`fix/<slug>-*` above is narrowed to `fix/<slug>-s<n>` (digits only), as built in #605: with `-*`, run `x` would match a longer slug's `fix/x-y-s1`, and gh's MERGED check does not read the PR's base. A fix branch with any other suffix is kept, never deleted. It moves no spec line and no locked decision.
