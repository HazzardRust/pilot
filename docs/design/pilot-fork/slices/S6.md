# S6 `pilot branches prune` deletes merged run branches, guarded

Feature `pilot-fork` · delivers spec 6, 7, 8 · source: `../architecture.md` §2, §3 Seams, L4, L5, L9, L12, L13 · after: S1 (remotes.mjs)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `scripts/branches.mjs` (new): `assertDeletable`, `deleteMerged`, and `main` for `pilot branches prune [--dry-run]`.
- `bin/pilot.mjs`: the `branches` subcommand and its help lines.
- `scripts/test/branches.test.mjs` (new): the guard, the merged test and the command, against scratch repos with gh injected.

## Interface

```
assertDeletable(branch: string, { git }): void
  // only plain slice/ fix/ qa/ design/ feat/ names; never pilot or origin's default; case-insensitive
deleteMerged({ git, gh, branches: string[], into?: string, wait?: number }): { deleted: string[], kept: { branch, why }[] }
  // merged = gh PR state MERGED; with no PR, tip an ancestor of origin/<into>
  // feat/ deleted on origin, the rest on S1's runRemote (skipped when null); one `git push <remote> --delete` per remote
pilot branches prune [--dry-run]   // every run branch on origin and the run remote; "deleted …" and "kept <branch>: <why>" lines
```

## Tests

1. `the guard refuses anything but run prefixes`: `assertDeletable` → throws for `pilot`, `main`, `Main`, `refs/heads/x`, `-d`, `feature/x`; passes `slice/a-s1`.
2. `an open PR's branch is kept and named`: `deleteMerged` → `kept: [{ branch: 'feat/x', why: 'PR #3 open' }]`.
3. `a merged PR's branch is deleted on origin`: `deleteMerged` → origin no longer lists `slice/x-s1`.
4. `a branch with no PR is deleted only when its tip is in into`: `deleteMerged` → on the second remote, `design/x` is deleted when it is an ancestor of `origin/feat/x`, and kept otherwise.
5. `dry-run deletes nothing`: `pilot branches prune [--dry-run]` → the same lines, and both remotes unchanged.
6. `a deleted branch's sha still resolves`: `deleteMerged` → `git cat-file -e <tip>` exits 0 on a fresh clone.

Rewrite check: deleting through the GitHub API instead of `git push --delete` keeps all six results.

## Done

- **Expected**: `pilot branches prune` lists or deletes every merged run branch and names each one it kept, with the reason.
- **Verification**: `node --test scripts/test/branches.test.mjs scripts/test/cli-wiring.test.mjs`; `npm test`.
- **Evidence**: all six red before, green after. Live: `node bin/pilot.mjs branches prune --dry-run` in a scratch clone, output pasted.
- **Prohibited**: no deletion outside `deleteMerged`; no `--force`; no deletion when gh fails; never run on HazzardRust/pilot (L12).
- **Done when**: the six tests and the suite are green, and the live dry-run output has been read.

## Seam change (co-pilot, 2026-10-12)

From the principles review and the security review of the integrated feature:

- `pilot branches prune --slug <slug> [--dry-run]`: `--slug` is required, and only that run's branches (`isRunBranch`)
  are judged; without it the command prints its usage and deletes nothing (K5, SR2). The closing step in
  `agents/pilot.md` runs it with the run's slug.
- `deleteMerged({ git, gh, select, into?, wait?, dryRun? })` lists origin and the run remote itself and judges each branch
  `select` takes, in place of a `branches` list (F5). `assertDeletable` is gone; its rule stays as the refusal a kept
  branch names (F1). One `gh pr list --state all` per call, indexed by head (F6).
- Each `git push <remote> --delete` carries `--force-with-lease=refs/heads/<branch>:<tip>`, the tip judged, so a branch
  that moved since is not deleted (K3). A failed push throws with `deleted` and `kept` (K4).
