## Interface

```
enterStage(deck, ticket, state: 'yellow' | 'green', place: 'tail' | 'head' | 'landed' = 'tail') -> void
  // already in `state`: nothing changes (L4)
  // 'tail': as S1. 'head': just before the stage queue's first ticket (the resume)
  // 'landed': before the first yellow with no greenAt or a later greenAt; none: the tail (A2)
  // state 'green' and no ticket.greenAt: ticket.greenAt = now (ISO), never rewritten or cleared
ticket.greenAt?: string               // first green entry; absent on tickets from before this ships
resolveItem(id, resolution, author)   // a signed gate1: its ticket yellow, the yellow tail
reopenItem(id)                        // a closed ticket: green, the green tail; greenAt kept
pivotTicket(id) -> { ticket, gate2 }  // the ticket yellow, in landing order (A1, A2)
```

## Tests

1. `a gate1 signed later is the yellow tail`: `resolveItem` → with one yellow queued, signing an older red's gate1 leaves it last in `ticketQueueOf(…, 'yellow')`.
2. `a reopened ticket is the green tail`: `reopenItem` → with one green queued, reopening an older closed ticket leaves it last of the green queue.
3. `the first green entry stamps greenAt once`: `enterStage` → `needTicket` writes `greenAt`; a pivot and a second gate2 post leave it unchanged; `yieldTicket` writes none.
4. `pivots in a row keep landing order`: `pivotTicket` → with yellow 5 (never green), greens 3 and 4 (3 first green earlier), pivoting 4 then 3 gives yellow queue 3, 4, 5, and 3 then 4 gives the same.
5. `an unstamped pivot follows the stamped ones`: `enterStage` → with place `'landed'` and no `greenAt`, it lands after every stamped yellow and before the never-green ones; other items keep their relative order.

Rewrite check: any implementation that leaves the yellow queue as stamped tickets by `greenAt`, then the rest in arrival order, keeps all five, and `resume.test.mjs` passes unchanged.
