## Interface

```
OWNER_KINDS = ['pilot', 'qa', 'teacher', 'auditor', 'architect']     // PASS_KINDS unchanged
mergeDecisionOf(items: Item[], ticketId: string): Item | undefined     // resolved, author 'architect', ticket === ticketId
GET /api/tickets?repo=<abs path> -> { live: Ticket | null, green: Ticket[], decision: { id, resolution } | null }
                                  // Ticket: { id, title, estimate, body, comments: { from, text }[] }; marks nothing delivered
pilot tickets                      // the above as Markdown: live first, then each green ticket, or "no other green ticket";
                                 // "merge decided: <id> — <resolution>" when decision is set; exit 1 if the deck is down
pilot wait --as architect --item <id>   // works unchanged once the kind is listed
```

## Tests

1. `an architect's own post is owned by the architect`: `postItem` with author `pilot:pilot-architect` stores `owner: 'architect'`.
2. `a reply on the architect's thread goes to the architect's wait alone`: a pilot `deck_wait` is handed nothing; an architect wait with `item` gets it and marks `deliveredTo` architect.
3. `a thread cannot be passed to the architect`: `deck_reply` with `to: "architect"` is refused (PASS_KINDS).
4. `the architect's quiet thread falls back to the pilot`: ADR 0045's windows hand the reply to the pilot, and the note offers no pass back.
5. `/api/tickets lists the live ticket and the repository's green queue in deck order`, excluding yellow, closed and other repositories' tickets, with bodies and comments.
6. `/api/tickets marks no reply delivered`.
7. `mergeDecisionOf finds a resolved architect item naming the ticket`, and not an open one, a pilot one, or one naming another ticket.
8. `pilot tickets prints "no other green ticket" on a one-ticket deck and "merge decided" once a decision exists`.
