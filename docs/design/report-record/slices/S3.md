# S3 A stored reply on a report reaches no pilot

Feature `report-record` · delivers spec 3 · source: `../architecture.md` §2, §3, L2, L3 · after: S1 (`deck/items.mjs` `isRecord`)
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`

## Files owned

- `deck/store-runs.mjs`: `repliesSince` skips user replies on a record, so every `deck_wait` (any `--as`, `--item` included) never sees one.
- `hooks/lib/deck.js`: `isRecord`, the hooks' spelling of S1's `RECORD_KINDS`, exported; `awaitsPilot` false on a record, so `unanswered` (Stop gate, inbox line) never names one.
- `hooks/test/join.test.js`: the daemon and the hooks agree on the record kinds.
- `hooks/test/report-record.test.js` (new): the Stop gate and inbox pins with a planted reply.
- `deck/test/wait-record.test.mjs` (new): the wait pins with a planted reply.
- `deck/server-tools.mjs`: `deck_read` hands off no user reply on a record and stamps none delivered (seam change, co-pilot, 2026-10-15: found by the S3 security review; spec 3).

## Interface

```
deck/store-runs.mjs
  export function repliesSince(since?: number, limit?: number): { replies, seq }   // no reply whose item isRecord
  fallbackDue(repo, …)  // never a record
hooks/lib/deck.js
  isRecord(item): boolean                          // ['report'], pinned equal to S1's isRecord
  unanswered(items, posted, baseline, repo): Item[] // never a record
S1's isRecord: deck/items.mjs
```

## Tests

1. `a planted reply on a report is not handed to a waiter`: `repliesSince` → the question's reply only, with a report's and a question's planted after `since`.
2. `wait --item on a report never returns`: `repliesSince` → nothing for the report's id; the `pilot wait --item` subprocess times out with `NO REPLY`.
3. `the Stop gate lets a turn end over a report's reply`: `unanswered` → `[]` for an open report whose last message is the user's, posted by this session.
4. `the inbox line names no report`: `unanswered` → the question only, over a report and a question both with fresh user replies.
5. `the daemon and the hooks agree on the record kinds`: `isRecord` → equal on every kind, chat, user, handoff, made-up, undefined.

Rewrite check: moving the filter from `repliesSince` into `deck_wait`'s predicate keeps tests 1, 2 and 5.
