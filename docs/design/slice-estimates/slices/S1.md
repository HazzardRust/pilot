## Interface

```
deck_post (kind ticket) { ..., sliceCount: integer >= 0 }   // required; `estimate` refused: "a ticket item takes no estimate. It takes ..."
deck_ticket merge -> "Merged <id> into <host>: <n> slices." (or ": no slice count." when neither ticket has a count; S2, PR #300)
function withoutTicketEstimate(item): item   // read migration: drops `estimate` from a ticket, idempotent
ticket.sliceCount: number                    // the posted count; mergeTicket sums it into the host
```

## Tests

1. `a ticket posted with sliceCount 15 is stored with it`.
2. `a ticket posted with estimate is refused naming estimate and listing sliceCount`.
3. `a ticket posted without sliceCount is refused: a ticket needs sliceCount`.
4. `an unplanned row reads "8 slices"; a planned row reads the plan's count; a ticket with no count shows no size`.
5. `merging a 4 into a live 8 leaves the host at 12 and answers "12 slices"`.
6. `a stored ticket with estimate reads back without it, and a second read changes nothing`.
