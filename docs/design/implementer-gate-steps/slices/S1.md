# S1 Skeleton: measure-prompt prints each agent's pinned share and its headroom

Feature `implementer-gate-steps` · delivers spec 2 · source: `../architecture.md` §2, §3 Seams, L3, L4 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: sonnet — precise: the Interface, the two pin files and the output shape are fixed, about 70 lines, no assumed line, no security trigger.

## Files owned

- `scripts/measure-prompt.mjs`: `ownShare`, `pinsOf`, `pinned`, `formatPinned`; the CLI prints the pinned table under the existing one.
- `scripts/test/measure-headroom.test.mjs` (new): the pins, on a fixture repository.

## Interface

```
scripts/measure-prompt.mjs
  ownShare(row) -> number            // (definition + skills + tools) / 4, unrounded: the figure every pin counts
  pinsOf(root: string) -> Map<string, number>
    // every scripts/test/*.test.mjs; a test( block naming row.agent === '<agent>' and `own <= <n>` pins <agent> at n
  pinned(rows, pins) -> Array<{ agent, own: number, pin: number | null, headroom: number | null }>
  formatPinned(pinned) -> string     // | Agent | Own share | Pin | Headroom |, '–' where there is no pin
  CLI (text mode): the existing table, a blank line, then formatPinned; --json unchanged (L4)
```

## Tests

1. `the own share is the unrounded figure a pin counts`: `ownShare` → 26.75 for definition 100, skills 0, tools 7.
2. `a pin is read off the test that names its agent`: `pinsOf` → a fixture test file pinning `pilot` at 30 and `pilot-qa` at 12.5 yields both; an agent with no pin test is absent.
3. `headroom is the pin less the own share`: `pinned` → headroom 3.25 against a pin of 30; `null` pin and headroom for an unpinned agent.
4. `the command prints the pinned table under the existing one`: `formatPinned` → the CLI's stdout carries `| Agent | Own share | Pin | Headroom |` after the existing header, and `--json` parses to the same rows as before.

Rewrite check: the pins are read from the pin tests' source text, not a parsed registry, which would fail the fixture test above.
