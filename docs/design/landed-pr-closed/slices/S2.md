## Interface

```
base({ cwd, say, warn, concluding, host }) -> exit code   // prints `base <pilot branch> <sha>…` or `base feat/<N> …`
RUN_BASE: RegExp   // unchanged: the read shape (any safe branch name)
isWriteBase(base: string) -> boolean   // deck/runs.mjs: RUN_BASE.test(base) && (isPilotName(base) || base starts feat/)
// record write: base not isWriteBase -> RunRefusal "base must be your pilot branch, pilot or feat/<slug>, not …"
```

Seam change (co-pilot, assumed): RUN_BASE stays the read shape (integrate.mjs:375, feature-pr.mjs:123, lineage.mjs:42 read it); the write check is isWriteBase. Moves no spec line and no locked decision.

## Behaviours

1. `pilot base prints the pilot branch on a host` (test): `base` → in `base-main.test.mjs`'s origin-with-host fixture the line is `base pilot <sha>`, not `base main`.
2. `a main base is refused at write` (test): `RUN_BASE` → `deck_status`'s record write with `base: "main"` throws `RunRefusal` naming the allowed forms; `hazzardrust-pilot`, `pilot` and `feat/x` pass.
3. `a stored main record still reads` (test): `RUN_BASE` → a run.json already holding `"base": "main"` reads back with base `main` after another status write that sends no base.

Rewrite check: whatever regex or check is used, `main` cannot be newly written and an existing `main` record is untouched.
Misses: an agent cutting its worktree from main while recording the pilot branch; S3's gate1 line shows the recorded base, and the lineage check (`deck/lineage.mjs`) refuses a design branch off the wrong tip.
