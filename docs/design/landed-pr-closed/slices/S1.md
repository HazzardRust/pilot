# S1 A main-cut run's landing merges its own PR (walking skeleton)

Feature `landed-pr-closed` · delivers spec 1 · source: `../architecture.md` §2, §3 F4, §5 L2-L3, §6 A2 · after: –
Reviewers: `pilot:typescript-reviewer`
Model: opus — the landing writes a PR on a shared remote, and the order against the pilot push decides whether it reads merged.

## Files owned

- `scripts/land.mjs`: `retargetOwn` before the merge loop; the `!legacy` early return, `featurePr` and `featureLine` deleted; the bin output keeps `mainLine`.
- `scripts/test/land-feature-line.test.mjs`: rewritten for the main-cut record: retarget, then the release PR line.

## Interface

```
retargetOwn({ host, head, name }) -> string[]
// each open own-repo PR whose head is `head` and base is not `name`: host.edit(n, { base: name });
// one `retarget #<n> to <name>` line each, or `retarget failed for #<n>: <why>`; never throws
land(...) -> { head, sha, retried, already, adr, retargeted, main, ... }   // no `feature` key
```

## Behaviours

1. `a main-cut record's PR moves to the pilot branch before pilot is pushed` (test): `retargetOwn` → with a `base: main` record and an open PR #12 base main, one `pr edit 12 --base pilot` while origin's pilot is still the pre-landing tip, and the output holds `retarget #12 to pilot`.
2. `a main-cut landing ends on the release PR line` (test): `land` → the last line matches `main gets pilot: #<m>` and no `feature PR:` line appears.
3. `a PR already on the pilot branch is left alone` (test): `retargetOwn` → a legacy record with PR base pilot: 0 `pr edit` calls, 0 retarget lines.
4. `a refused edit does not fail the landing` (test): `retargetOwn` → a `gh pr edit` that exits 1 gives `retarget failed for #12: …`, and the landing still lands on pilot.

Rewrite check: any implementation that merges the main-cut PR by the pilot push edits its base before that push and ends on `mainLine`.
Misses: whether GitHub reads the PR merged after the push (a fake `gh` cannot turn it). QA reads that on a real host or by `gh pr view` on the next real landing of a main record.

## Done

- **Expected**: landing a run whose record says `main` moves its PR onto the pilot branch, the push merges it, and the release PR carries it to main.
- **Verification**: `node --test scripts/test/land-feature-line.test.mjs scripts/test/land-main-pr.test.mjs scripts/test/land.test.mjs`; `npm run test:quiet`.
- **Evidence**: behaviours 1-2 red before (today: `feature PR: #12 into main`), green after; `git diff --stat` within 400 lines.
- **Prohibited**: no `gh pr close` or `ready` verb, and no edit to `deck/host-github.mjs`'s allowlist; no retarget after `mergeIntoPilot`; no edit to `restack`/`prBase` (A5).
- **Done when**: the four behaviours hold and the gate is green.
