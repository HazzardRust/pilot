# S2 Machine state lives in its own file

Feature `portable-store` · delivers spec 2, 8 · source: `../architecture.md` §2, §3 F3-F5, §5 L1, L3, §6 A4 · after: S1 (`store-codec.mjs`, `store-core.mjs`)
Reviewers: `pilot:typescript-reviewer`
Model: opus — spec 2 is assumed (A4) and the split touches every write of the store.

## Files owned

- `deck/machine.mjs` (new): read and write `machine.json`, roots with overrides.
- `deck/store-codec.mjs`: `toStored`/`fromStored` split and rejoin the machine fields of F4.
- `deck/store-core.mjs`: `readDeck` reads `machine.json`, `writeDeck` writes both files; at most 6 net lines.
- `deck/store-runs.mjs`: `registerRun`'s raw `existing.repo === run.repo` (:475, :483) becomes `sameRepo`; net 0 lines.
- `deck/test/machine.test.mjs` (new): the pins.

## Interface

```
type Machine = { roots: Roots, sessions: Record<runId, { pid, session, lastSeenAt }>,
                 coPilots: object, switches: object, live: itemId[], landingPids: Record<itemId, number> }
readMachine(dir: string): Machine          // a missing or unreadable file reads as an empty Machine
writeMachine(dir: string, machine: Machine): void   // atomic, through refuseGateHomeWrite
rootsOf(machine: Machine, home: string, platform: string): Roots   // S1's defaultRoots plus overrides
registerRun(run): Run   // existing, deck/store-runs.mjs; dedupes by sameRepo, not raw ===
writeDeck(deck): void   // existing, deck/store-core.mjs; the machine file first, then deck.json
S1's toStored / fromStored: now (deck, roots) -> { stored, machine } and (stored, machine, roots) -> deck
```

## Behaviours

1. `deck.json names no machine state` (test): `writeMachine` → after a `writeDeck` of a deck with a live run, a co-pilot lease, a switch, a live ticket and a landing pid, `deck.json` holds 0 `pid`, `session`, `lastSeenAt` keys and empty-or-absent `coPilots`, `switches`; `machine.json` holds each.
2. `a lost machine file loses no thread` (test): `readMachine` → with `machine.json` deleted, `readDeck` returns every item, record and chat, every repo decoded, runs present with no session; the next write creates the file.
3. `a run re-registers under another spelling` (test): `registerRun` → one run, not two, for `C:\Users\a\projects\pilot` after `C:/Users/a/Projects/pilot`.
4. `the deck starts without its machine file` (run): a scratch store from S1's real copy, `machine.json` deleted, `pilot deck` started; threads, the ticket queue and chat open in the browser.
5. `an unreadable machine file is set aside, never overwritten` (test): `writeMachine` → with `machine.json` holding bytes that do not parse, it reads as empty and the next write sets them aside as `machine.json.unreadable-<day>[-n]` first (the store's `setAside`); a file that cannot be set aside is not replaced. Added at the start of the build (co-pilot, assumed).
6. `the machine file is written first` (test): `writeDeck` → a `machine.json` that cannot be written leaves `deck.json` as it was; machine state a `deck.json` from before the split still holds is read, `machine.json` winning entry by entry. Added at the start of the build (co-pilot, assumed).

Rewrite check: storing machine state anywhere else keeps 1 and 2 as long as `deck.json` names none of it.
Misses: a live session's experience when its machine file vanishes mid-run; QA's walkthrough reads it.
