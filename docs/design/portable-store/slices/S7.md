# S7 The exporting deck warns its queue may live elsewhere

Feature `portable-store` · delivers spec 10 · source: `../architecture.md` §2, §5 L7, §6 A3 · after: S4 (`exported.json`)
Reviewers: `pilot:typescript-reviewer`
Model: opus — spec 10 is assumed (A3).

## Files owned

- `deck/exported.mjs` (new): read the mark, and the notice's text.
- `deck/daemon.mjs`: on start, one notice item when the mark is newer than the last notice.
- `deck/doctor.mjs`: an `exported` row.
- `deck/test/exported.test.mjs` (new): the pins.

## Interface

```
S4's exported.json, by reference
exportedMark(dir: string): { at: string, file: string } | null
exportedNotice(mark, lastNoticeAt: string | null): { title: string, body: string } | null   // null when already noticed
```

## Behaviours

1. `one notice per export` (test): `exportedNotice` → a notice for a mark newer than the last notice, null for the same mark again.
2. `doctor names the export` (test): `exportedMark` → doctor's `exported` row reads the mark's time; no row without a mark.
3. `the deck shows it once` (look): a scratch store exported, the deck started twice; one notice in the browser.

Rewrite check: any once-only rule keeps 1.
Misses: a user who never opens the deck after exporting; ADR 0230 says sync is the real guard.
