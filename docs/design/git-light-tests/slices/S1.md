# S1 Walking skeleton: the sync family builds once and restores per test

Feature `git-light-tests` · delivers spec 1, 3, 4, 6 · source: `../architecture.md` §2, §3 F3-F5 and Seams, §6 A1, A2, A6 · after: –
Reviewers: `pilot:typescript-reviewer`, `pilot:security-reviewer`
Model: opus — a new seam on assumed decisions (A1, A2), and it sets a process-wide git environment variable for every spawn below it.

## Files owned

- `scripts/test/lib/git-fixture.mjs` (new): `gitFixture`, plus the `GIT_CONFIG_GLOBAL` file written on import.
- `scripts/test/git-fixture.test.mjs` (new): the seam's pins.
- `scripts/test/sync.test.mjs`: `repos` becomes a `build`; its `config` loop and cleanup go.
- `scripts/test/sync-remote.test.mjs`: the same for `scratchRepos`.
- `scripts/test/merge-into-pilot.test.mjs`: the same for its builder.
- `scripts/test/pilot-branch.test.mjs`: the same for its builder.

## Interface

```
// import './lib/git-fixture.mjs' first: imports fake-home.mjs, then sets
// process.env.GIT_CONFIG_GLOBAL to a per-process file: user.name, user.email,
// commit.gpgsign=false, core.checkStat=minimal
gitFixture<T>(t: TestContext, key: string, build: (dir: string) => T): T
  // first call for key in this process: mkdtemp dir, build(dir), snapshot dir as the template
  // later calls: restore dir from the template (same path, timestamps kept), return the same T
  // a second call for key inside one test: builds fresh into a new temp dir
  // build must not call t.after, nor return closures over mutable in-memory state
  // dir and template are removed on process exit
```

## Tests

1. `the build runs once per key`: `gitFixture` → `build` is called once across three tests that share a key, and twice for two keys.
2. `a dirtied fixture is pristine for the next test`: `gitFixture` → a commit, a new branch and an untracked file made in one test are all absent in the next; `git status --porcelain` is empty and HEAD is the build's SHA.
3. `a second call in one test gets its own directory`: `gitFixture` → two different dirs, both pristine.
4. `identity comes from the global file`: `gitFixture` → `git commit` in a fresh `git init` succeeds with no `git config` call, and `git config user.email` reads the fixture's value.
5. `the sync family still passes`: `gitFixture` → sync, sync-remote, merge-into-pilot and pilot-branch pass with their test count unchanged.

Rewrite check: replacing restore-in-place with copy-and-rewrite to a new path keeps tests 1, 4 and 5 true.

## Seam rulings (co-pilot, after integration)

- **No `GIT_CONFIG_NOSYSTEM`** (*assumed*, co-pilot, 2026-10-16). The seam isolates the global config (`FAKE_HOME/.gitconfig` via `GIT_CONFIG_GLOBAL`) and each fixture's repository; it leaves git's system config read, as the suite did before S1. Git for Windows' system config carries `core.autocrlf`, and dropping it would change line endings under the code being tested. "Pristine" in spec 6 means the fixture directory and the global config, which is what its evidence tests. Later slices add nothing to the seam's environment.
- **Per-file wall time** in each slice's evidence is `node --test <file>`'s `duration_ms`, not gate wall time (the census adds a 10 s grace).
